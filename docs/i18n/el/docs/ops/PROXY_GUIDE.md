## Γιατί να χρησιμοποιήσετε Proxies;

Πολλοί πάροχοι AI περιορίζουν την πρόσβαση ανά γεωγραφική περιοχή. Προγραμματιστές σε** Ρωσία, Κίνα, Ιράν, Κούβα, Τουρκία** και άλλες χώρες αντιμετωπίζουν σφάλματα όπως:

```
unsupported_country_region_territory
```

Ακόμη και εκτός αποκλεισμένων περιοχών, οι διακομιστής μεσολάβησης είναι χρήσιμοι για:

| Περίπτωση χρήσης         | Περιγραφή                                                                        |
| ------------------------ | -------------------------------------------------------------------------------- |
| **Γεωγραφική παράκαμψη** | Πρόσβαση σε OpenAI, Anthropic, Codex, Copilot από αποκλεισμένες χώρες            |
| **περιστροφή IP**        | Διανείμετε αιτήματα σε πολλαπλά IPs για να αποφύγετε τον περιορισμό του ποσοστού |
| **Μυστικότητα**          | Απόκρυψη του πραγματικού σας IP από παρόχους ανάντη                              |
| **Συμμόρφωση**           | Δρομολογήστε την κυκλοφορία μέσω συγκεκριμένων δικαιοδοσιών                      |
| **Δοκιμές**              | Προσομοίωση αιτημάτων από διαφορετικές περιοχές                                  |

## Προεπιλεγμένη κατάσταση διακομιστή μεσολάβησης για νέους λογαριασμούς

Σε** Ρυθμίσεις → Proxy → Καθολική διαμόρφωση** , χρήση** Ενεργοποίηση διακομιστή μεσολάβησης από προεπιλογή για νέες συνδέσεις** για να επιλέξετε την αρχική κατάσταση διακομιστή μεσολάβησης των λογαριασμών παρόχου που προστέθηκαν πρόσφατα.

Η νέα ρύθμιση ελέγχει την αρχική κατάσταση διακομιστή μεσολάβησης των λογαριασμών παρόχου που προστέθηκαν πρόσφατα. Δεν αλλάζει τους υπάρχοντες λογαριασμούς ούτε αντικαθιστά τον γενικό διακόπτη διακομιστή μεσολάβησης. Η αρχική του τιμή διατηρεί την προηγούμενη συμπεριφορά. Απενεργοποιήστε το μία φορά για να δημιουργήσετε μελλοντικούς λογαριασμούς με τον διακομιστή μεσολάβησης απενεργοποιημένο από προεπιλογή.

Η προτίμηση αποθηκεύεται ως `defaultNewConnectionProxyEnabled` μέσω των υπαρχουσών ρυθμίσεων API. Είναι προεπιλογή σε `true` όταν δεν αποθηκεύεται ποτέ. Η αποθήκευση `false` τίθεται σε ισχύ για επόμενους νέους λογαριασμούς χωρίς επανεκκίνηση. `POST /api/providers` δέχεται ένα προαιρετικό αυστηρό boolean `proxyEnabled`. ένα ρητό `true` ή `false` έχει προτεραιότητα έναντι της προεπιλογής δημιουργίας. Παράλειψη σε διπλότυπο λογαριασμό ή επανασύνδεση OAuth διατηρεί την αποθηκευμένη κατάσταση αυτού του λογαριασμού. Οι μεμονωμένοι λογαριασμοί μπορούν ακόμα να ενεργοποιηθούν ή να απενεργοποιηθούν στη συνέχεια.

Οι επιλεκτικές μεταφορές παρόχου χρησιμοποιούν την προεπιλογή της εγκατάστασης προορισμού για νέους λογαριασμούς και διατηρούν την πολιτική προορισμού κατά την αντικατάσταση υπαρχόντων λογαριασμών. Οι εναλλαγές διακομιστή μεσολάβησης δεν είναι φορητά πεδία μεταφοράς. Η πλήρης επαναφορά αντιγράφων ασφαλείας και η ιστορική μετεγκατάσταση JSON/SQL διατηρούν την υπάρχουσα σημασιολογία επαναφοράς, συμπεριλαμβανομένων των αποθηκευμένων τιμών λογαριασμού και των προεπιλογών σχημάτων παλαιού τύπου. μια πλήρης επαναφορά ρυθμίσεων μπορεί επίσης να επαναφέρει αυτήν την προτίμηση.

Αυτή η προτίμηση δεν εκχωρεί πληρεξούσιο ούτε αποδεικνύει ότι κάποιος είναι υγιής ή σε χρήση. Η πραγματική δρομολόγηση εξακολουθεί να εξαρτάται από τον γενικό διακόπτη διακομιστή μεσολάβησης και την ισχύουσα διαμόρφωση διακομιστή μεσολάβησης. Οι συνθετικοί πάροχοι χωρίς διαρκή λογαριασμό, η επισκεψιμότητα OAuth πριν από τη δημιουργία λογαριασμού, οι διακομιστής μεσολάβησης environment/system και η δικτύωση εξωτερικών συστημάτων υποστήριξης δεν εμπίπτουν στο πεδίο εφαρμογής τους.

## Σύστημα μεσολάβησης 4 επιπέδων

OmniRoute υποστηρίζει διαμόρφωση διακομιστή μεσολάβησης στο** τέσσερα ανεξάρτητα πεδία** , επιλύθηκε με σειρά προτεραιότητας:

```
Priority Resolution Order (highest → lowest):

  1. 🔵 Account/Connection Proxy  →  per API key / OAuth connection
  2. 🟡 Provider Proxy            →  per provider (e.g., all OpenAI traffic)
  3. 🟠 Combo Proxy               →  per combo/routing configuration
  4. 🟢 Global Proxy              →  all traffic, all providers
```

### Πώς λειτουργεί η Ανάλυση

Όταν OmniRoute στέλνει ένα αίτημα σε έναν ανάντη πάροχο, καλεί `resolveProxyForConnectionFromRegistry()` που ελέγχει κάθε επίπεδο με τη σειρά:

1. **σε επίπεδο λογαριασμού** — Υπάρχει αντιστοιχισμένος διακομιστής μεσολάβησης σε αυτήν τη συγκεκριμένη σύνδεση ID;
2. **σε επίπεδο παρόχου** — Υπάρχει κάποιος διακομιστής μεσολάβησης που έχει εκχωρηθεί σε αυτόν τον πάροχο (π.χ. `openai`);
3. **Σε παγκόσμιο επίπεδο** — Υπάρχει ρυθμισμένος παγκόσμιος διακομιστής μεσολάβησης;
4. **Χωρίς πληρεξούσιο** — Απευθείας σύνδεση με τον πάροχο.

Ο πρώτος αγώνας κερδίζει. Αυτό σημαίνει ότι μπορείτε να ορίσετε έναν καθολικό διακομιστή μεσολάβησης ως εναλλακτικό αλλά να τον παρακάμψετε για συγκεκριμένους παρόχους ή συνδέσεις.

### Τι γίνεται με μεσολάβηση

| Τύπος κυκλοφορίας           | Πληρεξούσιος; | Σημειώσεις                                                      |
| --------------------------- | ------------- | --------------------------------------------------------------- |
| Ολοκληρώσεις συνομιλίας     | ✅            | Όλα τα αιτήματα `/v1/chat/completions`                          |
| Ενσωματώσεις                | ✅            | `/v1/embeddings`                                                |
| Δημιουργία εικόνας          | ✅            | `/v1/images/generations`                                        |
| Ήχος (TTS/STT)              | ✅            | `/v1/audio/*`                                                   |
| ανταλλαγή διακριτικών OAuth | ✅            | Λύνει `unsupported_country_region_territory`                    |
| Δοκιμές σύνδεσης            | ✅            | Το κουμπί "Δοκιμή σύνδεσης" χρησιμοποιεί διακομιστή μεσολάβησης |
| Ανανέωση διακριτικού        | ✅            | Ανανέωση φόντου OAuth                                           |
| Συγχρονισμός μοντέλου       | ✅            | Καταχώριση και ανακάλυψη μοντέλων                               |

## Μητρώο διακομιστή μεσολάβησης (CRUD)

Το μητρώο διακομιστή μεσολάβησης είναι ένας πίνακας SQLite (`proxy_registry`) που αποθηκεύει όλους τους διακομιστή μεσολάβησής σας. Κάθε διακομιστής μεσολάβησης έχει:

| Πεδίο      | Τύπος            | Περιγραφή                                                      |
| ---------- | ---------------- | -------------------------------------------------------------- |
| `id`       | UUID             | Μοναδικό αναγνωριστικό                                         |
| `name`     | Σειρά            | Ετικέτα αναγνώσιμη από τον άνθρωπο                             |
| `type`     | Σειρά            | Πρωτόκολλο: `http`, `https`, `socks5`                          |
| `host`     | Σειρά            | Όνομα διακομιστή μεσολάβησης ή IP                              |
| `port`     | Ακέραιος αριθμός | Αριθμός θύρας                                                  |
| `username` | Σειρά            | Όνομα χρήστη Auth (κρυπτογραφημένο σε κατάσταση ηρεμίας)       |
| `password` | Σειρά            | Κωδικός εξουσιοδότησης (κρυπτογραφημένος σε κατάσταση ηρεμίας) |
| `region`   | Σειρά            | Ετικέτα γεωγραφικής περιοχής                                   |
| `notes`    | Σειρά            | Σημειώσεις ελεύθερου κειμένου                                  |
| `status`   | Σειρά            | `active` ή `inactive`                                          |
| `source`   | Σειρά            | `manual` ή `oneproxy`                                          |

### Δημιουργία διακομιστή μεσολάβησης

**Μέσω πίνακα ελέγχου:**

1. Μεταβείτε στο** Ρυθμίσεις → Proxy**
2. Κλικ** Προσθήκη διακομιστή μεσολάβησης**
3. Συμπληρώστε τον τύπο, τον κεντρικό υπολογιστή, τη θύρα και τα προαιρετικά διαπιστευτήρια ελέγχου ταυτότητας
4. Εκτός

**Μέσω API:**

```bash
curl -X POST http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "name": "US Proxy",
    "type": "http",
    "host": "proxy.example.com",
    "port": 8080,
    "username": "user",
    "password": "pass",
    "region": "US"
  }'
```

### Ενημέρωση διακομιστή μεσολάβησης

```bash
curl -X PATCH http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "id": "proxy-uuid-here",
    "host": "new-proxy.example.com",
    "port": 9090
  }'
```

> **Σημείωμα:** Τα διαπιστευτήρια διατηρούνται εκτός εάν στείλετε ρητά μη κενές αντικαταστάσεις. Η αποστολή κενών συμβολοσειρών για `username`/`password` θα διατηρήσει τις αποθηκευμένες τιμές.

### Διαγραφή διακομιστή μεσολάβησης

```bash
# Fails if proxy is assigned to any scope
curl -X DELETE "http://localhost:20128/api/v1/management/proxies?id=proxy-uuid"

# Force delete (removes assignments too)
curl -X DELETE "http://localhost:20128/api/v1/management/proxies?id=proxy-uuid&force=1"
```

### Διακομιστές μεσολάβησης καταχώρισης

```bash
curl "http://localhost:20128/api/v1/management/proxies?limit=50&offset=0"
```

### Εκχώρηση διακομιστή μεσολάβησης σε Scopes

```bash
# Assign to global scope
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "global", "proxy": {"type":"http","host":"proxy.example.com","port":8080}}'

# Assign to a specific provider
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "provider", "id": "openai", "proxy": {"type":"socks5","host":"socks.example.com","port":1080}}'

# Assign to a specific connection/key
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "key", "id": "connection-uuid", "proxy": {"type":"http","host":"key-proxy.com","port":3128}}'
```

### Επίλυση αποτελεσματικού διακομιστή μεσολάβησης

Ελέγξτε ποιος διακομιστής μεσολάβησης θα χρησιμοποιηθεί για μια δεδομένη σύνδεση:

```bash
curl "http://localhost:20128/api/settings/proxy?resolve=connection-uuid"
```

Επιστρέφει τον επιλυμένο διακομιστή μεσολάβησης με το επίπεδο (`account`, `provider` ή `global`) και την πηγή του.

### Μαζική ανάθεση

Εκχωρήστε έναν διακομιστή μεσολάβησης σε πολλούς παρόχους ή συνδέσεις ταυτόχρονα:

```bash
curl -X POST http://localhost:20128/api/v1/management/proxies/bulk-assign \
  -H "Content-Type: application/json" \
  -d '{
    "scope": "provider",
    "scopeIds": ["openai", "anthropic", "codex"],
    "proxyId": "proxy-uuid"
  }'
```

### Import/Export

Οι πληρεξούσιοι περιλαμβάνονται στο**Backup/Restore** σύστημα. Όταν εξάγετε τη διαμόρφωση OmniRoute :

1. Μεταβείτε στο** Ταμπλό → Ρυθμίσεις → Δημιουργία αντιγράφων ασφαλείας**
2. Κλικ** Εξαγωγή** Περιλαμβάνονται το μητρώο διακομιστή μεσολάβησης — και οι αναθέσεις
3. Για επαναφορά, κάντε κλικ** Εισαγωγή** και ανεβάστε το αρχείο αντιγράφου ασφαλείας

Το μητρώο διακομιστή μεσολάβησης υποστηρίζει επίσης** upsert από τον κεντρικό υπολογιστή + port** — εάν εισαγάγετε έναν διακομιστή μεσολάβησης που υπάρχει ήδη (ίδιος κεντρικός υπολογιστής και θύρα), ενημερώνεται αντί να δημιουργεί ένα αντίγραφο.

### Μετανάστευση παλαιού τύπου

Εάν έχετε διαμορφώσει τους διακομιστές μεσολάβησης σε παλαιότερη έκδοση (προ-μητρώο), OmniRoute τους μετεγκαθιστά αυτόματα:

```
Legacy key_value store → proxy_registry + proxy_assignments
```

Αυτό συμβαίνει μία φορά κατά την πρώτη εκκίνηση μετά την αναβάθμιση. Χρησιμοποιήστε `migrateLegacyProxyConfigToRegistry({ force: true })` για επανάληψη.

## 1Proxy Δωρεάν Proxy Marketplace

> 🆕** Συνεισφορά από [@oyi77](https://github.com/oyi77)** — PR [#1847](https://github.com/diegosouzapw/OmniRoute/pull/1847) (Τεύχος [#1788](https://github.com/diegosouzapw/OmniRoute/issues/1788) )

OmniRoute ενσωματώνεται με το** [1 πληρεξούσιος](https://1proxy-api.aitradepulse.com)** κοινοτική πλατφόρμα για την παροχή πρόσβασης** εκατοντάδες δωρεάν, επικυρωμένα πληρεξούσια** από όλο τον κόσμο. Αυτό είναι τέλειο για χρήστες που δεν έχουν τη δική τους υποδομή διακομιστή μεσολάβησης.

### Πώς λειτουργεί

```
┌─────────────┐     Sync      ┌─────────────────┐    Rotate     ┌──────────┐
│  1proxy API │ ────────────▶ │  proxy_registry  │ ────────────▶ │ Provider │
│  (external) │   up to 500   │  source=oneproxy │  by quality   │   API    │
└─────────────┘    proxies    └─────────────────┘               └──────────┘
```

1. **Συγχρονισμός** — OmniRoute ανακτά επικυρωμένους διακομιστή μεσολάβησης από το 1proxy API
2. **Κατάστημα** Οι διακομιστής μεσολάβησης — αποθηκεύονται στον ίδιο πίνακα `proxy_registry` με `source = 'oneproxy'`
3. **Φίλτρο** — Φιλτράρισμα κατά πρωτόκολλο, χώρα, βαθμολογία ποιότητας
4. **Γυρίζω** — Επιλέξτε τον καλύτερο διακομιστή μεσολάβησης χρησιμοποιώντας ποιοτικές, τυχαίες ή διαδοχικές στρατηγικές
5. **Αυτόματη υποβάθμιση** Οι αποτυχημένοι πληρεξούσιοι — μειώνουν τη βαθμολογία ποιότητάς τους. κάτω από το όριο → επισημάνθηκε ως ανενεργό

### Συγχρονισμός διακομιστή μεσολάβησης

**Μέσω πίνακα ελέγχου:**

1. Μεταβείτε στο** Ρυθμίσεις → 1proxy** αυτί
2. Κλικ** "Συγχρονισμός τώρα"**
3. Προβολή στατιστικών στοιχείων: συνολικοί πληρεξούσιοι, πλήθος ενεργών, μέση ποιότητα, ανάλυση ανά χώρα

**Μέσω API:**

```bash
# Trigger sync
curl -X POST http://localhost:20128/api/settings/oneproxy \
  -H "Content-Type: application/json" \
  -d '{}'

# Response:
# { "success": true, "added": 127, "updated": 45, "failed": 2, "total": 172 }
```

### Φιλτράρισμα διακομιστή μεσολάβησης

```bash

# Filter by country
curl "http://localhost:20128/api/settings/oneproxy?countryCode=US"

curl "http://localhost:20128/api/settings/oneproxy?minQuality=80"

```

### Βαθμολογίες ποιότητας διακομιστή μεσολάβησης

Κάθε διακομιστής μεσολάβησης 1 έρχεται με μεταδεδομένα:

| Πεδίο           | Περιγραφή                                                                   |
| --------------- | --------------------------------------------------------------------------- |
| `qualityScore`  | Αξιολόγηση 0-100 από 1 επικύρωση διακομιστή μεσολάβησης                     |
| `latencyMs`     | Μετρημένη καθυστέρηση δικτύου                                               |

| `countryCode`   | Κωδικός χώρας ISO με δύο γράμματα                                           |

Οι βαθμολογίες ποιότητας προσαρμόζονται δυναμικά:

- **Αποτυχημένα αιτήματα** μειώσει τη βαθμολογία κατά 10 βαθμούς
- **Η βαθμολογία πέφτει στο ≤ 10** Ο διακομιστής μεσολάβησης → επισημαίνεται ως `inactive`
- Οι ανενεργοί πληρεξούσιοι εξαιρούνται από την εναλλαγή

## Anti-Detection & Stealth

OmniRoute δεν δρομολογεί απλώς την κυκλοφορία μέσω ενός διακομιστή μεσολάβησης — αλλά κάνει την κίνηση να φαίνεται νόμιμη:

### TLS πλαστογράφηση δακτυλικών αποτυπωμάτων

Χρησιμοποιεί `wreq-js` για τη δημιουργία δακτυλικών αποτυπωμάτων TLS που μοιάζουν με το πρόγραμμα περιήγησης, παρακάμπτοντας συστήματα ανίχνευσης bot που επισημαίνουν χειραψίες TLS εκτός προγράμματος περιήγησης.

### CLI Αντιστοίχιση δακτυλικών αποτυπωμάτων

Ο**CLI Εναλλαγή δακτυλικών αποτυπωμάτων** (`Settings → Security`) αναδιατάσσει τις κεφαλίδες HTTP και τα πεδία σώματος JSON ώστε να ταιριάζουν με την ακριβή υπογραφή των εγγενών δυαδικών αρχείων CLI (κωδικός Claude, Codex, κ.λπ.). Αυτό λειτουργεί** πάνω από** ο πληρεξούσιος:

```
Your IP (blocked) → Proxy IP (US) → Provider API
                    + TLS spoof
                    + CLI fingerprint
```

Παίρνετε και τα δύο** μάσκα IP** και** ζητήστε αυθεντικότητα** ταυτοχρόνως.

### Διατήρηση proxy IP

Τα χρωματικά κωδικοποιημένα σήματα στον πίνακα ελέγχου δείχνουν ποιο επίπεδο διακομιστή μεσολάβησης είναι ενεργό:

| Σήμα | Επίπεδο     | Εννοια                                                                         |
| ---- | ----------- | ------------------------------------------------------------------------------ |
| 🟢   | Καθολικός   | Όλη η κίνηση περνά μέσω αυτού του διακομιστή μεσολάβησης                       |
| 🟡   | Προμηθευτής | Μόνο η επισκεψιμότητα αυτού του παρόχου είναι μέσω διακομιστή μεσολάβησης      |
| 🔵   | Σύνδεση     | Αυτό το συγκεκριμένο key/account χρησιμοποιεί αυτόν τον διακομιστή μεσολάβησης |

Το σήμα εμφανίζει επίσης τον επιλυμένο διακομιστή μεσολάβησης IP για επαλήθευση.

Αυτό είναι φυσιολογικό με φθηνούς διακομιστές μεσολάβησης που αφήνουν τις αδρανείς συνδέσεις. OmniRoute το χειρίζεται ήδη με:

3. Βεβαιωθείτε ότι το εύρος της εκχώρησης διακομιστή μεσολάβησης ταιριάζει με τη σύνδεσή σας

### Τραπέζι `proxy_registry`

```sql
CREATE TABLE proxy_registry (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  type TEXT NOT NULL DEFAULT 'http',
  host TEXT NOT NULL,
  port INTEGER NOT NULL,
  username TEXT DEFAULT '',
  password TEXT DEFAULT '',
  region TEXT,
  notes TEXT,
  status TEXT DEFAULT 'active',
  source TEXT NOT NULL DEFAULT 'manual',    -- 'manual' or 'oneproxy'
  quality_score INTEGER,                     -- 0-100 (1proxy only)
  latency_ms INTEGER,                        -- milliseconds (1proxy only)
  anonymity TEXT,                            -- transparent/anonymous/elite
  google_access INTEGER DEFAULT 0,           -- can access Google? (1proxy)
  last_validated TEXT,                       -- ISO timestamp (1proxy)
  country_code TEXT,                         -- ISO 2-letter code (1proxy)
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

### Τραπέζι `proxy_assignments`

```sql
CREATE TABLE proxy_assignments (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  proxy_id TEXT NOT NULL REFERENCES proxy_registry(id),
  scope TEXT NOT NULL,        -- 'global', 'provider', 'account', 'combo'
  scope_id TEXT,              -- provider ID, connection ID, or combo ID
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE(scope, scope_id)
);
```

## Έλεγχος υγείας διακομιστή μεσολάβησης (v3.8.16 +)

OmniRoute** proxy fast-fail** ο μηχανισμός (`src/lib/proxyHealth.ts`) εντοπίζει νεκρούς διακομιστή μεσολάβησης σε < 2s μέσω ενός γρήγορου ελέγχου σύνδεσης TCP και, στη συνέχεια,** αποθηκεύει το αποτέλεσμα** για αποφυγή επιβαρύνσεων ανά αίτημα.

### Πώς λειτουργεί

```
Request ──▶ ProxyHealthCache.get(url)
             │
             ├─ Cache hit + fresh?  ──▶ return cached status
             │
             └─ Cache miss / stale?  ──▶ TCP connect to host:port
                                          (timeout: FAST_FAIL_TIMEOUT_MS)
                                          ──▶ cache for HEALTH_CACHE_TTL_MS
                                          ──▶ return result
```

Χωρίς αυτό, ένας νεκρός διακομιστής μεσολάβησης θα μπλοκάρει κάθε αίτημα για το πλήρες `PROXY_TIMEOUT_MS` (προεπιλογή 30s) πριν αποτύχει.

### Συντονίσιμες μεταβλητές περιβάλλοντος

| Μεταβλητός                   | Αθέτηση | Σκοπός                                                         |
| ---------------------------- | ------- | -------------------------------------------------------------- |
| `PROXY_FAST_FAIL_TIMEOUT_MS` | `2000`  | Χρονικό όριο σύνδεσης TCP ανά έλεγχο υγείας                    |
| `PROXY_HEALTH_CACHE_TTL_MS`  | `30000` | Πόσο καιρό αποθηκεύεται στην κρυφή μνήμη ένα αποτέλεσμα υγείας |

**Προτεινόμενες τιμές:**

| Σενάριο                  | Χρονικό όριο γρήγορης αποτυχίας | Cache TTL | Αιτιολογία                                                                                        |
| ------------------------ | ------------------------------- | --------- | ------------------------------------------------------------------------------------------------- |
| Πύλη API υψηλής απόδοσης | 1500 ms                         | 60000 ms  | Επιθετική γρήγορη αποτυχία, μεγαλύτερη κρυφή μνήμη για μείωση των ελέγχων                         |
| Γεω-κατανεμημένοι κόμβοι | 3000 ms                         | 15000 ms  | Τα πιο αργά δίκτυα χρειάζονται περισσότερο χρόνο. μικρότερη κρυφή μνήμη για γρήγορη ανακατεύθυνση |
| Dev / δοκιμή             | 1000 ms                         | 10000 ms  | Γρήγορη επανάληψη σε τοπικούς διακομιστές μεσολάβησης                                             |
| Stealth / αντι-ανίχνευση | 2500 ms                         | 45000 ms  | Αποφύγετε την ταχεία ανίχνευση που θα μπορούσε να προκαλέσει όρια ρυθμού                          |

### Επιθεώρηση Proxy Health

```ts
import { getAllProxyHealthStatuses, invalidateProxyHealth } from "omniroute/proxyHealth";

const statuses = getAllProxyHealthStatuses();
for (const s of statuses) {
  console.log(`${s.proxyUrl} → healthy=${s.healthy}, stale=${s.stale}`);
}

// Force re-check a specific proxy
invalidateProxyHealth("http://user:pass@203.0.113.7:8080");
```

Η σημαία `stale` είναι `true` όταν η καταχώριση της κρυφής μνήμης έχει υπερβεί `HEALTH_CACHE_TTL_MS` και το επόμενο αίτημα θα ενεργοποιήσει έναν νέο έλεγχο.

### Προεπιλογές τύπου ανά διακομιστή μεσολάβησης

Ο έλεγχος υγείας χρησιμοποιεί λογικές προεπιλογές με βάση το σχήμα URL :

| Σχέδιο                     | Προεπιλεγμένη θύρα |
| -------------------------- | ------------------ |
| `http://`                  | 8080               |
| `https://`                 | 443                |
| `socks5://` / `socks5h://` | 1080               |

Οι προσαρμοσμένες θύρες στο URL (`http://host:9999`) έχουν πάντα προτεραιότητα έναντι της προεπιλογής του σχήματος.

## Αναλύσεις μεσολάβησης και παρατηρησιμότητα

OmniRoute παρακολουθεί τη χρήση ανά διακομιστή μεσολάβησης για να βοηθήσει τους χειριστές να διαγνώσουν μοτίβα δρομολόγησης, αιχμές καθυστέρησης και επαναλαμβανόμενες αποτυχίες.

### Τι παρακολουθείται

Για κάθε αίτημα μέσω ενός διαμορφωμένου διακομιστή μεσολάβησης, OmniRoute καταγράφει:

| Μετρικός     | Περιγραφή                                                                       |
| ------------ | ------------------------------------------------------------------------------- |
| `proxy_url`  | Πλήρης διακομιστής μεσολάβησης URL (με καλυμμένα τα διαπιστευτήρια ταυτότητας)  |
| `provider`   | Ανοδικός πάροχος ID (openai, anthropic, κ.λπ.)                                  |
| `latency_ms` | Συνολικός χρόνος μετ' επιστροφής, συμπεριλαμβανομένης της χειραψίας μεσολάβησης |
| `connect_ms` | TCP μόνο χρόνος σύνδεσης                                                        |
| `status`     | Κωδικός κατάστασης HTTP από το upstream                                         |
| `error`      | Κατηγορία σφάλματος εάν το αίτημα απέτυχε                                       |
| `timestamp`  | ISO 8601 UTC                                                                    |

### Πρόσβαση στα Δεδομένα

```bash
# Recent proxy events
curl -H "Authorization: Bearer $OMNIROUTE_KEY" \
  "http://localhost:20128/api/usage/proxy-logs?limit=100"
```

Το πραγματικό τελικό σημείο είναι `/api/usage/proxy-logs` (βλ. `src/app/api/usage/proxy-logs/route.ts`). Αυτό το τελικό σημείο υποστηρίζει:

- `GET /api/usage/proxy-logs` — ανάκτηση αρχείων καταγραφής διακομιστή μεσολάβησης
- `DELETE /api/usage/proxy-logs` — εκκαθάριση όλων των αρχείων καταγραφής διακομιστή μεσολάβησης

Μπορείτε να αναζητήσετε συγκεντρωτικά στατιστικά απευθείας από τον πίνακα `proxy_logs` μέσω SQL εάν χρειάζεται. Το ταμπλό UI μπορεί να προσφέρει συγκεντρωτικές προβολές.

### Κοινά Μοτίβα

**Εντοπίστε έναν διαμεσολαβητή που φεύγει** (εναλλάσσεται μεταξύ success/failure):

```sql
SELECT proxy_url,
       COUNT(*) AS total,
       SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) AS errors,
       ROUND(100.0 * SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) / COUNT(*), 1) AS error_pct
FROM proxy_logs
WHERE timestamp > datetime('now', '-1 hour')
GROUP BY proxy_url
HAVING error_pct > 5
ORDER BY error_pct DESC;
```

**Βρείτε αργούς διακομιστές μεσολάβησης** (p95 latency > 2s):

```sql
WITH ranked AS (
  SELECT proxy_url, latency_ms,
         PERCENT_RANK() OVER (PARTITION BY proxy_url ORDER BY latency_ms) AS pct
  FROM proxy_logs
  WHERE timestamp > datetime('now', '-24 hour')
)
SELECT proxy_url, latency_ms
FROM ranked
WHERE pct >= 0.95
ORDER BY latency_ms DESC;
```

## Δένδρο απόφασης στρατηγικής εναλλαγής

Όταν εκχωρούνται πολλαπλοί διακομιστής μεσολάβησης σε ένα εύρος, OmniRoute χρησιμοποιεί a** στρατηγική εναλλαγής** για να επιλέξετε ποιο θα χρησιμοποιήσετε για κάθε αίτημα. Η στρατηγική διαμορφώνεται σε επίπεδο εμβέλειας (καθολικό, ανά πάροχο, ανά λογαριασμό, ανά σύνθετο).

### Διαθέσιμες στρατηγικές

| Στρατηγική             | Πότε να χρησιμοποιείται                        | Ανταλλαγή                                                                                    |
| ---------------------- | ---------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `quality` (προεπιλογή) | Παραγωγή με πληρεξούσιους μικτής ποιότητας     | Ευνοεί τους πληρεξούσιους υψηλής βαθμολογίας. μπορεί να πεινάσουν άτομα με χαμηλή βαθμολογία |
| `random`               | Κατανομή φορτίου, απόρρητο                     | Ομοιόμορφη διανομή. αγνοεί τα σήματα ποιότητας                                               |
| `sequential`           | Εντοπισμός σφαλμάτων, ντετερμινιστικός έλεγχος | Κυκλοφορεί μέσω διακομιστών με τη σειρά. εύκολο να αιτιολογηθεί                              |

### Δέντρο απόφασης

```
                    Do you have quality scores for your proxies?
                    │
        ┌───────────┴───────────┐
        │                       │
       YES                     NO
        │                       │
   Are all proxies             │
   roughly equal                  │
   in quality?                   │
        │                       │
   ┌────┴────┐                  │
   │         │                  │
  YES       NO                Use
   │         │              `random`
   │         │              (even spread
   │         │              builds quality
   │         │              data over time)
   │         │
   │    Use `quality`
   │    (best for
   │    mixed quality)
   │
Use `random`
(spread load
evenly)
```

## Αυτόματη εξαίρεση αποτυχίας για τους δικούς σας διακομιστή μεσολάβησης

Το pool 1proxy marketplace ήδη υποβαθμίζει αυτόματα τους αποτυχημένους διακομιστές μεσολάβησης από μόνο του (δείτε [Δείκτες ποιότητας διακομιστή μεσολάβησης](#proxy-quality-scores) ). Για πληρεξούσιους** εσείς** που προστέθηκε στο μητρώο, ο προγραμματιστής υγείας φόντου (`src/lib/proxyHealth/scheduler.ts`) παρέχει την ίδια συμπεριφορά "αποκλείστε ένα νεκρό μέλος από την αλυσίδα αυτόματα", χωρίς να διαγράψετε τίποτα:

```bash
# .env — soft-disable a proxy after 3 consecutive failed probes, re-enable it
# automatically once it starts answering probes again.
PROXY_AUTO_DISABLE=true
PROXY_AUTO_REMOVE_AFTER=3
```

Πώς ταιριάζει σε μια αλυσίδα πολλαπλών μεσολάβησης:

1. Ο προγραμματιστής εξετάζει κάθε καταχωρημένο διακομιστή μεσολάβησης κάθε `PROXY_HEALTH_INTERVAL_MS` (προεπιλογή 10 λεπτά, ελάχιστο 1 λεπτό).
2. Μετά `PROXY_AUTO_REMOVE_AFTER` συνεχόμενα** πειστικός** αποτυχίες (μια πραγματική αποτυχία σύνδεσης — ένα χρονικό όριο λήξης ή το 5xx του ίδιου του στόχου ανίχνευσης δεν μετράει ποτέ, βλ. [Έλεγχος υγείας του διακομιστή μεσολάβησης](#proxy-health-checking-v3816) ), το `status` του διακομιστή μεσολάβησης έχει οριστεί σε `dead`.
3. `dead` είναι μία από τις καταστάσεις που εξαιρεί το φίλτρο ζωντανής κατάστασης που χρησιμοποιείται από την ανάλυση pool/rotation, επομένως η περιστροφή ενός σκοπού (στρογγυλή / τυχαία / κολλώδης / λανθάνουσα κατάσταση — βλέπε [Δέντρο απόφασης στρατηγικής περιστροφής](#rotation-strategy-decision-tree) ) σταματά αμέσως να παραδίδει αυτόν τον διακομιστή μεσολάβησης σε νέα αιτήματα. Κανένας άλλος διακομιστής μεσολάβησης στην πισίνα δεν επηρεάζεται και ολόκληρη η πισίνα δεν επιστρέφει ποτέ σιωπηλά σε απευθείας σύνδεση — δείτε το κλειστό [προστατευτικό σύστημα διαμεσολάβησης 4 επιπέδων](#4-level-proxy-system).
4. Ο χρονοπρογραμματιστής συνεχίζει να διερευνά τους διακομιστή μεσολάβησης `dead` στο ίδιο διάστημα. Ο επόμενος επιτυχημένος ανιχνευτής επαναφέρει `status` στο `active` και εισέρχεται ξανά στην περιστροφή — χωρίς να απαιτείται χειροκίνητη εκ νέου προσθήκη.

Αυτό είναι σκόπιμα** opt-in και μη καταστροφικό** : από προεπιλογή ο προγραμματιστής μετράει και καταγράφει μόνο αποτυχίες (δείτε την πολιτική C στο `decision.ts`) και `PROXY_AUTO_DISABLE` δεν διαγράφει ποτέ μια σειρά — για την οποία χρησιμεύει η ξεχωριστή, πιο επιθετική σημαία `PROXY_AUTO_REMOVE`. Εάν και τα δύο έχουν ρυθμιστεί σε `true`, `PROXY_AUTO_REMOVE` κερδίζει (ένας διακομιστής μεσολάβησης που πρόκειται να διαγραφεί δεν έχει καμία χρήση για soft-disable ενδιάμεσα). Δείτε την αναφορά [Environment Config](../reference/ENVIRONMENT.md) για την πλήρη λίστα μεταβλητών.
