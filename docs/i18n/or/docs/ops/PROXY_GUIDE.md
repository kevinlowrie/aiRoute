> **ଭ ge ଗୋଳିକ ବ୍ଲକଗୁଡିକୁ ବାଇପାସ୍ କରନ୍ତୁ, ଆପଣଙ୍କର ପରିଚୟକୁ ସୁରକ୍ଷିତ କରନ୍ତୁ, ଏବଂ ଶୂନ୍ୟ ବିନ୍ୟାସ ଜଟିଳତା ସହିତ ଯେକ any ଣସି ପ୍ରକ୍ସି — ମାଧ୍ୟମରେ AI ଟ୍ରାଫିକ୍ ରୁଟ୍ କରନ୍ତୁ।**

OmniRoute ଏକ ପୂର୍ଣ୍ଣ-ବ featured ଶିଷ୍ଟ୍ୟଯୁକ୍ତ ପ୍ରକ୍ସି ମ୍ୟାନେଜମେଣ୍ଟ ସିଷ୍ଟମ ଅନ୍ତର୍ଭୂକ୍ତ କରେ ଯାହା ଆପଣଙ୍କୁ HTTP, HTTPS, କିମ୍ବା SOCKS5 ପ୍ରକ୍ସି ମାଧ୍ୟମରେ ଅପଷ୍ଟ୍ରିମ AI ପ୍ରଦାନକାରୀ ଟ୍ରାଫିକକୁ ମାର୍ଗ ଦିଏ। ଆପଣ ଏକ ଅବରୋଧିତ ଅଞ୍ଚଳରେ ଅଛନ୍ତି, IP ଘୂର୍ଣ୍ଣନ ଆବଶ୍ୟକ କରନ୍ତି, କିମ୍ବା ଚୋରି ଫିଙ୍ଗର ପ୍ରିଣ୍ଟିଂ — ଚାହୁଁଛନ୍ତି ଏହି ଗାଇଡ୍ ସବୁକିଛି ଅନ୍ତର୍ଭୁକ୍ତ କରେ।

## ପ୍ରକ୍ସି କାହିଁକି ବ୍ୟବହାର କରିବେ?

ଅନେକ AI ପ୍ରଦାନକାରୀ ଭ ographic ଗୋଳିକ ଅଞ୍ଚଳ ଦ୍ୱାରା ପ୍ରବେଶକୁ ପ୍ରତିବନ୍ଧିତ କରନ୍ତି। ବିକାଶକାରୀମାନେ** Russia ଷ, ଚୀନ୍, ଇରାନ, କ୍ୟୁବା, ତୁର୍କୀ।** , ଏବଂ ଅନ୍ୟ ଦେଶଗୁଡିକ ତ୍ରୁଟିର ସମ୍ମୁଖୀନ ହୁଅନ୍ତି:

```

```

ଏପରିକି ବାହାରେ ଅବରୋଧିତ ଅଞ୍ଚଳ, ପ୍ରକ୍ସିଗୁଡ଼ିକ ପାଇଁ ଉପଯୋଗୀ:

| କେସ୍ ବ୍ୟବହାର କରନ୍ତୁ।    | ବର୍ଣ୍ଣନା                                                       |
| ----------------------- | -------------------------------------------------------------- |
| **ଭ Ge ଗୋଳିକ ବାଇପାସ୍।** | ଅବରୋଧିତ ଦେଶରୁ OpenAI, Anthropic, Codex, Copilot ପ୍ରବେଶ କରନ୍ତୁ। |
| **IP ଘୂର୍ଣ୍ଣନ**         | ହାର ସୀମିତତାକୁ ଏଡାଇବା ପାଇଁ ଏକାଧିକ IPs ରେ ଅନୁରୋଧ ବଣ୍ଟନ କରନ୍ତୁ।   |

## ନୂତନ ଖାତା ପାଇଁ ଡିଫଲ୍ଟ ପ୍ରକ୍ସି ସ୍ଥିତି।

ଇନ୍** ସେଟିଂସମୂହ → ପ୍ରକ୍ସି → ଗ୍ଲୋବାଲ୍ ବିନ୍ୟାସକରଣ।** , ବ୍ୟବହାର କରନ୍ତୁ।** ନୂତନ ସଂଯୋଗ ପାଇଁ ଡିଫଲ୍ଟ ଭାବରେ ପ୍ରକ୍ସି ସକ୍ଷମ କରନ୍ତୁ।** ନୂତନ ଭାବରେ ଯୋଗାଯାଇଥିବା ପ୍ରଦାନକାରୀ ଖାତାଗୁଡ଼ିକର ପ୍ରାରମ୍ଭିକ ପ୍ରକ୍ସି ସ୍ଥିତି ବାଛିବା ପାଇଁ।

ନୂତନ ସେଟିଂ ନୂତନ ଯୋଗ ହୋଇଥିବା ପ୍ରଦାନକାରୀ ଖାତାର ପ୍ରାରମ୍ଭିକ ପ୍ରକ୍ସି ସ୍ଥିତିକୁ ନିୟନ୍ତ୍ରଣ କରେ। ଏହା ବିଦ୍ୟମାନ ଖାତାଗୁଡ଼ିକୁ ପରିବର୍ତ୍ତନ କରେ ନାହିଁ କିମ୍ବା ଗ୍ଲୋବାଲ୍ ପ୍ରକ୍ସି ସୁଇଚ୍ ସ୍ଥାନାନ୍ତର କରେ ନାହିଁ। ଏହାର ପ୍ରାରମ୍ଭିକ ମୂଲ୍ୟ ପୂର୍ବ ଆଚରଣକୁ ସଂରକ୍ଷଣ କରେ। ଡିଫଲ୍ଟ ଭାବରେ ପ୍ରକ୍ସି ଅକ୍ଷମ ସହିତ ଭବିଷ୍ୟତ ଆକାଉଣ୍ଟ ସୃଷ୍ଟି କରିବାକୁ ଏହାକୁ ଥରେ ବନ୍ଦ କରନ୍ତୁ।

ପ୍ରିଫରେନ୍ସ ବିଦ୍ୟମାନ ସେଟିଂସମୂହ API ମାଧ୍ୟମରେ `defaultNewConnectionProxyEnabled` ଭାବରେ ଗଚ୍ଛିତ। ଏହା କେବେ ବି ସେଭ୍ ହୋଇନଥିବାବେଳେ `true` କୁ ଡିଫଲ୍ଟ କରିଥାଏ। `false` ସଞ୍ଚୟ କରିବା ପୁନ rest ଆରମ୍ଭ ବିନା ପରବର୍ତ୍ତୀ ନୂତନ ଖାତାଗୁଡ଼ିକ ପାଇଁ କାର୍ଯ୍ୟକାରୀ ହୁଏ। `POST /api/providers` ଏକ ଇଚ୍ଛାଧୀନ କଠୋର ବୁଲିୟାନ୍ `proxyEnabled` ଗ୍ରହଣ କରେ; ଏକ ନିର୍ଦ୍ଦିଷ୍ଟ `true` କିମ୍ବା `false` ସୃଷ୍ଟି ଡିଫଲ୍ଟ ଉପରେ ପ୍ରାଧାନ୍ୟ ଦେଇଥାଏ। ଏକ ନକଲ ଆକାଉଣ୍ଟ କିମ୍ବା OAuth ପୁନ nect ସଂଯୋଗରେ ଖାତା ସେହି ଖାତାର ଗଚ୍ଛିତ ସ୍ଥିତିକୁ ସଂରକ୍ଷଣ କରେ। ବ୍ୟକ୍ତିଗତ ଖାତାଗୁଡ଼ିକ ପରେ ମଧ୍ୟ ସକ୍ଷମ କିମ୍ବା ଅକ୍ଷମ ହୋଇପାରିବ।

ଚୟନକାରୀ ପ୍ରଦାନକାରୀ ସ୍ଥାନାନ୍ତରଣ ନୂତନ ଖାତାଗୁଡ଼ିକ ପାଇଁ ଗନ୍ତବ୍ୟସ୍ଥଳ ସଂସ୍ଥାର ଡିଫଲ୍ଟ ବ୍ୟବହାର କରେ ଏବଂ ବିଦ୍ୟମାନ ଖାତାଗୁଡ଼ିକୁ ବଦଳାଇବା ସମୟରେ ଗନ୍ତବ୍ୟ ସ୍ଥଳ ସଂରକ୍ଷଣ କରେ। ପ୍ରକ୍ସି ଟୋଗଲ୍ ପୋର୍ଟେବଲ୍ ସ୍ଥାନାନ୍ତର କ୍ଷେତ୍ର ନୁହେଁ। ପୂର୍ଣ୍ଣ ବ୍ୟାକଅପ୍ ପୁନରୁଦ୍ଧାର ଏବଂ historical ତିହାସିକ JSON/SQL ସ୍ଥାନାନ୍ତରଣ ସେମାନଙ୍କର ବିଦ୍ୟମାନ ପୁନ restore ସ୍ଥାପନ ସେମାଣ୍ଟିକ୍ସକୁ ବଜାୟ ରଖେ, ସଞ୍ଚିତ ଖାତା ମୂଲ୍ୟ ଏବଂ ପୁରୁଣା ସ୍କିମା ଡିଫଲ୍ଟକୁ ଅନ୍ତର୍ଭୁକ୍ତ କରି; ଏକ ପୂର୍ଣ୍ଣ ସେଟିଂସମୂହ ପୁନ restore ସ୍ଥାପନ ମଧ୍ୟ ଏହି ପସନ୍ଦକୁ ପୁନ restore ସ୍ଥାପନ କରିପାରିବ।

ଏହି ପସନ୍ଦ ଏକ ପ୍ରକ୍ସି ନ୍ୟସ୍ତ କରେ ନାହିଁ କିମ୍ବା ସ୍ଥାପିତ କରେ ଯେ ଜଣେ ସୁସ୍ଥ କିମ୍ବା ବ୍ୟବହାରରେ ଅଛି। ପ୍ରକୃତ ରାଉଟିଙ୍ଗ୍ ଗ୍ଲୋବାଲ୍ ପ୍ରକ୍ସି ସୁଇଚ୍ ଏବଂ ପ୍ରଯୁଜ୍ୟ ପ୍ରକ୍ସି ବିନ୍ୟାସ ଉପରେ ନିର୍ଭର କରେ। ସ୍ଥାୟୀ ଆକାଉଣ୍ଟ ବିନା ସିନ୍ଥେଟିକ୍ ପ୍ରଦାନକାରୀ, ଖାତା ସୃଷ୍ଟି ପୂର୍ବରୁ OAuth ଟ୍ରାଫିକ୍, environment/system ପ୍ରକ୍ସି, ଏବଂ ବାହ୍ୟ ବ୍ୟାକେଣ୍ଡ୍ ନେଟୱାର୍କିଂ ଏହାର ପରିସର ବାହାରେ।

## 4-ସ୍ତରୀୟ ପ୍ରକ୍ସି ସିଷ୍ଟମ୍।

OmniRoute ପ୍ରକ୍ସି ବିନ୍ୟାସକୁ ସମର୍ଥନ କରେ।** ଚାରୋଟି ସ୍ independent ାଧୀନ ସ୍କୋପ୍।** , ପ୍ରାଥମିକ କ୍ରମରେ ସମାଧାନ ହୋଇଛି:

```
Priority Resolution Order (highest → lowest):

  1. 🔵 Account/Connection Proxy  →  per API key / OAuth connection
  2. 🟡 Provider Proxy            →  per provider (e.g., all OpenAI traffic)
  3. 🟠 Combo Proxy               →  per combo/routing configuration
  4. 🟢 Global Proxy              →  all traffic, all providers
```

### ରେଜୋଲୁସନ କିପରି କାମ କରେ।

ଯେତେବେଳେ OmniRoute ଏକ ଅପଷ୍ଟ୍ରିମ୍ ପ୍ରଦାନକାରୀଙ୍କୁ ଏକ ଅନୁରୋଧ ପଠାଏ, ଏହା `resolveProxyForConnectionFromRegistry()` ଡାକେ ଯାହା ପ୍ରତ୍ୟେକ ସ୍ତରକୁ କ୍ରମରେ ଯାଞ୍ଚ କରେ:

1. **ଖାତା ସ୍ତର** — ଏହି ନିର୍ଦ୍ଦିଷ୍ଟ ସଂଯୋଗ ID କୁ ଏକ ପ୍ରକ୍ସି ନ୍ୟସ୍ତ ହୋଇଛି କି?
2. **ପ୍ରଦାନକାରୀ-ସ୍ତର।** — ଏହି ପ୍ରଦାନକାରୀଙ୍କୁ ଏକ ପ୍ରକ୍ସି ନ୍ୟସ୍ତ କରାଯାଇଛି (ଯଥା, `openai`)?
3. **ବିଶ୍ୱ ସ୍ତରୀୟ।** — ସେଠାରେ ଏକ ବିଶ୍ୱସ୍ତରୀୟ ପ୍ରକ୍ସି ବିନ୍ୟାସିତ ହୋଇଛି କି?
4. **କ No ଣସି ପ୍ରକ୍ସି ନାହିଁ।** — ପ୍ରଦାନକାରୀ ସହିତ ସିଧାସଳଖ ସଂଯୋଗ।

ପ୍ରଥମ ମ୍ୟାଚ୍ ଜିତିଲା। ଏହାର ଅର୍ଥ ଆପଣ ଏକ ଗ୍ଲୋବାଲ୍ ପ୍ରକ୍ସିକୁ ଏକ ଫଲବ୍ୟାକ୍ ଭାବରେ ସେଟ୍ କରିପାରିବେ କିନ୍ତୁ ନିର୍ଦ୍ଦିଷ୍ଟ ପ୍ରଦାନକାରୀ କିମ୍ବା ସଂଯୋଗ ପାଇଁ ଏହାକୁ ନବଲିଖନ କରନ୍ତୁ।

## ପ୍ରକ୍ସି ରେଜିଷ୍ଟ୍ରି (CRUD)

ପ୍ରକ୍ସି ରେଜିଷ୍ଟ୍ରି ହେଉଛି ଏକ SQLite ଟେବୁଲ୍ (`proxy_registry`) ଯାହା ଆପଣଙ୍କର ସମସ୍ତ ପ୍ରକ୍ସି ଗଚ୍ଛିତ କରେ। ପ୍ରତ୍ୟେକ ପ୍ରକ୍ସି ଅଛି:

| କ୍ଷେତ୍ର    | ଟାଇପ୍ କରନ୍ତୁ। | ବର୍ଣ୍ଣନା                                        |
| ---------- | ------------- | ----------------------------------------------- |
| `id`       | UUID          | ଅନନ୍ୟ ପରିଚାୟକ।                                  |
| `name`     | ବାକ୍ୟ         | ମାନବ-ପଠନୀୟ ଲେବଲ୍।                               |
| `type`     | ବାକ୍ୟ         | ପ୍ରୋଟୋକଲ୍: `http`, `https`, `socks5`            |
| `host`     | ବାକ୍ୟ         | ପ୍ରକ୍ସି ହୋଷ୍ଟନାମ କିମ୍ବା IP                      |
| `port`     | ଇଣ୍ଟିଜର୍      | ପୋର୍ଟ ନମ୍ବର।                                    |
| `username` | ବାକ୍ୟ         | Auth ଉପଯୋଗକର୍ତ୍ତା ନାମ (ବିଶ୍ରାମ ସମୟରେ ଏନକ୍ରିପ୍ଟ) |
| `password` | ବାକ୍ୟ         | Auth ପାସୱାର୍ଡ (ବିଶ୍ରାମ ସମୟରେ ଏନକ୍ରିପ୍ଟ)         |
| `region`   | ବାକ୍ୟ         | ଭ Ge ଗଳିକ ଅଞ୍ଚଳ ଲେବଲ୍।                          |
| `notes`    | ବାକ୍ୟ         | ମାଗଣା ପାଠ୍ୟ ଟିପ୍ପଣୀ।                            |
| `status`   | ବାକ୍ୟ         | `active` କିମ୍ବା `inactive`                      |
| `source`   | ବାକ୍ୟ         | `manual` କିମ୍ବା `oneproxy`                      |

### ଏକ ପ୍ରକ୍ସି ସୃଷ୍ଟି କରିବା।

**ଡ୍ୟାସବୋର୍ଡ ମାଧ୍ୟମରେ:**

1. ଯାଆନ୍ତୁ।** → ପ୍ରକ୍ସି ସେଟିଂସମୂହ।**
2. କ୍ଲିକ୍ କରନ୍ତୁ।** ପ୍ରକ୍ସି ଯୋଡନ୍ତୁ।**
3. ପ୍ରକାର, ହୋଷ୍ଟ, ପୋର୍ଟ, ଏବଂ ଇଚ୍ଛାଧୀନ auth ପରିଚୟପତ୍ର ପୁରଣ କରନ୍ତୁ।
4. ସଞ୍ଚୟ କରନ୍ତୁ।

**API ମାଧ୍ୟମରେ:**

```bash
curl -X POST http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "name": "US Proxy",
    "type": "http",
    "host": "proxy.example.com",
    "port": 8080,
    "username": "user",
    "password": "pass",
    "region": "US"
  }'
```

### ଏକ ପ୍ରକ୍ସି ଅଦ୍ୟତନ କରିବା।

```bash
curl -X PATCH http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "id": "proxy-uuid-here",
    "host": "new-proxy.example.com",
    "port": 9090
  }'
```

> **ଟିପନ୍ତୁ:** ଯଦି ଆପଣ ସ୍ପଷ୍ଟ ଭାବରେ ଖାଲି ନଥିବା ସ୍ଥାନାନ୍ତର ପଠାନ୍ତି ତେବେ ପ୍ରମାଣପତ୍ରଗୁଡ଼ିକ ସଂରକ୍ଷିତ। `username`/`password` ପାଇଁ ଖାଲି ଷ୍ଟ୍ରିଙ୍ଗ୍ ପଠାଇବା ଗଚ୍ଛିତ ମୂଲ୍ୟଗୁଡ଼ିକୁ ରଖିବ।

### ଏକ ପ୍ରକ୍ସି ବିଲୋପ କରିବା।

```bash
# Fails if proxy is assigned to any scope
curl -X DELETE "http://localhost:20128/api/v1/management/proxies?id=proxy-uuid"

# Force delete (removes assignments too)
curl -X DELETE "http://localhost:20128/api/v1/management/proxies?id=proxy-uuid&force=1"
```

### ପ୍ରକ୍ସି ତାଲିକାଭୁକ୍ତ।

```bash
curl "http://localhost:20128/api/v1/management/proxies?limit=50&offset=0"
```

### ପରିସରକୁ ପ୍ରକ୍ସି ନ୍ୟସ୍ତ କରିବା।

```bash
# Assign to global scope
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "global", "proxy": {"type":"http","host":"proxy.example.com","port":8080}}'

# Assign to a specific provider
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "provider", "id": "openai", "proxy": {"type":"socks5","host":"socks.example.com","port":1080}}'

# Assign to a specific connection/key
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "key", "id": "connection-uuid", "proxy": {"type":"http","host":"key-proxy.com","port":3128}}'
```

### ପ୍ରଭାବଶାଳୀ ପ୍ରକ୍ସିର ସମାଧାନ।

ପ୍ରଦତ୍ତ ସଂଯୋଗ ପାଇଁ କେଉଁ ପ୍ରକ୍ସି ବ୍ୟବହୃତ ହେବ ଯାଞ୍ଚ କରନ୍ତୁ:

```bash
curl "http://localhost:20128/api/settings/proxy?resolve=connection-uuid"
```

ଏହାର ସ୍ତର (`account`, `provider`, କିମ୍ବା `global`) ଏବଂ ଉତ୍ସ ସହିତ ସମାଧାନ ହୋଇଥିବା ପ୍ରକ୍ସି ଫେରସ୍ତ କରେ।

### Import/Export

ପ୍ରକ୍ସିଗୁଡ଼ିକ ଏଥିରେ ଅନ୍ତର୍ଭୁକ୍ତ।**Backup/Restore** ସିଷ୍ଟମ୍ ଯେତେବେଳେ ତୁମେ ତୁମର OmniRoute ବିନ୍ୟାସ ରପ୍ତାନି କର:

1. ଯାଆନ୍ତୁ।** ଡ୍ୟାସବୋର୍ଡ → ସେଟିଂସମୂହ → ବ୍ୟାକଅପ୍।**
2. କ୍ଲିକ୍ କରନ୍ତୁ।** ରପ୍ତାନି କରନ୍ତୁ।** — ପ୍ରକ୍ସି ରେଜିଷ୍ଟ୍ରି ଏବଂ ଆସାଇନମେଣ୍ଟଗୁଡିକ ଅନ୍ତର୍ଭୂକ୍ତ କରାଯାଇଛି।
3. ପୁନ restore ସ୍ଥାପନ କରିବାକୁ, କ୍ଲିକ୍ କରନ୍ତୁ।** ଆମଦାନୀ କରନ୍ତୁ।** ଏବଂ ବ୍ୟାକଅପ୍ ଫାଇଲ୍ ଅପଲୋଡ୍ କରନ୍ତୁ।

ପ୍ରକ୍ସି ରେଜିଷ୍ଟ୍ରି ମଧ୍ୟ ସମର୍ଥନ କରେ।** ହୋଷ୍ଟ + ପୋର୍ଟ ଦ୍ୱାରା ଅପ୍ସର୍ଟ।** — ଯଦି ଆପଣ ଏକ ପ୍ରକ୍ସି ଆମଦାନି କରନ୍ତି ଯାହା ପୂର୍ବରୁ ବିଦ୍ୟମାନ ଅଛି (ସମାନ ହୋଷ୍ଟ ଏବଂ ପୋର୍ଟ), ଏହା ଏକ ନକଲ ସୃଷ୍ଟି କରିବା ପରିବର୍ତ୍ତେ ଅଦ୍ୟତନ କରିଥାଏ।

### ଉତ୍ତରାଧିକାରୀ ସ୍ଥାନାନ୍ତରଣ।

ଯଦି ଆପଣ ଏକ ପୁରାତନ ସଂସ୍କରଣରେ (ପ୍ରି-ରେଜିଷ୍ଟ୍ରି) ପ୍ରକ୍ସିଗୁଡ଼ିକୁ ବିନ୍ୟାସ କରନ୍ତି, OmniRoute ସ୍ୱୟଂଚାଳିତ ଭାବରେ ସେମାନଙ୍କୁ ସ୍ଥାନାନ୍ତର କରେ:

```
Legacy key_value store → proxy_registry + proxy_assignments
```

ଅପଗ୍ରେଡ୍ ପରେ ପ୍ରଥମ ଷ୍ଟାର୍ଟଅପ୍ ରେ ଏହା ଥରେ ହୁଏ। ପୁନ run ଚଲାଇବା ପାଇଁ `migrateLegacyProxyConfigToRegistry({ force: true })` ବ୍ୟବହାର କରନ୍ତୁ।

## 1 ପ୍ରୋକ୍ସି ମାଗଣା ପ୍ରକ୍ସି ମାର୍କେଟପ୍ଲେସ୍।


2. **ଗଚ୍ଛିତ କରନ୍ତୁ।** — ପ୍ରକ୍ସିଗୁଡ଼ିକ `source = 'oneproxy'` ସହିତ ସମାନ `proxy_registry` ସାରଣୀରେ ସେଭ୍ ହୋଇଛି।

5. **ଅଟୋ-ଡିଗ୍ରେଡ୍।** — ବିଫଳ ପ୍ରକ୍ସିମାନେ ସେମାନଙ୍କର ଗୁଣାତ୍ମକ ସ୍କୋର ହ୍ରାସ କରନ୍ତି; ଥ୍ରେସହୋଲ୍ଡ → ତଳେ ନିଷ୍କ୍ରିୟ ଚିହ୍ନିତ।

## ଆଣ୍ଟି-ଡିଟେକସନ ଏବଂ ଚୋରି

OmniRoute କେବଳ ପ୍ରକ୍ସି — ମାଧ୍ୟମରେ ଟ୍ରାଫିକକୁ ମାର୍ଗ ଦିଏ ନାହିଁ ଏହା ଟ୍ରାଫିକକୁ ଆଇନଗତ ଦେଖାଏ:

### TLS ଫିଙ୍ଗର ପ୍ରିଣ୍ଟ ସ୍ପୁଫିଙ୍ଗ୍।

ବ୍ରାଉଜର୍ ପରି TLS ଫିଙ୍ଗର ପ୍ରିଣ୍ଟ ସୃଷ୍ଟି କରିବାକୁ `wreq-js` ବ୍ୟବହାର କରେ, ବଟ୍ ଚିହ୍ନଟ ପ୍ରଣାଳୀକୁ ବାଇପାସ୍ କରେ ଯାହା ବ୍ରାଉଜର୍ ନଥିବା TLS ହ୍ୟାଣ୍ଡସେକକୁ ଫ୍ଲାଗ୍ କରେ।

### CLI ଫିଙ୍ଗର ପ୍ରିଣ୍ଟ ମେଳ।

The**CLI ଫିଙ୍ଗର ପ୍ରିଣ୍ଟ ଟୋଗଲ୍।** (`Settings → Security`) ସ୍ଥାନୀୟ CLI ବାଇନାରୀ (Claude କୋଡ୍, Codex, ଇତ୍ୟାଦି) ର ସଠିକ୍ ଦସ୍ତଖତ ସହିତ ମେଳ ହେବା ପାଇଁ HTTP ହେଡର୍ ଏବଂ JSON ବଡି ଫିଲ୍ଡକୁ ପୁନ re ରେକର୍ଡ କରେ। ଏହା କାମ କରେ।** ଉପରେ** ପ୍ରକ୍ସି:

```
Your IP (blocked) → Proxy IP (US) → Provider API
                    + TLS spoof
                    + CLI fingerprint
```

ତୁମେ ଉଭୟ ପାଇବ।**IP ମାସ୍କିଂ।** ଏବଂ** ପ୍ରାମାଣିକତା ପାଇଁ ଅନୁରୋଧ।** ଏକାସାଙ୍ଗରେ।

ଡ୍ୟାସବୋର୍ଡରେ ରଙ୍ଗ-କୋଡ୍ ବ୍ୟାଜ୍ କେଉଁ ପ୍ରକ୍ସି ସ୍ତର ସକ୍ରିୟ ଅଛି ତାହା ଦର୍ଶାଏ:

| ବ୍ୟାଜ୍ | ସ୍ତର        | ଅର୍ଥ                                                 |
| ------ | ----------- | ---------------------------------------------------- |
| 🟢     | ଗ୍ଲୋବାଲ୍    | ସମସ୍ତ ଟ୍ରାଫିକ୍ ଏହି ପ୍ରକ୍ସି ଦେଇ ଗତି କରେ।              |
| 🟡     | ପ୍ରଦାନକାରୀ। | କେବଳ ଏହି ପ୍ରଦାନକାରୀଙ୍କ ଟ୍ରାଫିକ୍ ପ୍ରକ୍ସିଡ୍।           |

## ଅପଷ୍ଟ୍ରିମ୍ ପ୍ରକ୍ସି ମୋଡ୍।

CLIProxyAPI ପ୍ୟାଟର୍ ବ୍ୟବହାର କରୁଥିବା ପ୍ରଦାନକାରୀଙ୍କ ପାଇଁ, OmniRoute ତିନୋଟି ଅପଷ୍ଟ୍ରିମ୍ ପ୍ରକ୍ସି ମୋଡ୍ କୁ ସମର୍ଥନ କରେ:

| ମୋଡ୍          | ବର୍ଣ୍ଣନା                                                       |
| ------------- | -------------------------------------------------------------- |
| `native`      | OmniRoute ପ୍ରକ୍ସି ରାଉଟିଙ୍ଗକୁ ସିଧାସଳଖ ନିୟନ୍ତ୍ରଣ କରିଥାଏ (ଡିଫଲ୍ଟ) |
| `cliproxyapi` | ଏକ ବାହ୍ୟ CLIProxyAPI ଉଦାହରଣକୁ ପ୍ରତିନିଧୀ।                       |
| `fallback`    | ପ୍ରଥମେ ଦେଶୀ ଚେଷ୍ଟା କରେ, CLIProxyAPI କୁ ଫେରିଯାଏ।                |

ପ୍ରତି-ପ୍ରଦାନକାରୀଙ୍କୁ ବିନ୍ୟାସ କରନ୍ତୁ:

```bash
curl -X PUT "http://localhost:20128/api/upstream-proxy/openai" \
  -H "Content-Type: application/json" \
  -d '{"mode": "native", "enabled": true}'
```

- **ବର୍ତ୍ତମାନ ସିଙ୍କ୍ କରନ୍ତୁ।** ମାଗଣା ପ୍ରକ୍ସି ଆଣିବା ପାଇଁ ବଟନ୍।
- **ପରିସଂଖ୍ୟାନ କାର୍ଡ।** : ସମୁଦାୟ, ସକ୍ରିୟ, ହାରାହାରି ଗୁଣ, ଶେଷ ସିଙ୍କ୍।
- **ଫିଲ୍ଟର୍।** : ପ୍ରୋଟୋକଲ୍, ଦେଶ କୋଡ୍, ସର୍ବନିମ୍ନ ଗୁଣ।

## ତ୍ରୁଟି ନିବାରଣ

### "SOCKS5 ପ୍ରକ୍ସି ଅକ୍ଷମ ହୋଇଛି"

`ENABLE_SOCKS5_PROXY=true` ଆପଣଙ୍କର `.env` ଫାଇଲରେ ସେଟ୍ କରନ୍ତୁ ଏବଂ ପୁନ rest ଆରମ୍ଭ କରନ୍ତୁ।

### ପ୍ରକ୍ସି ମାଧ୍ୟମରେ "ସକେଟ୍ ହ୍ୟାଙ୍ଗ୍" ତ୍ରୁଟି।

ଶସ୍ତା ପ୍ରକ୍ସି ସହିତ ଏହା ସ୍ normal ାଭାବିକ ଯାହା ନିଷ୍କ୍ରିୟ ସଂଯୋଗକୁ ଛାଡିଦିଏ। OmniRoute ଏହା ଦ୍ୱାରା ପୂର୍ବରୁ ନିୟନ୍ତ୍ରଣ କରେ:

- ପ୍ରକ୍ସି ସଂଯୋଗ (`keepAliveTimeout: 1`) ରେ ଜୀବନ୍ତ ରଖିବା ଅକ୍ଷମ କରନ୍ତୁ।
- ପାଇପଲାଇନ ଅକ୍ଷମ କରିବା (`pipelining: 0`)
- ବାରମ୍ବାର ହ୍ୟାଣ୍ଡସେକରୁ ରକ୍ଷା ପାଇବା ପାଇଁ ଡିସପେକ୍ଟରମାନଙ୍କୁ କ୍ୟାଚ୍ କରିବା।

ଯଦି ଏହା ଜାରି ରହେ, ଏକ ଭିନ୍ନ ପ୍ରକ୍ସି ଚେଷ୍ଟା କରନ୍ତୁ କିମ୍ବା 1 ପ୍ରୋକ୍ସି ଘୂର୍ଣ୍ଣନ ବ feature ଶିଷ୍ଟ୍ୟ ବ୍ୟବହାର କରନ୍ତୁ।

### OAuth ସମୟରେ "ଅସମର୍ଥିତ_କାଉଣ୍ଟ୍ରି_ଗ୍ରେସନ୍_ ଟେରିଟୋରୀ"।

ନିଶ୍ଚିତ କରନ୍ତୁ ଯେ ପ୍ରକ୍ସି ବିନ୍ୟାସିତ ହୋଇଛି।** ପୂର୍ବରୁ** OAuth ପ୍ରବାହ ଆରମ୍ଭ କରିବା। OmniRoute ମାର୍ଗଗୁଡ଼ିକ ବିନ୍ୟାସିତ ପ୍ରକ୍ସି ମାଧ୍ୟମରେ OAuth ଟୋକେନ୍ ବିନିମୟ। ପ୍ରଥମେ ଏକ ଗ୍ଲୋବାଲ୍ କିମ୍ବା ପ୍ରଦାନକାରୀ ସ୍ତରୀୟ ପ୍ରକ୍ସି ସେଟ୍ କରନ୍ତୁ, ତାପରେ ସଂଯୋଗ କରନ୍ତୁ।

### ପ୍ରକ୍ସି ବ୍ୟବହାର କରାଯାଉନାହିଁ।

ରେଜୋଲୁସନ କ୍ରମ ଯାଞ୍ଚ କରନ୍ତୁ:

1. `GET /api/settings/proxy?resolve=your-connection-id` ସହିତ ଯାଞ୍ଚ କରନ୍ତୁ।
2. ପ୍ରକ୍ସି `status` `active` କି ନାହିଁ ଯାଞ୍ଚ କରନ୍ତୁ ( `inactive` ନୁହେଁ)
3. ନିଶ୍ଚିତ କରନ୍ତୁ ଯେ ପ୍ରକ୍ସି ଆସାଇନମେଣ୍ଟ ପରିସର ଆପଣଙ୍କ ସଂଯୋଗ ସହିତ ମେଳ ଖାଉଛି।

### 1 ପ୍ରୋକ୍ସି ସିଙ୍କ ବିଫଳ।

ସିଙ୍କ ସ୍ଥିତି ଯାଞ୍ଚ କରନ୍ତୁ:

```bash
curl "http://localhost:20128/api/settings/oneproxy?action=status"
```

ଯଦି `consecutiveFailures >= 5`, ସର୍କିଟ ବ୍ରେକର୍ ଟ୍ରିପ୍ ହୋଇଛି। ପୁନ res ସେଟ୍ କରିବାକୁ ସର୍ଭରକୁ ପୁନ Rest ଆରମ୍ଭ କରନ୍ତୁ, କିମ୍ବା ମାନୁଆଲ ପୁନ et ସେଟ୍ ପାଇଁ ଅପେକ୍ଷା କରନ୍ତୁ।

## ଡାଟାବେସ୍ ସ୍କିମା।

### `proxy_registry` ସାରଣୀ।

```sql
CREATE TABLE proxy_registry (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  type TEXT NOT NULL DEFAULT 'http',
  host TEXT NOT NULL,
  port INTEGER NOT NULL,
  username TEXT DEFAULT '',
  password TEXT DEFAULT '',
  region TEXT,
  notes TEXT,
  status TEXT DEFAULT 'active',
  source TEXT NOT NULL DEFAULT 'manual',    -- 'manual' or 'oneproxy'
  quality_score INTEGER,                     -- 0-100 (1proxy only)
  latency_ms INTEGER,                        -- milliseconds (1proxy only)
  anonymity TEXT,                            -- transparent/anonymous/elite
  google_access INTEGER DEFAULT 0,           -- can access Google? (1proxy)
  last_validated TEXT,                       -- ISO timestamp (1proxy)
  country_code TEXT,                         -- ISO 2-letter code (1proxy)
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

### `proxy_assignments` ସାରଣୀ।

```sql
CREATE TABLE proxy_assignments (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  proxy_id TEXT NOT NULL REFERENCES proxy_registry(id),
  scope TEXT NOT NULL,        -- 'global', 'provider', 'account', 'combo'
  scope_id TEXT,              -- provider ID, connection ID, or combo ID
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE(scope, scope_id)
);
```

## ପ୍ରକ୍ସି ସ୍ୱାସ୍ଥ୍ୟ ଯାଞ୍ଚ (v3.8.16 +)

OmniRoute ର** ପ୍ରକ୍ସି ଫାଷ୍ଟ-ଫେଲ୍।** ଯାନ୍ତ୍ରିକ (`src/lib/proxyHealth.ts`) ଶୀଘ୍ର TCP ସଂଯୋଗ ଯାଞ୍ଚ ମାଧ୍ୟମରେ < 2s ରେ ମୃତ ପ୍ରକ୍ସିଗୁଡ଼ିକୁ ଚିହ୍ନଟ କରେ।** ଫଳାଫଳକୁ କ୍ୟାଚ୍ କରେ।** ପ୍ରତି-ଅନୁରୋଧକୁ ଏଡାଇବାକୁ।

### ଏହା କିପରି କାମ କରେ।

```
Request ──▶ ProxyHealthCache.get(url)
             │
             ├─ Cache hit + fresh?  ──▶ return cached status
             │
             └─ Cache miss / stale?  ──▶ TCP connect to host:port
                                          (timeout: FAST_FAIL_TIMEOUT_MS)
                                          ──▶ cache for HEALTH_CACHE_TTL_MS
                                          ──▶ return result
```

ଏହା ବିନା, ଏକ ମୃତ ପ୍ରକ୍ସି ବିଫଳ ହେବା ପୂର୍ବରୁ ପୂର୍ଣ୍ଣ `PROXY_TIMEOUT_MS` (ଡିଫଲ୍ଟ 30s) ପାଇଁ ପ୍ରତ୍ୟେକ ଅନୁରୋଧକୁ ଅବରୋଧ କରିବ।

### ଟ୍ୟୁନେବଲ୍ ପରିବେଶ ଭେରିଏବଲ୍।

| ଭେରିଏବଲ୍                     | ଡିଫଲ୍ଟ। | ଉଦ୍ଦେଶ୍ୟ                                       |
| ---------------------------- | ------- | ---------------------------------------------- |
| `PROXY_FAST_FAIL_TIMEOUT_MS` | `2000`  | ସ୍ୱାସ୍ଥ୍ୟ ଯାଞ୍ଚ ପାଇଁTCP ସଂଯୋଗ ସମୟ ସମାପ୍ତ।      |
| `PROXY_HEALTH_CACHE_TTL_MS`  | `30000` | କେତେ ଦିନ ପର୍ଯ୍ୟନ୍ତ ସ୍ୱାସ୍ଥ୍ୟ ଫଳାଫଳ କ୍ୟାଚ୍ ହୁଏ। |

**ସୁପାରିଶ କରାଯାଇଥିବା ମୂଲ୍ୟଗୁଡିକ:**

| ------------------------ | ----------------------- | ---------- | -------------------------------------------------------------------------- |
| ଉଚ୍ଚ-ଥ୍ରୋପୁଟ୍ API ଗେଟୱେ। | 1500 ମି                 | 60000 ମି   | ଚେକ୍ ହ୍ରାସ କରିବାକୁ ଆକ୍ରମଣାତ୍ମକ ବିଫଳ-ଦ୍ରୁତ, ଅଧିକ କ୍ୟାଚ୍।                    |
| ଜିଓ-ବଣ୍ଟିତ ନୋଡଗୁଡ଼ିକ।    | 3000 ମି                 | 15000 ମି   | ମନ୍ଥର ନେଟୱାର୍କଗୁଡ଼ିକ ଅଧିକ ସମୟ ଆବଶ୍ୟକ କରନ୍ତି; ଦ୍ରୁତ ବିଫଳତା ପାଇଁ ଛୋଟ କ୍ୟାଚ୍। |

### ପ୍ରକ୍ସି ସ୍ୱାସ୍ଥ୍ୟ ଯାଞ୍ଚ କରିବା।

```ts

  console.log(`${s.proxyUrl} → healthy=${s.healthy}, stale=${s.stale}`);
```

## ପ୍ରକ୍ସି ଆନାଲିଟିକ୍ସ ଏବଂ ପର୍ଯ୍ୟବେକ୍ଷଣ ଯୋଗ୍ୟତା।

OmniRoute ପ୍ରତି-ପ୍ରକ୍ସି ବ୍ୟବହାରକୁ ଅପରେଟର୍ମାନଙ୍କୁ ରାଉଟିଙ୍ଗ୍ s ାଞ୍ଚା, ବିଳମ୍ବତା ସ୍ପାଇକ୍ ଏବଂ ବାରମ୍ବାର ବିଫଳତା ନିର୍ଣ୍ଣୟ କରିବାରେ ସାହାଯ୍ୟ କରେ।

### କ’ଣ ଟ୍ରାକ୍ ହୋଇଛି।

ଏକ ବିନ୍ୟାସିତ ପ୍ରକ୍ସି ମାଧ୍ୟମରେ ପ୍ରତ୍ୟେକ ଅନୁରୋଧ ପାଇଁ, OmniRoute ରେକର୍ଡଗୁଡିକ:

| ମେଟ୍ରିକ୍।    | ବର୍ଣ୍ଣନା                                                |
| ------------ | ------------------------------------------------------- |
| `proxy_url`  | ପୂର୍ଣ୍ଣ ପ୍ରକ୍ସି URL (auth ପରିଚୟପତ୍ର ସହିତ ମାସ୍କେଡ୍ ସହିତ) |
| `provider`   | ଅପଷ୍ଟ୍ରିମ ପ୍ରଦାନକାରୀ ID (ଓପନାଇ, ଆନ୍ଥ୍ରୋପିକ୍, ଇତ୍ୟାଦି)   |
| `latency_ms` | ପ୍ରକ୍ସି ହ୍ୟାଣ୍ଡସ୍ୟାକ୍ ସହିତ ସମୁଦାୟ ରାଉଣ୍ଡ-ଟ୍ରିପ୍ ସମୟ।    |
| `connect_ms` | TCP କେବଳ ସମୟ ସଂଯୋଗ କରନ୍ତୁ।                              |
| `status`     | ଅପଷ୍ଟ୍ରିମରୁHTTP ସ୍ଥିତି କୋଡ୍।                            |
| `error`      | ଅନୁରୋଧ ବିଫଳ ହେଲେ ତ୍ରୁଟି ଶ୍ରେଣୀ।                         |
| `timestamp`  | ISO 8601 UTC                                            |

### ଡାଟା ଆକ୍ସେସ୍ କରିବା।

```bash
# Recent proxy events
curl -H "Authorization: Bearer $OMNIROUTE_KEY" \
  "http://localhost:20128/api/usage/proxy-logs?limit=100"
```

ପ୍ରକୃତ ଶେଷ ପଏଣ୍ଟ ହେଉଛି `/api/usage/proxy-logs` ( `src/app/api/usage/proxy-logs/route.ts` ଦେଖନ୍ତୁ)। ଏହି ଶେଷ ପଏଣ୍ଟ ସମର୍ଥନ କରେ:

- `GET /api/usage/proxy-logs` — ପ୍ରକ୍ସି ଲଗ୍ ପୁନରୁଦ୍ଧାର କରନ୍ତୁ।
- `DELETE /api/usage/proxy-logs` — ସମସ୍ତ ପ୍ରକ୍ସି ଲଗ୍ ସଫା କର।

ଯଦି ଆବଶ୍ୟକ ହୁଏ ତେବେ `proxy_logs` ଟେବୁଲରୁ ସିଧାସଳଖ SQL ଟେବୁଲରୁ ପ୍ରଶ୍ନ କରାଯାଇପାରିବ। ଡ୍ୟାସବୋର୍ଡ UI ସମୁଦାୟ ଦୃଶ୍ୟ ପ୍ରଦାନ କରିପାରେ।

### ସାଧାରଣ ନମୁନା

**ଏକ ଫ୍ଲାପିଂ ପ୍ରକ୍ସି ଚିହ୍ନଟ କରନ୍ତୁ।** ( success/failure ମଧ୍ୟରେ ବିକଳ୍ପ):

```sql
SELECT proxy_url,
       COUNT(*) AS total,
       SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) AS errors,
       ROUND(100.0 * SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) / COUNT(*), 1) AS error_pct
FROM proxy_logs
WHERE timestamp > datetime('now', '-1 hour')
GROUP BY proxy_url
HAVING error_pct > 5
ORDER BY error_pct DESC;
```

**ଧୀର ପ୍ରକ୍ସି ଖୋଜ।** (p95 ବିଳମ୍ବତା > 2s):

```sql
WITH ranked AS (
  SELECT proxy_url, latency_ms,
         PERCENT_RANK() OVER (PARTITION BY proxy_url ORDER BY latency_ms) AS pct
  FROM proxy_logs
  WHERE timestamp > datetime('now', '-24 hour')
)
SELECT proxy_url, latency_ms
FROM ranked
WHERE pct >= 0.95
ORDER BY latency_ms DESC;
```

## ଆପଣଙ୍କର ନିଜ ପ୍ରକ୍ସି ପାଇଁ ସ୍ୱୟଂଚାଳିତ ବିଫଳତା ବହିଷ୍କାର।

1 ପ୍ରୋକ୍ସି ମାର୍କେଟପ୍ଲେସ୍ ପୁଲ୍ ନିଜେ ସ୍ୱୟଂଚାଳିତ ପ୍ରକ୍ସି ବିଫଳ ହୋଇଛି ( [ପ୍ରକ୍ସି କ୍ୱାଲିଟି ସ୍କୋର](#proxy-quality-scores) ଦେଖନ୍ତୁ)। ପ୍ରକ୍ସି ପାଇଁ।** ତୁମେ** ରେଜିଷ୍ଟ୍ରିରେ ଯୋଡା ଯାଇଛି, ପୃଷ୍ଠଭୂମି ସ୍ୱାସ୍ଥ୍ୟ ନିର୍ଧାରକ (`src/lib/proxyHealth/scheduler.ts`) ସମାନ "କ dead ଣସି ବିଲୋପ ନକରି ସ୍ୱୟଂଚାଳିତ ଭାବରେ ଶୃଙ୍ଖଳାରୁ ଜଣେ ମୃତ ସଦସ୍ୟଙ୍କୁ ବାଦ ଦିଅ" ପ୍ରଦାନ କରିଥାଏ:

```bash
# .env — soft-disable a proxy after 3 consecutive failed probes, re-enable it
# automatically once it starts answering probes again.
PROXY_AUTO_DISABLE=true
PROXY_AUTO_REMOVE_AFTER=3
```

ଏହା କିପରି ଏକ ମଲ୍ଟି-ପ୍ରକ୍ସି ଶୃଙ୍ଖଳରେ ଫିଟ୍ ହୁଏ:

1. ସିଡ୍ୟୁଲର୍ ପ୍ରତ୍ୟେକ ପଞ୍ଜୀକୃତ ପ୍ରକ୍ସି ପ୍ରତ୍ୟେକ `PROXY_HEALTH_INTERVAL_MS` (ଡିଫଲ୍ଟ 10 ମିନିଟ୍; ସର୍ବନିମ୍ନ 1 ମିନିଟ୍) ଯାଞ୍ଚ କରେ।
2. `PROXY_AUTO_REMOVE_AFTER` କ୍ରମାଗତ ପରେ।** ଚରମ** ବିଫଳତା (ଏକ ପ୍ରକୃତ ସଂଯୋଗ ବିଫଳତା — ଏକ ସମୟ ସମାପ୍ତି କିମ୍ବା ଅନୁସନ୍ଧାନ ଲକ୍ଷ୍ୟର ନିଜସ୍ୱ 5xx କଦାପି ଗଣନା କରେ ନାହିଁ, [ପ୍ରକ୍ସି ସ୍ୱାସ୍ଥ୍ୟ ଯାଞ୍ଚ](#proxy-health-checking-v3816) ଦେଖନ୍ତୁ), ପ୍ରକ୍ସିର `status` `dead` ରେ ସେଟ୍ ହୋଇଛି।
3. `dead` ହେଉଛି ଜୀବନ୍ତ-ସ୍ଥିତି ଫିଲ୍ଟର ଯାହାକି pool/rotation ରେଜୋଲୁସନ ଦ୍ used ାରା ବ୍ୟବହୃତ ହୁଏ, ତେଣୁ ଏକ ପରିସରର ଘୂର୍ଣ୍ଣନ (ରାଉଣ୍ଡ-ରୋବିନ / ରାଣ୍ଡମ / ଷ୍ଟିକି / ବିଳମ୍ବତା — [ରୋଟେସନ୍ ଷ୍ଟ୍ରାଟେଜୀ ନିଷ୍ପତ୍ତି ବୃକ୍ଷ](#rotation-strategy-decision-tree) ଦେଖନ୍ତୁ) ତୁରନ୍ତ ସେହି ପ୍ରକ୍ସିକୁ ନୂତନ ଅନୁରୋଧକୁ ଦେବା ବନ୍ଦ କରିଦିଏ। ପୁଲରେ ଅନ୍ୟ କ pro ଣସି ପ୍ରକ୍ସି ପ୍ରଭାବିତ ହୁଏ ନାହିଁ, ଏବଂ ପୁରା ପୁଲ୍ ଚୁପଚାପ୍ ସିଧାସଳଖ ସଂଯୋଗକୁ ଫେରିଯାଏ ନାହିଁ — [4-ସ୍ତରୀୟ ପ୍ରକ୍ସି ସିଷ୍ଟମ୍](#4-level-proxy-system) ବିଫଳ-ବନ୍ଦ ଗାର୍ଡ ଦେଖନ୍ତୁ।
4. ସମାନ ବ୍ୟବଧାନରେ ନିର୍ଧାରକ `dead` ପ୍ରକ୍ସି ଅନୁସନ୍ଧାନ ଜାରି ରଖେ। ପରବର୍ତ୍ତୀ ସଫଳ ଅନୁସନ୍ଧାନ `status` `active` କୁ ଫ୍ଲିପ୍ କରେ ଏବଂ ଏହା ଘୂର୍ଣ୍ଣନ — କୁ ପୁନ ent ପ୍ରବେଶ କରେ କ man ଣସି ମାନୁଆଲ୍ ପୁନ add- ଯୋଗ ଆବଶ୍ୟକ ନାହିଁ।

ଏହା ଜାଣିଶୁଣି।** ଅପ୍ଟ-ଇନ୍ ଏବଂ ବିନାଶକାରୀ।** : ଡିଫଲ୍ଟ ଭାବରେ ସିଡ୍ୟୁଲର୍ କେବଳ ଗଣନା କରେ ଏବଂ ବିଫଳତାକୁ ଲଗ୍ କରେ ( `decision.ts` ରେ ନୀତି C ଦେଖନ୍ତୁ), ଏବଂ `PROXY_AUTO_DISABLE` କଦାପି — ଧାଡି ବିଲୋପ କରେ ନାହିଁ ଯାହା ପୃଥକ, ଅଧିକ ଆକ୍ରମଣାତ୍ମକ `PROXY_AUTO_REMOVE` ପତାକା ପାଇଁ ଅଟେ। ଯଦି ଉଭୟ `true` ରେ ସେଟ୍ ହୋଇଛି, `PROXY_AUTO_REMOVE` ଜିତେ (ବିଲୋପ ହେବାକୁ ଥିବା ଏକ ପ୍ରକ୍ସି ମଧ୍ୟରେ ମୃଦୁ-ଅକ୍ଷମତା ପାଇଁ କ use ଣସି ବ୍ୟବହାର ନାହିଁ)। ପୂର୍ଣ୍ଣ ଭେରିଏବଲ୍ ତାଲିକା ପାଇଁ [ପରିବେଶ କନଫିଗ୍](../reference/ENVIRONMENT.md) ରେଫରେନ୍ସ ଦେଖନ୍ତୁ।
