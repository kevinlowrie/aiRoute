> **భౌగోళిక బ్లాక్లను దాటవేయండి, మీ గుర్తింపును రక్షించండి మరియు సున్నా కాన్ఫిగరేషన్ సంక్లిష్టతతో ఏదైనా ప్రాక్సీ — ద్వారా AI ట్రాఫిక్ను రూట్ చేయండి.**

OmniRoute పూర్తి-ఫీచర్ చేయబడిన ప్రాక్సీ మేనేజ్మెంట్ సిస్టమ్ను కలిగి ఉంది, ఇది HTTP, HTTPS, లేదా SOCKS5 ప్రాక్సీల ద్వారా అప్స్ట్రీమ్ AI ప్రొవైడర్ ట్రాఫిక్ను రూట్ చేయడానికి మిమ్మల్ని అనుమతిస్తుంది. మీరు బ్లాక్ చేయబడిన ప్రాంతంలో ఉన్నా, IP రొటేషన్ కావాలన్నా, లేదా స్టెల్త్ ఫింగర్ప్రింటింగ్ — కావాలన్నా ఈ గైడ్ అన్నింటినీ కవర్ చేస్తుంది.

## ప్రాక్సీలను ఎందుకు ఉపయోగించాలి?

చాలా మంది AI ప్రొవైడర్లు భౌగోళిక ప్రాంతం వారీగా యాక్సెస్ను నియంత్రిస్తారు. డెవలపర్లు** రష్యా, చైనా, ఇరాన్, క్యూబా, టర్కీ** , మరియు ఇతర దేశాలు ఇలాంటి లోపాలను ఎదుర్కొంటాయి:

```
unsupported_country_region_territory
```

బ్లాక్ చేయబడిన ప్రాంతాల వెలుపల కూడా, ప్రాక్సీలు వీటికి ఉపయోగపడతాయి:

| కేస్ ఉపయోగించండి   | వివరణ                                                                           |
| ------------------ | ------------------------------------------------------------------------------- |
| **భౌగోళిక బైపాస్** | బ్లాక్ చేయబడిన దేశాల నుండి OpenAI, Anthropic, Codex, Copilot ని యాక్సెస్ చేయండి |
| **IP భ్రమణం**      | రేటు పరిమితిని నివారించడానికి బహుళ IPs అంతటా అభ్యర్థనలను పంపిణీ చేయండి          |
| **గోప్యత**         | అప్స్ట్రీమ్ ప్రొవైడర్ల నుండి మీ నిజమైన IP దాచండి                                |
| **వర్తింపు**       | నిర్దిష్ట అధికార పరిధిలో ట్రాఫిక్ను రూట్ చేయండి                                 |
| **పరీక్షిస్తోంది** | వివిధ ప్రాంతాల నుండి అభ్యర్థనలను అనుకరించండి                                    |

## కొత్త ఖాతాల కోసం డిఫాల్ట్ ప్రాక్సీ స్థితి

లో** సెట్టింగులు → ప్రాక్సీ → గ్లోబల్ కాన్ఫిగరేషన్** , ఉపయోగించండి** కొత్త కనెక్షన్ల కోసం డిఫాల్ట్గా ప్రాక్సీని ప్రారంభించండి** కొత్తగా జోడించిన ప్రొవైడర్ ఖాతాల ప్రారంభ ప్రాక్సీ స్థితిని ఎంచుకోవడానికి.

కొత్త సెట్టింగ్ కొత్తగా జోడించిన ప్రొవైడర్ ఖాతాల ప్రారంభ ప్రాక్సీ స్థితిని నియంత్రిస్తుంది. ఇది ఇప్పటికే ఉన్న ఖాతాలను మార్చదు లేదా గ్లోబల్ ప్రాక్సీ స్విచ్ని భర్తీ చేయదు. దీని ప్రారంభ విలువ మునుపటి ప్రవర్తనను సంరక్షిస్తుంది. డిఫాల్ట్గా డిజేబుల్ చేయబడిన ప్రాక్సీతో భవిష్యత్ ఖాతాలను సృష్టించడానికి దీన్ని ఒకసారి ఆఫ్ చేయండి.

ఇప్పటికే ఉన్న సెట్టింగ్ల API ద్వారా ప్రాధాన్యత `defaultNewConnectionProxyEnabled` గా నిల్వ చేయబడుతుంది. ఎప్పుడూ సేవ్ చేయనప్పుడు ఇది `true` కి డిఫాల్ట్ అవుతుంది. పునఃప్రారంభించకుండానే తదుపరి కొత్త ఖాతాలకు `false` సేవ్ చేయడం ప్రభావం చూపుతుంది. `POST /api/providers` ఐచ్ఛిక కఠినమైన బూలియన్ `proxyEnabled` ని అంగీకరిస్తుంది; సృష్టి డిఫాల్ట్ కంటే స్పష్టమైన `true` లేదా `false` ప్రాధాన్యతనిస్తుంది. డూప్లికేట్ ఖాతా లేదా OAuth రీకనెక్ట్ని మినహాయించడం ఆ ఖాతా యొక్క నిల్వ స్థితిని భద్రపరుస్తుంది. వ్యక్తిగత ఖాతాలను ఇప్పటికీ ప్రారంభించవచ్చు లేదా నిలిపివేయవచ్చు.

సెలెక్టివ్ ప్రొవైడర్ బదిలీలు కొత్త ఖాతాల కోసం డెస్టినేషన్ ఇన్స్టాలేషన్ డిఫాల్ట్ను ఉపయోగిస్తాయి మరియు ఇప్పటికే ఉన్న ఖాతాలను భర్తీ చేసేటప్పుడు గమ్యస్థాన విధానాన్ని భద్రపరుస్తాయి. ప్రాక్సీ టోగుల్స్ పోర్టబుల్ బదిలీ ఫీల్డ్లు కాదు. పూర్తి బ్యాకప్ పునరుద్ధరణ మరియు హిస్టారికల్ JSON/SQL మైగ్రేషన్ సేవ్ చేయబడిన ఖాతా విలువలు మరియు లెగసీ స్కీమా డిఫాల్ట్లతో సహా వాటి ప్రస్తుత పునరుద్ధరణ అర్థాలను కలిగి ఉంటాయి; పూర్తి సెట్టింగ్ల పునరుద్ధరణ కూడా ఈ ప్రాధాన్యతను పునరుద్ధరించగలదు.

ఈ ప్రాధాన్యత ప్రాక్సీని కేటాయించదు లేదా ఒకటి ఆరోగ్యంగా ఉందని లేదా ఉపయోగంలో ఉందని నిర్ధారించదు. వాస్తవ రూటింగ్ ఇప్పటికీ గ్లోబల్ ప్రాక్సీ స్విచ్ మరియు వర్తించే ప్రాక్సీ కాన్ఫిగరేషన్పై ఆధారపడి ఉంటుంది. నిరంతర ఖాతా లేకుండా సింథటిక్ ప్రొవైడర్లు, ఖాతా సృష్టికి ముందు OAuth ట్రాఫిక్, environment/system ప్రాక్సీలు మరియు బాహ్య బ్యాకెండ్ల నెట్వర్కింగ్ దాని పరిధికి వెలుపల ఉన్నాయి.

## 4-స్థాయి ప్రాక్సీ సిస్టమ్

OmniRoute ప్రాక్సీ కాన్ఫిగరేషన్కు మద్దతు ఇస్తుంది** నాలుగు స్వతంత్ర పరిధులు** , ప్రాధాన్యత క్రమంలో పరిష్కరించబడింది:

```
Priority Resolution Order (highest → lowest):

  1. 🔵 Account/Connection Proxy  →  per API key / OAuth connection
  2. 🟡 Provider Proxy            →  per provider (e.g., all OpenAI traffic)
  3. 🟠 Combo Proxy               →  per combo/routing configuration
  4. 🟢 Global Proxy              →  all traffic, all providers
```

### రిజల్యూషన్ ఎలా పనిచేస్తుంది

OmniRoute అప్స్ట్రీమ్ ప్రొవైడర్కు అభ్యర్థనను పంపినప్పుడు, ఇది `resolveProxyForConnectionFromRegistry()` అని పిలుస్తుంది, ఇది ప్రతి స్థాయిని క్రమంలో తనిఖీ చేస్తుంది:

1. **ఖాతా స్థాయి** — ఈ నిర్దిష్ట కనెక్షన్ ID కి ప్రాక్సీ కేటాయించబడిందా?
2. **ప్రొవైడర్-స్థాయి** — ఈ ప్రొవైడర్కు ప్రాక్సీ కేటాయించబడిందా (ఉదా, `openai`)?
3. **ప్రపంచ స్థాయి** — గ్లోబల్ ప్రాక్సీ కాన్ఫిగర్ చేయబడిందా?
4. **ప్రాక్సీ లేదు** ప్రొవైడర్కు — డైరెక్ట్ కనెక్షన్.

మొదటి మ్యాచ్ గెలుస్తుంది. దీని అర్థం మీరు గ్లోబల్ ప్రాక్సీని ఫాల్బ్యాక్గా సెట్ చేయవచ్చు కానీ నిర్దిష్ట ప్రొవైడర్లు లేదా కనెక్షన్ల కోసం దాన్ని భర్తీ చేయవచ్చు.

### ఏది ప్రాక్సీడ్ అవుతుంది

| ట్రాఫిక్ రకం          | ప్రాక్సీడ్? | గమనికలు                                                |
| --------------------- | ----------- | ------------------------------------------------------ |
| చాట్ పూర్తి చేయడం     | ✅          | అన్ని `/v1/chat/completions` అభ్యర్థనలు                |
| పొందుపరచడం            | ✅          | `/v1/embeddings`                                       |
| చిత్రం తరం            | ✅          | `/v1/images/generations`                               |
| ఆడియో (TTS/STT)       | ✅          | `/v1/audio/*`                                          |
| OAuth టోకెన్ మార్పిడి | ✅          | `unsupported_country_region_territory` పరిష్కరిస్తుంది |
| కనెక్షన్ పరీక్షలు     | ✅          | "టెస్ట్ కనెక్షన్" బటన్ ప్రాక్సీని ఉపయోగిస్తుంది        |
| టోకెన్ రిఫ్రెష్       | ✅          | నేపథ్యం OAuth పునరుద్ధరణ                               |
| మోడల్ సమకాలీకరణ       | ✅          | మోడల్ జాబితా మరియు ఆవిష్కరణ                            |

## ప్రాక్సీ రిజిస్ట్రీ (CRUD)

ప్రాక్సీ రిజిస్ట్రీ అనేది మీ అన్ని ప్రాక్సీలను నిల్వ చేసే SQLite టేబుల్ (`proxy_registry`). ప్రతి ప్రాక్సీ కలిగి ఉంది:

| ఫీల్డ్     | టైప్ చేయండి | వివరణ                                                             |
| ---------- | ----------- | ----------------------------------------------------------------- |
| `id`       | UUID        | ప్రత్యేక ఐడెంటిఫైయర్                                              |
| `name`     | స్ట్రింగ్   | మానవులు చదవగలిగే లేబుల్                                           |
| `type`     | స్ట్రింగ్   | ప్రోటోకాల్: `http`, `https`, `socks5`                             |
| `host`     | స్ట్రింగ్   | ప్రాక్సీ హోస్ట్ పేరు లేదా IP                                      |
| `port`     | పూర్ణాంకం   | పోర్ట్ సంఖ్య                                                      |
| `username` | స్ట్రింగ్   | ప్రామాణీకరణ వినియోగదారు పేరు (విశ్రాంతి సమయంలో గుప్తీకరించబడింది) |
| `password` | స్ట్రింగ్   | ప్రామాణీకరణ పాస్వర్డ్ (విశ్రాంతి సమయంలో గుప్తీకరించబడింది)        |
| `region`   | స్ట్రింగ్   | భౌగోళిక ప్రాంత లేబుల్                                             |
| `notes`    | స్ట్రింగ్   | ఉచిత-వచన గమనికలు                                                  |
| `status`   | స్ట్రింగ్   | `active` లేదా `inactive`                                          |
| `source`   | స్ట్రింగ్   | `manual` లేదా `oneproxy`                                          |

### ప్రాక్సీని సృష్టిస్తోంది

**డాష్బోర్డ్ ద్వారా:**

1. వెళ్ళండి** సెట్టింగులు → ప్రాక్సీ**
2. క్లిక్ చేయండి** ప్రాక్సీని జోడించండి**
3. రకం, హోస్ట్, పోర్ట్ మరియు ఐచ్ఛిక ప్రామాణీకరణ ఆధారాలను పూరించండి
4. సేవ్ చేయండి

**API ద్వారా:**

```bash
curl -X POST http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "name": "US Proxy",
    "type": "http",
    "host": "proxy.example.com",
    "port": 8080,
    "username": "user",
    "password": "pass",
    "region": "US"
  }'
```

### ప్రాక్సీని నవీకరిస్తోంది

```bash
curl -X PATCH http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "id": "proxy-uuid-here",
    "host": "new-proxy.example.com",
    "port": 9090
  }'
```

> **గమనిక:** మీరు ఖాళీ కాని రీప్లేస్మెంట్లను స్పష్టంగా పంపితే మినహా ఆధారాలు భద్రపరచబడతాయి. `username`/`password` కోసం ఖాళీ స్ట్రింగ్లను పంపడం నిల్వ విలువలను ఉంచుతుంది.

### ప్రాక్సీని తొలగిస్తోంది

```bash
# Fails if proxy is assigned to any scope
curl -X DELETE "http://localhost:20128/api/v1/management/proxies?id=proxy-uuid"

# Force delete (removes assignments too)
curl -X DELETE "http://localhost:20128/api/v1/management/proxies?id=proxy-uuid&force=1"
```

### లిస్టింగ్ ప్రాక్సీలు

```bash
curl "http://localhost:20128/api/v1/management/proxies?limit=50&offset=0"
```

### స్కోప్లకు ప్రాక్సీలను కేటాయించడం

```bash
# Assign to global scope
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "global", "proxy": {"type":"http","host":"proxy.example.com","port":8080}}'

# Assign to a specific provider
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "provider", "id": "openai", "proxy": {"type":"socks5","host":"socks.example.com","port":1080}}'

# Assign to a specific connection/key
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "key", "id": "connection-uuid", "proxy": {"type":"http","host":"key-proxy.com","port":3128}}'
```

### ఎఫెక్టివ్ ప్రాక్సీని పరిష్కరిస్తోంది

ఇచ్చిన కనెక్షన్ కోసం ఏ ప్రాక్సీ ఉపయోగించబడుతుందో తనిఖీ చేయండి:

```bash
curl "http://localhost:20128/api/settings/proxy?resolve=connection-uuid"
```

పరిష్కరించబడిన ప్రాక్సీని దాని స్థాయి (`account`, `provider`, లేదా `global`) మరియు మూలంతో అందిస్తుంది.

### బల్క్ అసైన్మెంట్

ఒకేసారి బహుళ ప్రొవైడర్లు లేదా కనెక్షన్లకు ఒక ప్రాక్సీని కేటాయించండి:

```bash
curl -X POST http://localhost:20128/api/v1/management/proxies/bulk-assign \
  -H "Content-Type: application/json" \
  -d '{
    "scope": "provider",
    "scopeIds": ["openai", "anthropic", "codex"],
    "proxyId": "proxy-uuid"
  }'
```

### Import/Export

ప్రాక్సీలు చేర్చబడ్డాయి**Backup/Restore** వ్యవస్థ. మీరు మీ OmniRoute కాన్ఫిగరేషన్ను ఎగుమతి చేసినప్పుడు:

1. వెళ్ళండి** డాష్బోర్డ్ → సెట్టింగ్లు → బ్యాకప్**
2. క్లిక్ చేయండి** ఎగుమతి చేయండి** — ప్రాక్సీ రిజిస్ట్రీ మరియు అసైన్మెంట్లు చేర్చబడ్డాయి
3. పునరుద్ధరించడానికి, క్లిక్ చేయండి** దిగుమతి** మరియు బ్యాకప్ ఫైల్ను అప్లోడ్ చేయండి

ప్రాక్సీ రిజిస్ట్రీ కూడా మద్దతు ఇస్తుంది** హోస్ట్+ పోర్ట్ ద్వారా అప్సర్ట్** — మీరు ఇప్పటికే ఉన్న ప్రాక్సీని (అదే హోస్ట్ మరియు పోర్ట్) దిగుమతి చేసుకుంటే, అది నకిలీని సృష్టించే బదులు నవీకరించబడుతుంది.

### లెగసీ మైగ్రేషన్

మీరు పాత వెర్షన్ (ప్రీ-రిజిస్ట్రీ)లో ప్రాక్సీలను కాన్ఫిగర్ చేసినట్లయితే, OmniRoute వాటిని స్వయంచాలకంగా మైగ్రేట్ చేస్తుంది:

```
Legacy key_value store → proxy_registry + proxy_assignments
```

అప్గ్రేడ్ చేసిన తర్వాత మొదటి స్టార్టప్లో ఒకసారి ఇది జరుగుతుంది. మళ్లీ అమలు చేయడానికి `migrateLegacyProxyConfigToRegistry({ force: true })` ఉపయోగించండి.

## 1ప్రాక్సీ ఉచిత ప్రాక్సీ మార్కెట్ప్లేస్

> 🆕** [@oyi77](https://github.com/oyi77) ద్వారా అందించబడింది** — PR [#1847](https://github.com/diegosouzapw/OmniRoute/pull/1847) (ఇష్యూ [#1788](https://github.com/diegosouzapw/OmniRoute/issues/1788) )

OmniRoute తో కలిసిపోతుంది** [1ప్రాక్సీ](https://1proxy-api.aitradepulse.com)** యాక్సెస్ అందించడానికి కమ్యూనిటీ వేదిక** వందల కొద్దీ ఉచిత, ధృవీకరించబడిన ప్రాక్సీలు** ప్రపంచం నలుమూలల నుండి. సొంత ప్రాక్సీ మౌలిక సదుపాయాలు లేని వినియోగదారులకు ఇది సరైనది.

### ఇది ఎలా పనిచేస్తుంది

```
┌─────────────┐     Sync      ┌─────────────────┐    Rotate     ┌──────────┐
│  1proxy API │ ────────────▶ │  proxy_registry  │ ────────────▶ │ Provider │
│  (external) │   up to 500   │  source=oneproxy │  by quality   │   API    │
└─────────────┘    proxies    └─────────────────┘               └──────────┘
```

1. **సమకాలీకరించు** — OmniRoute 1proxy API నుండి ధృవీకరించబడిన ప్రాక్సీలను పొందుతుంది
2. **స్టోర్** — ప్రాక్సీలు అదే `proxy_registry` పట్టికలో `source = 'oneproxy'` తో సేవ్ చేయబడతాయి
3. **ఫిల్టర్ చేయండి** — ప్రోటోకాల్, దేశం, నాణ్యత స్కోర్ ద్వారా ఫిల్టర్ చేయండి
4. **తిప్పండి** — నాణ్యత, యాదృచ్ఛిక లేదా సీక్వెన్షియల్ వ్యూహాలను ఉపయోగించి ఉత్తమ ప్రాక్సీని ఎంచుకోండి
5. **ఆటో-డిగ్రేడ్** — విఫలమైన ప్రాక్సీలు వాటి నాణ్యత స్కోర్ను తగ్గించాయి; దిగువ థ్రెషోల్డ్ → నిష్క్రియంగా గుర్తించబడింది

### ప్రాక్సీలను సమకాలీకరిస్తోంది

**డాష్బోర్డ్ ద్వారా:**

1. వెళ్ళండి** సెట్టింగులు → 1ప్రాక్సీ** ట్యాబ్
2. క్లిక్ చేయండి** "ఇప్పుడే సమకాలీకరించు"**
3. గణాంకాలను వీక్షించండి: మొత్తం ప్రాక్సీలు, సక్రియ గణన, సగటు నాణ్యత, దేశ-దేశాల విభజన

**API ద్వారా:**

```bash
# Trigger sync
curl -X POST http://localhost:20128/api/settings/oneproxy \
  -H "Content-Type: application/json" \
  -d '{}'

# Response:
# { "success": true, "added": 127, "updated": 45, "failed": 2, "total": 172 }
```

### ఫిల్టరింగ్ ప్రాక్సీలు

```bash
# Filter by protocol
curl "http://localhost:20128/api/settings/oneproxy?protocol=socks5"

# Filter by country
curl "http://localhost:20128/api/settings/oneproxy?countryCode=US"

# Filter by minimum quality score
curl "http://localhost:20128/api/settings/oneproxy?minQuality=80"

# Combine filters
curl "http://localhost:20128/api/settings/oneproxy?protocol=http&countryCode=DE&minQuality=70"
```

### ప్రాక్సీ నాణ్యత స్కోర్లు

ప్రతి 1ప్రాక్సీ ప్రాక్సీ మెటాడేటాతో వస్తుంది:

| ఫీల్డ్          | వివరణ                                    |
| --------------- | ---------------------------------------- |
| `qualityScore`  | 1ప్రాక్సీ ధ్రువీకరణ నుండి 0-100 రేటింగ్  |
| `latencyMs`     | నెట్వర్క్ జాప్యాన్ని కొలుస్తారు          |
| `anonymity`     | `transparent`, `anonymous`, లేదా `elite` |
| `googleAccess`  | ప్రాక్సీ Google సేవలను యాక్సెస్ చేయగలదా  |
| `countryCode`   | రెండు అక్షరాల ISO దేశం కోడ్              |
| `lastValidated` | చివరి ధ్రువీకరణ సమయముద్ర                 |

నాణ్యత స్కోర్లు డైనమిక్గా సర్దుబాటు చేయబడ్డాయి:

- **విఫలమైన అభ్యర్థనలు** స్కోరును 10 పాయింట్లు తగ్గించండి
- **స్కోరు ≤ 10కి పడిపోతుంది** → ప్రాక్సీ `inactive` గుర్తు పెట్టబడింది
- నిష్క్రియ ప్రాక్సీలు భ్రమణం నుండి మినహాయించబడ్డాయి

### భ్రమణ వ్యూహాలు

```bash
# Rotate by quality (best proxy first) — default
curl -X POST http://localhost:20128/api/settings/oneproxy/rotate \
  -H "Content-Type: application/json" \
  -d '{"strategy": "quality"}'

# Random rotation
curl -X POST http://localhost:20128/api/settings/oneproxy/rotate \
  -d '{"strategy": "random"}'

# Sequential (least recently validated first)
curl -X POST http://localhost:20128/api/settings/oneproxy/rotate \
  -d '{"strategy": "sequential"}'
```

### సర్క్యూట్ బ్రేకర్

1ప్రాక్సీ సమకాలీకరణలో అంతర్నిర్మిత సర్క్యూట్ బ్రేకర్ ఉంది:

- తర్వాత** 5 వరుస సమకాలీకరణ వైఫల్యాలు** , తదుపరి సమకాలీకరణ ప్రయత్నాలు బ్లాక్ చేయబడ్డాయి
- దీనితో రీసెట్ చేయండి: `resetOneproxyCircuitBreaker()` లేదా సర్వర్ని పునఃప్రారంభించండి
- `GET /api/settings/oneproxy?action=status` వద్ద సమకాలీకరణ స్థితి అందుబాటులో ఉంది

## యాంటీ-డిటెక్షన్ & స్టెల్త్

OmniRoute కేవలం ప్రాక్సీ — ద్వారా ట్రాఫిక్ను రూట్ చేయదు, ఇది ట్రాఫిక్ను చట్టబద్ధంగా కనిపించేలా చేస్తుంది:

### TLS ఫింగర్ప్రింట్ స్పూఫింగ్

బ్రౌజర్ లాంటి TLS వేలిముద్రలను రూపొందించడానికి `wreq-js` ఉపయోగిస్తుంది, బ్రౌజర్ కాని TLS హ్యాండ్షేక్లను ఫ్లాగ్ చేసే బోట్ డిటెక్షన్ సిస్టమ్లను దాటవేస్తుంది.

### CLI వేలిముద్ర సరిపోలిక

ది**CLI వేలిముద్ర టోగుల్** (`Settings → Security`) స్థానిక CLI బైనరీల (Claude కోడ్, Codex, మొదలైనవి) యొక్క ఖచ్చితమైన సంతకంతో సరిపోలడానికి HTTP హెడర్లు మరియు JSON బాడీ ఫీల్డ్లను రీఆర్డర్ చేస్తుంది. ఇది పనిచేస్తుంది** పైన** ప్రాక్సీ:

```
Your IP (blocked) → Proxy IP (US) → Provider API
                    + TLS spoof
                    + CLI fingerprint
```

మీరు రెండూ పొందుతారు**IP మాస్కింగ్** మరియు** ప్రామాణికతను అభ్యర్థించండి** ఏకకాలంలో.

### ప్రాక్సీ IP సంరక్షణ

డాష్బోర్డ్లోని రంగు-కోడెడ్ బ్యాడ్జ్లు ఏ ప్రాక్సీ స్థాయి సక్రియంగా ఉందో చూపుతుంది:

| బ్యాడ్జ్ | స్థాయి    | అర్థం                                              |
| -------- | --------- | -------------------------------------------------- |
| 🟢       | గ్లోబల్   | ట్రాఫిక్ అంతా ఈ ప్రాక్సీ గుండా వెళుతుంది           |
| 🟡       | ప్రొవైడర్ | ఈ ప్రొవైడర్ ట్రాఫిక్ మాత్రమే ప్రాక్సీ చేయబడింది    |
| 🔵       | కనెక్షన్  | ఈ నిర్దిష్ట key/account ఈ ప్రాక్సీని ఉపయోగిస్తుంది |

బ్యాడ్జ్ ధృవీకరణ కోసం పరిష్కరించబడిన ప్రాక్సీ IP కూడా చూపుతుంది.

## అప్స్ట్రీమ్ ప్రాక్సీ మోడ్లు

CLIProxyAPI నమూనాను ఉపయోగించే ప్రొవైడర్ల కోసం, OmniRoute మూడు అప్స్ట్రీమ్ ప్రాక్సీ మోడ్లకు మద్దతు ఇస్తుంది:

| మోడ్          | వివరణ                                                           |
| ------------- | --------------------------------------------------------------- |
| `native`      | OmniRoute నేరుగా ప్రాక్సీ రూటింగ్ను నిర్వహిస్తుంది (డిఫాల్ట్)   |
| `cliproxyapi` | బాహ్య CLIProxyAPI ఉదాహరణకి ప్రతినిధులు                          |
| `fallback`    | మొదట స్థానికంగా ప్రయత్నిస్తుంది, తిరిగి CLIProxyAPI కి వస్తుంది |

ప్రతి ప్రొవైడర్ని కాన్ఫిగర్ చేయండి:

```bash
curl -X PUT "http://localhost:20128/api/upstream-proxy/openai" \
  -H "Content-Type: application/json" \
  -d '{"mode": "native", "enabled": true}'
```

- **ప్రతి-కనెక్షన్ ప్రాక్సీ** కేటాయింపులు
- **కనెక్షన్ పరీక్ష** కాన్ఫిగర్ చేయబడిన ప్రాక్సీ ద్వారా
- **రంగు-కోడెడ్ బ్యాడ్జ్లు** క్రియాశీల ప్రాక్సీ స్థాయిని చూపుతోంది

### సెట్టింగులు → 1ప్రాక్సీ టాబ్

- **ఇప్పుడు సమకాలీకరించండి** ఉచిత ప్రాక్సీలను పొందేందుకు బటన్
- **గణాంకాలు కార్డులు** : మొత్తం, సక్రియం, సగటు నాణ్యత, చివరి సమకాలీకరణ
- **ఫిల్టర్లు** : ప్రోటోకాల్, దేశం కోడ్, కనీస నాణ్యత
- **ప్రాక్సీ టేబుల్** హోస్ట్, ప్రోటోకాల్, దేశం, నాణ్యత స్కోర్, జాప్యం, అనామకత, Google యాక్సెస్తో
- **సమకాలీకరణ స్థితి** success/failure ట్రాకింగ్ మరియు వరుస వైఫల్యాల సంఖ్యతో ప్యానెల్
- **అన్నీ క్లియర్ చేయండి** అన్ని 1ప్రాక్సీ ఎంట్రీలను తీసివేయడానికి

### ప్రాక్సీ ద్వారా "సాకెట్ హ్యాంగ్ అప్" లోపాలు

నిష్క్రియ కనెక్షన్లను తగ్గించే చౌక ప్రాక్సీలతో ఇది సాధారణం. OmniRoute ఇప్పటికే దీని ద్వారా నిర్వహిస్తోంది:

- ప్రాక్సీ కనెక్షన్లలో కీప్-ఎలైవ్ని నిలిపివేయడం (`keepAliveTimeout: 1`)
- పైప్లైనింగ్ను నిలిపివేయడం (`pipelining: 0`)
- పదేపదే హ్యాండ్షేక్లను నివారించడానికి డిస్పాచర్లను కాషింగ్ చేస్తుంది

ఇది కొనసాగితే, వేరే ప్రాక్సీని ప్రయత్నించండి లేదా 1ప్రాక్సీ భ్రమణ లక్షణాన్ని ఉపయోగించండి.

### OAuth సమయంలో "unsupported_country_region_territory"

ప్రాక్సీ కాన్ఫిగర్ చేయబడిందని నిర్ధారించుకోండి** ముందు** OAuth ప్రవాహాన్ని ప్రారంభించడం. OmniRoute మార్గాలు కాన్ఫిగర్ చేయబడిన ప్రాక్సీ ద్వారా OAuth టోకెన్ మార్పిడి. ముందుగా గ్లోబల్ లేదా ప్రొవైడర్-స్థాయి ప్రాక్సీని సెట్ చేసి, ఆపై కనెక్ట్ చేయండి.

### ప్రాక్సీ ఉపయోగించబడదు

రిజల్యూషన్ క్రమాన్ని తనిఖీ చేయండి:

1. `GET /api/settings/proxy?resolve=your-connection-id` తో ధృవీకరించండి
2. ప్రాక్సీ `status` `active` కాదా అని తనిఖీ చేయండి ( `inactive` కాదు)
3. ప్రాక్సీ అసైన్మెంట్ స్కోప్ మీ కనెక్షన్తో సరిపోలుతుందని నిర్ధారించుకోండి

### 1ప్రాక్సీ సమకాలీకరణ విఫలమైంది

సమకాలీకరణ స్థితిని తనిఖీ చేయండి:

```bash
curl "http://localhost:20128/api/settings/oneproxy?action=status"
```

`consecutiveFailures >= 5` అయితే, సర్క్యూట్ బ్రేకర్ ట్రిప్ చేయబడింది. రీసెట్ చేయడానికి సర్వర్ని పునఃప్రారంభించండి లేదా మాన్యువల్ రీసెట్ కోసం వేచి ఉండండి.

### `proxy_registry` టేబుల్

```sql
CREATE TABLE proxy_registry (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  type TEXT NOT NULL DEFAULT 'http',
  host TEXT NOT NULL,
  port INTEGER NOT NULL,
  username TEXT DEFAULT '',
  password TEXT DEFAULT '',
  region TEXT,
  notes TEXT,
  status TEXT DEFAULT 'active',
  source TEXT NOT NULL DEFAULT 'manual',    -- 'manual' or 'oneproxy'
  quality_score INTEGER,                     -- 0-100 (1proxy only)
  latency_ms INTEGER,                        -- milliseconds (1proxy only)
  anonymity TEXT,                            -- transparent/anonymous/elite
  google_access INTEGER DEFAULT 0,           -- can access Google? (1proxy)
  last_validated TEXT,                       -- ISO timestamp (1proxy)
  country_code TEXT,                         -- ISO 2-letter code (1proxy)
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

### `proxy_assignments` టేబుల్

```sql
CREATE TABLE proxy_assignments (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  proxy_id TEXT NOT NULL REFERENCES proxy_registry(id),
  scope TEXT NOT NULL,        -- 'global', 'provider', 'account', 'combo'
  scope_id TEXT,              -- provider ID, connection ID, or combo ID
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE(scope, scope_id)
);
```

## ప్రాక్సీ ఆరోగ్య తనిఖీ (v3.8.16 +)

OmniRoute లు** ప్రాక్సీ ఫాస్ట్-ఫెయిల్** మెకానిజం (`src/lib/proxyHealth.ts`) శీఘ్ర TCP కనెక్షన్ చెక్ ద్వారా < 2sలో డెడ్ ప్రాక్సీలను గుర్తిస్తుంది, ఆపై** ఫలితాన్ని క్యాష్ చేస్తుంది** ప్రతి అభ్యర్థన ఓవర్హెడ్ను నివారించడానికి.

### ఇది ఎలా పనిచేస్తుంది

```
Request ──▶ ProxyHealthCache.get(url)
             │
             ├─ Cache hit + fresh?  ──▶ return cached status
             │
             └─ Cache miss / stale?  ──▶ TCP connect to host:port
                                          (timeout: FAST_FAIL_TIMEOUT_MS)
                                          ──▶ cache for HEALTH_CACHE_TTL_MS
                                          ──▶ return result
```

ఇది లేకుండా, డెడ్ ప్రాక్సీ విఫలమయ్యే ముందు పూర్తి `PROXY_TIMEOUT_MS` (డిఫాల్ట్ 30సె) కోసం ప్రతి అభ్యర్థనను బ్లాక్ చేస్తుంది.

### ట్యూనబుల్ ఎన్విరాన్మెంట్ వేరియబుల్స్

| వేరియబుల్                    | డిఫాల్ట్ | ప్రయోజనం                                  |
| ---------------------------- | -------- | ----------------------------------------- |
| `PROXY_FAST_FAIL_TIMEOUT_MS` | `2000`   | ఆరోగ్య తనిఖీకిTCP కనెక్షన్ సమయం ముగిసింది |
| `PROXY_HEALTH_CACHE_TTL_MS`  | `30000`  | ఆరోగ్య ఫలితం ఎంతకాలం కాష్ చేయబడుతుంది     |

**సిఫార్సు చేయబడిన విలువలు:**

| దృశ్యం                     | ఫాస్ట్-ఫెయిల్ సమయం ముగిసింది | కాష్ TTL | రీజనింగ్                                                                       |
| -------------------------- | ---------------------------- | -------- | ------------------------------------------------------------------------------ |
| హై-త్రూపుట్ API గేట్వే     | 1500ms                       | 60000ms  | తనిఖీలను తగ్గించడానికి ఉగ్రమైన వైఫల్యం-వేగవంతమైన, పొడవైన కాష్                  |
| జియో-పంపిణీ నోడ్లు         | 3000ms                       | 15000ms  | నెమ్మదించిన నెట్వర్క్లకు ఎక్కువ సమయం కావాలి; ఫాస్ట్ ఫెయిల్ఓవర్ కోసం చిన్న కాష్ |
| దేవ్ / పరీక్ష              | 1000ms                       | 10000ms  | స్థానిక ప్రాక్సీలపై త్వరిత పునరావృతం                                           |
| స్టెల్త్ / యాంటీ డిటెక్షన్ | 2500ms                       | 45000ms  | రేటు పరిమితులను ప్రేరేపించే వేగవంతమైన విచారణను నివారించండి                     |

### ప్రాక్సీ ఆరోగ్యాన్ని తనిఖీ చేస్తోంది

```ts
import { getAllProxyHealthStatuses, invalidateProxyHealth } from "omniroute/proxyHealth";

const statuses = getAllProxyHealthStatuses();
for (const s of statuses) {
  console.log(`${s.proxyUrl} → healthy=${s.healthy}, stale=${s.stale}`);
}

// Force re-check a specific proxy
invalidateProxyHealth("http://user:pass@203.0.113.7:8080");
```

కాష్ నమోదు `HEALTH_CACHE_TTL_MS` ని మించిపోయినప్పుడు `stale` ఫ్లాగ్ `true` అవుతుంది మరియు తదుపరి అభ్యర్థన తాజా తనిఖీని ప్రేరేపిస్తుంది.

### ప్రతి-ప్రాక్సీ రకం డిఫాల్ట్లు

ఆరోగ్య తనిఖీ URL పథకం ఆధారంగా సెన్సిబుల్ డిఫాల్ట్లను ఉపయోగిస్తుంది:

| పథకం                       | డిఫాల్ట్ పోర్ట్ |
| -------------------------- | --------------- |
| `http://`                  | 8080            |
| `https://`                 | 443             |
| `socks5://` / `socks5h://` | 1080            |

URL (`http://host:9999`)లోని కస్టమ్ పోర్ట్లు ఎల్లప్పుడూ స్కీమ్ డిఫాల్ట్ కంటే ప్రాధాన్యతనిస్తాయి.

## ప్రాక్సీ అనలిటిక్స్ & పరిశీలన

రూటింగ్ నమూనాలు, జాప్యం వచ్చే చిక్కులు మరియు పునరావృత వైఫల్యాలను నిర్ధారించడంలో ఆపరేటర్లకు సహాయం చేయడానికిOmniRoute ప్రతి-ప్రాక్సీ వినియోగాన్ని ట్రాక్ చేస్తుంది.

### ఏమి ట్రాక్ చేయబడింది

కాన్ఫిగర్ చేయబడిన ప్రాక్సీ ద్వారా ప్రతి అభ్యర్థన కోసం, OmniRoute రికార్డ్లు:

| మెట్రిక్     | వివరణ                                                  |
| ------------ | ------------------------------------------------------ |
| `proxy_url`  | పూర్తి ప్రాక్సీ URL (మాస్క్డ్ ప్రామాణీకరణ ఆధారాలతో)    |
| `provider`   | అప్స్ట్రీమ్ ప్రొవైడర్ ID (ఓపెనై, ఆంత్రోపిక్, మొదలైనవి) |
| `latency_ms` | ప్రాక్సీ హ్యాండ్షేక్తో సహా మొత్తం రౌండ్-ట్రిప్ సమయం    |
| `connect_ms` | TCP కనెక్ట్ సమయం మాత్రమే                               |
| `status`     | అప్స్ట్రీమ్ నుండిHTTP స్థితి కోడ్                      |
| `error`      | అభ్యర్థన విఫలమైతే తరగతి లోపం                           |
| `timestamp`  | ISO 8601 UTC                                           |

### డేటాను యాక్సెస్ చేస్తోంది

```bash
# Recent proxy events
curl -H "Authorization: Bearer $OMNIROUTE_KEY" \
  "http://localhost:20128/api/usage/proxy-logs?limit=100"
```

నిజమైన ముగింపు స్థానం `/api/usage/proxy-logs` ( `src/app/api/usage/proxy-logs/route.ts` చూడండి). ఈ ముగింపు స్థానం మద్దతు ఇస్తుంది:

- `GET /api/usage/proxy-logs` — ప్రాక్సీ లాగ్లను తిరిగి పొందండి
- `DELETE /api/usage/proxy-logs` — అన్ని ప్రాక్సీ లాగ్లను క్లియర్ చేస్తుంది

అవసరమైతే మొత్తం గణాంకాలను `proxy_logs` పట్టిక నుండి నేరుగా SQL ద్వారా ప్రశ్నించవచ్చు. డాష్బోర్డ్ UI మొత్తం వీక్షణలను అందించవచ్చు.

### సాధారణ నమూనాలు

**ఫ్లాపింగ్ ప్రాక్సీని గుర్తించండి** ( success/failure మధ్య ప్రత్యామ్నాయాలు):

```sql
SELECT proxy_url,
       COUNT(*) AS total,
       SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) AS errors,
       ROUND(100.0 * SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) / COUNT(*), 1) AS error_pct
FROM proxy_logs
WHERE timestamp > datetime('now', '-1 hour')
GROUP BY proxy_url
HAVING error_pct > 5
ORDER BY error_pct DESC;
```

**స్లో ప్రాక్సీలను కనుగొనండి** (p95 జాప్యం > 2s):

```sql
WITH ranked AS (
  SELECT proxy_url, latency_ms,
         PERCENT_RANK() OVER (PARTITION BY proxy_url ORDER BY latency_ms) AS pct
  FROM proxy_logs
  WHERE timestamp > datetime('now', '-24 hour')
)
SELECT proxy_url, latency_ms
FROM ranked
WHERE pct >= 0.95
ORDER BY latency_ms DESC;
```

## భ్రమణ వ్యూహం నిర్ణయ చెట్టు

స్కోప్కి బహుళ ప్రాక్సీలు కేటాయించబడినప్పుడు, OmniRoute aని ఉపయోగిస్తుంది** భ్రమణ వ్యూహం** ప్రతి అభ్యర్థనకు ఏది ఉపయోగించాలో ఎంచుకోవడానికి. వ్యూహం స్కోప్ స్థాయిలో కాన్ఫిగర్ చేయబడింది (గ్లోబల్, పర్-ప్రొవైడర్, పర్-అకౌంట్, పర్-కాంబో).

### అందుబాటులో ఉన్న వ్యూహాలు

| వ్యూహం               | ఎప్పుడు ఉపయోగించాలి                   | ట్రేడ్ ఆఫ్                                                                                |
| -------------------- | ------------------------------------- | ----------------------------------------------------------------------------------------- |
| `quality` (డిఫాల్ట్) | మిశ్రమ-నాణ్యత ప్రాక్సీలతో ఉత్పత్తి    | అధిక-రేటెడ్ ప్రాక్సీలకు అనుకూలంగా ఉంటుంది; తక్కువ రేటింగ్ ఉన్న వాటిని ఆకలితో అలమటించవచ్చు |
| `random`             | లోడ్ పంపిణీ, గోప్యత                   | పంపిణీ కూడా; నాణ్యత సంకేతాలను విస్మరిస్తుంది                                              |
| `sequential`         | డీబగ్గింగ్, డిటర్మినిస్టిక్ టెస్టింగ్ | క్రమంలో ప్రాక్సీల ద్వారా సైకిళ్లు; తర్కించడం సులభం                                        |

## మీ స్వంత ప్రాక్సీల కోసం ఆటోమేటిక్ ఫెయిల్యూర్ మినహాయింపు

1ప్రాక్సీ మార్కెట్ప్లేస్ పూల్ ఇప్పటికే విఫలమైన ప్రాక్సీలను స్వయంచాలకంగా తగ్గించింది ( [ప్రాక్సీ నాణ్యత స్కోర్లను](#proxy-quality-scores) చూడండి). ప్రాక్సీల కోసం** మీరు** రిజిస్ట్రీకి జోడించబడింది, బ్యాక్గ్రౌండ్ హెల్త్ షెడ్యూలర్ (`src/lib/proxyHealth/scheduler.ts`) దేన్నీ తొలగించకుండా అదే "చైన్ నుండి చనిపోయిన సభ్యుడిని స్వయంచాలకంగా మినహాయించండి" ప్రవర్తనను అందిస్తుంది:

```bash
# .env — soft-disable a proxy after 3 consecutive failed probes, re-enable it
# automatically once it starts answering probes again.
PROXY_AUTO_DISABLE=true
PROXY_AUTO_REMOVE_AFTER=3
```

మల్టీ-ప్రాక్సీ చైన్కి ఇది ఎలా సరిపోతుంది:

1. షెడ్యూలర్ ప్రతి నమోదిత ప్రాక్సీని ప్రతి `PROXY_HEALTH_INTERVAL_MS` (డిఫాల్ట్ 10 నిమి; కనిష్టంగా 1 నిమి) ప్రోబ్ చేస్తుంది.
2. `PROXY_AUTO_REMOVE_AFTER` వరుసగా తర్వాత** నిశ్చయాత్మకమైనది** వైఫల్యాలు (నిజమైన కనెక్షన్ వైఫల్యం — గడువు ముగిసింది లేదా ప్రోబ్ లక్ష్యం యొక్క స్వంత 5xx ఎప్పటికీ లెక్కించబడదు, [ప్రాక్సీ ఆరోగ్య తనిఖీని](#proxy-health-checking-v3816) చూడండి), ప్రాక్సీ యొక్క `status` `dead` కి సెట్ చేయబడింది.
3. `dead` అనేది pool/rotation రిజల్యూషన్ మినహాయించబడిన సజీవ-స్టేటస్ ఫిల్టర్ యొక్క స్టేటస్లలో ఒకటి, కాబట్టి స్కోప్ యొక్క రొటేషన్ (రౌండ్-రాబిన్ / యాదృచ్ఛిక / స్టిక్కీ / లేటెన్సీ — చూడండి [రొటేషన్ స్ట్రాటజీ డెసిషన్ ట్రీ](#rotation-strategy-decision-tree) ) ఆ ప్రాక్సీని కొత్త అభ్యర్థనలకు అందజేయడాన్ని వెంటనే ఆపివేస్తుంది. పూల్లోని ఇతర ప్రాక్సీలు ఏవీ ప్రభావితం కావు మరియు మొత్తం పూల్ ఎప్పుడూ నిశ్శబ్దంగా ప్రత్యక్ష కనెక్షన్కి తిరిగి వెళ్లదు — [4-స్థాయి ప్రాక్సీ సిస్టమ్](#4-level-proxy-system) ఫెయిల్-క్లోజ్డ్ గార్డ్ని చూడండి.
4. షెడ్యూలర్ అదే విరామంలో `dead` ప్రాక్సీలను ప్రోబింగ్ చేస్తూనే ఉంటుంది. తదుపరి విజయవంతమైన ప్రోబ్ `status` తిరిగి `active` కి తిప్పుతుంది మరియు ఇది రొటేషన్ — మాన్యువల్ రీ-యాడ్ అవసరం లేకుండా తిరిగి ప్రవేశిస్తుంది.

ఇది ఉద్దేశపూర్వకంగా** ఎంపిక మరియు నాన్-డిస్ట్రక్టివ్** : డిఫాల్ట్గా షెడ్యూలర్ వైఫల్యాలను మాత్రమే లెక్కిస్తుంది మరియు లాగ్ చేస్తుంది ( `decision.ts` లో C విధానాన్ని చూడండి), మరియు `PROXY_AUTO_DISABLE` ప్రత్యేక, మరింత దూకుడుగా ఉండే `PROXY_AUTO_REMOVE` ఫ్లాగ్ కోసం — వరుసను ఎప్పటికీ తొలగించదు. రెండూ `true` కి సెట్ చేయబడితే, `PROXY_AUTO_REMOVE` గెలుస్తుంది (తొలగించబోయే ప్రాక్సీకి మధ్యలో సాఫ్ట్-డిసేబుల్ కోసం ఎటువంటి ఉపయోగం ఉండదు). పూర్తి వేరియబుల్ జాబితా కోసం [పర్యావరణ కాన్ఫిగరేషన్](../reference/ENVIRONMENT.md) సూచనను చూడండి.
