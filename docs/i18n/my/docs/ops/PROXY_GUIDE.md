> **ပထဝီဝင် ပိတ်ဆို့မှုများကို ရှောင်ကွင်းကာ သင်၏ အထောက်အထားကို ကာကွယ်ကာ မည်သည့် proxy — မှတဆင့် AI အသွားအလာကို လမ်းကြောင်းပေးမည်နည်း။**

OmniRoute တွင် HTTP၊ HTTPS၊ သို့မဟုတ် SOCKS5 proxies များမှတစ်ဆင့် အထက်စီးကြောင်း AI ဝန်ဆောင်မှုပေးသူ၏ လမ်းကြောင်းကို လမ်းကြောင်းပေးစေသော အင်္ဂါရပ်အပြည့်ရှိသော ပရောက်စီစီမံခန့်ခွဲမှုစနစ်တစ်ခု ပါဝင်သည်။ သင်သည် ပိတ်ဆို့ထားသော ဒေသတွင်ဖြစ်စေ၊ IP လည်ပတ်မှု လိုအပ်သည်ဖြစ်စေ သို့မဟုတ် ကိုယ်ပျောက်လက်ဗွေနှိပ်ခြင်း — လိုချင်သည်ဖြစ်စေ ဤလမ်းညွှန်ချက်သည် အရာအားလုံးကို အကျုံးဝင်ပါသည်။

## Proxies ကို ဘာကြောင့် သုံးတာလဲ။

AI ပံ့ပိုးပေးသူအများအပြားသည် ပထဝီဝင်ဒေသအလိုက် ဝင်ရောက်ခွင့်ကို ကန့်သတ်ထားသည်။ Developers တွေ အတွက်ပါ။** ရုရှား၊ တရုတ်၊ အီရန်၊ ကျူးဘား၊ တူရကီ** နှင့် အခြားနိုင်ငံများတွင် ကဲ့သို့သော အမှားအယွင်းများ ကြုံတွေ့ရသည်-

```
unsupported_country_region_territory
```

ပိတ်ဆို့ထားသော ဒေသများ ပြင်ပတွင်ပင်၊ ပရောက်စီများသည် အောက်ပါတို့အတွက် အသုံးဝင်သည်-

| Case ကိုသုံးပါ။                      | ဖော်ပြချက်                                                                         |
| ------------------------------------ | ---------------------------------------------------------------------------------- |
| **ပထဝီဝင်အနေအထားကို ရှောင်ကွင်းပါ။** | ပိတ်ထားသောနိုင်ငံများမှ OpenAI, Anthropic, Codex, Copilot ကိုဝင်ရောက်ပါ။           |
| **IP လည်ပတ်မှု**                     | နှုန်းကန့်သတ်ချက်မှရှောင်ရှားရန် IPs အများအပြားတွင် တောင်းဆိုမှုများကို ဖြန့်ဝေပါ။ |
| **ကိုယ်ရေးကိုယ်တာ**                  | အထက်ပိုင်းဝန်ဆောင်မှုပေးသူများထံမှ သင်၏ IP အစစ်အမှန်ကို ဝှက်ထားပါ။                 |
| **လိုက်နာမှု**                       | သတ်မှတ်ထားသော တရားစီရင်ပိုင်ခွင့်များမှတဆင့် လမ်းကြောင်းများ                       |
| **စမ်းသပ်ခြင်း။**                    | မတူညီသော ဒေသများမှ တောင်းဆိုမှုများကို အတုယူပါ။                                    |

## အကောင့်အသစ်များအတွက် မူရင်းပရောက်စီအခြေအနေ

၌** ဆက်တင်များ → Proxy → ကမ္ဘာလုံးဆိုင်ရာ ဖွဲ့စည်းမှုပုံစံ** သုံး၊** ချိတ်ဆက်မှုအသစ်များအတွက် မူရင်းအတိုင်း ပရောက်စီကို ဖွင့်ပါ။** အသစ်ထည့်ထားသော ဝန်ဆောင်မှုပေးသူအကောင့်များ၏ ကနဦးပရောက်စီအခြေအနေကို ရွေးချယ်ရန်။

အသစ်ထည့်သွင်းထားသော ဝန်ဆောင်မှုပေးအကောင့်များ၏ ကနဦးပရောက်စီအခြေအနေကို ထိန်းချုပ်သည်။ ၎င်းသည် လက်ရှိအကောင့်များကို ပြောင်းလဲခြင်း သို့မဟုတ် ကမ္ဘာလုံးဆိုင်ရာ ပရောက်စီခလုတ်ကို အစားထိုးခြင်းမဟုတ်ပါ။ ၎င်း၏ မူလတန်ဖိုးသည် ယခင်အပြုအမူကို ထိန်းသိမ်းသည်။ ပရောက်စီကို ပုံမှန်အားဖြင့် ပိတ်ထားသော အနာဂတ်အကောင့်များ ဖန်တီးရန် တစ်ကြိမ်ပိတ်ပါ။

ဦးစားပေးအား လက်ရှိဆက်တင်များ API မှတဆင့် `defaultNewConnectionProxyEnabled` အဖြစ် သိမ်းဆည်းထားသည်။ မသိမ်းဆည်းသောအခါတွင် ၎င်းသည် `true` သို့ ပုံသေသတ်မှတ်ထားသည်။ `false` သိမ်းဆည်းခြင်းသည် ပြန်လည်စတင်ခြင်းမရှိဘဲ နောက်ဆက်တွဲ အကောင့်အသစ်များအတွက် အကျိုးသက်ရောက်မှုရှိပါသည်။ `POST /api/providers` ရွေးချယ်နိုင်သော တင်းကျပ်သော boolean `proxyEnabled` လက်ခံသည်။ တိကျပြတ်သားသော `true` သို့မဟုတ် `false` သည် ဖန်တီးမှုမူရင်းထက် သာလွန်သည်။ ပွားနေသောအကောင့် သို့မဟုတ် OAuth ပြန်လည်ချိတ်ဆက်မှုတွင် ချန်လှပ်ထားခြင်းသည် ထိုအကောင့်၏သိမ်းဆည်းထားသည့်အခြေအနေကို ထိန်းသိမ်းထားသည်။ တစ်ဦးချင်း အကောင့်များကို နောက်ပိုင်းတွင် ဖွင့်နိုင် သို့မဟုတ် ပိတ်နိုင်သေးသည်။

ရွေးချယ်ပေးသူလွှဲပြောင်းမှုများသည် အကောင့်အသစ်များအတွက် ဦးတည်ရာတပ်ဆင်မှု၏မူလကိုအသုံးပြုပြီး ရှိပြီးသားအကောင့်များကိုအစားထိုးသည့်အခါ ဦးတည်ရာမူဝါဒကို ထိန်းသိမ်းပါ။ ပရောက်စီခလုတ်များသည် ခရီးဆောင်အပြောင်းအရွှေ့အကွက်များမဟုတ်ပါ။ အပြည့်အ၀ အရန်သိမ်းဆည်းခြင်း နှင့် သမိုင်းဝင် JSON/SQL ရွှေ့ပြောင်းခြင်းတို့သည် သိမ်းဆည်းထားသော အကောင့်တန်ဖိုးများနှင့် အမွေအနှစ် အစီအစဉ်ပုံသေများ အပါအဝင် ၎င်းတို့၏ လက်ရှိပြန်လည်ရယူထားသော ဝေါဟာရများကို ဆက်လက်ထိန်းသိမ်းထားသည်။ အပြည့်အဝဆက်တင်များပြန်လည်ရယူခြင်းသည်လည်း ဤစိတ်ကြိုက်ရွေးချယ်မှုကို ပြန်လည်ရယူနိုင်သည်။

ဤဦးစားပေးမှုသည် ပရောက်စီကို သတ်မှတ်ပေးသည် သို့မဟုတ် ၎င်းသည် ကျန်းမာသော သို့မဟုတ် အသုံးပြုနေသည်ဟု သတ်မှတ်ခြင်းမပြုပါ။ အမှန်တကယ် လမ်းကြောင်းပေးခြင်းသည် ကမ္ဘာလုံးဆိုင်ရာ ပရောက်စီခလုတ်နှင့် သက်ဆိုင်သော ပရောက်စီဖွဲ့စည်းမှုအပေါ် မူတည်နေသေးသည်။ ဆက်ရှိနေသောအကောင့်မရှိသော ပေါင်းစပ်ပံ့ပိုးပေးသူများ၊ အကောင့်ဖန်တီးခြင်းမပြုမီ OAuth အသွားအလာ၊ environment/system proxies နှင့် ပြင်ပနောက်ကွယ်ရှိ ကွန်ရက်ချိတ်ဆက်ခြင်းတို့သည် ၎င်း၏နယ်ပယ်ပြင်ပတွင် ရှိနေပါသည်။

## 4-Level Proxy စနစ်

OmniRoute proxy configuration ကို at ပံ့ပိုးသည်။** လွတ်လပ်သော နယ်ပယ် လေးခု** ဦးစားပေးအစီအစဉ်ဖြင့် ဖြေရှင်းသည်-

```
Priority Resolution Order (highest → lowest):

  1. 🔵 Account/Connection Proxy  →  per API key / OAuth connection
  2. 🟡 Provider Proxy            →  per provider (e.g., all OpenAI traffic)
  3. 🟠 Combo Proxy               →  per combo/routing configuration
  4. 🟢 Global Proxy              →  all traffic, all providers
```

### Resolution ဘယ်လိုအလုပ်လုပ်လဲ။

OmniRoute အထက်စီးကြောင်းပံ့ပိုးသူထံ တောင်းဆိုချက်တစ်ခုပေးပို့သောအခါ၊ အဆင့်တစ်ခုစီကို အစဉ်လိုက်စစ်ဆေးသည့် `resolveProxyForConnectionFromRegistry()` ခေါ်သည်-

1. **အကောင့်အဆင့်** — ဤတိကျသောချိတ်ဆက်မှု ID အတွက်သတ်မှတ်ထားသော proxy ရှိပါသလား။
2. **ပံ့ပိုးသူအဆင့်** — ဤဝန်ဆောင်မှုပေးသူထံ သတ်မှတ်ပေးထားသော ပရောက်စီတစ်ခုရှိပါသလား (ဥပမာ `openai`)
3. **ကမ္ဘာ့အဆင့်** — ကမ္ဘာလုံးဆိုင်ရာ ပရောက်စီကို ပြင်ဆင်သတ်မှတ်ထားခြင်း ရှိပါသလား။
4. **ပရောက်စီမရှိပါ။** — ပံ့ပိုးသူထံသို့ တိုက်ရိုက်ချိတ်ဆက်မှု။

ပထမပွဲက အနိုင်ရတယ်။ ဆိုလိုသည်မှာ သင်သည် ကမ္ဘာလုံးဆိုင်ရာ ပရောက်စီကို လှည့်စားအဖြစ် သတ်မှတ်နိုင်သော်လည်း သတ်မှတ်ထားသော ဝန်ဆောင်မှုပေးသူများ သို့မဟုတ် ချိတ်ဆက်မှုများအတွက် ၎င်းကို အစားထိုးနိုင်သည်။

## ပရောက်စီမှတ်ပုံတင်ခြင်း (CRUD)

ပရောက်စီ မှတ်ပုံတင်ခြင်းသည် သင့်ပရောက်စီအားလုံးကို သိမ်းဆည်းသည့် SQLite ဇယား (`proxy_registry`) ဖြစ်သည်။ ပရောက်စီတစ်ခုစီတွင်-

| လယ်ကွင်း   | ရိုက်ပါ။        | ဖော်ပြချက်                                                 |
| ---------- | --------------- | ---------------------------------------------------------- |
| `id`       | UUID            | ထူးခြားသော အမှတ်အသား                                       |
| `name`     | ကြိုးတစ်ချောင်း | လူသားဖတ်နိုင်သော အညွှန်း                                   |
| `type`     | ကြိုးတစ်ချောင်း | ပရိုတိုကော- `http`၊ `https`၊ `socks5`                      |
| `host`     | ကြိုးတစ်ချောင်း | ပရောက်စီ hostname သို့မဟုတ် IP                             |
| `port`     | ကိန်းပြည့်      | ဆိပ်ကမ်းနံပါတ်                                             |
| `username` | ကြိုးတစ်ချောင်း | အသုံးပြုသူအမည် အစစ်အမှန် (ကျန်သည့်နေရာတွင် ကုဒ်ဝှက်ထားသည်) |
| `password` | ကြိုးတစ်ချောင်း | Auth password (ကျန်သည့်နေရာတွင် ကုဒ်ဝှက်ထားသည်)            |
| `region`   | ကြိုးတစ်ချောင်း | ပထဝီဝင်ဒေသ တံဆိပ်                                          |
| `notes`    | ကြိုးတစ်ချောင်း | အခမဲ့စာသားမှတ်စုများ                                       |
| `status`   | ကြိုးတစ်ချောင်း | `active` သို့မဟုတ် `inactive`                              |
| `source`   | ကြိုးတစ်ချောင်း | `manual` သို့မဟုတ် `oneproxy`                              |

### Proxy ဖန်တီးခြင်း။

**Dashboard မှတဆင့်-**

1. သွားပါ။** ဆက်တင်များ → ပရောက်စီ**
2. နှိပ်ပါ။** Proxy ထည့်ပါ။**
3. အမျိုးအစား၊ အိမ်ရှင်၊ ဆိပ်ကမ်းနှင့် ရွေးချယ်နိုင်သော စစ်မှန်ကြောင်းအထောက်အထားများကို ဖြည့်ပါ။
4. သိမ်းဆည်းပါ။

**API မှတဆင့်**

```bash
curl -X POST http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "name": "US Proxy",
    "type": "http",
    "host": "proxy.example.com",
    "port": 8080,
    "username": "user",
    "password": "pass",
    "region": "US"
  }'
```

### ပရောက်စီကို အပ်ဒိတ်လုပ်ခြင်း။

```bash
curl -X PATCH http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "id": "proxy-uuid-here",
    "host": "new-proxy.example.com",
    "port": 9090
  }'
```

> **မှတ်ချက် -** အချည်းနှီးမဟုတ်သော အစားထိုးမှုများကို သင် အတိအလင်း မပေးပို့ပါက အထောက်အထားများကို သိမ်းဆည်းထားသည်။ `username`/`password` အတွက် ဗလာစာကြောင်းများ ပေးပို့ခြင်းသည် သိမ်းဆည်းထားသော တန်ဖိုးများကို သိမ်းဆည်းထားမည်ဖြစ်သည်။

### Proxy ဖျက်ခြင်း။

```bash
# Fails if proxy is assigned to any scope
curl -X DELETE "http://localhost:20128/api/v1/management/proxies?id=proxy-uuid"

# Force delete (removes assignments too)
curl -X DELETE "http://localhost:20128/api/v1/management/proxies?id=proxy-uuid&force=1"
```

### Proxy စာရင်းသွင်းခြင်း။

```bash
curl "http://localhost:20128/api/v1/management/proxies?limit=50&offset=0"
```

### Proxies များကို Scopes များသို့ သတ်မှတ်ခြင်း။

```bash
# Assign to global scope
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "global", "proxy": {"type":"http","host":"proxy.example.com","port":8080}}'

# Assign to a specific provider
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "provider", "id": "openai", "proxy": {"type":"socks5","host":"socks.example.com","port":1080}}'

# Assign to a specific connection/key
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "key", "id": "connection-uuid", "proxy": {"type":"http","host":"key-proxy.com","port":3128}}'
```

### ထိရောက်သော Proxy ဖြေရှင်းခြင်း။

ပေးထားသည့်ချိတ်ဆက်မှုအတွက် မည်သည့်ပရောက်စီကို အသုံးပြုမည်ကို စစ်ဆေးပါ-

```bash
curl "http://localhost:20128/api/settings/proxy?resolve=connection-uuid"
```

ဖြေရှင်းထားသော ပရောက်စီကို ၎င်း၏အဆင့် (`account`၊ `provider`၊ သို့မဟုတ် `global`) နှင့် အရင်းအမြစ်ဖြင့် ပြန်ပေးသည်။

### အစုလိုက်တာဝန်

ဝန်ဆောင်မှုပေးသူအများအပြား သို့မဟုတ် ချိတ်ဆက်မှုများအတွက် ပရောက်စီတစ်ခုအား တစ်ပြိုင်နက် သတ်မှတ်ပါ-

```bash
curl -X POST http://localhost:20128/api/v1/management/proxies/bulk-assign \
  -H "Content-Type: application/json" \
  -d '{
    "scope": "provider",
    "scopeIds": ["openai", "anthropic", "codex"],
    "proxyId": "proxy-uuid"
  }'
```

### Import/Export

Proxy များ ပါဝင်ပါသည်။**Backup/Restore** စနစ်။ သင်၏ OmniRoute configuration ကို ထုတ်ယူသောအခါ-

1. သွားပါ။** ဒက်ရှ်ဘုတ် → ဆက်တင်များ → အရန်သိမ်းခြင်း။**
2. နှိပ်ပါ။** တင်ပို့ခြင်း။** — proxy မှတ်ပုံတင်ခြင်းနှင့် တာဝန်များ ပါဝင်သည်။
3. ပြန်လည်ရယူရန်၊ နှိပ်ပါ။** သွင်းကုန်** ပြီးလျှင် အရန်ဖိုင်ကို အပ်လုဒ်လုပ်ပါ။

ပရောက်စီ မှတ်ပုံတင်ခြင်းကိုလည်း ပံ့ပိုးပေးသည်။** host + port ဖြင့် upsert** — ရှိနှင့်ပြီးသား (အိမ်ရှင်နှင့် ဆိပ်ကမ်းတူ) ပရောက်စီကို သင်ထည့်သွင်းပါက မိတ္တူပွားခြင်းကို ဖန်တီးမည့်အစား ၎င်းသည် အပ်ဒိတ်လုပ်မည်ဖြစ်သည်။

### အမွေအနှစ် ရွှေ့ပြောင်းခြင်း။

အကယ်၍ သင်သည် ပရောက်စီများကို ဗားရှင်းအဟောင်း (ကြိုတင်စာရင်းသွင်းခြင်း) တွင် configure လုပ်ထားလျှင် OmniRoute ၎င်းတို့ကို အလိုအလျောက် ရွှေ့ပြောင်းပေးသည်-

```
Legacy key_value store → proxy_registry + proxy_assignments
```

အဆင့်မြှင့်ပြီးနောက် ပထမဆုံးစတင်ချိန်တွင် တစ်ကြိမ်ဖြစ်ပေါ်သည်။ ပြန်လည်လည်ပတ်ရန် `migrateLegacyProxyConfigToRegistry({ force: true })` သုံးပါ။

## 1proxy အခမဲ့ Proxy Marketplace

> 🆕** [@oyi77](https://github.com/oyi77) မှ ပံ့ပိုးပေးပါသည်။** — PR [#1847](https://github.com/diegosouzapw/OmniRoute/pull/1847) (ထုတ်ဝေမှု [#1788](https://github.com/diegosouzapw/OmniRoute/issues/1788) )

OmniRoute သည် the နှင့်ပေါင်းစပ်သည်။** [1 ပရောက်စီ](https://1proxy-api.aitradepulse.com)** သုံးစွဲခွင့် ပေးဆောင်ရန် အသိုင်းအဝိုင်း ပလက်ဖောင်း** ရာနှင့်ချီသော အခမဲ့၊ တရားဝင်သော proxy များ** ကမ္ဘာတစ်ဝှမ်းမှ။ ၎င်းသည် ၎င်းတို့၏ကိုယ်ပိုင် proxy အခြေခံအဆောက်အအုံမရှိသော အသုံးပြုသူများအတွက် ပြီးပြည့်စုံသည်။

### ဘယ်လိုအလုပ်လုပ်လဲ။

```
┌─────────────┐     Sync      ┌─────────────────┐    Rotate     ┌──────────┐
│  1proxy API │ ────────────▶ │  proxy_registry  │ ────────────▶ │ Provider │
│  (external) │   up to 500   │  source=oneproxy │  by quality   │   API    │
└─────────────┘    proxies    └─────────────────┘               └──────────┘
```

1. **ထပ်တူကျသည်။** — OmniRoute သည် 1proxy API မှ တရားဝင်သော ပရောက်စီများကို ထုတ်ယူသည်။
2. **စတိုး** — Proxies များကို `source = 'oneproxy'` ဖြင့် တူညီသော `proxy_registry` ဇယားတွင် သိမ်းဆည်းထားသည်။
3. **ဇကာ** — ပရိုတိုကော၊ နိုင်ငံ၊ အရည်အသွေးရမှတ်ဖြင့် စစ်ထုတ်ပါ။
4. **အလှည့်** — အရည်အသွေး၊ ကျပန်း သို့မဟုတ် ဆက်တိုက်နည်းဗျူဟာများကို အသုံးပြု၍ အကောင်းဆုံး proxy ကို ရွေးပါ။
5. **အလိုအလျောက် ကျဆင်းခြင်း။** — မအောင်မြင်သော ပရောက်စီများသည် ၎င်းတို့၏ အရည်အသွေးရမှတ်များကို လျှော့ချပေးသည်။ → သတ်မှတ်ချက်အောက်တွင် မလှုပ်ရှားကြောင်း အမှတ်အသားပြုထားသည်။

### Proxy များကို ထပ်တူပြုခြင်း။

**Dashboard မှတဆင့်-**

1. သွားပါ။** ဆက်တင်များ → 1proxy** တက်ဘ်
2. နှိပ်ပါ။** "ယခု စင့်ခ်လုပ်ပါ"**
3. ကိန်းဂဏာန်းများကိုကြည့်ပါ- စုစုပေါင်း ပရောက်စီများ၊ တက်ကြွသောရေတွက်မှု၊ ပျမ်းမျှအရည်အသွေး၊ နိုင်ငံအလိုက် ပိုင်းခြားမှု

**API မှတဆင့်**

```bash
# Trigger sync
curl -X POST http://localhost:20128/api/settings/oneproxy \
  -H "Content-Type: application/json" \
  -d '{}'

# Response:
# { "success": true, "added": 127, "updated": 45, "failed": 2, "total": 172 }
```

### Proxy အရည်အသွေးရမှတ်များ

1proxy proxy တစ်ခုစီတွင် မက်တာဒေတာများ ပါရှိသည်။

| လယ်ကွင်း        | ဖော်ပြချက်                                              |
| --------------- | ------------------------------------------------------- |
| `qualityScore`  | 1proxy အတည်ပြုခြင်းမှ 0-100 အဆင့်သတ်မှတ်ချက်            |
| `latencyMs`     | ကွန်ရက် တုံ့ပြန်ချိန်ကို တိုင်းတာသည်။                   |
| `anonymity`     | `transparent`၊ `anonymous` သို့မဟုတ် `elite`            |
| `googleAccess`  | ပရောက်စီသည် Google ဝန်ဆောင်မှုများကို ဝင်သုံးနိုင်မလား။ |
| `countryCode`   | ISO နိုင်ငံကုဒ် စာလုံးနှစ်လုံး                          |
| `lastValidated` | နောက်ဆုံးအတည်ပြုချက်၏အချိန်တံဆိပ်                       |

အရည်အသွေးရမှတ်များကို ဒိုင်းနမစ်ဖြင့် ချိန်ညှိထားသည်-

- **တောင်းဆိုချက်များ မအောင်မြင်ပါ။** ရမှတ် 10 မှတ်လျှော့ချပါ။
- **ရမှတ်သည် ≤ 10 သို့ကျဆင်းသွားသည်။** → ပရောက်စီကို `inactive` အမှတ်အသားပြုထားသည်။
- မလှုပ်ရှားနိုင်သော ပရောက်စီများကို လည်ပတ်ခြင်းမှ ဖယ်ထုတ်ထားသည်။

### အလှည့်ကျနည်းဗျူဟာများ

```bash
# Rotate by quality (best proxy first) — default
curl -X POST http://localhost:20128/api/settings/oneproxy/rotate \
  -H "Content-Type: application/json" \
  -d '{"strategy": "quality"}'

# Random rotation
curl -X POST http://localhost:20128/api/settings/oneproxy/rotate \
  -d '{"strategy": "random"}'

# Sequential (least recently validated first)
curl -X POST http://localhost:20128/api/settings/oneproxy/rotate \
  -d '{"strategy": "sequential"}'
```

### Circuit Breaker

1proxy စင့်ခ်တွင် တပ်ဆင်ထားသော circuit breaker ပါရှိသည်-

- ပြီးနောက်** 5 ဆက်တိုက် ထပ်တူကျမှု မအောင်မြင်ပါ။** နောက်ထပ် ထပ်တူကူးရန် ကြိုးပမ်းမှုများကို ပိတ်ဆို့ထားသည်။
- `resetOneproxyCircuitBreaker()` ဖြင့် ပြန်လည်သတ်မှတ်ပါ သို့မဟုတ် ဆာဗာကို ပြန်လည်စတင်ပါ။
- စင့်ခ်လုပ်ခြင်းအခြေအနေကို `GET /api/settings/oneproxy?action=status` တွင်ရနိုင်သည်။

### 1proxy ပရောက်စီများကို ရှင်းလင်းခြင်း။

```bash
# Delete a single 1proxy proxy
curl -X DELETE "http://localhost:20128/api/settings/oneproxy?id=proxy-uuid"

# Clear ALL 1proxy proxies (manual proxies are untouched)
curl -X DELETE "http://localhost:20128/api/settings/oneproxy?clearAll=1"
```

## Anti-Detection & Stealth

OmniRoute proxy — မှတဆင့် traffic ကိုလမ်းကြောင်းပေးရုံသာမက၊ ၎င်းသည် traffic ကိုတရားဝင်ဖြစ်စေသည်-

### TLS လက်ဗွေ အတုအယောင်

ဘရောက်ဆာကဲ့သို့သော TLS လက်ဗွေများကို ထုတ်လုပ်ရန် `wreq-js` အသုံးပြုပြီး ဘရောက်ဆာမဟုတ်သည့် TLS လက်ဆွဲနှုတ်ဆက်မှုများကို အလံပြသည့် bot detection စနစ်များကို ကျော်ဖြတ်ခြင်း။

### CLI လက်ဗွေ ကိုက်ညီမှု

ဟိ**CLI လက်ဗွေခလုတ်** (`Settings → Security`) သည် မူရင်း CLI binaries (Claude Code၊ Codex စသည်ဖြင့်) ၏ တိကျသော လက်မှတ်နှင့် ကိုက်ညီရန် HTTP ခေါင်းစီးများနှင့် JSON စာကိုယ်အကွက်များကို ပြန်စီသည်။ ဒါက အလုပ်ဖြစ်တယ်။** အပေါ်မှ** ပရောက်စီ-

```
Your IP (blocked) → Proxy IP (US) → Provider API
                    + TLS spoof
                    + CLI fingerprint
```

နှစ်ခုလုံးရပြီ။**IP မျက်နှာဖုံးစွပ်** နှင့်** စစ်မှန်မှုကို တောင်းဆိုပါ။** တပြိုင်နက်တည်း

### ပရောက်စီ IP ထိန်းသိမ်းခြင်း။

ဒက်ရှ်ဘုတ်ရှိ ရောင်စုံကုဒ်တံဆိပ်များသည် မည်သည့် proxy အဆင့်ကို လုပ်ဆောင်နေကြောင်း ပြသသည်-

| တံဆိပ် | အဆင့်            | အဓိပ္ပါယ်                                              |
| ------ | ---------------- | ------------------------------------------------------ |
| 🟢     | ကမ္ဘာလုံးဆိုင်ရာ | အသွားအလာအားလုံးသည် ဤပရောက်စီမှတဆင့် ဖြတ်သန်းသွားပါသည်။ |
| 🟡     | ပံ့ပိုးပေးသူ     | ဤဝန်ဆောင်မှုပေးသူ၏အသွားအလာကိုသာ proxyed ထားသည်။        |
| 🔵     | ချိတ်ဆက်မှု      | ဤတိကျသော key/account ဤပရောက်စီကို အသုံးပြုသည်။         |

တံဆိပ်သည် အတည်ပြုခြင်းအတွက် ဖြေရှင်းထားသော proxy IP ပြသည်။

## ဒက်ရှ်ဘုတ် UI

### ဆက်တင်များ → Proxy တဘ်

- **ကမ္ဘာလုံးဆိုင်ရာ ပရောက်စီ** ဖွဲ့စည်းမှုစနစ် (အသွားအလာအားလုံးအတွက် တစ်ကြိမ်သတ်မှတ်ထားသည်)
- **ဝန်ဆောင်မှုပေးသူ ပရောက်စီ** ထပ်ရေးသည်။
- **ချိတ်ဆက်မှု ပရောက်စီ** တာဝန်တွေ
- **ချိတ်ဆက်မှုစမ်းသပ်မှု** configured proxy မှတဆင့်
- **အရောင်-ကုဒ်တံဆိပ်များ** တက်ကြွသော proxy အဆင့်ကိုပြသသည်။

### ဆက်တင်များ → 1proxy တက်ဘ်

- **ယခု စင့်ခ်လုပ်ပါ။** အခမဲ့ proxy ရယူရန် ခလုတ်
- **စာရင်းဇယားကတ်များ** စုစုပေါင်း၊ အသက်ဝင်သော၊ ပျမ်းမျှ အရည်အသွေး၊ နောက်ဆုံး စင့်ခ်လုပ်ခြင်း။
- **စစ်ထုတ်မှုများ** − ပရိုတိုကော၊ နိုင်ငံကုဒ်၊ အနည်းဆုံး အရည်အသွေး
- **ပရောက်စီဇယား** အိမ်ရှင်၊ ပရိုတိုကော၊ နိုင်ငံ၊ အရည်အသွေးရမှတ်၊ latency၊ အမည်ဝှက်၊ Google ဝင်ရောက်မှုတို့ဖြင့်
- **ထပ်တူပြုမှု အနေအထား** success/failure ခြေရာခံခြင်းနှင့် ဆက်တိုက် ကျရှုံးမှုရေတွက်ပါရှိသော panel
- **အားလုံးကို ရှင်းလင်းပါ။** 1proxy ထည့်သွင်းမှုများအားလုံးကို ဖယ်ရှားရန်

## ပြသာနာရှာဖွေရှင်းပေးခြင်း

### "SOCKS5 proxy ကို ပိတ်ထားသည်"

သင်၏ `.env` ဖိုင်တွင် `ENABLE_SOCKS5_PROXY=true` သတ်မှတ်ပြီး ပြန်လည်စတင်ပါ။

### proxy မှတဆင့် "socket hang up" အမှားများ

idle ချိတ်ဆက်မှုများကို ကျဆင်းစေသည့် စျေးပေါသော proxy များဖြင့် ၎င်းသည် ပုံမှန်ဖြစ်သည်။ OmniRoute ဤအရာကို ကိုင်တွယ်ပြီးသားဖြစ်သည်-

- proxy ချိတ်ဆက်မှုများ (`keepAliveTimeout: 1`) တွင် Keep-alive ကို ပိတ်ခြင်း
- ပိုက်လိုင်းပိတ်ခြင်း (`pipelining: 0`)
- ထပ်ခါတလဲလဲ လက်ဆွဲနှုတ်ဆက်ခြင်းကို ရှောင်ရှားရန် အရာရှိများကို သိမ်းဆည်းပါ။

ဆက်ရှိနေပါက အခြားပရောက်စီကို စမ်းကြည့်ပါ သို့မဟုတ် 1proxy လှည့်ခြင်းအင်္ဂါရပ်ကို အသုံးပြုပါ။

### OAuth အတွင်း "unsupported_country_region_territory"

ပရောက်စီကို စီစဉ်သတ်မှတ်ထားကြောင်း သေချာပါစေ။** မီ** OAuth စီးဆင်းမှုကိုစတင်သည်။ OmniRoute configured proxy မှတဆင့် OAuth တိုကင်လဲလှယ်မှုကို လမ်းကြောင်းပေးသည်။ ကမ္ဘာလုံးဆိုင်ရာ သို့မဟုတ် ဝန်ဆောင်မှုပေးသူအဆင့် ပရောက်စီကို ဦးစွာသတ်မှတ်ပြီးနောက် ချိတ်ဆက်ပါ။

### ပရောက်စီကို အသုံးမပြုပါ။

ဆုံးဖြတ်ချက်အမိန့်ကို စစ်ဆေးပါ-

1. `GET /api/settings/proxy?resolve=your-connection-id` ဖြင့်စစ်ဆေးပါ။
2. proxy `status` `active` ( `inactive` မဟုတ်ပါ) စစ်ဆေးပါ။
3. ပရောက်စီတာဝန်ပေးသည့်နယ်ပယ်သည် သင့်ချိတ်ဆက်မှုနှင့် ကိုက်ညီကြောင်း သေချာပါစေ။

### 1proxy စင့်ခ်လုပ်ခြင်း မအောင်မြင်ပါ။

စင့်ခ်လုပ်ခြင်း အခြေအနေကို စစ်ဆေးပါ-

```bash
curl "http://localhost:20128/api/settings/oneproxy?action=status"
```

`consecutiveFailures >= 5` ဖြစ်ပါက circuit breaker ခလုတ်တိုက်သွားပါသည်။ ပြန်လည်သတ်မှတ်ရန် ဆာဗာကို ပြန်လည်စတင်ပါ သို့မဟုတ် လူကိုယ်တိုင် ပြန်လည်သတ်မှတ်ခြင်းအတွက် စောင့်ပါ။

## ပရောက်စီကျန်းမာရေးစစ်ဆေးခြင်း (v3.8.16 +)

OmniRoute's** proxy အမြန်ပျက်ကွက်** ယန္တရား (`src/lib/proxyHealth.ts`) သည် < 2s တွင် dead proxies များကို TCP ချိတ်ဆက်မှု အမြန်စစ်ဆေးခြင်းဖြင့် ရှာဖွေသည်၊ ထို့နောက်** ရလဒ်ကို သိမ်းဆည်းပါ။** တောင်းဆိုမှုအပေါ် ရှောင်ရှားရန်။

### ဘယ်လိုအလုပ်လုပ်လဲ။

```
Request ──▶ ProxyHealthCache.get(url)
             │
             ├─ Cache hit + fresh?  ──▶ return cached status
             │
             └─ Cache miss / stale?  ──▶ TCP connect to host:port
                                          (timeout: FAST_FAIL_TIMEOUT_MS)
                                          ──▶ cache for HEALTH_CACHE_TTL_MS
                                          ──▶ return result
```

၎င်းမရှိဘဲ၊ dead proxy သည် မအောင်မြင်မီ `PROXY_TIMEOUT_MS` အပြည့်အစုံ (မူလ 30s) အတွက် တောင်းဆိုမှုတိုင်းကို ပိတ်ဆို့သွားမည်ဖြစ်သည်။

### ချိန်ညှိနိုင်သော ပတ်ဝန်းကျင် ပြောင်းလဲမှုများ

| ပြောင်းလဲနိုင်သော            | ပုံသေ   | ရည်ရွယ်ချက်                                                  |
| ---------------------------- | ------- | ------------------------------------------------------------ |
| `PROXY_FAST_FAIL_TIMEOUT_MS` | `2000`  | ကျန်းမာရေးစစ်ဆေးမှုအတွက်TCP ချိတ်ဆက်မှု အချိန်ကုန်သွားပါသည်။ |
| `PROXY_HEALTH_CACHE_TTL_MS`  | `30000` | ကျန်းမာရေးရလဒ်ကို အချိန်မည်မျှကြာအောင် သိမ်းဆည်းထားသနည်း။    |

**အကြံပြုထားသော တန်ဖိုးများ-**

| ဇာတ်လမ်း                             | အမြန်ပျက်ချိန် | ကက်ရှ် TTL | ကျိုးကြောင်းဆင်ခြင်ခြင်း။                                                                   |
| ------------------------------------ | -------------- | ---------- | ------------------------------------------------------------------------------------------- |
| high-throughput API တံခါးပေါက်       | 1500ms         | 60000ms    | စစ်ဆေးမှုများကို လျှော့ချရန် ပြင်းထန်သော ကျရှုံးမှု- လျင်မြန်သော၊ ပိုရှည်သော ကက်ရှ်         |
| Geo-distributed nodes                | 3000ms         | 15000ms    | နှေးကွေးသောကွန်ရက်များသည် အချိန်ပိုလိုအပ်သည်။ အမြန်ပျက်ကွက်မှုအတွက် ပိုတိုသော ကက်ရှ်        |
| Dev/testing                          | 1000ms         | 10000ms    | ဒေသတွင်း proxy များပေါ်တွင် အမြန်ပြန်ဆိုခြင်း။                                              |
| ကိုယ်ပျောက်/ဆန့်ကျင်ထောက်လှမ်းခြင်း။ | 2500ms         | 45000ms    | အတိုးနှုန်းကန့်သတ်ချက်များကို ဖြစ်ပေါ်စေနိုင်သည့် လျင်မြန်စွာ စုံစမ်းခြင်းကို ရှောင်ကြဉ်ပါ။ |

### Proxy ကျန်းမာရေး စစ်ဆေးခြင်း။

```ts
import { getAllProxyHealthStatuses, invalidateProxyHealth } from "omniroute/proxyHealth";

const statuses = getAllProxyHealthStatuses();
for (const s of statuses) {
  console.log(`${s.proxyUrl} → healthy=${s.healthy}, stale=${s.stale}`);
}

// Force re-check a specific proxy
invalidateProxyHealth("http://user:pass@203.0.113.7:8080");
```

ကက်ရှ်ဝင်ရောက်မှုသည် `HEALTH_CACHE_TTL_MS` ကျော်လွန်သွားသောအခါ `stale` အလံသည် `true` ဖြစ်ပြီး နောက်တောင်းဆိုချက်အသစ်တစ်ခု စတင်မည်ဖြစ်သည်။

### Per-Proxy အမျိုးအစား ပုံသေများ

ကျန်းမာရေးစစ်ဆေးမှုသည် URL အစီအစဥ်အပေါ် အခြေခံ၍ ဆင်ခြင်တုံတရားရှိသော ပုံသေများကို အသုံးပြုသည်-

| အစီအစဥ်                    | ပုံသေ ဆိပ်ကမ်း |
| -------------------------- | -------------- |
| `http://`                  | 8080           |
| `https://`                 | 443            |
| `socks5://` / `socks5h://` | 1080           |

URL (`http://host:9999`) ရှိ စိတ်ကြိုက် port များသည် scheme မူရင်းထက် အမြဲတမ်း ဦးစားပေးပါသည်။

## ပရောက်စီ ပိုင်းခြားစိတ်ဖြာမှု နှင့် စောင့်ကြည့်နိုင်မှု

OmniRoute tracks per-proxy usage to help operators diagnose routing patterns, latency spikes, and recurring failures.

### ဘယ်ကို ခြေရာခံမလဲ။

စီစဉ်သတ်မှတ်ထားသော ပရောက်စီမှတဆင့် တောင်းဆိုမှုတိုင်းအတွက် OmniRoute မှတ်တမ်းများ-

| မက်ထရစ်      | ဖော်ပြချက်                                                        |
| ------------ | ----------------------------------------------------------------- |
| `proxy_url`  | ပရောက်စီ URL အပြည့်အစုံ (အထောက်အထားအထောက်အထားများ ဖုံးအုပ်ထားသော) |
| `provider`   | အထက်ပိုင်းပံ့ပိုးပေးသူ ID (ဖွင့်နိုင်၊ မနုဿ စသည်တို့)             |
| `latency_ms` | ပရောက်စီ လက်ဆွဲနှုတ်ဆက်ခြင်း အပါအဝင် စုစုပေါင်း အသွားအပြန် အချိန် |
| `connect_ms` | TCP ချိတ်ဆက်ချိန်သာ                                               |
| `status`     | ရေဆန်မှHTTP အခြေအနေကုဒ်                                           |
| `error`      | တောင်းဆိုမှု မအောင်မြင်ပါက အတန်းအမှား                             |
| `timestamp`  | ISO 8601 UTC                                                      |

### Data ကိုရယူခြင်း။

```bash
# Recent proxy events
curl -H "Authorization: Bearer $OMNIROUTE_KEY" \
  "http://localhost:20128/api/usage/proxy-logs?limit=100"
```

စစ်မှန်သောအဆုံးမှတ်သည် `/api/usage/proxy-logs` ( `src/app/api/usage/proxy-logs/route.ts` ကြည့်ပါ)။ ဤအဆုံးမှတ်ကို ထောက်ခံသည်-

- `GET /api/usage/proxy-logs` — ပရောက်စီမှတ်တမ်းများကို ထုတ်ယူသည်။
- `DELETE /api/usage/proxy-logs` — ပရောက်စီမှတ်တမ်းများအားလုံးကို ရှင်းလင်းပါ။

လိုအပ်ပါက စုစုပေါင်းကိန်းဂဏန်းများကို `proxy_logs` ဇယားမှ တိုက်ရိုက်မေးမြန်းနိုင်ပါသည် SQL ဒက်ရှ်ဘုတ် UI အစုလိုက်ကြည့်ရှုမှုများကို ပေးဆောင်နိုင်ပါသည်။

### ဘုံပုံစံများ

**ခေါက်ဆွဲနေသော ပရောက်စီကို ရှာဖွေပါ။** ( success/failure၏ ခြားနားချက် ):

```sql
SELECT proxy_url,
       COUNT(*) AS total,
       SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) AS errors,
       ROUND(100.0 * SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) / COUNT(*), 1) AS error_pct
FROM proxy_logs
WHERE timestamp > datetime('now', '-1 hour')
GROUP BY proxy_url
HAVING error_pct > 5
ORDER BY error_pct DESC;
```

**နှေးကွေးသော proxy ကိုရှာပါ။** (p95 latency > 2s):

```sql
WITH ranked AS (
  SELECT proxy_url, latency_ms,
         PERCENT_RANK() OVER (PARTITION BY proxy_url ORDER BY latency_ms) AS pct
  FROM proxy_logs
  WHERE timestamp > datetime('now', '-24 hour')
)
SELECT proxy_url, latency_ms
FROM ranked
WHERE pct >= 0.95
ORDER BY latency_ms DESC;
```

## အလှည့်ကျ မဟာဗျူဟာ ဆုံးဖြတ်ချက်သစ်ပင်

များစွာသော proxy များကို နယ်ပယ်တစ်ခုသို့ သတ်မှတ်သောအခါ၊ OmniRoute a ကို အသုံးပြုသည်။** အလှည့်ဗျူဟာ** တောင်းဆိုမှုတစ်ခုစီအတွက် ဘယ်တစ်ခုကို ရွေးမလဲ။ မဟာဗျူဟာကို နယ်ပယ်အဆင့် (ကမ္ဘာလုံးဆိုင်ရာ၊ ဝန်ဆောင်မှုပေးသူ၊ အကောင့်တစ်ခုစီ၊ ပေါင်းစပ်မှုတစ်ခု) တွင် ထည့်သွင်းထားသည်။

### ရနိုင်သောဗျူဟာများ

| ဗျူဟာ              | ဘယ်အချိန်မှာ သုံးမလဲ။                                | အပေးအယူလုပ်သည်                                                                   |
| ------------------ | ---------------------------------------------------- | -------------------------------------------------------------------------------- |
| `quality` (မူရင်း) | အရည်အသွေးရောစပ်ထားသော proxy များဖြင့် ထုတ်လုပ်ခြင်း။ | အဆင့်မြင့်မားသော proxy များကို နှစ်သက်သည်။ အဆင့်နိမ့်သူများကို ငတ်စေနိုင်သည်။    |
| `random`           | ဝန်ထုပ်ဝန်ပိုး၊ လျှို့ဝှက်ရေး                        | ဖြန့်ဖြူးခြင်းပင်; အရည်အသွေးအချက်ပြမှုများကို လျစ်လျူရှုသည်။                     |
| `sequential`       | အမှားရှာပြင်ခြင်း၊ အဆုံးအဖြတ်စမ်းသပ်ခြင်း။           | အစီအစဥ်အတိုင်း ပရောက်စီများမှတဆင့် လည်ပတ်ခြင်း၊ ကျိုးကြောင်းဆင်ခြင်ရန်လွယ်ကူသည်။ |

## သင့်ကိုယ်ပိုင် Proxies အတွက် အလိုအလျောက် ပျက်ကွက်မှုကို ဖယ်ထုတ်ခြင်း

1proxy စျေးကွက်အုပ်စုသည် မအောင်မြင်သော ပရောက်စီများကို သူ့ဘာသာသူ အလိုအလျောက် ကျဆင်းနေပြီ ( [Proxy အရည်အသွေးရမှတ်များကို](#proxy-quality-scores) ကြည့်ပါ)။ proxy အတွက်** သင်** မှတ်ပုံတင်ခြင်းသို့ ပေါင်းထည့်ထားသော၊ နောက်ခံကျန်းမာရေး အစီအစဉ်ဆွဲသူ (`src/lib/proxyHealth/scheduler.ts`) သည် မည်သည့်အရာမှ မဖျက်ဘဲ တူညီသော "သေနေသော အဖွဲ့ဝင်ကို ကွင်းဆက်မှ အလိုအလျောက် ဖယ်ထုတ်သည်" အပြုအမူကို ပံ့ပိုးပေးသည်-

```bash
# .env — soft-disable a proxy after 3 consecutive failed probes, re-enable it
# automatically once it starts answering probes again.
PROXY_AUTO_DISABLE=true
PROXY_AUTO_REMOVE_AFTER=3
```

၎င်းသည် multi-proxy ကွင်းဆက်သို့ မည်ကဲ့သို့ လိုက်ဖက်သည်-

1. အချိန်ဇယားဆွဲသူသည် `PROXY_HEALTH_INTERVAL_MS` တိုင်းတွင် စာရင်းသွင်းထားသော ပရောက်စီတိုင်းကို စစ်ဆေးသည် (ပုံမှန် 10 မိနစ်၊ အနည်းဆုံး 1 မိနစ်)။
2. `PROXY_AUTO_REMOVE_AFTER` ပြီးနောက်ဆက်တိုက်** ခိုင်လုံသော** ပျက်ကွက်မှုများ (အမှန်တကယ် ချိတ်ဆက်မှု ပျက်ကွက်မှု — အချိန်ကုန်သွားခြင်း သို့မဟုတ် စုံစမ်းစစ်ဆေးမှုပစ်မှတ်၏ ကိုယ်ပိုင် 5xx ကို ဘယ်သောအခါမှ မရေတွက်ပါ၊ [Proxy ကျန်းမာရေးစစ်ဆေးခြင်းကို](#proxy-health-checking-v3816) ကြည့်ပါ)၊ ပရောက်စီ၏ `status` ကို `dead` ဟု သတ်မှတ်သည်။
3. `dead` သည် pool/rotation ကြည်လင်ပြတ်သားမှုမှ ဖယ်ထုတ်ထားသော ရှင်သန်မှုအခြေအနေ စစ်ထုတ်မှု အခြေအနေများထဲမှ တစ်ခုဖြစ်ပြီး နယ်ပယ်တစ်ခု၏ လှည့်ခြင်း ( round-robin / random / sticky / latency — ကိုကြည့်ပါ [Rotation Strategy Decision Tree](#rotation-strategy-decision-tree) ) သည် အဆိုပါ proxy ကို တောင်းဆိုချက်အသစ်များသို့ လွှဲပြောင်းပေးခြင်းကို ချက်ချင်းရပ်တန့်သွားမည်ဖြစ်သည်။ ရေကူးကန်ရှိ အခြား proxy များကို ထိခိုက်ခြင်းမရှိပါ၊ နှင့် ရေကူးကန်တစ်ခုလုံးသည် တိုက်ရိုက်ချိတ်ဆက်မှု — သို့ တိတ်တဆိတ်ပြန်ကျသွားသည့် [4-Level Proxy System](#4-level-proxy-system) fail-closed guard ကိုကြည့်ပါ။
4. အချိန်ဇယားဆွဲသူသည် တူညီသောကြားကာလတွင် `dead` ပရောက်စီများကို ဆက်လက်စစ်ဆေးသည်။ နောက်အောင်မြင်သော probe သည် `status` `active` သို့ ပြန်ပြောင်းပြီး ၎င်းသည် rotation — ပြန်လည်ထည့်သွင်းရန်မလိုဘဲ manual re-add လုပ်ရန် မလိုအပ်ပါ။

ဒါက တမင်တကာ** ရွေးချယ်ဝင်ရောက်ပြီး အပျက်အဆီးမရှိပါ။** : အစီအစဉ်ဆွဲသူသည် ပုံမှန်အားဖြင့် ပျက်ကွက်မှုများကို ရေတွက်ပြီး မှတ်တမ်းများသာ ( `decision.ts` တွင် မူဝါဒ C ကိုကြည့်ပါ) နှင့် `PROXY_AUTO_DISABLE` သီးခြား၊ ပိုမိုပြင်းထန်သော `PROXY_AUTO_REMOVE` အလံအတွက် ဖြစ်သည့် အတန်း — ဘယ်သောအခါမှ မဖျက်ပါ။ နှစ်ခုလုံးကို `true` ဟုသတ်မှတ်ပါက `PROXY_AUTO_REMOVE` အနိုင်ရသည် (ဖျက်ပစ်မည့် proxy တစ်ခုကြားတွင် soft-disable အတွက် အသုံးမဝင်ပါ)။ ပြောင်းလဲနိုင်သောစာရင်းအပြည့်အစုံအတွက် [Environment Config](../reference/ENVIRONMENT.md) ရည်ညွှန်းချက်ကို ကြည့်ပါ။
