## Ինչու՞ օգտագործել վստահված անձինք:

Շատ AI պրովայդերներ սահմանափակում են մուտքն ըստ աշխարհագրական տարածաշրջանի: Մշակողները ներս** Ռուսաստան, Չինաստան, Իրան, Կուբա, Թուրքիա** և այլ երկրներ բախվում են այնպիսի սխալների, ինչպիսիք են՝

```
unsupported_country_region_territory
```

Նույնիսկ արգելափակված շրջաններից դուրս վստահված անձինք օգտակար են հետևյալի համար.

| Օգտագործեք գործը            | Նկարագրություն                                                                      |
| --------------------------- | ----------------------------------------------------------------------------------- |
| **Աշխարհագրական շրջանցում** | Մուտք գործեք OpenAI, Anthropic, Codex, Copilot արգելափակված երկրներից               |
| **IP ռոտացիա**              | Տարածեք հարցումները մի քանի IPs վրա՝ տոկոսադրույքի սահմանափակումից խուսափելու համար |
| **Գաղտնիություն**           | Թաքցրեք ձեր իրական IP հոսանքին հակառակ պրովայդերներից                               |
| **Համապատասխանություն**     | Երթուղային երթևեկությունը որոշակի իրավասությունների միջով                           |
| **Փորձարկում**              | Մոդելավորել հարցումները տարբեր տարածաշրջաններից                                     |

## Նոր հաշիվների համար կանխադրված վստահված անձի կարգավիճակ

Մեջ** Կարգավորումներ → Proxy → Համաշխարհային կոնֆիգուրացիա** , օգտագործել** Նոր կապերի համար լռելյայն միացրեք վստահված անձը** ընտրել նոր ավելացված մատակարարի հաշիվների սկզբնական վստահված կարգավիճակը:

Նոր կարգավորումը վերահսկում է նոր ավելացված մատակարարի հաշիվների նախնական վստահված անձի վիճակը: Այն չի փոխում գոյություն ունեցող հաշիվները և չի փոխարինում գլոբալ պրոքսի փոխարկիչը: Դրա սկզբնական արժեքը պահպանում է նախորդ վարքագիծը: Անջատեք այն մեկ անգամ՝ կանխադրված կերպով անջատված վստահված անձի հետ ապագա հաշիվներ ստեղծելու համար:

Նախապատվությունը պահվում է որպես `defaultNewConnectionProxyEnabled` գոյություն ունեցող APIկարգավորումների միջոցով: Այն կանխադրված է `true`, երբ երբեք չի պահպանվում: `false` պահպանումն ուժի մեջ է մտնում հետագա նոր հաշիվների համար՝ առանց վերագործարկման: `POST /api/providers` ընդունում է կամընտիր խիստ բուլյան `proxyEnabled`; բացահայտ `true` կամ `false` գերակայում է ստեղծման լռելյայնից: Կրկնվող հաշվի բացթողումը կամ OAuth վերամիացումը պահպանում է այդ հաշվի պահված վիճակը: Անհատական հաշիվները դեռ կարող են միացվել կամ անջատվել դրանից հետո:

Ընտրովի մատակարարի փոխանցումները օգտագործում են նպատակակետի տեղադրման լռելյայն նոր հաշիվների համար և պահպանում են նպատակակետ քաղաքականությունը գոյություն ունեցող հաշիվները փոխարինելիս: Proxy-ի անջատիչները շարժական փոխանցման դաշտեր չեն: Պահուստային ամբողջական վերականգնումը և պատմական JSON/SQL միգրացիան պահպանում են վերականգնման իրենց գոյություն ունեցող իմաստաբանությունը, ներառյալ պահված հաշվի արժեքները և ժառանգական սխեմայի լռելյայնությունները. կարգավորումների ամբողջական վերականգնումը կարող է նաև վերականգնել այս նախապատվությունը:

Այս նախապատվությունը չի նշանակում վստահված անձ կամ չի հաստատում, որ մեկը առողջ է կամ օգտագործվում է: Փաստացի երթուղավորումը դեռևս կախված է գլոբալ պրոքսի փոխարկիչից և կիրառելի պրոքսի կազմաձևից: Սինթետիկ պրովայդերները՝ առանց մշտական հաշվի, OAuth տրաֆիկը մինչև հաշվի ստեղծումը, environment/system վստահված անձինք և արտաքին հետադարձ կապի ցանցերը դուրս են դրա շրջանակից:

## 4-Մակարդակ վստահված անձի համակարգ

OmniRoute աջակցում է վստահված անձի կոնֆիգուրացիան ժամը** չորս անկախ շրջանակներ** , լուծվել է առաջնահերթության կարգով.

```
Priority Resolution Order (highest → lowest):

  1. 🔵 Account/Connection Proxy  →  per API key / OAuth connection
  2. 🟡 Provider Proxy            →  per provider (e.g., all OpenAI traffic)
  3. 🟠 Combo Proxy               →  per combo/routing configuration
  4. 🟢 Global Proxy              →  all traffic, all providers
```

### Ինչպես է աշխատում բանաձեւը

Երբ OmniRoute հարցում է ուղարկում վերին հոսքի մատակարարին, այն կանչում է `resolveProxyForConnectionFromRegistry()`, որը ստուգում է յուրաքանչյուր մակարդակ ըստ հերթականության.

1. **Հաշվի մակարդակով** — Կա՞ արդյոք վստահված անձ նշանակված այս կոնկրետ կապին ID:
2. **Մատակարարի մակարդակ** — Կա՞ արդյոք վստահված անձ նշանակված այս մատակարարին (օրինակ՝ `openai`):
3. **Համաշխարհային մակարդակով** — Կա՞ գլոբալ պրոքսի կազմաձևված:
4. **Ոչ մի վստահված անձ** — Ուղիղ միացում մատակարարին:

Առաջին հանդիպումը հաղթում է. Սա նշանակում է, որ դուք կարող եք սահմանել գլոբալ վստահված անձը որպես հետադարձ, բայց անտեսել այն հատուկ մատակարարների կամ կապերի համար:

### Ինչ է ստացվում վստահված անձի կողմից

| Երթևեկության տեսակը   | Վստահված՞: | Նշումներ                                            |
| --------------------- | ---------- | --------------------------------------------------- |
| Զրույցի ավարտ         | ✅         | Բոլոր `/v1/chat/completions` հարցումները            |
| Ներդրումներ           | ✅         | `/v1/embeddings`                                    |
| Պատկերի գեներացիա     | ✅         | `/v1/images/generations`                            |
| Աուդիո (TTS/STT)      | ✅         | `/v1/audio/*`                                       |
| OAuth նշան փոխանակում | ✅         | Լուծում է `unsupported_country_region_territory`    |
| Միացման թեստեր        | ✅         | «Test Connection» կոճակը օգտագործում է վստահված անձ |
| Նշանների թարմացում    | ✅         | Ֆոնային OAuth նորացում                              |
| Մոդելի համաժամեցում   | ✅         | Մոդելների ցուցակագրում և հայտնաբերում               |

## Վստահված անձի ռեեստր (CRUD)

Վստահված անձի ռեեստրը SQLite աղյուսակ է (`proxy_registry`), որը պահում է ձեր բոլոր վստահված անձինք: Յուրաքանչյուր վստահված անձ ունի.

| Դաշտ       | Տեսակ      | Նկարագրություն                                       |
| ---------- | ---------- | ---------------------------------------------------- |
| `id`       | UUID       | Եզակի նույնացուցիչ                                   |
| `name`     | Լարային    | Մարդկանց համար ընթեռնելի պիտակ                       |
| `type`     | Լարային    | Արձանագրություն՝ `http`, `https`, `socks5`           |
| `host`     | Լարային    | Վստահված անձի հյուրընկալողի անունը կամ IP            |
| `port`     | Ամբողջ թիվ | Նավահանգստի համարը                                   |
| `username` | Լարային    | Հաստատել օգտանունը (գաղտնագրված է հանգիստ վիճակում)  |
| `password` | Լարային    | Հաստատման գաղտնաբառ (գաղտնագրված է հանգիստ վիճակում) |
| `region`   | Լարային    | Աշխարհագրական տարածաշրջանի պիտակ                     |
| `notes`    | Լարային    | Ազատ տեքստային նշումներ                              |
| `status`   | Լարային    | `active` կամ `inactive`                              |
| `source`   | Լարային    | `manual` կամ `oneproxy`                              |

### Վստահված անձի ստեղծում

**Վահանակի միջոցով.**

1. Գնալ դեպի** Կարգավորումներ → Proxy**
2. Սեղմեք** Ավելացնել վստահված անձ**
3. Լրացրեք տեսակը, հյուրընկալողը, նավահանգիստը և կամընտիր վավերացման հավատարմագրերը
4. Պահպանել

**API միջոցով.**

```bash
curl -X POST http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "name": "US Proxy",
    "type": "http",
    "host": "proxy.example.com",
    "port": 8080,
    "username": "user",
    "password": "pass",
    "region": "US"
  }'
```

### Վստահված անձի թարմացում

```bash
curl -X PATCH http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "id": "proxy-uuid-here",
    "host": "new-proxy.example.com",
    "port": 9090
  }'
```

> **Նշում.** Հավատարմագրերը պահպանվում են, եթե դուք բացահայտորեն չուղարկեք ոչ դատարկ փոխարինումներ: `username`/`password` համար դատարկ տողեր ուղարկելը կպահպանի պահված արժեքները:

### Վստահված անձի ջնջում

```bash
# Fails if proxy is assigned to any scope
curl -X DELETE "http://localhost:20128/api/v1/management/proxies?id=proxy-uuid"

# Force delete (removes assignments too)
curl -X DELETE "http://localhost:20128/api/v1/management/proxies?id=proxy-uuid&force=1"
```

### Ցուցակման վստահված անձինք

```bash
curl "http://localhost:20128/api/v1/management/proxies?limit=50&offset=0"
```

### Scopes-ին վստահված անձանց նշանակում

```bash
# Assign to global scope
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "global", "proxy": {"type":"http","host":"proxy.example.com","port":8080}}'

# Assign to a specific provider
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "provider", "id": "openai", "proxy": {"type":"socks5","host":"socks.example.com","port":1080}}'

# Assign to a specific connection/key
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "key", "id": "connection-uuid", "proxy": {"type":"http","host":"key-proxy.com","port":3128}}'
```

### Արդյունավետ վստահված անձի լուծում

Ստուգեք, թե որ վստահված սերվերը կօգտագործվի տվյալ կապի համար.

```bash
curl "http://localhost:20128/api/settings/proxy?resolve=connection-uuid"
```

Վերադարձնում է լուծված պրոքսին իր մակարդակով (`account`, `provider` կամ `global`) և աղբյուրով:

### Զանգվածային հանձնարարություն

Նշանակեք մեկ վստահված անձ միանգամից մի քանի մատակարարների կամ կապերի.

```bash
curl -X POST http://localhost:20128/api/v1/management/proxies/bulk-assign \
  -H "Content-Type: application/json" \
  -d '{
    "scope": "provider",
    "scopeIds": ["openai", "anthropic", "codex"],
    "proxyId": "proxy-uuid"
  }'
```

### Import/Export

Վստահված անձինք ներառված են**Backup/Restore** համակարգ. Երբ արտահանում եք ձեր OmniRoute կոնֆիգուրացիան.

1. Գնալ դեպի** Գործակալության վահանակ → Կարգավորումներ → Կրկնօրինակում**
2. Սեղմեք** Արտահանում** Ներառված են — վստահված անձի ռեեստրը և հանձնարարությունները
3. Վերականգնելու համար սեղմեք** Ներմուծում** և վերբեռնեք պահուստային ֆայլը

Վստահված անձի ռեեստրը նույնպես աջակցում է** upsert կողմից host + port** — եթե ներմուծում եք արդեն գոյություն ունեցող վստահված սերվեր (նույն հոսթ և պորտ), այն թարմացվում է կրկնօրինակ ստեղծելու փոխարեն:

### Ժառանգության միգրացիա

Եթե վստահված անձինք կարգավորել եք ավելի հին տարբերակում (նախագրանցում), OmniRoute ավտոմատ կերպով տեղափոխում է դրանք՝

```
Legacy key_value store → proxy_registry + proxy_assignments
```

Դա տեղի է ունենում մեկ անգամ՝ թարմացումից հետո առաջին գործարկման ժամանակ: Վերագործարկելու համար օգտագործեք `migrateLegacyProxyConfigToRegistry({ force: true })` :

## 1proxy Անվճար վստահված անձի շուկա

> 🆕** Աջակցել է [@oyi77](https://github.com/oyi77)** — PR [#1847](https://github.com/diegosouzapw/OmniRoute/pull/1847) (Թողարկում [#1788](https://github.com/diegosouzapw/OmniRoute/issues/1788) )

OmniRoute ինտեգրվում է** [1 վստահված անձ](https://1proxy-api.aitradepulse.com)** համայնքային հարթակ՝ մուտք ապահովելու համար** հարյուրավոր անվճար, վավերացված վստահված անձինք** ամբողջ աշխարհից: Սա կատարյալ է այն օգտվողների համար, ովքեր չունեն իրենց սեփական վստահված անձի ենթակառուցվածքը:

### Ինչպես է այն աշխատում

```
┌─────────────┐     Sync      ┌─────────────────┐    Rotate     ┌──────────┐
│  1proxy API │ ────────────▶ │  proxy_registry  │ ────────────▶ │ Provider │
│  (external) │   up to 500   │  source=oneproxy │  by quality   │   API    │
└─────────────┘    proxies    └─────────────────┘               └──────────┘
```

1. **Համաժամեցում** — OmniRoute 1proxy API ից վերցնում է վավերացված պրոքսիներ
2. **Խանութ** — վստահված անձինք պահվում են `source = 'oneproxy'` հետ նույն `proxy_registry` աղյուսակում
3. **Զտել** — Զտել ըստ արձանագրության, երկրի, որակի գնահատականի
4. **Պտտել** — Ընտրեք լավագույն վստահված անձը՝ օգտագործելով որակյալ, պատահական կամ հաջորդական ռազմավարություններ
5. **Ավտոմատ դեգրադացիա** — Չհաջողված վստահված անձինք ստանում են իրենց որակի գնահատականը նվազեցված. շեմից ցածր → նշված է որպես ոչ ակտիվ

### Վստահված անձանց համաժամացում

**Վահանակի միջոցով.**

1. Գնալ դեպի** Կարգավորումներ → 1proxy** ներդիր
2. Սեղմեք** «Հիմա համաժամեցիր»**
3. Դիտեք վիճակագրությունը՝ վստահված անձանց ընդհանուր թիվը, ակտիվների քանակը, միջին որակը, ըստ երկրների բաժանումը

**API միջոցով.**

```bash
# Trigger sync
curl -X POST http://localhost:20128/api/settings/oneproxy \
  -H "Content-Type: application/json" \
  -d '{}'

# Response:
# { "success": true, "added": 127, "updated": 45, "failed": 2, "total": 172 }
```

### Վստահված անձանց զտում

```bash
# Filter by protocol
curl "http://localhost:20128/api/settings/oneproxy?protocol=socks5"

# Filter by country
curl "http://localhost:20128/api/settings/oneproxy?countryCode=US"

# Filter by minimum quality score
curl "http://localhost:20128/api/settings/oneproxy?minQuality=80"

# Combine filters
curl "http://localhost:20128/api/settings/oneproxy?protocol=http&countryCode=DE&minQuality=70"
```

### Վստահված անձի որակի միավորներ

Յուրաքանչյուր 1 վստահված անձ գալիս է մետատվյալներով.

| Դաշտ            | Նկարագրություն                                                   |
| --------------- | ---------------------------------------------------------------- |
| `qualityScore`  | 0-100 վարկանիշ 1 վստահված անձի վավերացումից                      |
| `latencyMs`     | Չափված ցանցի ուշացում                                            |
| `anonymity`     | `transparent`, `anonymous`, or `elite`                           |
| `googleAccess`  | Արդյոք վստահված անձը կարող է մուտք գործել Google ծառայություններ |
| `countryCode`   | Երկու տառ ISO երկրի կոդը                                         |
| `lastValidated` | Վերջին վավերացման ժամանակացույցը                                 |

Որակի միավորները դինամիկ կերպով ճշգրտվում են.

- **Չհաջողված հարցումներ** միավորը կրճատել 10 միավորով
- **Միավորը նվազում է մինչև ≤ 10** → վստահված անձը նշված է `inactive`
- Անգործուն պրոքսիները բացառվում են ռոտացիայից

### Պտտման ռազմավարություններ

```bash
# Rotate by quality (best proxy first) — default
curl -X POST http://localhost:20128/api/settings/oneproxy/rotate \
  -H "Content-Type: application/json" \
  -d '{"strategy": "quality"}'

# Random rotation
curl -X POST http://localhost:20128/api/settings/oneproxy/rotate \
  -d '{"strategy": "random"}'

# Sequential (least recently validated first)
curl -X POST http://localhost:20128/api/settings/oneproxy/rotate \
  -d '{"strategy": "sequential"}'
```

### Անջատիչ

1proxy sync-ն ունի ներկառուցված անջատիչ.

- հետո** 5 անընդմեջ համաժամացման ձախողումներ** , հետագա համաժամացման փորձերն արգելափակված են
- Վերագործարկեք `resetOneproxyCircuitBreaker()` ով կամ վերագործարկեք սերվերը
- Համաժամացման կարգավիճակը հասանելի է `GET /api/settings/oneproxy?action=status` ում

### 1 վստահված անձերի մաքրում

```bash
# Delete a single 1proxy proxy
curl -X DELETE "http://localhost:20128/api/settings/oneproxy?id=proxy-uuid"

# Clear ALL 1proxy proxies (manual proxies are untouched)
curl -X DELETE "http://localhost:20128/api/settings/oneproxy?clearAll=1"
```

## Հակահայտնաբերում և գաղտնիություն

OmniRoute ոչ միայն ուղղորդում է երթևեկությունը — վստահված անձի միջոցով, այլ երթևեկությունն օրինական է դարձնում.

### TLS Մատնահետքերի կեղծում

Օգտագործում է `wreq-js` զննարկիչի նման TLS մատնահետքեր ստեղծելու համար՝ շրջանցելով բոտերի հայտնաբերման համակարգերը, որոնք նշում են ոչ զննարկիչ TLS ձեռքսեղմումները:

### CLI Մատնահետքի համապատասխանեցում

Այն**CLI Մատնահետքի անջատիչ** (`Settings → Security`) վերադասավորում է HTTP վերնագրերը և JSON մարմնի դաշտերը՝ տեղական CLI երկուականների ճշգրիտ ստորագրությանը համապատասխանելու համար (Claude Code, Codex և այլն): Սա աշխատում է** գագաթին** վստահված անձ:

```
Your IP (blocked) → Proxy IP (US) → Provider API
                    + TLS spoof
                    + CLI fingerprint
```

Դուք երկուսն էլ ստանում եք**IP դիմակավորում** և** խնդրեք իսկությունը** միաժամանակ։

### Proxy IP պահպանում

Վահանակի գունային կոդավորված կրծքանշանները ցույց են տալիս, թե որ պրոքսի մակարդակն է ակտիվ՝

| Կրծքանշան | Մակարդակ      | Իմաստը                                                    |
| --------- | ------------- | --------------------------------------------------------- |
| 🟢        | Համաշխարհային | Ամբողջ երթևեկությունը անցնում է այս վստահված անձի միջոցով |
| 🟡        | Մատակարար     | Միայն այս մատակարարի տրաֆիկը պրոքսիավորված է              |
| 🔵        | Միացում       | Այս կոնկրետ key/account օգտագործում է այս վստահված անձը   |

Կրծքանշանը նաև ցույց է տալիս լուծված IP վստահված անձը ստուգման համար:

## Վերին հոսքի վստահված անձի ռեժիմներ

Պրովայդերների համար, ովքեր օգտագործում են CLIProxyAPI օրինաչափությունը, OmniRoute աջակցում է երեք վերին հոսանքով վստահված անձի ռեժիմ.

| Ռեժիմ         | Նկարագրություն                                                          |
| ------------- | ----------------------------------------------------------------------- |
| `native`      | OmniRoute ուղղակիորեն կարգավորում է վստահված անձի երթուղին (կանխադրված) |
| `cliproxyapi` | Պատվիրակներ արտաքին CLIProxyAPI օրինակին                                |
| `fallback`    | Փորձում է սկզբում հայրենի, ընկնում է CLIProxyAPI                        |

Կարգավորել յուրաքանչյուր մատակարարի համար՝

```bash
curl -X PUT "http://localhost:20128/api/upstream-proxy/openai" \
  -H "Content-Type: application/json" \
  -d '{"mode": "native", "enabled": true}'
```

### Կարգավորումներ → Proxy Tab

- **Համաշխարհային վստահված անձ** կոնֆիգուրացիա (սահմանված է մեկ անգամ ամբողջ երթևեկության համար)

- **Միացման փորձարկում** կազմաձևված վստահված անձի միջոցով
- **Գույնի կոդավորված կրծքանշաններ** ցույց տալով ակտիվ վստահված անձի մակարդակը

- **Համաժամացնել հիմա** կոճակ՝ անվճար վստահված օգտատերեր ստանալու համար
- **Վիճակագրության քարտեր** Ընդհանուր, Ակտիվ, Միջին որակ, Վերջին համաժամացում

- **Վստահված անձի աղյուսակ** հյուրընկալող, արձանագրություն, երկիր, որակի գնահատական, ուշացում, անանունություն, Google հասանելիություն
- **Համաժամեցման կարգավիճակը** վահանակ success/failure հետևումով և հաջորդական ձախողումների քանակով
- **Մաքրել բոլորը** հեռացնել բոլոր 1 վստահված անձի գրառումները

## Անսարքությունների վերացում

### «SOCKS5 վստահված անձը անջատված է»

Տեղադրեք `ENABLE_SOCKS5_PROXY=true` ձեր `.env` ֆայլում և վերագործարկեք:

### «socket hang up» սխալները վստահված անձի միջոցով

Սա նորմալ է էժան պրոքսիների դեպքում, որոնք թողնում են անգործուն կապերը: OmniRoute արդեն լուծում է սա՝

- Անջատում է պահպանել ակտիվությունը վստահված անձի միացումների վրա (`keepAliveTimeout: 1`)
- Խողովակաշարերի անջատում (`pipelining: 0`)
- Դիսպետչերների քեշավորում՝ կրկնվող ձեռքսեղմումներից խուսափելու համար

Եթե այն շարունակվի, փորձեք այլ վստահված անձ կամ օգտագործեք 1proxy-ի ռոտացիայի հատկությունը:

### «unsupported_country_region_territory» OAuth ի ժամանակ

Համոզվեք, որ վստահված անձը կազմաձևված է** առաջ** սկսելով OAuth հոսքը. OmniRoute ուղղորդում է OAuth նշանների փոխանակումը կազմաձևված վստահված անձի միջոցով: Նախ սահմանեք գլոբալ կամ մատակարարի մակարդակի վստահված անձ, այնուհետև միացեք:

### Չի օգտագործվում վստահված անձ

Ստուգեք լուծման կարգը.

1. Ստուգեք `GET /api/settings/proxy?resolve=your-connection-id` ով
2. Ստուգեք, արդյոք `status` վստահված անձը `active` է (ոչ `inactive`)
3. Համոզվեք, որ վստահված անձի նշանակման շրջանակը համապատասխանում է ձեր կապին

### 1 վստահված անձի համաժամացումը ձախողվեց

Ստուգեք համաժամացման կարգավիճակը.

```bash
curl "http://localhost:20128/api/settings/oneproxy?action=status"
```

Եթե `consecutiveFailures >= 5`, ապա անջատիչը միացել է: Վերագործարկեք սերվերը վերագործարկելու համար կամ սպասեք ձեռքով վերակայման:

## Տվյալների բազայի սխեման

### `proxy_registry` Աղյուսակ

```sql
CREATE TABLE proxy_registry (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  type TEXT NOT NULL DEFAULT 'http',
  host TEXT NOT NULL,
  port INTEGER NOT NULL,
  username TEXT DEFAULT '',
  password TEXT DEFAULT '',
  region TEXT,
  notes TEXT,
  status TEXT DEFAULT 'active',
  source TEXT NOT NULL DEFAULT 'manual',    -- 'manual' or 'oneproxy'
  quality_score INTEGER,                     -- 0-100 (1proxy only)
  latency_ms INTEGER,                        -- milliseconds (1proxy only)
  anonymity TEXT,                            -- transparent/anonymous/elite
  google_access INTEGER DEFAULT 0,           -- can access Google? (1proxy)
  last_validated TEXT,                       -- ISO timestamp (1proxy)
  country_code TEXT,                         -- ISO 2-letter code (1proxy)
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

### `proxy_assignments` Աղյուսակ

```sql
CREATE TABLE proxy_assignments (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  proxy_id TEXT NOT NULL REFERENCES proxy_registry(id),
  scope TEXT NOT NULL,        -- 'global', 'provider', 'account', 'combo'
  scope_id TEXT,              -- provider ID, connection ID, or combo ID
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE(scope, scope_id)
);
```

## Վստահված անձի առողջության ստուգում (v3.8.16 +)

OmniRoute's** վստահված անձի արագ ձախողում** մեխանիզմը (`src/lib/proxyHealth.ts`) հայտնաբերում է < 2s-ում մահացած վստահված անձինք՝ TCP կապի արագ ստուգման միջոցով, այնուհետև** պահում է արդյունքը** յուրաքանչյուր հարցման վերևից խուսափելու համար:

### Ինչպես է այն աշխատում

```
Request ──▶ ProxyHealthCache.get(url)
             │
             ├─ Cache hit + fresh?  ──▶ return cached status
             │
             └─ Cache miss / stale?  ──▶ TCP connect to host:port
                                          (timeout: FAST_FAIL_TIMEOUT_MS)
                                          ──▶ cache for HEALTH_CACHE_TTL_MS
                                          ──▶ return result
```

Առանց դրա, մահացած վստահված անձը կարգելափակի ամբողջական `PROXY_TIMEOUT_MS` (կանխադրված 30-ականներ) յուրաքանչյուր հարցում, նախքան ձախողումը:

### Կարգավորելի միջավայրի փոփոխականներ

| Փոփոխական                    | Կանխադրված | Նպատակը                                                |
| ---------------------------- | ---------- | ------------------------------------------------------ |
| `PROXY_FAST_FAIL_TIMEOUT_MS` | `2000`     | TCP կապի ժամանակի ընդհատում առողջության ստուգման համար |
| `PROXY_HEALTH_CACHE_TTL_MS`  | `30000`    | Որքա՞ն ժամանակ է պահվում առողջության արդյունքը         |

**Առաջարկվող արժեքներ.**

| Սցենար                           | Արագ ձախողման ժամանակի սպառում | Cache TTL | Պատճառաբանություն                                                                  |
| -------------------------------- | ------------------------------ | --------- | ---------------------------------------------------------------------------------- |
| Բարձր թողունակությամբ API դարպաս | 1500 մս                        | 60000 մս  | Ագրեսիվ ձախողման արագ, ավելի երկար քեշ՝ ստուգումները նվազեցնելու համար             |
| Աշխարհաբաշխված հանգույցներ       | 3000 մս                        | 15000 մս  | Ավելի դանդաղ ցանցերին ավելի շատ ժամանակ է պետք. ավելի կարճ քեշ արագ ձախողման համար |
| Dev / փորձարկում                 | 1000 մս                        | 10000 մս  | Արագ կրկնություն տեղական վստահված սերվերների վրա                                   |
| Գաղտնիություն / հակահայտնաբերում | 2500 մս                        | 45000 մս  | Խուսափեք արագ զոնդավորումից, որը կարող է առաջացնել տոկոսադրույքի սահմանաչափեր      |

### Վստահված անձի առողջության ստուգում

```ts
import { getAllProxyHealthStatuses, invalidateProxyHealth } from "omniroute/proxyHealth";

const statuses = getAllProxyHealthStatuses();
for (const s of statuses) {
  console.log(`${s.proxyUrl} → healthy=${s.healthy}, stale=${s.stale}`);
}

// Force re-check a specific proxy
invalidateProxyHealth("http://user:pass@203.0.113.7:8080");
```

`stale` դրոշը `true` է, երբ քեշի մուտքագրումը գերազանցել է `HEALTH_CACHE_TTL_MS`, և հաջորդ հարցումը կսկսի նոր ստուգում:

### Յուրաքանչյուր վստահված անձի տեսակի լռելյայն

Առողջության ստուգումն օգտագործում է խելամիտ լռելյայններ՝ հիմնված URL սխեմայի վրա.

| Սխեման                     | Կանխադրված նավահանգիստ |
| -------------------------- | ---------------------- |
| `http://`                  | 8080                   |
| `https://`                 | 443                    |
| `socks5://` / `socks5h://` | 1080                   |

Հատուկ նավահանգիստները URL ում (`http://host:9999`) միշտ գերակայում են սխեմայի լռելյայնից:

## Վստահված անձի վերլուծություն և դիտելիություն

OmniRoute հետևում է յուրաքանչյուր վստահված անձի օգտագործմանը՝ օգնելու օպերատորներին ախտորոշել երթուղիների օրինաչափությունները, հետաձգման բարձրացումները և կրկնվող ձախողումները:

### Ինչ է Հետևվում

Կազմաձևված վստահված անձի միջոցով յուրաքանչյուր հարցման համար OmniRoute գրանցում է.

| Մետրիկա      | Նկարագրություն                                                         |
| ------------ | ---------------------------------------------------------------------- |
| `proxy_url`  | Ամբողջական վստահված անձ URL (հավաստագրման հավատարմագրերը դիմակավորված) |
| `provider`   | Վերին հոսքի մատակարար ID (openai, anthropic և այլն)                    |
| `latency_ms` | Շրջայցի ընդհանուր ժամանակը, ներառյալ վստահված անձի ձեռքսեղմումը        |
| `connect_ms` | TCP միացման ժամանակը միայն                                             |
| `status`     | HTTP կարգավիճակի կոդը վերին հոսանքով                                   |
| `error`      | Սխալի դաս, եթե հարցումը ձախողվեց                                       |
| `timestamp`  | ISO 8601 UTC                                                           |

### Տվյալների մուտք

```bash
# Recent proxy events
curl -H "Authorization: Bearer $OMNIROUTE_KEY" \
  "http://localhost:20128/api/usage/proxy-logs?limit=100"
```

Իրական վերջնակետը `/api/usage/proxy-logs` է (տես `src/app/api/usage/proxy-logs/route.ts`): Այս վերջնակետն աջակցում է.

- `GET /api/usage/proxy-logs` — առբերեք վստահված անձի տեղեկամատյանները
- `DELETE /api/usage/proxy-logs` — մաքրել բոլոր վստահված տեղեկամատյանները

Համախառն վիճակագրությունը կարող է ուղղակիորեն հարցվել `proxy_logs` աղյուսակից SQL միջոցով, եթե անհրաժեշտ է: UI վահանակը կարող է առաջարկել ընդհանուր դիտումներ:

### Ընդհանուր նախշեր

**Հայտնաբերել թռչող վստահված անձ** (փոխարինվում է success/failure միջև):

```sql
SELECT proxy_url,
       COUNT(*) AS total,
       SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) AS errors,
       ROUND(100.0 * SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) / COUNT(*), 1) AS error_pct
FROM proxy_logs
WHERE timestamp > datetime('now', '-1 hour')
GROUP BY proxy_url
HAVING error_pct > 5
ORDER BY error_pct DESC;
```

**Գտեք դանդաղ վստահված անձինք** (p95 latency > 2s):

```sql
WITH ranked AS (
  SELECT proxy_url, latency_ms,
         PERCENT_RANK() OVER (PARTITION BY proxy_url ORDER BY latency_ms) AS pct
  FROM proxy_logs
  WHERE timestamp > datetime('now', '-24 hour')
)
SELECT proxy_url, latency_ms
FROM ranked
WHERE pct >= 0.95
ORDER BY latency_ms DESC;
```

## Ռոտացիայի ռազմավարության որոշումների ծառ

Երբ մի քանի պրոքսիներ են նշանակվում շրջանակի, OmniRoute օգտագործում է a** ռոտացիայի ռազմավարություն** ընտրել, թե որն է օգտագործել յուրաքանչյուր հարցման համար: Ռազմավարությունը կազմաձևված է շրջանակի մակարդակով (համաշխարհային, յուրաքանչյուր մատակարարի, մեկ հաշվի, մեկ համակցվածի համար):

### Հասանելի ռազմավարություններ

| Ռազմավարություն        | Երբ օգտագործել                           | Փոխանակում                                                                                                         |
| ---------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `quality` (կանխադրված) | Արտադրություն խառը որակի պրոքսիներով     | Նախապատվությունը տալիս է բարձր վարկանիշ ունեցող վստահված անձանց; կարող են սովամահ լինել ցածր վարկանիշ ունեցողներին |
| `random`               | Բեռնվածության բաշխում, գաղտնիություն     | հավասարաչափ բաշխում; անտեսում է որակի ազդանշանները                                                                 |
| `sequential`           | Վրիպազերծում, դետերմինիստական փորձարկում | Շրջանցում վստահված անձանց միջոցով հերթականությամբ. հեշտ է պատճառաբանել                                             |

### Որոշման ծառ

```
                    Do you have quality scores for your proxies?
                    │
        ┌───────────┴───────────┐
        │                       │
       YES                     NO
        │                       │
   Are all proxies             │
   roughly equal                  │
   in quality?                   │
        │                       │
   ┌────┴────┐                  │
   │         │                  │
  YES       NO                Use
   │         │              `random`
   │         │              (even spread
   │         │              builds quality
   │         │              data over time)
   │         │
   │    Use `quality`
   │    (best for
   │    mixed quality)
   │
Use `random`
(spread load
evenly)
```

## Ավտոմատ ձախողման բացառում ձեր սեփական վստահված անձանց համար

1proxy marketplace լողավազանն արդեն ինքնաբերաբար դեգրադացնում է ձախողված վստահված օգտատերերը (տես [վստահված անձի որակի գնահատականները](#proxy-quality-scores) ): Վստահված անձանց համար** դու** ռեեստրում ավելացված ֆոնային առողջության ժամանակացույցը (`src/lib/proxyHealth/scheduler.ts`) ապահովում է նույն «մահացած անդամին ավտոմատ կերպով բացառել շղթայից» վարքագիծը՝ առանց որևէ բան ջնջելու.

```bash
# .env — soft-disable a proxy after 3 consecutive failed probes, re-enable it
# automatically once it starts answering probes again.
PROXY_AUTO_DISABLE=true
PROXY_AUTO_REMOVE_AFTER=3
```

Ինչպես է այն տեղավորվում բազմակողմ վստահված շղթայի մեջ.

1. Ժամանակացույցը զննում է յուրաքանչյուր գրանցված վստահված անձի յուրաքանչյուր `PROXY_HEALTH_INTERVAL_MS` (կանխադրված 10 րոպե, նվազագույնը 1 րոպե):
2. Հետո `PROXY_AUTO_REMOVE_AFTER` հաջորդական** վերջնական** խափանումները (միացման իրական ձախողում — մի ժամանակի ավարտ կամ զոնդային թիրախի սեփական 5xx-ը երբեք չի հաշվվում, տես [վստահված անձի առողջության ստուգում](#proxy-health-checking-v3816) ), վստահված անձի `status` սահմանված է `dead`:
3. `dead` այն կարգավիճակներից մեկն է, որը կենդանի կարգավիճակի զտիչը բացառում է pool/rotation լուծաչափով, ուստի շրջանակի ռոտացիան (կլոր ռոտացիա / պատահական / կպչուն / ուշացում — տե՛ս [Ռոտացիայի ռազմավարության որոշման ծառը](#rotation-strategy-decision-tree) ) անմիջապես դադարեցնում է այդ վստահված անձի տրամադրումը նոր հարցումներին: Լողավազանում ոչ մի այլ վստահված անձ չի տուժում, և ամբողջ լողավազանը երբեք լուռ չի վերադառնում ուղիղ միացմանը — տե՛ս [4-մակարդակ վստահված անձի համակարգի](#4-level-proxy-system) ձախողման պատճառով փակ պահակը:
4. Ժամանակացույցը շարունակում է ստուգել `dead` վստահված անձինք նույն ընդմիջումով: Հաջորդ հաջողված զոնդը `status` վերադարձնում է `active` և այն նորից մտնում է պտտման — ձեռքով նորից ավելացում չի պահանջվում:

Սա միտումնավոր է** ընտրված և ոչ կործանարար** լռելյայնորեն ժամանակացույցը հաշվում և գրանցում է միայն ձախողումները (տես C քաղաքականությունը `decision.ts` ում), և `PROXY_AUTO_DISABLE` երբեք չի ջնջում — տողը, որի համար նախատեսված է առանձին, ավելի ագրեսիվ `PROXY_AUTO_REMOVE` դրոշը: Եթե երկուսն էլ դրված են `true` վրա, `PROXY_AUTO_REMOVE` հաղթում է (հավաստագրված սերվերը, որը պատրաստվում է ջնջվել, չի օգտվում դրանց միջև եղած soft-disable-ից): Տե՛ս [Environment Config](../reference/ENVIRONMENT.md) հղումը փոփոխականների ամբողջական ցանկի համար:
