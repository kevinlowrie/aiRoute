## Зашто користити проксије?

Многи AI провајдери ограничавају приступ према географском региону. Програмери у** Русија, Кина, Иран, Куба, Турска** , а друге земље наилазе на грешке као што су:

```
unsupported_country_region_territory
```

Чак и изван блокираних региона, проксији су корисни за:

| Случај употребе           | Опис                                                                    |
| ------------------------- | ----------------------------------------------------------------------- |
| **Географска обилазница** | Приступите OpenAI, Anthropic, Codex, Copilot из блокираних земаља       |
| **IP ротација**           | Дистрибуирајте захтеве на више IPs да бисте избегли ограничавање брзине |
| **Приватност**            | Сакријте своју праву IP од упстреам провајдера                          |
| **Усклађеност**           | Рутирајте саобраћај кроз одређене јурисдикције                          |
| **Тестирање**             | Симулирајте захтеве из различитих региона                               |

## Подразумевано стање проксија за нове налоге

У** Подешавања → Проки → Глобална конфигурација** , користити** Подразумевано омогући прокси за нове везе** да бисте изабрали почетно стање проксија за новододате налоге провајдера.

Ново подешавање контролише почетно стање проксија новододатих налога провајдера. Не мења постојеће налоге нити замењује глобални прокси прекидач. Његова почетна вредност чува претходно понашање. Искључите га једном да бисте креирали будуће налоге са подразумевано онемогућеним прокси сервером.

Преференце се чувају као `defaultNewConnectionProxyEnabled` кроз постојећа подешавања API. Подразумевано је `true` када се никада не сачува. Чување `false` ступа на снагу за следеће нове налоге без поновног покретања. `POST /api/providers` прихвата опциони строги логички `proxyEnabled`; експлицитни `true` или `false` има предност над подразумеваним креирањем. Изостављање дупликата налога или OAuth поновно повезивање чува сачувано стање тог налога. Појединачни налози се и даље могу омогућити или онемогућити касније.

Селективни трансфери провајдера користе подразумевану инсталацију одредишта за нове налоге и чувају смернице одредишта приликом замене постојећих налога. Прокси преклопници нису преносива поља за пренос. Потпуно обнављање резервне копије и историјска JSON/SQL миграција задржавају постојећу семантику враћања, укључујући сачуване вредности налога и подразумеване вредности застареле шеме; потпуно враћање подешавања такође може да врати ову опцију.

Ово подешавање не додељује прокси нити утврђује да ли је он здрав или у употреби. Стварно рутирање и даље зависи од глобалног прокси прекидача и применљиве конфигурације проксија. Синтетички провајдери без трајног налога, OAuth саобраћај пре креирања налога, environment/system проксији и спољно умрежавање позадинских делова су ван његовог делокруга.

## Прокси систем на 4 нивоа

OmniRoute подржава проки конфигурацију на** четири независна опсега** , решено по приоритету:

```
Priority Resolution Order (highest → lowest):

  1. 🔵 Account/Connection Proxy  →  per API key / OAuth connection
  2. 🟡 Provider Proxy            →  per provider (e.g., all OpenAI traffic)
  3. 🟠 Combo Proxy               →  per combo/routing configuration
  4. 🟢 Global Proxy              →  all traffic, all providers
```

### Како Резолуција функционише

Када OmniRoute пошаље захтев упстреам провајдеру, он позива `resolveProxyForConnectionFromRegistry()` који проверава сваки ниво по реду:

1. **На нивоу налога** — Да ли постоји проки додељен овој специфичној вези ID?
2. **Ниво провајдера** — Да ли је овом провајдеру додељен прокси (нпр. `openai`)?
3. **Глобални ниво** — Да ли је конфигурисан глобални прокси?
4. **Нема проксија** — Директна веза са провајдером.

Први меч побеђује. То значи да можете поставити глобални прокси као резервни, али га заменити за одређене провајдере или везе.

### Шта се проксимира

| Тип саобраћаја        | Прокси? | Напомене                                      |
| --------------------- | ------- | --------------------------------------------- |
| Завршетак ћаскања     | ✅      | Сви `/v1/chat/completions` захтеви            |
| Ембеддингс            | ✅      | `/v1/embeddings`                              |
| Генерисање слике      | ✅      | `/v1/images/generations`                      |
| аудио (TTS/STT)       | ✅      | `/v1/audio/*`                                 |
| OAuth размена токена  | ✅      | Решава `unsupported_country_region_territory` |
| Тестови везе          | ✅      | Дугме „Тестирај везу“ користи прокси          |
| Освежавање токена     | ✅      | Позадинско обнављање OAuth                    |
| Синхронизација модела | ✅      | Списак модела и откриће                       |

## Прокси регистар (CRUD)

Прокси регистар је SQLite табела (`proxy_registry`) која чува све ваше прокси сервере. Сваки прокси има:

| Поље       | Тип     | Опис                                              |
| ---------- | ------- | ------------------------------------------------- |
| `id`       | UUID    | Јединствени идентификатор                         |
| `name`     | Стринг  | Људски читљива етикета                            |
| `type`     | Стринг  | Протокол: `http`, `https`, `socks5`               |
| `host`     | Стринг  | Име хоста проксија или IP                         |
| `port`     | Интегер | Број порта                                        |
| `username` | Стринг  | Аутх корисничко име (шифровано у мировању)        |
| `password` | Стринг  | Лозинка за аутентификацију (шифрована у мировању) |
| `region`   | Стринг  | Ознака географског региона                        |
| `notes`    | Стринг  | Белешке у слободном тексту                        |
| `status`   | Стринг  | `active` или `inactive`                           |
| `source`   | Стринг  | `manual` или `oneproxy`                           |

### Креирање проксија

**Преко контролне табле:**

1. Иди на** Подешавања → проксија**
2. Кликните** Додај прокси**
3. Попуните тип, хост, порт и опционе акредитиве за потврду
4. Сачувај

**Преко API:**

```bash
curl -X POST http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "name": "US Proxy",
    "type": "http",
    "host": "proxy.example.com",
    "port": 8080,
    "username": "user",
    "password": "pass",
    "region": "US"
  }'
```

### Ажурирање проксија

```bash
curl -X PATCH http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "id": "proxy-uuid-here",
    "host": "new-proxy.example.com",
    "port": 9090
  }'
```

> **Напомена:** Акредитиви се чувају осим ако експлицитно не пошаљете непразне замене. Слање празних стрингова за `username`/`password` ће задржати сачуване вредности.

### Брисање проксија

```bash
# Fails if proxy is assigned to any scope
curl -X DELETE "http://localhost:20128/api/v1/management/proxies?id=proxy-uuid"

# Force delete (removes assignments too)
curl -X DELETE "http://localhost:20128/api/v1/management/proxies?id=proxy-uuid&force=1"
```

### Листинг Прокиес

```bash
curl "http://localhost:20128/api/v1/management/proxies?limit=50&offset=0"
```

### Додељивање проксија областима

```bash
# Assign to global scope
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "global", "proxy": {"type":"http","host":"proxy.example.com","port":8080}}'

# Assign to a specific provider
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "provider", "id": "openai", "proxy": {"type":"socks5","host":"socks.example.com","port":1080}}'

# Assign to a specific connection/key
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "key", "id": "connection-uuid", "proxy": {"type":"http","host":"key-proxy.com","port":3128}}'
```

### Решавање ефективног проксија

Проверите који прокси би се користио за дату везу:

```bash
curl "http://localhost:20128/api/settings/proxy?resolve=connection-uuid"
```

Враћа разрешени прокси са његовим нивоом (`account`, `provider` или `global`) и извором.

### Булк Ассигнмент

Доделите један прокси за више провајдера или веза одједном:

```bash
curl -X POST http://localhost:20128/api/v1/management/proxies/bulk-assign \
  -H "Content-Type: application/json" \
  -d '{
    "scope": "provider",
    "scopeIds": ["openai", "anthropic", "codex"],
    "proxyId": "proxy-uuid"
  }'
```

### Import/Export

Заступници су укључени у**Backup/Restore** система. Када извезете своју OmniRoute конфигурацију:

1. Иди на** Контролна табла → Сеттингс → Бацкуп**
2. Кликните** Извоз** — проки регистар и задаци су укључени
3. Да бисте вратили, кликните** Увоз** и отпремите датотеку резервне копије

Прокси регистар такође подржава** упсерт би хост + порт** — ако увезете проки који већ постоји (исти хост и порт), он се ажурира уместо да прави дупликат.

### Миграција наслеђа

Ако сте конфигурисали проксије у старијој верзији (пре-регистри), OmniRoute их аутоматски мигрира:

```
Legacy key_value store → proxy_registry + proxy_assignments
```

Ово се дешава једном приликом првог покретања након надоградње. Користите `migrateLegacyProxyConfigToRegistry({ force: true })` за поновно покретање.

## 1проки Фрее Проки Маркетплаце

> 🆕** Приложио [@оии77](https://github.com/oyi77)** — PR [#1847](https://github.com/diegosouzapw/OmniRoute/pull/1847) (Издање [#1788](https://github.com/diegosouzapw/OmniRoute/issues/1788) )

OmniRoute се интегрише са** [1проки](https://1proxy-api.aitradepulse.com)** платформа заједнице којој треба омогућити приступ** стотине бесплатних, потврђених проксија** из целог света. Ово је савршено за кориснике који немају сопствену прокси инфраструктуру.

### Како то ради

```
┌─────────────┐     Sync      ┌─────────────────┐    Rotate     ┌──────────┐
│  1proxy API │ ────────────▶ │  proxy_registry  │ ────────────▶ │ Provider │
│  (external) │   up to 500   │  source=oneproxy │  by quality   │   API    │
└─────────────┘    proxies    └─────────────────┘               └──────────┘
```

1. **Синц** — OmniRoute преузима валидиране проксије из 1проки API
2. **Продавница** — Проксији се чувају у истој `proxy_registry` табели са `source = 'oneproxy'`
3. **Филтер** — Филтрирај по протоколу, земљи, оцени квалитета
4. **Ротирај** — Изаберите најбољи прокси користећи квалитетне, насумичне или секвенцијалне стратегије
5. **Ауто-деграде** — Неуспели проксији добијају смањење оцене квалитета; испод прага → означен као неактиван

### Синхронизација проксија

**Преко контролне табле:**

1. Иди на** Подешавања → 1проки** таб
2. Кликните** „Синхронизуј сада“**
3. Погледајте статистику: укупни проксији, број активних, просечан квалитет, подела по земљама

**Преко API:**

```bash
# Trigger sync
curl -X POST http://localhost:20128/api/settings/oneproxy \
  -H "Content-Type: application/json" \
  -d '{}'

# Response:
# { "success": true, "added": 127, "updated": 45, "failed": 2, "total": 172 }
```

### Филтрирање проксија

```bash
# Filter by protocol
curl "http://localhost:20128/api/settings/oneproxy?protocol=socks5"

# Filter by country
curl "http://localhost:20128/api/settings/oneproxy?countryCode=US"

# Filter by minimum quality score
curl "http://localhost:20128/api/settings/oneproxy?minQuality=80"

# Combine filters
curl "http://localhost:20128/api/settings/oneproxy?protocol=http&countryCode=DE&minQuality=70"
```

### Оцене квалитета проксија

Сваки 1проки проки долази са метаподацима:

| Поље            | Опис                                          |
| --------------- | --------------------------------------------- |
| `qualityScore`  | 0-100 оцена од 1проки валидације              |
| `latencyMs`     | Измерено кашњење мреже                        |
| `anonymity`     | `transparent`, `anonymous` или `elite`        |
| `googleAccess`  | Да ли прокси може да приступи Google услугама |
| `countryCode`   | Двословни ISO код земље                       |
| `lastValidated` | Временска ознака последње валидације          |

Оцене квалитета се динамички прилагођавају:

- **Неуспели захтеви** смањити резултат за 10 поена
- **Резултат пада на ≤ 10** → проки је означен `inactive`
- Неактивни проксији су искључени из ротације

### Стратегије ротације

```bash
# Rotate by quality (best proxy first) — default
curl -X POST http://localhost:20128/api/settings/oneproxy/rotate \
  -H "Content-Type: application/json" \
  -d '{"strategy": "quality"}'

# Random rotation
curl -X POST http://localhost:20128/api/settings/oneproxy/rotate \
  -d '{"strategy": "random"}'

# Sequential (least recently validated first)
curl -X POST http://localhost:20128/api/settings/oneproxy/rotate \
  -d '{"strategy": "sequential"}'
```

### Прекидач

1проки синхронизација има уграђени прекидач:

- После** 5 узастопних грешака у синхронизацији** , даљи покушаји синхронизације су блокирани
- Ресетујте помоћу: `resetOneproxyCircuitBreaker()` или поново покрените сервер
- Статус синхронизације је доступан на `GET /api/settings/oneproxy?action=status`

### Брисање 1проки проксија

```bash
# Delete a single 1proxy proxy
curl -X DELETE "http://localhost:20128/api/settings/oneproxy?id=proxy-uuid"

# Clear ALL 1proxy proxies (manual proxies are untouched)
curl -X DELETE "http://localhost:20128/api/settings/oneproxy?clearAll=1"
```

## Анти-Детецтион & Стеалтх

OmniRoute не усмерава само саобраћај кроз прокси — већ чини да саобраћај изгледа легитимно:

### TLS Превара отиска прста

Користи `wreq-js` за генерисање TLS отисака прстију сличних претраживачу, заобилазећи системе за откривање ботова који означавају TLS руковања која нису у претраживачу.

### CLI Подударање отиска прста

Тхе**CLI Пребацивање отиска прста** (`Settings → Security`) мења HTTP заглавља и JSON поља тела тако да одговарају тачном потпису изворних CLI бинарних датотека (Claude код, Codex итд.). Ово ради** на врху** прокси:

```
Your IP (blocked) → Proxy IP (US) → Provider API
                    + TLS spoof
                    + CLI fingerprint
```

Добијате обоје**IP маскинг** и** захтевати аутентичност** истовремено.

### Проки IP Пресерватион

Значке означене бојама на контролној табли показују који је ниво проксија активан:

| Значка | Ниво      | Значење                                        |
| ------ | --------- | ---------------------------------------------- |
| 🟢     | Глобал    | Сав саобраћај иде преко овог проксија          |
| 🟡     | Провајдер | Само саобраћај овог провајдера је прокси       |
| 🔵     | Веза      | Овај специфични key/account користи овај проки |

Значка такође приказује решени прокси IP ради верификације.

## Решавање проблема

### "SOCKS5 проки је онемогућен"

Поставите `ENABLE_SOCKS5_PROXY=true` у своју `.env` датотеку и поново покрените.

### грешке „утичнице прекине“ преко проксија

Ово је нормално са јефтиним проксијима који испуштају неактивне везе. OmniRoute већ обрађује ово тако што:

- Онемогућавање одржавања на прокси везама (`keepAliveTimeout: 1`)
- Онемогућавање цевовода (`pipelining: 0`)
- Кеширање диспечера да би се избегло поновљено руковање

Ако се настави, покушајте са другим прокси сервером или користите функцију ротације 1проксија.

### "унсуппортед_цоунтри_регион_территори" током OAuth

Проверите да ли је прокси конфигурисан** пре** покретање OAuth тока. OmniRoute усмерава OAuth размену токена преко конфигурисаног проксија. Прво поставите глобални прокси или проки на нивоу провајдера, а затим се повежите.

### Прокси се не користи

Проверите редослед решавања:

1. Проверите са `GET /api/settings/proxy?resolve=your-connection-id`
2. Проверите да ли је прокси `status` `active` (не `inactive`)
3. Уверите се да опсег доделе проксија одговара вашој вези

### 1прокси синхронизација није успела

Проверите статус синхронизације:

```bash
curl "http://localhost:20128/api/settings/oneproxy?action=status"
```

Ако `consecutiveFailures >= 5`, прекидач се откачио. Поново покрените сервер да бисте га ресетовали или сачекајте ручно ресетовање.

## Провера здравља проксија (в3.8.16 +)

OmniRoute'с** проки фаст-фаил** механизам (`src/lib/proxyHealth.ts`) открива мртве проксије у < 2с путем брзе провере TCP везе, а затим** кешира резултат** да би се избегли додатни трошкови по захтеву.

### Како то ради

```
Request ──▶ ProxyHealthCache.get(url)
             │
             ├─ Cache hit + fresh?  ──▶ return cached status
             │
             └─ Cache miss / stale?  ──▶ TCP connect to host:port
                                          (timeout: FAST_FAIL_TIMEOUT_MS)
                                          ──▶ cache for HEALTH_CACHE_TTL_MS
                                          ──▶ return result
```

Без овога, мртви прокси би блокирао сваки захтев за пун `PROXY_TIMEOUT_MS` (подразумевано 30с) пре него што не успе.

### Променљиве окружења које се могу подешавати

| Променљива                   | Подразумевано | Сврха                                                 |
| ---------------------------- | ------------- | ----------------------------------------------------- |
| `PROXY_FAST_FAIL_TIMEOUT_MS` | `2000`        | TCP временско ограничење везе по здравственој провери |
| `PROXY_HEALTH_CACHE_TTL_MS`  | `30000`       | Колико дуго се здравствени резултат кешује            |

**Препоручене вредности:**

| Сценарио                    | Фаст-фаил тимеоут | Цацхе TTL | Реасонинг                                                                                |
| --------------------------- | ----------------- | --------- | ---------------------------------------------------------------------------------------- |
| Високо пропусни API гејтвеј | 1500мс            | 60000мс   | Агресивни, брзи, дужи кеш за смањење провера                                             |
| Гео-дистрибуирани чворови   | 3000мс            | 15000мс   | Споријим мрежама је потребно више времена; краћа кеш меморија за брзо прелазак на грешку |
| Дев / тестирање             | 1000мс            | 10000мс   | Брза итерација на локалним проксијима                                                    |
| Стеалтх / анти-детекција    | 2500мс            | 45000мс   | Избегавајте брзо испитивање које би могло да изазове ограничења брзине                   |

### Провера здравља проксија

```ts
import { getAllProxyHealthStatuses, invalidateProxyHealth } from "omniroute/proxyHealth";

const statuses = getAllProxyHealthStatuses();
for (const s of statuses) {
  console.log(`${s.proxyUrl} → healthy=${s.healthy}, stale=${s.stale}`);
}

// Force re-check a specific proxy
invalidateProxyHealth("http://user:pass@203.0.113.7:8080");
```

Ознака `stale` је `true` када је унос у кеш прекорачио `HEALTH_CACHE_TTL_MS` и следећи захтев ће покренути нову проверу.

### Подразумеване вредности типа по проксију

Провера здравља користи разумне подразумеване вредности засноване на URL шеми:

| Шема                       | Подразумевани порт |
| -------------------------- | ------------------ |
| `http://`                  | 8080               |
| `https://`                 | 443                |
| `socks5://` / `socks5h://` | 1080               |

Прилагођени портови у URL (`http://host:9999`) увек имају предност над подразумеваном шемом.

## Аналитика проксија и могућност посматрања

OmniRoute прати употребу по проксију да би помогао оператерима да дијагностикују обрасце рутирања, скокове кашњења и понављајуће грешке.

### Шта се прати

За сваки захтев преко конфигурисаног проксија, OmniRoute бележи:

| Метриц       | Опис                                                               |
| ------------ | ------------------------------------------------------------------ |
| `proxy_url`  | Потпуни прокси URL (са маскираним акредитивима за аутентификацију) |
| `provider`   | Упстреам провајдер ID (опенаи, антхропиц, итд.)                    |
| `latency_ms` | Укупно време повратног пута укључујући руковање проксија           |
| `connect_ms` | само време повезивања TCP                                          |
| `status`     | HTTP статусни код од узводно                                       |
| `error`      | Класа грешке ако захтев није успео                                 |
| `timestamp`  | ISO 8601 UTC                                                       |

### Приступ подацима

```bash
# Recent proxy events
curl -H "Authorization: Bearer $OMNIROUTE_KEY" \
  "http://localhost:20128/api/usage/proxy-logs?limit=100"
```

Права крајња тачка је `/api/usage/proxy-logs` (погледајте `src/app/api/usage/proxy-logs/route.ts`). Ова крајња тачка подржава:

- `GET /api/usage/proxy-logs` — преузима проки дневнике
- `DELETE /api/usage/proxy-logs` — обришите све прокси евиденције

Збирна статистика се може тражити директно из `proxy_logs` табеле преко SQL ако је потребно. Контролна табла UI може да нуди збирне приказе.

### Цоммон Паттернс

**Откријте проки који се креће** (наизменично између success/failure):

```sql
SELECT proxy_url,
       COUNT(*) AS total,
       SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) AS errors,
       ROUND(100.0 * SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) / COUNT(*), 1) AS error_pct
FROM proxy_logs
WHERE timestamp > datetime('now', '-1 hour')
GROUP BY proxy_url
HAVING error_pct > 5
ORDER BY error_pct DESC;
```

**Пронађите споре проксије** (кашњење п95 > 2с):

```sql
WITH ranked AS (
  SELECT proxy_url, latency_ms,
         PERCENT_RANK() OVER (PARTITION BY proxy_url ORDER BY latency_ms) AS pct
  FROM proxy_logs
  WHERE timestamp > datetime('now', '-24 hour')
)
SELECT proxy_url, latency_ms
FROM ranked
WHERE pct >= 0.95
ORDER BY latency_ms DESC;
```

## Стабло одлучивања о стратегији ротације

Када је више проксија додељено опсегу, OmniRoute користи а** стратегија ротације** да изаберете који ћете користити за сваки захтев. Стратегија је конфигурисана на нивоу опсега (глобално, по добављачу, по налогу, по комбинацији).

### Доступне стратегије

| Стратегија                | Када користити                               | Компромис                                                              |
| ------------------------- | -------------------------------------------- | ---------------------------------------------------------------------- |
| `quality` (подразумевано) | Производња са проксијима мешовитог квалитета | Фаворизира проксије високе оцене; могу гладовати оне са ниским оценама |
| `random`                  | Дистрибуција оптерећења, приватност          | Равномерна дистрибуција; игнорише сигнале квалитета                    |
| `sequential`              | Отклањање грешака, детерминистичко тестирање | Циклуси кроз проксије по реду; лако расуђивати                         |

## Аутоматско искључивање грешака за ваше сопствене проксије

Група 1проки тржишта већ сама аутоматски деградира неуспеле прокси сервере (погледајте [Оцене квалитета проксија](#proxy-quality-scores) ). За пуномоћнике** ти** додат у регистар, планер здравља у позадини (`src/lib/proxyHealth/scheduler.ts`) обезбеђује исто понашање „аутоматски искључи мртвог члана из ланца“, без брисања било чега:

```bash
# .env — soft-disable a proxy after 3 consecutive failed probes, re-enable it
# automatically once it starts answering probes again.
PROXY_AUTO_DISABLE=true
PROXY_AUTO_REMOVE_AFTER=3
```

Како се уклапа у мулти-прокси ланац:

1. Планер испитује сваки регистровани прокси сваки `PROXY_HEALTH_INTERVAL_MS` (подразумевано 10 мин; минимум 1 мин).
2. После `PROXY_AUTO_REMOVE_AFTER` узастопно** коначан** грешке (стварни неуспех везе — а тимеоут или сопствени 5кк циљне сонде се никада не рачунају, погледајте [Провера здравља проксија](#proxy-health-checking-v3816) ), `status` проксија је подешен на `dead`.
3. `dead` је један од статуса који филтер статуса живог који користи pool/rotation резолуција искључује, тако да ротација опсега (окружно / насумично / лепљиво / латенција — види [Стабло одлучивања стратегије ротације](#rotation-strategy-decision-tree) ) одмах престаје да предаје тај прокси новим захтевима. Ниједан други прокси сервер у групи није погођен, а цео скуп се никада не враћа тихо на директну везу — види [4-нивоа прокси система](#4-level-proxy-system) за заштиту од отказа.
4. Планер наставља да испитује `dead` проксије у истом интервалу. Следећа успешна сонда окреће `status` назад на `active` и поново улази у ротацију — није потребно ручно поновно додавање.

Ово је намерно** опт-ин и недеструктивни** : подразумевано, планер само броји и бележи грешке (погледајте политику Ц у `decision.ts`), а `PROXY_AUTO_DISABLE` никада не брише ред — за шта је посебна, агресивнија `PROXY_AUTO_REMOVE` заставица. Ако су оба постављена на `true`, `PROXY_AUTO_REMOVE` побеђује (прокси који ће бити обрисан нема користи за софт-дисабле између). Погледајте референцу [Енвиронмент Цонфиг](../reference/ENVIRONMENT.md) за комплетну листу променљивих.
