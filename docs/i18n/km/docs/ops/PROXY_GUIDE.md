## ហេតុអ្វីត្រូវប្រើប្រូកស៊ី?

អ្នកផ្តល់សេវា AI ជាច្រើនដាក់កម្រិតការចូលប្រើប្រាស់តាមតំបន់ភូមិសាស្ត្រ។ អ្នកអភិវឌ្ឍន៍នៅក្នុង** រុស្ស៊ី ចិន អ៊ីរ៉ង់ គុយបា តួកគី** ហើយប្រទេសផ្សេងទៀតជួបប្រទះបញ្ហាដូចជា៖

```
unsupported_country_region_territory
```

សូម្បីតែនៅខាងក្រៅតំបន់ដែលត្រូវបានរារាំងក៏ដោយ ប្រូកស៊ីមានប្រយោជន៍សម្រាប់៖

| ប្រើករណី                | ការពិពណ៌នា                                                        |
| ----------------------- | ----------------------------------------------------------------- |
| **ផ្លូវវាងភូមិសាស្ត្រ** | ចូលប្រើ OpenAI, Anthropic, Codex, Copilot ពីប្រទេសដែលបានទប់ស្កាត់ |
| **ការបង្វិល IP**        | ចែកចាយសំណើនៅទូទាំង IPs ច្រើន ដើម្បីជៀសវាងការកំណត់អត្រា            |
| **ឯកជនភាព**             | លាក់ IP ពិតប្រាកដរបស់អ្នកពីអ្នកផ្តល់សេវាចរន្ត                     |
| **ការអនុលោមតាម**        | ចរាចរណ៍ផ្លូវឆ្លងកាត់ដែនសមត្ថកិច្ចជាក់លាក់                         |
| **ការធ្វើតេស្ត**        | ក្លែងធ្វើសំណើពីតំបន់ផ្សេងៗ                                        |

## ស្ថានភាពប្រូកស៊ីលំនាំដើមសម្រាប់គណនីថ្មី។

ក្នុង** ការកំណត់ → ប្រូកស៊ី → ការកំណត់រចនាសម្ព័ន្ធសកល** , ប្រើ** បើកប្រូកស៊ីតាមលំនាំដើមសម្រាប់ការតភ្ជាប់ថ្មី។** ដើម្បីជ្រើសរើសស្ថានភាពប្រូកស៊ីដំបូងនៃគណនីអ្នកផ្តល់សេវាដែលបានបន្ថែមថ្មី។

ការកំណត់ថ្មីគ្រប់គ្រងស្ថានភាពប្រូកស៊ីដំបូងនៃគណនីអ្នកផ្តល់សេវាដែលបានបន្ថែមថ្មី។ វាមិនផ្លាស់ប្តូរគណនីដែលមានស្រាប់ ឬជំនួសកុងតាក់ប្រូកស៊ីសកលទេ។ តម្លៃដំបូងរបស់វារក្សាឥរិយាបថពីមុន។ បិទវាម្តងដើម្បីបង្កើតគណនីនាពេលអនាគតជាមួយប្រូកស៊ីបិទតាមលំនាំដើម។

ចំណូលចិត្តត្រូវបានរក្សាទុកជា `defaultNewConnectionProxyEnabled` តាមរយៈការកំណត់ដែលមានស្រាប់ API។ វាកំណត់លំនាំដើមទៅ `true` នៅពេលដែលមិនដែលរក្សាទុក។ ការរក្សាទុក `false` មានប្រសិទ្ធភាពសម្រាប់គណនីថ្មីជាបន្តបន្ទាប់ដោយមិនចាំបាច់ចាប់ផ្តើមឡើងវិញ។ `POST /api/providers` ទទួលយក `proxyEnabled` boolean ដ៏តឹងរឹងស្រេចចិត្តមួយ; `true` ឬ `false` ច្បាស់លាស់ មានអាទិភាពលើលំនាំដើមនៃការបង្កើត។ ការខកខាននៅលើគណនីស្ទួន ឬ OAuth ភ្ជាប់ឡើងវិញរក្សាស្ថានភាពរក្សាទុកគណនីនោះ។ គណនីបុគ្គលនៅតែអាចបើក ឬបិទនៅពេលក្រោយ។

ការផ្ទេរអ្នកផ្តល់សេវាដែលបានជ្រើសរើសប្រើលំនាំដើមនៃការដំឡើងគោលដៅសម្រាប់គណនីថ្មី និងរក្សាគោលការណ៍ទិសដៅនៅពេលជំនួសគណនីដែលមានស្រាប់។ បិទបើកប្រូកស៊ីមិនមែនជាកន្លែងផ្ទេរចល័តទេ។ ការស្ដារការបម្រុងទុកពេញលេញ និងការផ្ទេរទិន្នន័យ JSON/SQL ជាប្រវត្តិសាស្ត្ររក្សានូវអត្ថន័យនៃការស្ដារឡើងវិញដែលមានស្រាប់របស់ពួកគេ រួមទាំងតម្លៃគណនីដែលបានរក្សាទុក និងលំនាំដើមគ្រោងការណ៍កេរ្តិ៍ដំណែល។ ការស្ដារការកំណត់ពេញលេញក៏អាចស្ដារចំណូលចិត្តនេះឡើងវិញផងដែរ។

ចំណូលចិត្តនេះមិនកំណត់ប្រូកស៊ី ឬកំណត់ថាវាមានសុខភាពល្អ ឬកំពុងប្រើប្រាស់ទេ។ ការកំណត់ផ្លូវពិតប្រាកដនៅតែអាស្រ័យលើកុងតាក់ប្រូកស៊ីសកល និងការកំណត់រចនាសម្ព័ន្ធប្រូកស៊ីដែលអាចអនុវត្តបាន។ អ្នកផ្តល់សេវាសំយោគដោយគ្មានគណនីបន្ត ចរាចរណ៍ OAuth មុនពេលបង្កើតគណនី ប្រូកស៊ី environment/system និងបណ្តាញរបស់ backend ខាងក្រៅគឺនៅក្រៅវិសាលភាពរបស់វា។

## ប្រព័ន្ធប្រូកស៊ី 4 កម្រិត

OmniRoute គាំទ្រការកំណត់រចនាសម្ព័ន្ធប្រូកស៊ីនៅ** វិសាលភាពឯករាជ្យចំនួនបួន** ដោះស្រាយតាមលំដាប់អាទិភាព៖

```
Priority Resolution Order (highest → lowest):

  1. 🔵 Account/Connection Proxy  →  per API key / OAuth connection
  2. 🟡 Provider Proxy            →  per provider (e.g., all OpenAI traffic)
  3. 🟠 Combo Proxy               →  per combo/routing configuration
  4. 🟢 Global Proxy              →  all traffic, all providers
```

### របៀបដែលដំណោះស្រាយដំណើរការ

នៅពេលដែល OmniRoute ផ្ញើសំណើទៅកាន់អ្នកផ្តល់សេវាខាងលើ វាហៅ `resolveProxyForConnectionFromRegistry()` ដែលពិនិត្យកម្រិតនីមួយៗតាមលំដាប់លំដោយ៖

1. **កម្រិតគណនី** — តើមានប្រូកស៊ីដែលត្រូវបានកំណត់ទៅនឹងការតភ្ជាប់ជាក់លាក់នេះ ID ទេ?
2. **កម្រិតអ្នកផ្តល់សេវា** — តើមានប្រូកស៊ីដែលត្រូវបានផ្តល់ឱ្យអ្នកផ្តល់សេវានេះ (ឧ. `openai`) ទេ?
3. **កម្រិតសកល** — តើមានប្រូកស៊ីសកលដែលបានកំណត់រចនាសម្ព័ន្ធទេ?
4. **គ្មានប្រូកស៊ី** — ការតភ្ជាប់ដោយផ្ទាល់ទៅអ្នកផ្តល់សេវា។

ការប្រកួតដំបូងឈ្នះ។ នេះមានន័យថាអ្នកអាចកំណត់ប្រូកស៊ីសកលជាការជំនួស ប៉ុន្តែបដិសេធវាសម្រាប់អ្នកផ្តល់សេវា ឬការតភ្ជាប់ជាក់លាក់។

## ការចុះឈ្មោះប្រូកស៊ី (CRUD)

បញ្ជីឈ្មោះប្រូកស៊ីគឺជាតារាង SQLite (`proxy_registry`) ដែលរក្សាទុកប្រូកស៊ីរបស់អ្នកទាំងអស់។ ប្រូកស៊ីនីមួយៗមាន៖

| វាល        | ប្រភេទ    | ការពិពណ៌នា                                         |
| ---------- | --------- | -------------------------------------------------- |
| `id`       | UUID      | ឧបករណ៍កំណត់អត្តសញ្ញាណតែមួយគត់                      |
| `name`     | ខ្សែអក្សរ | ស្លាកដែលអាចអានបានរបស់មនុស្ស                        |
| `type`     | ខ្សែអក្សរ | ពិធីការ៖ `http`, `https`, `socks5`                 |
| `host`     | ខ្សែអក្សរ | ឈ្មោះម៉ាស៊ីនប្រូកស៊ី ឬ IP                          |
| `port`     | ចំនួនគត់  | លេខច្រក                                            |
| `username` | ខ្សែអក្សរ | ឈ្មោះអ្នកប្រើដែលបានផ្ទៀងផ្ទាត់ (បានអ៊ិនគ្រីបនៅសល់) |
| `password` | ខ្សែអក្សរ | ពាក្យសម្ងាត់ផ្ទៀងផ្ទាត់ (អ៊ិនគ្រីបនៅពេលសម្រាក)     |
| `region`   | ខ្សែអក្សរ | ស្លាកតំបន់ភូមិសាស្ត្រ                              |
| `notes`    | ខ្សែអក្សរ | កំណត់ចំណាំអត្ថបទឥតគិតថ្លៃ                          |
| `status`   | ខ្សែអក្សរ | `active` ឬ `inactive`                              |
| `source`   | ខ្សែអក្សរ | `manual` ឬ `oneproxy`                              |

### ការបង្កើតប្រូកស៊ី

**តាមរយៈផ្ទាំងគ្រប់គ្រង៖**

1. ទៅ** ការកំណត់ →**
2. ចុច** បន្ថែមប្រូកស៊ី**
3. បំពេញប្រភេទ ម៉ាស៊ីន ច្រក និងព័ត៌មានបញ្ជាក់អត្តសញ្ញាណជាជម្រើស
4. រក្សាទុក

**តាមរយៈ API:**

```bash
curl -X POST http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "name": "US Proxy",
    "type": "http",
    "host": "proxy.example.com",
    "port": 8080,
    "username": "user",
    "password": "pass",
    "region": "US"
  }'
```

### ការធ្វើបច្ចុប្បន្នភាពប្រូកស៊ី

```bash
curl -X PATCH http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "id": "proxy-uuid-here",
    "host": "new-proxy.example.com",
    "port": 9090
  }'
```

> **ចំណាំ៖** លិខិតសម្គាល់ត្រូវបានរក្សាទុក លុះត្រាតែអ្នកផ្ញើការជំនួសដោយមិនទទេ។ ការផ្ញើខ្សែអក្សរទទេសម្រាប់ `username`/`password` នឹងរក្សាតម្លៃដែលបានរក្សាទុក។

### ការលុបប្រូកស៊ី

```bash
# Fails if proxy is assigned to any scope
curl -X DELETE "http://localhost:20128/api/v1/management/proxies?id=proxy-uuid"

# Force delete (removes assignments too)
curl -X DELETE "http://localhost:20128/api/v1/management/proxies?id=proxy-uuid&force=1"
```

### ការចុះបញ្ជីប្រូកស៊ី

```bash
curl "http://localhost:20128/api/v1/management/proxies?limit=50&offset=0"
```

### ការចាត់តាំងប្រូកស៊ីទៅវិសាលភាព

```bash
# Assign to global scope
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "global", "proxy": {"type":"http","host":"proxy.example.com","port":8080}}'

# Assign to a specific provider
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "provider", "id": "openai", "proxy": {"type":"socks5","host":"socks.example.com","port":1080}}'

# Assign to a specific connection/key
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "key", "id": "connection-uuid", "proxy": {"type":"http","host":"key-proxy.com","port":3128}}'
```

### ការដោះស្រាយប្រូកស៊ីដែលមានប្រសិទ្ធភាព

ពិនិត្យមើលប្រូកស៊ីមួយណាដែលត្រូវប្រើសម្រាប់ការតភ្ជាប់ដែលបានផ្តល់ឱ្យ៖

```bash
curl "http://localhost:20128/api/settings/proxy?resolve=connection-uuid"
```

ត្រឡប់ប្រូកស៊ីដែលបានដោះស្រាយជាមួយនឹងកម្រិតរបស់វា (`account`, `provider`, ឬ `global`) និងប្រភព។

### កិច្ចការច្រើន

កំណត់ប្រូកស៊ីមួយទៅអ្នកផ្តល់សេវា ឬការតភ្ជាប់ច្រើនក្នុងពេលតែមួយ៖

```bash
curl -X POST http://localhost:20128/api/v1/management/proxies/bulk-assign \
  -H "Content-Type: application/json" \
  -d '{
    "scope": "provider",
    "scopeIds": ["openai", "anthropic", "codex"],
    "proxyId": "proxy-uuid"
  }'
```

### Import/Export

ប្រូកស៊ីត្រូវបានរួមបញ្ចូលនៅក្នុង**Backup/Restore** ប្រព័ន្ធ។ នៅពេលអ្នកនាំចេញការកំណត់ OmniRoute របស់អ្នក៖

1. ទៅ** ផ្ទាំងគ្រប់គ្រង → ការកំណត់ → ការបម្រុងទុក**
2. ចុច** នាំចេញ** — ប្រូកស៊ីចុះបញ្ជី និងកិច្ចការត្រូវបានរួមបញ្ចូល
3. ដើម្បីស្តារ សូមចុច** នាំចូល** ហើយផ្ទុកឡើងឯកសារបម្រុងទុក

ការចុះឈ្មោះប្រូកស៊ីក៏គាំទ្រផងដែរ។** បញ្ចូលដោយច្រក + ម៉ាស៊ីន** — ប្រសិនបើអ្នកនាំចូលប្រូកស៊ីដែលមានរួចហើយ (ម៉ាស៊ីន និងច្រកដូចគ្នា) វាធ្វើបច្ចុប្បន្នភាពជំនួសឱ្យការបង្កើតស្ទួន។

### ការធ្វើចំណាកស្រុកចាស់

ប្រសិនបើអ្នកបានកំណត់រចនាសម្ព័ន្ធប្រូកស៊ីនៅក្នុងកំណែចាស់ (ការចុះឈ្មោះជាមុន) OmniRoute ផ្ទេរពួកវាដោយស្វ័យប្រវត្តិ៖

```
Legacy key_value store → proxy_registry + proxy_assignments
```

វាកើតឡើងម្តងនៅពេលចាប់ផ្តើមដំបូងបន្ទាប់ពីការធ្វើឱ្យប្រសើរឡើង។ ប្រើ `migrateLegacyProxyConfigToRegistry({ force: true })` ដើម្បីដំណើរការឡើងវិញ។

## 1proxy ទីផ្សារប្រូកស៊ីឥតគិតថ្លៃ

> 🆕** រួមចំណែកដោយ [@oyi77](https://github.com/oyi77)** — PR [#1847](https://github.com/diegosouzapw/OmniRoute/pull/1847) (បញ្ហា [#1788](https://github.com/diegosouzapw/OmniRoute/issues/1788) )

OmniRoute រួមបញ្ចូលជាមួយ** [ប្រូកស៊ី 1](https://1proxy-api.aitradepulse.com)** វេទិកាសហគមន៍ដើម្បីផ្តល់សិទ្ធិចូលប្រើ** ប្រូកស៊ីដែលមានសុពលភាពរាប់រយឥតគិតថ្លៃ** ពីជុំវិញពិភពលោក។ នេះគឺល្អឥតខ្ចោះសម្រាប់អ្នកប្រើប្រាស់ដែលមិនមានហេដ្ឋារចនាសម្ព័ន្ធប្រូកស៊ីផ្ទាល់ខ្លួនរបស់ពួកគេ។

### របៀបដែលវាដំណើរការ

```
┌─────────────┐     Sync      ┌─────────────────┐    Rotate     ┌──────────┐
│  1proxy API │ ────────────▶ │  proxy_registry  │ ────────────▶ │ Provider │
│  (external) │   up to 500   │  source=oneproxy │  by quality   │   API    │
└─────────────┘    proxies    └─────────────────┘               └──────────┘
```

1. **ធ្វើសមកាលកម្ម** — OmniRoute ទាញយកប្រូកស៊ីដែលមានសុពលភាពពី 1proxy API
2. **ហាង** — ប្រូកស៊ីត្រូវបានរក្សាទុកក្នុងតារាង `proxy_registry` ដូចគ្នាជាមួយ `source = 'oneproxy'`
3. **តម្រង** — ត្រងតាមពិធីការ ប្រទេស ពិន្ទុគុណភាព
4. **បង្វិល** — ជ្រើសរើសប្រូកស៊ីដ៏ល្អបំផុតដោយប្រើយុទ្ធសាស្រ្តគុណភាព ចៃដន្យ ឬតាមលំដាប់លំដោយ
5. **បន្ទាបខ្លួនដោយស្វ័យប្រវត្តិ** — ប្រូកស៊ីដែលបរាជ័យទទួលបានពិន្ទុគុណភាពរបស់ពួកគេត្រូវបានកាត់បន្ថយ។ នៅក្រោមកម្រិត → ត្រូវបានសម្គាល់ថាអសកម្ម

### ធ្វើសមកាលកម្មប្រូកស៊ី

**តាមរយៈផ្ទាំងគ្រប់គ្រង៖**

1. ទៅ** ការកំណត់ → 1proxy** ផ្ទាំង
2. ចុច** "ធ្វើសមកាលកម្មឥឡូវនេះ"**
3. មើលស្ថិតិ៖ ប្រូកស៊ីសរុប ចំនួនសកម្ម គុណភាពមធ្យម ការវិភាគតាមប្រទេស

**តាមរយៈ API:**

```bash
# Trigger sync
curl -X POST http://localhost:20128/api/settings/oneproxy \
  -H "Content-Type: application/json" \
  -d '{}'

# Response:
# { "success": true, "added": 127, "updated": 45, "failed": 2, "total": 172 }
```

### ត្រងប្រូកស៊ី

```bash
# Filter by protocol
curl "http://localhost:20128/api/settings/oneproxy?protocol=socks5"

# Filter by country
curl "http://localhost:20128/api/settings/oneproxy?countryCode=US"

# Filter by minimum quality score
curl "http://localhost:20128/api/settings/oneproxy?minQuality=80"

# Combine filters
curl "http://localhost:20128/api/settings/oneproxy?protocol=http&countryCode=DE&minQuality=70"
```

### ពិន្ទុគុណភាពប្រូកស៊ី

ប្រូកស៊ី 1proxy នីមួយៗភ្ជាប់មកជាមួយទិន្នន័យមេតា៖

| វាល             | ការពិពណ៌នា                                   |
| --------------- | -------------------------------------------- |
| `qualityScore`  | ការវាយតម្លៃ 0-100 ពី 1 សុពលភាពប្រូកស៊ី       |
| `latencyMs`     | ភាពយឺតនៃបណ្តាញដែលបានវាស់វែង                  |
| `anonymity`     | `transparent`, `anonymous`, ឬ `elite`        |
| `googleAccess`  | ថាតើប្រូកស៊ីអាចចូលប្រើសេវាកម្ម Google ដែរឬទេ |
| `countryCode`   | លេខកូដប្រទេស ISO ពីរអក្សរ                    |
| `lastValidated` | ត្រាពេលវេលានៃការបញ្ជាក់ចុងក្រោយ              |

ពិន្ទុគុណភាពត្រូវបានកែសម្រួលថាមវន្ត៖

- **សំណើដែលបរាជ័យ** កាត់បន្ថយពិន្ទុ ១០ ពិន្ទុ
- **ពិន្ទុធ្លាក់ចុះដល់ ≤ 10** → ប្រូកស៊ីត្រូវបានសម្គាល់ `inactive`
- ប្រូកស៊ីអសកម្មត្រូវបានដកចេញពីការបង្វិល

## ការប្រឆាំងការរកឃើញ និងការបំបាំងកាយ

OmniRoute មិនគ្រាន់តែបញ្ជូនចរាចរណ៍តាមរយៈប្រូកស៊ី — ប៉ុណ្ណោះទេ វាធ្វើឱ្យចរាចរណ៍មើលទៅស្របច្បាប់៖

### TLS ការក្លែងបន្លំស្នាមម្រាមដៃ

ប្រើ `wreq-js` ដើម្បីបង្កើតស្នាមម្រាមដៃ TLS ដូចកម្មវិធីរុករក ដោយឆ្លងកាត់ប្រព័ន្ធរកឃើញ bot ដែលដាក់ទង់ការចាប់ដៃ TLS ដែលមិនមែនជាកម្មវិធីរុករក។

### CLI ការផ្គូផ្គងស្នាមម្រាមដៃ

នេះ។**CLI បិទបើកស្នាមម្រាមដៃ** (`Settings → Security`) តម្រៀបបឋមកថា HTTP និងវាលតួ JSON ឡើងវិញដើម្បីផ្គូផ្គងហត្ថលេខាពិតប្រាកដនៃ CLI គោលពីរដើម (Claude Code, Codex ជាដើម)។ នេះដំណើរការ** នៅលើកំពូលនៃ** ប្រូកស៊ី៖

```
Your IP (blocked) → Proxy IP (US) → Provider API
                    + TLS spoof
                    + CLI fingerprint
```

អ្នកទទួលបានទាំងពីរ** របាំង IP** និង** ស្នើសុំភាពត្រឹមត្រូវ** ក្នុងពេលដំណាលគ្នា។

- **តារាងប្រូកស៊ី** ជាមួយម៉ាស៊ីន ពិធីការ ប្រទេស ពិន្ទុគុណភាព ភាពយឺតយ៉ាវ ភាពអនាមិក ការចូលប្រើ Google
- **ស្ថានភាពសមកាលកម្ម** បន្ទះជាមួយនឹងការតាមដាន success/failure និងការបរាជ័យជាបន្តបន្ទាប់
- **ជម្រះទាំងអស់។** ដើម្បីលុបធាតុប្រូកស៊ី 1 ទាំងអស់។

## ការដោះស្រាយបញ្ហា

### "ប្រូកស៊ីSOCKS5 ត្រូវបានបិទ"

កំណត់ `ENABLE_SOCKS5_PROXY=true` នៅក្នុងឯកសារ `.env` របស់អ្នក ហើយចាប់ផ្តើមឡើងវិញ។

### កំហុស "socket hang up" តាមរយៈប្រូកស៊ី

នេះគឺជារឿងធម្មតាជាមួយនឹងប្រូកស៊ីថោកដែលទម្លាក់ការភ្ជាប់ទំនេរ។ OmniRoute ដោះស្រាយវារួចហើយដោយ៖

- ការបិទដំណើរការរក្សាជីវិតនៅលើការតភ្ជាប់ប្រូកស៊ី (`keepAliveTimeout: 1`)
- បិទដំណើរការបំពង់បង្ហូរ (`pipelining: 0`)
- រក្សាទុកអ្នកចែកចាយ ដើម្បីជៀសវាងការចាប់ដៃម្តងហើយម្តងទៀត

ប្រសិនបើវានៅតែបន្ត សូមសាកល្បងប្រូកស៊ីផ្សេង ឬប្រើមុខងារបង្វិល 1proxy។

### "unsupported_country_region_territory" កំឡុងពេល OAuth

ត្រូវប្រាកដថាប្រូកស៊ីត្រូវបានកំណត់រចនាសម្ព័ន្ធ** មុន** ចាប់ផ្តើមលំហូរ OAuth ។ OmniRoute ដឹកនាំការផ្លាស់ប្តូរសញ្ញាសម្ងាត់ OAuth តាមរយៈប្រូកស៊ីដែលបានកំណត់រចនាសម្ព័ន្ធ។ កំណត់ប្រូកស៊ីកម្រិតសកល ឬកម្រិតអ្នកផ្តល់សេវាជាមុនសិន បន្ទាប់មកភ្ជាប់។

### ប្រូកស៊ីមិនត្រូវបានប្រើទេ។

ពិនិត្យមើលលំដាប់នៃដំណោះស្រាយ៖

1. ផ្ទៀងផ្ទាត់ជាមួយ `GET /api/settings/proxy?resolve=your-connection-id`
2. ពិនិត្យមើលថាតើប្រូកស៊ី `status` គឺ `active` (មិនមែន `inactive`)
3. ត្រូវប្រាកដថាវិសាលភាពកិច្ចការប្រូកស៊ីត្រូវគ្នានឹងការតភ្ជាប់របស់អ្នក។

### ការធ្វើសមកាលកម្មប្រូកស៊ី 1 បរាជ័យ

## គ្រោងការណ៍មូលដ្ឋានទិន្នន័យ

### តារាង `proxy_registry`

```sql
CREATE TABLE proxy_registry (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  type TEXT NOT NULL DEFAULT 'http',
  host TEXT NOT NULL,
  port INTEGER NOT NULL,
  username TEXT DEFAULT '',
  password TEXT DEFAULT '',
  region TEXT,
  notes TEXT,
  status TEXT DEFAULT 'active',
  source TEXT NOT NULL DEFAULT 'manual',    -- 'manual' or 'oneproxy'
  quality_score INTEGER,                     -- 0-100 (1proxy only)
  latency_ms INTEGER,                        -- milliseconds (1proxy only)
  anonymity TEXT,                            -- transparent/anonymous/elite
  google_access INTEGER DEFAULT 0,           -- can access Google? (1proxy)
  last_validated TEXT,                       -- ISO timestamp (1proxy)
  country_code TEXT,                         -- ISO 2-letter code (1proxy)
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

### តារាង `proxy_assignments`

```sql
CREATE TABLE proxy_assignments (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  proxy_id TEXT NOT NULL REFERENCES proxy_registry(id),
  scope TEXT NOT NULL,        -- 'global', 'provider', 'account', 'combo'
  scope_id TEXT,              -- provider ID, connection ID, or combo ID
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE(scope, scope_id)
);
```

## ការពិនិត្យសុខភាពប្រូកស៊ី (v3.8.16 +)

OmniRoute កា** ប្រូកស៊ីលឿន-បរាជ័យ** យន្តការ (`src/lib/proxyHealth.ts`) រកឃើញប្រូកស៊ីស្លាប់នៅក្នុង < 2s តាមរយៈការត្រួតពិនិត្យការតភ្ជាប់ TCP រហ័ស បន្ទាប់មក** រក្សាទុកលទ្ធផល** ដើម្បីជៀសវាងការស្នើសុំលើស។

### របៀបដែលវាដំណើរការ

```
Request ──▶ ProxyHealthCache.get(url)
             │
             ├─ Cache hit + fresh?  ──▶ return cached status
             │
             └─ Cache miss / stale?  ──▶ TCP connect to host:port
                                          (timeout: FAST_FAIL_TIMEOUT_MS)
                                          ──▶ cache for HEALTH_CACHE_TTL_MS
                                          ──▶ return result
```

បើគ្មាននេះទេប្រូកស៊ីដែលស្លាប់នឹងរារាំងរាល់សំណើសម្រាប់ `PROXY_TIMEOUT_MS` ពេញ (30s លំនាំដើម) មុនពេលបរាជ័យ។

### អថេរបរិស្ថានដែលអាចលៃតម្រូវបាន។

| `PROXY_FAST_FAIL_TIMEOUT_MS` | `2000`   | ការអស់ពេលនៃការតភ្ជាប់TCP សម្រាប់ការពិនិត្យសុខភាព           |
| `PROXY_HEALTH_CACHE_TTL_MS`  | `30000`  | រយៈពេលប៉ុន្មានដែលលទ្ធផលសុខភាពត្រូវបានទុកក្នុងឃ្លាំងសម្ងាត់ |

```ts
invalidateProxyHealth("http://user:pass@203.0.113.7:8080");
```

ទង់ `stale` គឺ `true` នៅពេលដែលការបញ្ចូលឃ្លាំងសម្ងាត់លើសពី `HEALTH_CACHE_TTL_MS` ហើយសំណើបន្ទាប់នឹងចាប់ផ្តើមការពិនិត្យថ្មី។

## ការវិភាគប្រូកស៊ី & ការសង្កេត

OmniRoute តាមដានការប្រើប្រាស់ប្រូកស៊ីក្នុងមួយដង ដើម្បីជួយប្រតិបត្តិករវិភាគលំនាំផ្លូវ ការបង្កើនភាពយឺតយ៉ាវ និងការបរាជ័យដែលកើតឡើងម្តងទៀត។

### អ្វីដែលត្រូវបានតាមដាន

| ម៉ែត្រ       | ការពិពណ៌នា                                          |
| ------------ | --------------------------------------------------- |
| `proxy_url`  | URL ប្រូកស៊ីពេញលេញ (ជាមួយការបិទបាំងអត្តសញ្ញាណប័ណ្ណ) |
| `provider`   | អ្នកផ្តល់សេវាខាងលើ ID (openai, anthropic ។ល។)       |

### ការចូលប្រើទិន្នន័យ

```bash
# Recent proxy events
curl -H "Authorization: Bearer $OMNIROUTE_KEY" \
  "http://localhost:20128/api/usage/proxy-logs?limit=100"
```

ចំណុចបញ្ចប់ពិតប្រាកដគឺ `/api/usage/proxy-logs` (សូមមើល `src/app/api/usage/proxy-logs/route.ts`) ។ ចំណុចបញ្ចប់នេះគាំទ្រ៖

- `GET /api/usage/proxy-logs` — ទាញយកកំណត់ហេតុប្រូកស៊ី
- `DELETE /api/usage/proxy-logs` — ជម្រះកំណត់ហេតុប្រូកស៊ីទាំងអស់។

ស្ថិតិសរុបអាចត្រូវបានសួរដោយផ្ទាល់ពីតារាង `proxy_logs` តាមរយៈ SQL ប្រសិនបើចាំបាច់។ ផ្ទាំងគ្រប់គ្រង UI អាចផ្តល់នូវទិដ្ឋភាពសរុប។

### លំនាំទូទៅ

**រកឃើញប្រូកស៊ីលោត** (ជំនួសរវាង success/failure)៖

```sql
SELECT proxy_url,
       COUNT(*) AS total,
       SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) AS errors,
       ROUND(100.0 * SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) / COUNT(*), 1) AS error_pct
FROM proxy_logs
WHERE timestamp > datetime('now', '-1 hour')
GROUP BY proxy_url
HAVING error_pct > 5
ORDER BY error_pct DESC;
```

**ស្វែងរកប្រូកស៊ីយឺត** (p95 latency > 2s):

```sql
WITH ranked AS (
  SELECT proxy_url, latency_ms,
         PERCENT_RANK() OVER (PARTITION BY proxy_url ORDER BY latency_ms) AS pct
  FROM proxy_logs
  WHERE timestamp > datetime('now', '-24 hour')
)
SELECT proxy_url, latency_ms
FROM ranked
WHERE pct >= 0.95
ORDER BY latency_ms DESC;
```

នៅពេលដែលប្រូកស៊ីច្រើនត្រូវបានកំណត់ទៅវិសាលភាព OmniRoute ប្រើ a** យុទ្ធសាស្ត្របង្វិល** ដើម្បីជ្រើសរើសមួយណាដែលត្រូវប្រើសម្រាប់សំណើនីមួយៗ។ យុទ្ធសាស្ត្រត្រូវបានកំណត់រចនាសម្ព័ន្ធនៅកម្រិតវិសាលភាព (សកល អ្នកផ្តល់សេវា ក្នុងមួយគណនី ក្នុងមួយបន្សំ)។

## ការបដិសេធការបរាជ័យដោយស្វ័យប្រវត្តិសម្រាប់ប្រូកស៊ីផ្ទាល់ខ្លួនរបស់អ្នក។

បណ្តុំទីផ្សារ 1proxy បានធ្វើការបំប្លែងប្រូកស៊ីដែលបរាជ័យដោយស្វ័យប្រវត្តិដោយខ្លួនឯង (សូមមើល [ពិន្ទុគុណភាពប្រូកស៊ី](#proxy-quality-scores) )។ សម្រាប់ប្រូកស៊ី** អ្នក** បានបន្ថែមទៅបញ្ជីឈ្មោះ កម្មវិធីកំណត់ពេលសុខភាពផ្ទៃខាងក្រោយ (`src/lib/proxyHealth/scheduler.ts`) ផ្តល់នូវឥរិយាបថដូចគ្នា "ដកសមាជិកដែលស្លាប់ចេញពីសង្វាក់ដោយស្វ័យប្រវត្តិ" ដោយមិនចាំបាច់លុបអ្វីទាំងអស់៖

```bash
# .env — soft-disable a proxy after 3 consecutive failed probes, re-enable it
# automatically once it starts answering probes again.
PROXY_AUTO_DISABLE=true
PROXY_AUTO_REMOVE_AFTER=3
```

របៀបដែលវាសមនឹងខ្សែសង្វាក់ពហុប្រូកស៊ី៖

1. កម្មវិធីកំណត់ពេលស៊ើបអង្កេតរាល់ប្រូកស៊ីដែលបានចុះឈ្មោះរាល់ `PROXY_HEALTH_INTERVAL_MS` (លំនាំដើម 10 នាទី អប្បបរមា 1 នាទី)។
2. បន្ទាប់ពី `PROXY_AUTO_REMOVE_AFTER` ជាប់គ្នា។** សេចក្តីសន្និដ្ឋាន** ការបរាជ័យ (ការបរាជ័យនៃការតភ្ជាប់ពិតប្រាកដ — អស់ពេល ឬ 5xx ផ្ទាល់របស់គោលដៅស៊ើបអង្កេតមិនដែលរាប់ទេ សូមមើល [ការពិនិត្យសុខភាពប្រូកស៊ី](#proxy-health-checking-v3816) ) `status` របស់ប្រូកស៊ីត្រូវបានកំណត់ទៅ `dead`។
3. `dead` គឺជាស្ថានភាពមួយដែលតម្រងស្ថានភាពរស់រានមានជីវិតដែលប្រើដោយដំណោះស្រាយ pool/rotation មិនរាប់បញ្ចូល ដូច្នេះការបង្វិលនៃវិសាលភាព (round-robin / random / sticky / latency — សូមមើល [Rotation Strategy Decision Tree](#rotation-strategy-decision-tree) ) ភ្លាមៗបញ្ឈប់ការប្រគល់ប្រូកស៊ីនោះទៅសំណើថ្មី។ គ្មានប្រូកស៊ីផ្សេងទៀតនៅក្នុងអាងត្រូវបានប៉ះពាល់ទេ ហើយអាងទាំងមូលមិនដែលនៅស្ងៀមត្រឡប់ទៅការភ្ជាប់ដោយផ្ទាល់ — ឃើញ [ប្រព័ន្ធប្រូកស៊ីកម្រិត 4-Level](#4-level-proxy-system) យាមបិទ។
4. កម្មវិធីកំណត់ពេលរក្សាការស៊ើបអង្កេត `dead` ប្រូកស៊ីនៅលើចន្លោះពេលដូចគ្នា។ ការស៊ើបអង្កេតជោគជ័យបន្ទាប់ត្រឡប់ `status` ត្រឡប់ទៅ `active` ហើយវាបញ្ចូលការបង្វិល — ឡើងវិញដោយមិនចាំបាច់បន្ថែមដោយដៃ។

នេះជាចេតនា** ជ្រើសរើសចូលនិងមិនបំផ្លិចបំផ្លាញ** ៖ តាមលំនាំដើម កម្មវិធីកំណត់ពេលរាប់តែការបរាជ័យក្នុងការកត់ត្រាប៉ុណ្ណោះ (សូមមើលគោលការណ៍ C ក្នុង `decision.ts`) ហើយ `PROXY_AUTO_DISABLE` មិនដែលលុបជួរដេក — ដែលជាទង់ `PROXY_AUTO_REMOVE` ដាច់ដោយឡែក និងកាន់តែឈ្លានពាននោះទេ។ ប្រសិនបើទាំងពីរត្រូវបានកំណត់ទៅ `true` `PROXY_AUTO_REMOVE` ឈ្នះ (ប្រូកស៊ីដែលនឹងត្រូវបានលុបមិនមានការប្រើប្រាស់សម្រាប់ Soft-disable នៅចន្លោះ)។ សូមមើល [Environment Config](../reference/ENVIRONMENT.md) reference សម្រាប់បញ្ជីអថេរពេញលេញ។
