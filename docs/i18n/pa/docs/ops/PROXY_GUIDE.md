> **ਭੂਗੋਲਿਕ ਬਲਾਕਾਂ ਨੂੰ ਬਾਈਪਾਸ ਕਰੋ, ਆਪਣੀ ਪਛਾਣ ਦੀ ਰੱਖਿਆ ਕਰੋ, ਅਤੇ ਜ਼ੀਰੋ ਕੌਂਫਿਗਰੇਸ਼ਨ ਜਟਿਲਤਾ ਦੇ ਨਾਲ ਕਿਸੇ ਵੀ ਪ੍ਰੌਕਸੀ — ਦੁਆਰਾ AI ਟ੍ਰੈਫਿਕ ਨੂੰ ਰੂਟ ਕਰੋ।**

OmniRoute ਵਿੱਚ ਇੱਕ ਪੂਰਾ-ਵਿਸ਼ੇਸ਼ ਪ੍ਰੌਕਸੀ ਪ੍ਰਬੰਧਨ ਸਿਸਟਮ ਸ਼ਾਮਲ ਹੈ ਜੋ ਤੁਹਾਨੂੰ HTTP, HTTPS, ਜਾਂ SOCKS5 ਪ੍ਰੌਕਸੀ ਦੁਆਰਾ ਅੱਪਸਟ੍ਰੀਮ AI ਪ੍ਰਦਾਤਾ ਟ੍ਰੈਫਿਕ ਨੂੰ ਰੂਟ ਕਰਨ ਦਿੰਦਾ ਹੈ। ਭਾਵੇਂ ਤੁਸੀਂ ਬਲੌਕ ਕੀਤੇ ਖੇਤਰ ਵਿੱਚ ਹੋ, IP ਰੋਟੇਸ਼ਨ ਦੀ ਲੋੜ ਹੈ, ਜਾਂ ਸਟੀਲਥ ਫਿੰਗਰਪ੍ਰਿੰਟਿੰਗ — ਚਾਹੁੰਦੇ ਹੋ ਇਹ ਗਾਈਡ ਹਰ ਚੀਜ਼ ਨੂੰ ਕਵਰ ਕਰਦੀ ਹੈ।

## ਪ੍ਰੌਕਸੀਆਂ ਦੀ ਵਰਤੋਂ ਕਿਉਂ ਕਰੀਏ?

ਬਹੁਤ ਸਾਰੇ AI ਪ੍ਰਦਾਤਾ ਭੂਗੋਲਿਕ ਖੇਤਰ ਦੁਆਰਾ ਪਹੁੰਚ ਨੂੰ ਪ੍ਰਤਿਬੰਧਿਤ ਕਰਦੇ ਹਨ। ਵਿੱਚ ਵਿਕਾਸਕਾਰ** ਰੂਸ, ਚੀਨ, ਈਰਾਨ, ਕਿਊਬਾ, ਤੁਰਕੀ** , ਅਤੇ ਹੋਰ ਦੇਸ਼ਾਂ ਵਿੱਚ ਗਲਤੀਆਂ ਦਾ ਸਾਹਮਣਾ ਕਰਨਾ ਪੈਂਦਾ ਹੈ ਜਿਵੇਂ ਕਿ:

```
unsupported_country_region_territory
```

ਇੱਥੋਂ ਤੱਕ ਕਿ ਬਾਹਰੋਂ ਬਲੌਕ ਕੀਤੇ ਖੇਤਰਾਂ, ਪ੍ਰੌਕਸੀ ਇਹਨਾਂ ਲਈ ਲਾਭਦਾਇਕ ਹਨ:

| ਕੇਸ ਦੀ ਵਰਤੋਂ ਕਰੋ   | ਵਰਣਨ                                                                 |
| ------------------ | -------------------------------------------------------------------- |
| **ਭੂਗੋਲਿਕ ਬਾਈਪਾਸ** | ਬਲੌਕ ਕੀਤੇ ਦੇਸ਼ਾਂ ਤੋਂ OpenAI, Anthropic, Codex, Copilot ਤੱਕ ਪਹੁੰਚ ਕਰੋ |
| **IP ਰੋਟੇਸ਼ਨ**     | ਦਰ ਨੂੰ ਸੀਮਤ ਕਰਨ ਤੋਂ ਬਚਣ ਲਈ ਬੇਨਤੀਆਂ ਨੂੰ ਇੱਕ ਤੋਂ ਵੱਧ IPs ਵਿੱਚ ਵੰਡੋ     |
| **ਗੋਪਨੀਯਤਾ**       | ਅਪਸਟ੍ਰੀਮ ਪ੍ਰਦਾਤਾਵਾਂ ਤੋਂ ਆਪਣਾ ਅਸਲ IP ਲੁਕਾਓ                            |
| **ਪਾਲਣਾ**          | ਖਾਸ ਅਧਿਕਾਰ ਖੇਤਰਾਂ ਰਾਹੀਂ ਆਵਾਜਾਈ ਨੂੰ ਰੂਟ ਕਰੋ                           |
| **ਟੈਸਟਿੰਗ**        | ਵੱਖ-ਵੱਖ ਖੇਤਰਾਂ ਤੋਂ ਬੇਨਤੀਆਂ ਦੀ ਨਕਲ ਕਰੋ                                |

## ਨਵੇਂ ਖਾਤਿਆਂ ਲਈ ਪੂਰਵ-ਨਿਰਧਾਰਤ ਪ੍ਰੌਕਸੀ ਸਥਿਤੀ

ਵਿੱਚ** ਸੈਟਿੰਗਾਂ → ਪ੍ਰੌਕਸੀ → ਗਲੋਬਲ ਕੌਂਫਿਗਰੇਸ਼ਨ** , ਵਰਤੋ** ਨਵੇਂ ਕਨੈਕਸ਼ਨਾਂ ਲਈ ਮੂਲ ਰੂਪ ਵਿੱਚ ਪ੍ਰੌਕਸੀ ਨੂੰ ਸਮਰੱਥ ਬਣਾਓ** ਨਵੇਂ ਸ਼ਾਮਲ ਕੀਤੇ ਪ੍ਰਦਾਤਾ ਖਾਤਿਆਂ ਦੀ ਸ਼ੁਰੂਆਤੀ ਪ੍ਰੌਕਸੀ ਸਥਿਤੀ ਚੁਣਨ ਲਈ।

ਨਵੀਂ ਸੈਟਿੰਗ ਨਵੇਂ ਸ਼ਾਮਲ ਕੀਤੇ ਪ੍ਰਦਾਤਾ ਖਾਤਿਆਂ ਦੀ ਸ਼ੁਰੂਆਤੀ ਪ੍ਰੌਕਸੀ ਸਥਿਤੀ ਨੂੰ ਨਿਯੰਤਰਿਤ ਕਰਦੀ ਹੈ। ਇਹ ਮੌਜੂਦਾ ਖਾਤਿਆਂ ਨੂੰ ਨਹੀਂ ਬਦਲਦਾ ਹੈ ਜਾਂ ਗਲੋਬਲ ਪ੍ਰੌਕਸੀ ਸਵਿੱਚ ਨੂੰ ਨਹੀਂ ਬਦਲਦਾ ਹੈ। ਇਸਦਾ ਸ਼ੁਰੂਆਤੀ ਮੁੱਲ ਪਿਛਲੇ ਵਿਵਹਾਰ ਨੂੰ ਸੁਰੱਖਿਅਤ ਰੱਖਦਾ ਹੈ। ਪੂਰਵ-ਨਿਰਧਾਰਤ ਤੌਰ 'ਤੇ ਅਯੋਗ ਪ੍ਰੌਕਸੀ ਦੇ ਨਾਲ ਭਵਿੱਖ ਦੇ ਖਾਤੇ ਬਣਾਉਣ ਲਈ ਇਸਨੂੰ ਇੱਕ ਵਾਰ ਬੰਦ ਕਰੋ।

ਤਰਜੀਹ ਮੌਜੂਦਾ ਸੈਟਿੰਗਜ਼ API ਰਾਹੀਂ `defaultNewConnectionProxyEnabled` ਵਜੋਂ ਸਟੋਰ ਕੀਤੀ ਜਾਂਦੀ ਹੈ। ਇਹ `true` ਲਈ ਡਿਫਾਲਟ ਹੁੰਦਾ ਹੈ ਜਦੋਂ ਕਦੇ ਸੰਭਾਲਿਆ ਨਹੀਂ ਜਾਂਦਾ ਹੈ। `false` ਸੁਰੱਖਿਅਤ ਕਰਨਾ ਬਿਨਾਂ ਰੀਸਟਾਰਟ ਕੀਤੇ ਅਗਲੇ ਨਵੇਂ ਖਾਤਿਆਂ ਲਈ ਪ੍ਰਭਾਵੀ ਹੁੰਦਾ ਹੈ। `POST /api/providers` ਇੱਕ ਵਿਕਲਪਿਕ ਸਖਤ ਬੁਲੀਅਨ `proxyEnabled` ਨੂੰ ਸਵੀਕਾਰ ਕਰਦਾ ਹੈ; ਇੱਕ ਸਪਸ਼ਟ `true` ਜਾਂ `false` ਰਚਨਾ ਡਿਫੌਲਟ ਉੱਤੇ ਤਰਜੀਹ ਲੈਂਦਾ ਹੈ। ਡੁਪਲੀਕੇਟ ਖਾਤੇ ਜਾਂ OAuth ਰੀਕਨੈਕਟ 'ਤੇ ਛੱਡਣਾ ਉਸ ਖਾਤੇ ਦੀ ਸਟੋਰ ਕੀਤੀ ਸਥਿਤੀ ਨੂੰ ਸੁਰੱਖਿਅਤ ਰੱਖਦਾ ਹੈ। ਵਿਅਕਤੀਗਤ ਖਾਤਿਆਂ ਨੂੰ ਬਾਅਦ ਵਿੱਚ ਅਜੇ ਵੀ ਸਮਰੱਥ ਜਾਂ ਅਯੋਗ ਕੀਤਾ ਜਾ ਸਕਦਾ ਹੈ।

ਚੋਣਵੇਂ ਪ੍ਰਦਾਤਾ ਟ੍ਰਾਂਸਫਰ ਨਵੇਂ ਖਾਤਿਆਂ ਲਈ ਮੰਜ਼ਿਲ ਸਥਾਪਨਾ ਦੇ ਡਿਫੌਲਟ ਦੀ ਵਰਤੋਂ ਕਰਦੇ ਹਨ ਅਤੇ ਮੌਜੂਦਾ ਖਾਤਿਆਂ ਨੂੰ ਬਦਲਣ ਵੇਲੇ ਮੰਜ਼ਿਲ ਨੀਤੀ ਨੂੰ ਸੁਰੱਖਿਅਤ ਰੱਖਦੇ ਹਨ। ਪ੍ਰੌਕਸੀ ਟੌਗਲ ਪੋਰਟੇਬਲ ਟ੍ਰਾਂਸਫਰ ਖੇਤਰ ਨਹੀਂ ਹਨ। ਪੂਰੀ ਬੈਕਅੱਪ ਬਹਾਲੀ ਅਤੇ ਇਤਿਹਾਸਕ JSON/SQL ਮਾਈਗ੍ਰੇਸ਼ਨ ਉਹਨਾਂ ਦੇ ਮੌਜੂਦਾ ਰੀਸਟੋਰ ਸਿਮੈਨਟਿਕਸ ਨੂੰ ਬਰਕਰਾਰ ਰੱਖਦੇ ਹਨ, ਜਿਸ ਵਿੱਚ ਸੁਰੱਖਿਅਤ ਕੀਤੇ ਖਾਤਾ ਮੁੱਲ ਅਤੇ ਵਿਰਾਸਤੀ ਸਕੀਮਾ ਡਿਫੌਲਟ ਸ਼ਾਮਲ ਹਨ; ਇੱਕ ਪੂਰੀ ਸੈਟਿੰਗ ਰੀਸਟੋਰ ਵੀ ਇਸ ਤਰਜੀਹ ਨੂੰ ਰੀਸਟੋਰ ਕਰ ਸਕਦੀ ਹੈ।

ਇਹ ਤਰਜੀਹ ਇੱਕ ਪ੍ਰੌਕਸੀ ਨਿਰਧਾਰਤ ਨਹੀਂ ਕਰਦੀ ਜਾਂ ਇਹ ਸਥਾਪਿਤ ਨਹੀਂ ਕਰਦੀ ਹੈ ਕਿ ਇੱਕ ਸਿਹਤਮੰਦ ਜਾਂ ਵਰਤੋਂ ਵਿੱਚ ਹੈ। ਅਸਲ ਰੂਟਿੰਗ ਅਜੇ ਵੀ ਗਲੋਬਲ ਪ੍ਰੌਕਸੀ ਸਵਿੱਚ ਅਤੇ ਲਾਗੂ ਪ੍ਰੌਕਸੀ ਕੌਂਫਿਗਰੇਸ਼ਨ 'ਤੇ ਨਿਰਭਰ ਕਰਦੀ ਹੈ। ਸਥਾਈ ਖਾਤੇ ਦੇ ਬਿਨਾਂ ਸਿੰਥੈਟਿਕ ਪ੍ਰਦਾਤਾ, ਖਾਤਾ ਬਣਾਉਣ ਤੋਂ ਪਹਿਲਾਂ OAuth ਟ੍ਰੈਫਿਕ, environment/system ਪ੍ਰੌਕਸੀਆਂ, ਅਤੇ ਬਾਹਰੀ ਬੈਕਐਂਡਸ ਨੈੱਟਵਰਕਿੰਗ ਇਸਦੇ ਦਾਇਰੇ ਤੋਂ ਬਾਹਰ ਹਨ।

## 4-ਪੱਧਰੀ ਪ੍ਰੌਕਸੀ ਸਿਸਟਮ

OmniRoute ਤੇ ਪ੍ਰੌਕਸੀ ਸੰਰਚਨਾ ਦਾ ਸਮਰਥਨ ਕਰਦਾ ਹੈ** ਚਾਰ ਸੁਤੰਤਰ ਸਕੋਪ** , ਤਰਜੀਹੀ ਕ੍ਰਮ ਵਿੱਚ ਹੱਲ ਕੀਤਾ ਗਿਆ:

```
Priority Resolution Order (highest → lowest):

  1. 🔵 Account/Connection Proxy  →  per API key / OAuth connection
  2. 🟡 Provider Proxy            →  per provider (e.g., all OpenAI traffic)
  3. 🟠 Combo Proxy               →  per combo/routing configuration
  4. 🟢 Global Proxy              →  all traffic, all providers
```

### ਰੈਜ਼ੋਲਿਊਸ਼ਨ ਕਿਵੇਂ ਕੰਮ ਕਰਦਾ ਹੈ

ਜਦੋਂ OmniRoute ਇੱਕ ਅੱਪਸਟ੍ਰੀਮ ਪ੍ਰਦਾਤਾ ਨੂੰ ਇੱਕ ਬੇਨਤੀ ਭੇਜਦਾ ਹੈ, ਤਾਂ ਇਹ `resolveProxyForConnectionFromRegistry()` ਕਾਲ ਕਰਦਾ ਹੈ ਜੋ ਹਰੇਕ ਪੱਧਰ ਦੀ ਕ੍ਰਮ ਵਿੱਚ ਜਾਂਚ ਕਰਦਾ ਹੈ:

1. **ਖਾਤਾ-ਪੱਧਰ** — ਕੀ ਇਸ ਖਾਸ ਕੁਨੈਕਸ਼ਨ ID ਲਈ ਕੋਈ ਪ੍ਰੌਕਸੀ ਨਿਰਧਾਰਤ ਕੀਤੀ ਗਈ ਹੈ?
2. **ਪ੍ਰਦਾਤਾ—ਪੱਧਰ** — ਕੀ ਇਸ ਪ੍ਰਦਾਤਾ ਨੂੰ ਕੋਈ ਪ੍ਰੌਕਸੀ ਸੌਂਪੀ ਗਈ ਹੈ (ਜਿਵੇਂ ਕਿ, `openai`)?
3. **ਗਲੋਬਲ-ਪੱਧਰ** — ਕੀ ਕੋਈ ਗਲੋਬਲ ਪ੍ਰੌਕਸੀ ਕੌਂਫਿਗਰ ਕੀਤੀ ਗਈ ਹੈ?
4. **ਕੋਈ ਪ੍ਰੌਕਸੀ ਨਹੀਂ** — ਪ੍ਰਦਾਤਾ ਨਾਲ ਸਿੱਧਾ ਕਨੈਕਸ਼ਨ।

ਪਹਿਲਾ ਮੈਚ ਜਿੱਤਦਾ ਹੈ। ਇਸਦਾ ਮਤਲਬ ਹੈ ਕਿ ਤੁਸੀਂ ਇੱਕ ਗਲੋਬਲ ਪ੍ਰੌਕਸੀ ਨੂੰ ਫਾਲਬੈਕ ਵਜੋਂ ਸੈਟ ਕਰ ਸਕਦੇ ਹੋ ਪਰ ਖਾਸ ਪ੍ਰਦਾਤਾਵਾਂ ਜਾਂ ਕਨੈਕਸ਼ਨਾਂ ਲਈ ਇਸਨੂੰ ਓਵਰਰਾਈਡ ਕਰ ਸਕਦੇ ਹੋ।

### ਕੀ ਪ੍ਰੌਕਸੀਡ ਹੋ ਜਾਂਦਾ ਹੈ

| ਆਵਾਜਾਈ ਦੀ ਕਿਸਮ     | ਪ੍ਰੌਕਸੀਡ? | ਨੋਟਸ                                               |
| ------------------ | --------- | -------------------------------------------------- |
| ਚੈਟ ਸੰਪੂਰਨਤਾਵਾਂ    | ✅        | ਸਾਰੀਆਂ `/v1/chat/completions` ਬੇਨਤੀਆਂ              |
| ਏਮਬੈਡਿੰਗਸ          | ✅        | `/v1/embeddings`                                   |
| ਚਿੱਤਰ ਬਣਾਉਣਾ       | ✅        | `/v1/images/generations`                           |
| ਆਡੀਓ (TTS/STT)     | ✅        | `/v1/audio/*`                                      |
| OAuth ਟੋਕਨ ਐਕਸਚੇਂਜ | ✅        | `unsupported_country_region_territory` ਹੱਲ ਕਰਦਾ ਹੈ |
| ਕਨੈਕਸ਼ਨ ਟੈਸਟ       | ✅        | "ਟੈਸਟ ਕਨੈਕਸ਼ਨ" ਬਟਨ ਪ੍ਰੌਕਸੀ ਦੀ ਵਰਤੋਂ ਕਰਦਾ ਹੈ        |
| ਟੋਕਨ ਰਿਫ੍ਰੈਸ਼      | ✅        | ਬੈਕਗ੍ਰਾਊਂਡ OAuth ਨਵੀਨੀਕਰਨ                          |
| ਮਾਡਲ ਸਿੰਕ          | ✅        | ਮਾਡਲ ਸੂਚੀਕਰਨ ਅਤੇ ਖੋਜ                               |

## ਪ੍ਰੌਕਸੀ ਰਜਿਸਟਰੀ (CRUD)

ਪ੍ਰੌਕਸੀ ਰਜਿਸਟਰੀ ਇੱਕ SQLite ਟੇਬਲ (`proxy_registry`) ਹੈ ਜੋ ਤੁਹਾਡੀਆਂ ਸਾਰੀਆਂ ਪ੍ਰੌਕਸੀਜ਼ ਨੂੰ ਸਟੋਰ ਕਰਦੀ ਹੈ। ਹਰੇਕ ਪ੍ਰੌਕਸੀ ਕੋਲ ਹੈ:

| ਖੇਤਰ       | ਟਾਈਪ ਕਰੋ | ਵਰਣਨ                                         |
| ---------- | -------- | -------------------------------------------- |
| `id`       | UUID     | ਵਿਲੱਖਣ ਪਛਾਣਕਰਤਾ                              |
| `name`     | ਸਤਰ      | ਮਨੁੱਖੀ-ਪੜ੍ਹਨਯੋਗ ਲੇਬਲ                         |
| `type`     | ਸਤਰ      | ਪ੍ਰੋਟੋਕੋਲ: `http`, `https`, `socks5`         |
| `host`     | ਸਤਰ      | ਪ੍ਰੌਕਸੀ ਹੋਸਟਨਾਮ ਜਾਂ IP                       |
| `port`     | ਪੂਰਨ ਅੰਕ | ਪੋਰਟ ਨੰਬਰ                                    |
| `username` | ਸਤਰ      | ਪ੍ਰਮਾਣਿਕਤਾ ਉਪਭੋਗਤਾ ਨਾਮ (ਬਾਕੀ ਸਮੇਂ ਐਨਕ੍ਰਿਪਟਡ) |
| `password` | ਸਤਰ      | ਪ੍ਰਮਾਣਿਕਤਾ ਪਾਸਵਰਡ (ਬਾਕੀ ਵੇਲੇ ਏਨਕ੍ਰਿਪਟਡ)      |
| `region`   | ਸਤਰ      | ਭੂਗੋਲਿਕ ਖੇਤਰ ਲੇਬਲ                            |
| `notes`    | ਸਤਰ      | ਮੁਫਤ-ਟੈਕਸਟ ਨੋਟਸ                              |
| `status`   | ਸਤਰ      | `active` ਜਾਂ `inactive`                      |
| `source`   | ਸਤਰ      | `manual` ਜਾਂ `oneproxy`                      |

### ਇੱਕ ਪ੍ਰੌਕਸੀ ਬਣਾਉਣਾ

**ਡੈਸ਼ਬੋਰਡ ਰਾਹੀਂ:**

1. 'ਤੇ ਜਾਓ** ਸੈਟਿੰਗਾਂ → ਪਰਾਕਸੀ**
2. ਕਲਿੱਕ ਕਰੋ** ਪ੍ਰੌਕਸੀ ਸ਼ਾਮਲ ਕਰੋ**
3. ਕਿਸਮ, ਹੋਸਟ, ਪੋਰਟ ਅਤੇ ਵਿਕਲਪਿਕ ਪ੍ਰਮਾਣ ਪੱਤਰ ਭਰੋ
4. ਸੇਵ ਕਰੋ

**API ਰਾਹੀਂ:**

```bash
curl -X POST http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "name": "US Proxy",
    "type": "http",
    "host": "proxy.example.com",
    "port": 8080,
    "username": "user",
    "password": "pass",
    "region": "US"
  }'
```

### ਇੱਕ ਪ੍ਰੌਕਸੀ ਨੂੰ ਅੱਪਡੇਟ ਕੀਤਾ ਜਾ ਰਿਹਾ ਹੈ

```bash
curl -X PATCH http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "id": "proxy-uuid-here",
    "host": "new-proxy.example.com",
    "port": 9090
  }'
```

> **ਨੋਟ:** ਪ੍ਰਮਾਣ ਪੱਤਰ ਉਦੋਂ ਤੱਕ ਸੁਰੱਖਿਅਤ ਰੱਖੇ ਜਾਂਦੇ ਹਨ ਜਦੋਂ ਤੱਕ ਤੁਸੀਂ ਸਪੱਸ਼ਟ ਤੌਰ 'ਤੇ ਗੈਰ-ਖਾਲੀ ਤਬਦੀਲੀਆਂ ਨਹੀਂ ਭੇਜਦੇ। `username`/`password` ਲਈ ਖਾਲੀ ਸਤਰ ਭੇਜਣਾ ਸਟੋਰ ਕੀਤੇ ਮੁੱਲਾਂ ਨੂੰ ਰੱਖੇਗਾ।

### ਇੱਕ ਪ੍ਰੌਕਸੀ ਨੂੰ ਮਿਟਾਉਣਾ

```bash
# Fails if proxy is assigned to any scope
curl -X DELETE "http://localhost:20128/api/v1/management/proxies?id=proxy-uuid"

# Force delete (removes assignments too)
curl -X DELETE "http://localhost:20128/api/v1/management/proxies?id=proxy-uuid&force=1"
```

### ਸੂਚੀਕਰਨ ਪਰਾਕਸੀ

```bash
curl "http://localhost:20128/api/v1/management/proxies?limit=50&offset=0"
```

### ਸਕੋਪਾਂ ਲਈ ਪ੍ਰੌਕਸੀਜ਼ ਨੂੰ ਸੌਂਪਣਾ

```bash
# Assign to global scope
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "global", "proxy": {"type":"http","host":"proxy.example.com","port":8080}}'

# Assign to a specific provider
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "provider", "id": "openai", "proxy": {"type":"socks5","host":"socks.example.com","port":1080}}'

# Assign to a specific connection/key
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "key", "id": "connection-uuid", "proxy": {"type":"http","host":"key-proxy.com","port":3128}}'
```

### ਪ੍ਰਭਾਵੀ ਪ੍ਰੌਕਸੀ ਨੂੰ ਹੱਲ ਕਰਨਾ

ਜਾਂਚ ਕਰੋ ਕਿ ਦਿੱਤੇ ਗਏ ਕਨੈਕਸ਼ਨ ਲਈ ਕਿਹੜੀ ਪ੍ਰੌਕਸੀ ਵਰਤੀ ਜਾਵੇਗੀ:

```bash
curl "http://localhost:20128/api/settings/proxy?resolve=connection-uuid"
```

ਹੱਲ ਕੀਤੀ ਪ੍ਰੌਕਸੀ ਨੂੰ ਇਸਦੇ ਪੱਧਰ (`account`, `provider`, ਜਾਂ `global`) ਅਤੇ ਸਰੋਤ ਨਾਲ ਵਾਪਸ ਕਰਦਾ ਹੈ।

### ਬਲਕ ਅਸਾਈਨਮੈਂਟ

ਇੱਕ ਵਾਰ ਵਿੱਚ ਕਈ ਪ੍ਰਦਾਤਾਵਾਂ ਜਾਂ ਕਨੈਕਸ਼ਨਾਂ ਨੂੰ ਇੱਕ ਪ੍ਰੌਕਸੀ ਦਿਓ:

```bash
curl -X POST http://localhost:20128/api/v1/management/proxies/bulk-assign \
  -H "Content-Type: application/json" \
  -d '{
    "scope": "provider",
    "scopeIds": ["openai", "anthropic", "codex"],
    "proxyId": "proxy-uuid"
  }'
```

### Import/Export

ਵਿੱਚ ਪ੍ਰੌਕਸੀ ਸ਼ਾਮਲ ਹਨ**Backup/Restore** ਸਿਸਟਮ. ਜਦੋਂ ਤੁਸੀਂ ਆਪਣੀ OmniRoute ਸੰਰਚਨਾ ਨੂੰ ਨਿਰਯਾਤ ਕਰਦੇ ਹੋ:

1. 'ਤੇ ਜਾਓ** ਡੈਸ਼ਬੋਰਡ → ਸੈਟਿੰਗਾਂ → ਬੈਕਅੱਪ**
2. ਕਲਿੱਕ ਕਰੋ** ਨਿਰਯਾਤ** — ਪ੍ਰੌਕਸੀ ਰਜਿਸਟਰੀ ਅਤੇ ਅਸਾਈਨਮੈਂਟ ਸ਼ਾਮਲ ਹਨ
3. ਰੀਸਟੋਰ ਕਰਨ ਲਈ, ਕਲਿੱਕ ਕਰੋ** ਆਯਾਤ ਕਰੋ** ਅਤੇ ਬੈਕਅੱਪ ਫਾਈਲ ਅਪਲੋਡ ਕਰੋ

ਪਰਾਕਸੀ ਰਜਿਸਟਰੀ ਨੂੰ ਵੀ ਸਹਿਯੋਗ ਦਿੰਦਾ ਹੈ** ਹੋਸਟ + ਪੋਰਟ ਦੁਆਰਾ upsert** — ਜੇਕਰ ਤੁਸੀਂ ਇੱਕ ਪ੍ਰੌਕਸੀ ਆਯਾਤ ਕਰਦੇ ਹੋ ਜੋ ਪਹਿਲਾਂ ਤੋਂ ਮੌਜੂਦ ਹੈ (ਇੱਕੋ ਹੋਸਟ ਅਤੇ ਪੋਰਟ), ਇਹ ਇੱਕ ਡੁਪਲੀਕੇਟ ਬਣਾਉਣ ਦੀ ਬਜਾਏ ਅੱਪਡੇਟ ਕਰਦਾ ਹੈ।

### ਵਿਰਾਸਤੀ ਮਾਈਗ੍ਰੇਸ਼ਨ

ਜੇਕਰ ਤੁਸੀਂ ਇੱਕ ਪੁਰਾਣੇ ਸੰਸਕਰਣ (ਪ੍ਰੀ-ਰਜਿਸਟਰੀ) ਵਿੱਚ ਪ੍ਰੌਕਸੀਜ਼ ਨੂੰ ਕੌਂਫਿਗਰ ਕੀਤਾ ਹੈ, ਤਾਂ OmniRoute ਉਹਨਾਂ ਨੂੰ ਆਟੋਮੈਟਿਕਲੀ ਮਾਈਗਰੇਟ ਕਰਦਾ ਹੈ:

```
Legacy key_value store → proxy_registry + proxy_assignments
```

ਇਹ ਅੱਪਗ੍ਰੇਡ ਤੋਂ ਬਾਅਦ ਪਹਿਲੀ ਵਾਰ ਸ਼ੁਰੂ ਹੋਣ 'ਤੇ ਹੁੰਦਾ ਹੈ। ਦੁਬਾਰਾ ਚਲਾਉਣ ਲਈ `migrateLegacyProxyConfigToRegistry({ force: true })` ਵਰਤੋਂ ਕਰੋ।

## 1ਪ੍ਰੌਕਸੀ ਮੁਫਤ ਪ੍ਰੌਕਸੀ ਮਾਰਕੀਟਪਲੇਸ

> 🆕** [@oyi77](https://github.com/oyi77) ਦੁਆਰਾ ਯੋਗਦਾਨ ਪਾਇਆ ਗਿਆ** — PR [#1847](https://github.com/diegosouzapw/OmniRoute/pull/1847) ( ਮੁੱਦਾ [#1788](https://github.com/diegosouzapw/OmniRoute/issues/1788) )

OmniRoute ਨਾਲ ਏਕੀਕ੍ਰਿਤ ਹੈ** [1 ਪ੍ਰੌਕਸੀ](https://1proxy-api.aitradepulse.com)** ਤੱਕ ਪਹੁੰਚ ਪ੍ਰਦਾਨ ਕਰਨ ਲਈ ਕਮਿਊਨਿਟੀ ਪਲੇਟਫਾਰਮ** ਸੈਂਕੜੇ ਮੁਫ਼ਤ, ਪ੍ਰਮਾਣਿਤ ਪ੍ਰੌਕਸੀਜ਼** ਦੁਨੀਆ ਭਰ ਤੋਂ। ਇਹ ਉਹਨਾਂ ਉਪਭੋਗਤਾਵਾਂ ਲਈ ਸੰਪੂਰਨ ਹੈ ਜਿਨ੍ਹਾਂ ਕੋਲ ਆਪਣਾ ਪ੍ਰੌਕਸੀ ਬੁਨਿਆਦੀ ਢਾਂਚਾ ਨਹੀਂ ਹੈ।

### ਇਹ ਕਿਵੇਂ ਕੰਮ ਕਰਦਾ ਹੈ

```
┌─────────────┐     Sync      ┌─────────────────┐    Rotate     ┌──────────┐
│  1proxy API │ ────────────▶ │  proxy_registry  │ ────────────▶ │ Provider │
│  (external) │   up to 500   │  source=oneproxy │  by quality   │   API    │
└─────────────┘    proxies    └─────────────────┘               └──────────┘
```

1. **ਸਿੰਕ** — OmniRoute 1proxy API ਤੋਂ ਪ੍ਰਮਾਣਿਤ ਪ੍ਰੌਕਸੀ ਲਿਆਉਂਦਾ ਹੈ
2. **ਸਟੋਰ** — ਪ੍ਰੌਕਸੀਆਂ ਨੂੰ `source = 'oneproxy'` ਨਾਲ ਉਸੇ `proxy_registry` ਟੇਬਲ ਵਿੱਚ ਸੁਰੱਖਿਅਤ ਕੀਤਾ ਜਾਂਦਾ ਹੈ
3. **ਫਿਲਟਰ** — ਪ੍ਰੋਟੋਕੋਲ, ਦੇਸ਼, ਗੁਣਵੱਤਾ ਸਕੋਰ ਦੁਆਰਾ ਫਿਲਟਰ ਕਰੋ
4. **ਘੁੰਮਾਓ** — ਗੁਣਵੱਤਾ, ਬੇਤਰਤੀਬੇ, ਜਾਂ ਕ੍ਰਮਵਾਰ ਰਣਨੀਤੀਆਂ ਦੀ ਵਰਤੋਂ ਕਰਕੇ ਸਭ ਤੋਂ ਵਧੀਆ ਪ੍ਰੌਕਸੀ ਚੁਣੋ
5. **ਆਟੋ-ਡਿਗਰੇਡ** — ਅਸਫਲ ਪ੍ਰੌਕਸੀ ਆਪਣੇ ਗੁਣਵੱਤਾ ਸਕੋਰ ਨੂੰ ਘਟਾ ਦਿੰਦੇ ਹਨ; ਥ੍ਰੈਸ਼ਹੋਲਡ ਦੇ ਹੇਠਾਂ → ਨੂੰ ਅਕਿਰਿਆਸ਼ੀਲ ਚਿੰਨ੍ਹਿਤ ਕੀਤਾ ਗਿਆ ਹੈ

### ਸਮਕਾਲੀਕਰਨ ਪ੍ਰੌਕਸੀ

**ਡੈਸ਼ਬੋਰਡ ਰਾਹੀਂ:**

1. 'ਤੇ ਜਾਓ** ਸੈਟਿੰਗਾਂ → 1proxy** ਟੈਬ
2. ਕਲਿੱਕ ਕਰੋ** "ਹੁਣ ਸਿੰਕ ਕਰੋ"**
3. ਅੰਕੜੇ ਦੇਖੋ: ਕੁੱਲ ਪ੍ਰੌਕਸੀਜ਼, ਕਿਰਿਆਸ਼ੀਲ ਗਿਣਤੀ, ਔਸਤ ਗੁਣਵੱਤਾ, ਦੇਸ਼ ਦੇ ਅਨੁਸਾਰ ਟੁੱਟਣਾ

**API ਰਾਹੀਂ:**

```bash
# Trigger sync
curl -X POST http://localhost:20128/api/settings/oneproxy \
  -H "Content-Type: application/json" \
  -d '{}'

# Response:
# { "success": true, "added": 127, "updated": 45, "failed": 2, "total": 172 }
```

### ਫਿਲਟਰਿੰਗ ਪ੍ਰੌਕਸੀਜ਼

```bash
# Filter by protocol
curl "http://localhost:20128/api/settings/oneproxy?protocol=socks5"

# Filter by country
curl "http://localhost:20128/api/settings/oneproxy?countryCode=US"

# Filter by minimum quality score
curl "http://localhost:20128/api/settings/oneproxy?minQuality=80"

# Combine filters
curl "http://localhost:20128/api/settings/oneproxy?protocol=http&countryCode=DE&minQuality=70"
```

### ਪ੍ਰੌਕਸੀ ਕੁਆਲਿਟੀ ਸਕੋਰ

ਹਰੇਕ 1 ਪ੍ਰੌਕਸੀ ਪ੍ਰੌਕਸੀ ਮੈਟਾਡੇਟਾ ਦੇ ਨਾਲ ਆਉਂਦੀ ਹੈ:

| ਖੇਤਰ            | ਵਰਣਨ                                           |
| --------------- | ---------------------------------------------- |
| `qualityScore`  | 1 ਪ੍ਰੌਕਸੀ ਪ੍ਰਮਾਣਿਕਤਾ ਤੋਂ 0-100 ਰੇਟਿੰਗ          |
| `latencyMs`     | ਮਾਪਿਆ ਨੈੱਟਵਰਕ ਲੇਟੈਂਸੀ                          |
| `anonymity`     | `transparent`, `anonymous`, ਜਾਂ `elite`        |
| `googleAccess`  | ਕੀ ਪ੍ਰੌਕਸੀ Google ਸੇਵਾਵਾਂ ਤੱਕ ਪਹੁੰਚ ਕਰ ਸਕਦੀ ਹੈ |
| `countryCode`   | ਦੋ-ਅੱਖਰਾਂ ਦਾ ISO ਦੇਸ਼ ਕੋਡ                      |
| `lastValidated` | ਆਖਰੀ ਪ੍ਰਮਾਣਿਕਤਾ ਦਾ ਟਾਈਮਸਟੈਂਪ                   |

ਕੁਆਲਿਟੀ ਸਕੋਰ ਗਤੀਸ਼ੀਲ ਤੌਰ 'ਤੇ ਐਡਜਸਟ ਕੀਤੇ ਜਾਂਦੇ ਹਨ:

- **ਅਸਫਲ ਬੇਨਤੀਆਂ** ਸਕੋਰ ਨੂੰ 10 ਅੰਕ ਘਟਾਓ
- **ਸਕੋਰ ≤ 10 ਤੱਕ ਘੱਟ ਗਿਆ** → ਪ੍ਰੌਕਸੀ ਨੂੰ `inactive` ਵਜੋਂ ਚਿੰਨ੍ਹਿਤ ਕੀਤਾ ਗਿਆ ਹੈ
- ਅਕਿਰਿਆਸ਼ੀਲ ਪ੍ਰੌਕਸੀਆਂ ਨੂੰ ਰੋਟੇਸ਼ਨ ਤੋਂ ਬਾਹਰ ਰੱਖਿਆ ਗਿਆ ਹੈ

### ਰੋਟੇਸ਼ਨ ਰਣਨੀਤੀਆਂ

```bash
# Rotate by quality (best proxy first) — default
curl -X POST http://localhost:20128/api/settings/oneproxy/rotate \
  -H "Content-Type: application/json" \
  -d '{"strategy": "quality"}'

# Random rotation
curl -X POST http://localhost:20128/api/settings/oneproxy/rotate \
  -d '{"strategy": "random"}'

# Sequential (least recently validated first)
curl -X POST http://localhost:20128/api/settings/oneproxy/rotate \
  -d '{"strategy": "sequential"}'
```

### ਸਰਕਟ ਤੋੜਨ ਵਾਲਾ

1 ਪ੍ਰੌਕਸੀ ਸਿੰਕ ਵਿੱਚ ਇੱਕ ਬਿਲਟ-ਇਨ ਸਰਕਟ ਬ੍ਰੇਕਰ ਹੈ:

- ਤੋਂ ਬਾਅਦ** 5 ਲਗਾਤਾਰ ਸਿੰਕ ਅਸਫਲਤਾਵਾਂ** , ਹੋਰ ਸਮਕਾਲੀਕਰਨ ਕੋਸ਼ਿਸ਼ਾਂ ਨੂੰ ਬਲੌਕ ਕੀਤਾ ਗਿਆ ਹੈ
- ਇਸ ਨਾਲ ਰੀਸੈਟ ਕਰੋ: `resetOneproxyCircuitBreaker()` ਜਾਂ ਸਰਵਰ ਨੂੰ ਮੁੜ ਚਾਲੂ ਕਰੋ
- ਸਿੰਕ ਸਥਿਤੀ `GET /api/settings/oneproxy?action=status`'ਤੇ ਉਪਲਬਧ ਹੈ

### 1 ਪਰਾਕਸੀ ਪ੍ਰੌਕਸੀਆਂ ਨੂੰ ਕਲੀਅਰ ਕੀਤਾ ਜਾ ਰਿਹਾ ਹੈ

```bash
# Delete a single 1proxy proxy
curl -X DELETE "http://localhost:20128/api/settings/oneproxy?id=proxy-uuid"

# Clear ALL 1proxy proxies (manual proxies are untouched)
curl -X DELETE "http://localhost:20128/api/settings/oneproxy?clearAll=1"
```

## ਐਂਟੀ-ਡਿਟੈਕਸ਼ਨ ਅਤੇ ਸਟੀਲਥ

OmniRoute ਕੇਵਲ ਇੱਕ ਪ੍ਰੌਕਸੀ — ਰਾਹੀਂ ਟ੍ਰੈਫਿਕ ਨੂੰ ਰੂਟ ਨਹੀਂ ਕਰਦਾ ਹੈ ਇਹ ਟ੍ਰੈਫਿਕ ਨੂੰ ਜਾਇਜ਼ ਬਣਾਉਂਦਾ ਹੈ:

### TLS ਫਿੰਗਰਪ੍ਰਿੰਟ ਸਪੂਫਿੰਗ

ਗੈਰ-ਬ੍ਰਾਊਜ਼ਰ TLS ਹੈਂਡਸ਼ੇਕ ਨੂੰ ਫਲੈਗ ਕਰਨ ਵਾਲੇ ਬੋਟ ਖੋਜ ਪ੍ਰਣਾਲੀਆਂ ਨੂੰ ਬਾਈਪਾਸ ਕਰਦੇ ਹੋਏ, ਬ੍ਰਾਊਜ਼ਰ-ਵਰਗੇ TLS ਫਿੰਗਰਪ੍ਰਿੰਟਸ ਬਣਾਉਣ ਲਈ `wreq-js` ਵਰਤੋਂ ਕਰਦਾ ਹੈ।

### CLI ਫਿੰਗਰਪ੍ਰਿੰਟ ਮੈਚਿੰਗ

ਦ**CLI ਫਿੰਗਰਪ੍ਰਿੰਟ ਟੌਗਲ** (`Settings → Security`) ਨੇਟਿਵ CLI ਬਾਈਨਰੀਆਂ (Claude ਕੋਡ, Codex, ਆਦਿ) ਦੇ ਸਹੀ ਦਸਤਖਤ ਨਾਲ ਮੇਲ ਕਰਨ ਲਈ HTTP ਸਿਰਲੇਖਾਂ ਅਤੇ JSON ਬਾਡੀ ਫੀਲਡਾਂ ਨੂੰ ਮੁੜ ਕ੍ਰਮਬੱਧ ਕਰਦਾ ਹੈ। ਇਹ ਕੰਮ ਕਰਦਾ ਹੈ** ਦੇ ਸਿਖਰ 'ਤੇ** ਪ੍ਰੌਕਸੀ:

```
Your IP (blocked) → Proxy IP (US) → Provider API
                    + TLS spoof
                    + CLI fingerprint
```

ਤੁਸੀਂ ਦੋਵੇਂ ਪ੍ਰਾਪਤ ਕਰੋ**IP ਮਾਸਕਿੰਗ** ਅਤੇ** ਪ੍ਰਮਾਣਿਕਤਾ ਦੀ ਬੇਨਤੀ ਕਰੋ** ਨਾਲ ਹੀ.

### ਪਰਾਕਸੀ IP ਸੁਰੱਖਿਆ

ਡੈਸ਼ਬੋਰਡ ਵਿੱਚ ਰੰਗ-ਕੋਡ ਕੀਤੇ ਬੈਜ ਦਿਖਾਉਂਦੇ ਹਨ ਕਿ ਕਿਹੜਾ ਪ੍ਰੌਕਸੀ ਪੱਧਰ ਕਿਰਿਆਸ਼ੀਲ ਹੈ:

| ਬੈਜ | ਪੱਧਰ    | ਭਾਵ                                            |
| --- | ------- | ---------------------------------------------- |
| 🟢  | ਗਲੋਬਲ   | ਸਾਰਾ ਟਰੈਫਿਕ ਇਸ ਪ੍ਰੌਕਸੀ ਰਾਹੀਂ ਜਾਂਦਾ ਹੈ          |
| 🟡  | ਪ੍ਰਦਾਤਾ | ਸਿਰਫ਼ ਇਸ ਪ੍ਰਦਾਤਾ ਦਾ ਟ੍ਰੈਫਿਕ ਪ੍ਰੌਕਸੀਡ ਹੈ        |
| 🔵  | ਕਨੈਕਸ਼ਨ | ਇਹ ਖਾਸ key/account ਇਸ ਪ੍ਰੌਕਸੀ ਦੀ ਵਰਤੋਂ ਕਰਦਾ ਹੈ |

ਬੈਜ ਤਸਦੀਕ ਲਈ ਹੱਲ ਕੀਤਾ ਗਿਆ ਪ੍ਰੌਕਸੀ IP ਵੀ ਦਿਖਾਉਂਦਾ ਹੈ।

## ਅੱਪਸਟਰੀਮ ਪ੍ਰੌਕਸੀ ਮੋਡਸ

CLIProxyAPI ਪੈਟਰਨ ਦੀ ਵਰਤੋਂ ਕਰਨ ਵਾਲੇ ਪ੍ਰਦਾਤਾਵਾਂ ਲਈ, OmniRoute ਤਿੰਨ ਅੱਪਸਟ੍ਰੀਮ ਪ੍ਰੌਕਸੀ ਮੋਡਾਂ ਦਾ ਸਮਰਥਨ ਕਰਦਾ ਹੈ:

| ਮੋਡ           | ਵਰਣਨ                                                        |
| ------------- | ----------------------------------------------------------- |
| `native`      | OmniRoute ਸਿੱਧੇ ਪ੍ਰੌਕਸੀ ਰੂਟਿੰਗ ਨੂੰ ਹੈਂਡਲ ਕਰਦਾ ਹੈ (ਡਿਫੌਲਟ)   |
| `cliproxyapi` | ਇੱਕ ਬਾਹਰੀ CLIProxyAPI ਉਦਾਹਰਨ ਲਈ ਡੈਲੀਗੇਟ                     |
| `fallback`    | ਪਹਿਲਾਂ ਮੂਲ ਦੀ ਕੋਸ਼ਿਸ਼ ਕਰਦਾ ਹੈ, CLIProxyAPI ਤੇ ਵਾਪਸ ਆਉਂਦਾ ਹੈ |

ਪ੍ਰਤੀ-ਪ੍ਰਦਾਤਾ ਨੂੰ ਕੌਂਫਿਗਰ ਕਰੋ:

```bash
curl -X PUT "http://localhost:20128/api/upstream-proxy/openai" \
  -H "Content-Type: application/json" \
  -d '{"mode": "native", "enabled": true}'
```

## ਡੈਸ਼ਬੋਰਡ UI

### ਸੈਟਿੰਗਾਂ → ਪ੍ਰੌਕਸੀ ਟੈਬ

- **ਗਲੋਬਲ ਪ੍ਰੌਕਸੀ** ਸੰਰਚਨਾ (ਸਾਰੇ ਟ੍ਰੈਫਿਕ ਲਈ ਇੱਕ ਵਾਰ ਸੈੱਟ ਕਰੋ)
- **ਪ੍ਰਤੀ-ਪ੍ਰਦਾਤਾ ਪ੍ਰੌਕਸੀ** ਓਵਰਰਾਈਡ ਕਰਦਾ ਹੈ
- **ਪ੍ਰਤੀ-ਕੁਨੈਕਸ਼ਨ ਪ੍ਰੌਕਸੀ** ਅਸਾਈਨਮੈਂਟ
- **ਕੁਨੈਕਸ਼ਨ ਟੈਸਟ** ਸੰਰਚਿਤ ਪ੍ਰੌਕਸੀ ਦੁਆਰਾ
- **ਰੰਗ-ਕੋਡ ਕੀਤੇ ਬੈਜ** ਸਰਗਰਮ ਪ੍ਰੌਕਸੀ ਪੱਧਰ ਦਿਖਾ ਰਿਹਾ ਹੈ

### ਸੈਟਿੰਗਾਂ → 1proxy ਟੈਬ

- **ਹੁਣੇ ਸਿੰਕ ਕਰੋ** ਮੁਫ਼ਤ ਪ੍ਰੌਕਸੀ ਪ੍ਰਾਪਤ ਕਰਨ ਲਈ ਬਟਨ
- **ਅੰਕੜੇ ਕਾਰਡ** : ਕੁੱਲ, ਕਿਰਿਆਸ਼ੀਲ, ਔਸਤ ਗੁਣਵੱਤਾ, ਆਖਰੀ ਸਮਕਾਲੀਕਰਨ
- **ਫਿਲਟਰ** : ਪ੍ਰੋਟੋਕੋਲ, ਦੇਸ਼ ਦਾ ਕੋਡ, ਘੱਟੋ-ਘੱਟ ਗੁਣਵੱਤਾ
- **ਪ੍ਰੌਕਸੀ ਟੇਬਲ** ਹੋਸਟ, ਪ੍ਰੋਟੋਕੋਲ, ਦੇਸ਼, ਗੁਣਵੱਤਾ ਸਕੋਰ, ਲੇਟੈਂਸੀ, ਅਗਿਆਤਤਾ, Google ਪਹੁੰਚ ਦੇ ਨਾਲ
- **ਸਮਕਾਲੀ ਸਥਿਤੀ** success/failure ਟਰੈਕਿੰਗ ਅਤੇ ਲਗਾਤਾਰ ਅਸਫਲਤਾ ਦੀ ਗਿਣਤੀ ਵਾਲਾ ਪੈਨਲ
- **ਸਭ ਸਾਫ਼ ਕਰੋ** ਸਾਰੀਆਂ 1 ਪ੍ਰੌਕਸੀ ਐਂਟਰੀਆਂ ਨੂੰ ਹਟਾਉਣ ਲਈ

### ਪ੍ਰੌਕਸੀ ਸੈਟਿੰਗਜ਼ API

| ਵਿਧੀ     | ਅੰਤ ਬਿੰਦੂ                                      | ਵਰਣਨ                            |
| -------- | ---------------------------------------------- | ------------------------------- |

## ਸਮੱਸਿਆ ਨਿਪਟਾਰਾ

### "SOCKS5 ਪ੍ਰੌਕਸੀ ਅਯੋਗ ਹੈ"

ਆਪਣੀ `.env` ਫਾਈਲ ਵਿੱਚ `ENABLE_SOCKS5_PROXY=true` ਸੈੱਟ ਕਰੋ ਅਤੇ ਰੀਸਟਾਰਟ ਕਰੋ।

### ਪ੍ਰੌਕਸੀ ਰਾਹੀਂ "ਸਾਕੇਟ ਹੈਂਗ ਅੱਪ" ਤਰੁੱਟੀਆਂ

ਇਹ ਸਸਤੇ ਪ੍ਰੌਕਸੀਆਂ ਨਾਲ ਆਮ ਹੈ ਜੋ ਵਿਹਲੇ ਕਨੈਕਸ਼ਨਾਂ ਨੂੰ ਛੱਡ ਦਿੰਦੇ ਹਨ। OmniRoute ਪਹਿਲਾਂ ਹੀ ਇਸ ਦੁਆਰਾ ਹੈਂਡਲ ਕਰਦਾ ਹੈ:

- ਪ੍ਰੌਕਸੀ ਕਨੈਕਸ਼ਨਾਂ (`keepAliveTimeout: 1`) 'ਤੇ ਕੀਪ-ਲਾਈਵ ਨੂੰ ਅਯੋਗ ਕਰਨਾ
- ਪਾਈਪਲਾਈਨਿੰਗ ਨੂੰ ਅਯੋਗ ਕਰਨਾ (`pipelining: 0`)
- ਵਾਰ-ਵਾਰ ਹੱਥ ਮਿਲਾਉਣ ਤੋਂ ਬਚਣ ਲਈ ਡਿਸਪੈਚਰ ਨੂੰ ਕੈਚ ਕਰਨਾ

ਜੇਕਰ ਇਹ ਜਾਰੀ ਰਹਿੰਦਾ ਹੈ, ਤਾਂ ਇੱਕ ਵੱਖਰੀ ਪ੍ਰੌਕਸੀ ਅਜ਼ਮਾਓ ਜਾਂ 1ਪ੍ਰੌਕਸੀ ਰੋਟੇਸ਼ਨ ਵਿਸ਼ੇਸ਼ਤਾ ਦੀ ਵਰਤੋਂ ਕਰੋ।

### OAuth ਦੌਰਾਨ "unsupported_country_region_territory"

ਯਕੀਨੀ ਬਣਾਓ ਕਿ ਪ੍ਰੌਕਸੀ ਕੌਂਫਿਗਰ ਕੀਤੀ ਗਈ ਹੈ** ਅੱਗੇ** OAuth ਪ੍ਰਵਾਹ ਸ਼ੁਰੂ ਕਰਨਾ। OmniRoute ਸੰਰਚਿਤ ਪ੍ਰੌਕਸੀ ਰਾਹੀਂ OAuth ਟੋਕਨ ਐਕਸਚੇਂਜ ਨੂੰ ਰੂਟ ਕਰਦਾ ਹੈ। ਪਹਿਲਾਂ ਇੱਕ ਗਲੋਬਲ ਜਾਂ ਪ੍ਰਦਾਤਾ-ਪੱਧਰ ਦੀ ਪ੍ਰੌਕਸੀ ਸੈਟ ਕਰੋ, ਫਿਰ ਕਨੈਕਟ ਕਰੋ।

### ਪ੍ਰੌਕਸੀ ਦੀ ਵਰਤੋਂ ਨਹੀਂ ਕੀਤੀ ਜਾ ਰਹੀ ਹੈ

ਰੈਜ਼ੋਲਿਊਸ਼ਨ ਆਰਡਰ ਦੀ ਜਾਂਚ ਕਰੋ:

1. `GET /api/settings/proxy?resolve=your-connection-id` ਨਾਲ ਪੁਸ਼ਟੀ ਕਰੋ
2. ਜਾਂਚ ਕਰੋ ਕਿ ਕੀ ਪ੍ਰੌਕਸੀ `status` `active` ਹੈ ( `inactive` ਨਹੀਂ)
3. ਯਕੀਨੀ ਬਣਾਓ ਕਿ ਪ੍ਰੌਕਸੀ ਅਸਾਈਨਮੈਂਟ ਸਕੋਪ ਤੁਹਾਡੇ ਕਨੈਕਸ਼ਨ ਨਾਲ ਮੇਲ ਖਾਂਦਾ ਹੈ

### 1ਪ੍ਰੌਕਸੀ ਸਿੰਕ ਅਸਫਲ ਹੋ ਰਿਹਾ ਹੈ

ਸਿੰਕ ਸਥਿਤੀ ਦੀ ਜਾਂਚ ਕਰੋ:

```bash
curl "http://localhost:20128/api/settings/oneproxy?action=status"
```

ਜੇਕਰ `consecutiveFailures >= 5`, ਤਾਂ ਸਰਕਟ ਬ੍ਰੇਕਰ ਟ੍ਰਿਪ ਹੋ ਗਿਆ ਹੈ। ਰੀਸੈਟ ਕਰਨ ਲਈ ਸਰਵਰ ਨੂੰ ਰੀਸਟਾਰਟ ਕਰੋ, ਜਾਂ ਮੈਨੂਅਲ ਰੀਸੈਟ ਦੀ ਉਡੀਕ ਕਰੋ।

```sql
CREATE TABLE proxy_registry (

  password TEXT DEFAULT '',
  region TEXT,

  google_access INTEGER DEFAULT 0,           -- can access Google? (1proxy)

);
```

## ਪ੍ਰੌਕਸੀ ਸਿਹਤ ਜਾਂਚ (v3.8.16 +)

OmniRoute's** ਪ੍ਰੌਕਸੀ ਫਾਸਟ-ਫੇਲ** ਮਕੈਨਿਜ਼ਮ (`src/lib/proxyHealth.ts`) ਇੱਕ ਤੇਜ਼ TCP ਕੁਨੈਕਸ਼ਨ ਜਾਂਚ ਦੁਆਰਾ < 2s ਵਿੱਚ ਮਰੇ ਹੋਏ ਪ੍ਰੌਕਸੀਆਂ ਦਾ ਪਤਾ ਲਗਾਉਂਦਾ ਹੈ, ਫਿਰ** ਨਤੀਜਾ ਕੈਸ਼ ਕਰਦਾ ਹੈ** ਪ੍ਰਤੀ ਬੇਨਤੀ ਓਵਰਹੈੱਡ ਤੋਂ ਬਚਣ ਲਈ।

### ਇਹ ਕਿਵੇਂ ਕੰਮ ਕਰਦਾ ਹੈ

```
Request ──▶ ProxyHealthCache.get(url)
             │
             ├─ Cache hit + fresh?  ──▶ return cached status
             │
             └─ Cache miss / stale?  ──▶ TCP connect to host:port
                                          (timeout: FAST_FAIL_TIMEOUT_MS)
                                          ──▶ cache for HEALTH_CACHE_TTL_MS
                                          ──▶ return result
```

ਇਸ ਤੋਂ ਬਿਨਾਂ, ਇੱਕ ਡੈੱਡ ਪ੍ਰੌਕਸੀ ਅਸਫਲ ਹੋਣ ਤੋਂ ਪਹਿਲਾਂ ਪੂਰੇ `PROXY_TIMEOUT_MS` (ਡਿਫਾਲਟ 30s) ਲਈ ਹਰ ਬੇਨਤੀ ਨੂੰ ਬਲੌਕ ਕਰ ਦੇਵੇਗੀ।

### ਟਿਊਨੇਬਲ ਵਾਤਾਵਰਨ ਵੇਰੀਏਬਲ

| ਵੇਰੀਏਬਲ                      | ਡਿਫਾਲਟ  | ਮਕਸਦ                                           |
| ---------------------------- | ------- | ---------------------------------------------- |
| `PROXY_FAST_FAIL_TIMEOUT_MS` | `2000`  | ਪ੍ਰਤੀ ਸਿਹਤ ਜਾਂਚ ਲਈ TCP ਕੁਨੈਕਸ਼ਨ ਦਾ ਸਮਾਂ ਸਮਾਪਤ  |
| `PROXY_HEALTH_CACHE_TTL_MS`  | `30000` | ਸਿਹਤ ਦਾ ਨਤੀਜਾ ਕਿੰਨੀ ਦੇਰ ਤੱਕ ਕੈਸ਼ ਕੀਤਾ ਜਾਂਦਾ ਹੈ |

**ਸਿਫਾਰਸ਼ੀ ਮੁੱਲ:**

| ਦ੍ਰਿਸ਼                | ਤੇਜ਼-ਅਸਫ਼ਲ ਸਮਾਂ ਸਮਾਪਤ | ਕੈਸ਼ TTL | ਤਰਕ                                                           |
| --------------------- | --------------------- | -------- | ------------------------------------------------------------- |
| ਉੱਚ-ਥਰੂਪੁੱਟ API ਗੇਟਵੇ | 1500 ਮਿ               | 60000ms  | ਚੈਕਾਂ ਨੂੰ ਘਟਾਉਣ ਲਈ ਹਮਲਾਵਰ ਅਸਫਲ-ਤੇਜ਼, ਲੰਬਾ ਕੈਸ਼                |
| ਜੀਓ-ਵਿਤਰਿਤ ਨੋਡਸ       | 3000 ਮਿ               | 15000 ਮਿ | ਹੌਲੀ ਨੈੱਟਵਰਕ ਨੂੰ ਹੋਰ ਸਮਾਂ ਚਾਹੀਦਾ ਹੈ; ਤੇਜ਼ ਫੇਲਓਵਰ ਲਈ ਛੋਟਾ ਕੈਸ਼ |
| ਦੇਵ / ਟੈਸਟਿੰਗ         | 1000 ਮਿ               | 10000ms  | ਸਥਾਨਕ ਪ੍ਰੌਕਸੀ 'ਤੇ ਤੇਜ਼ ਦੁਹਰਾਓ                                 |
| ਸਟੀਲਥ / ਵਿਰੋਧੀ ਖੋਜ    | 2500 ਮਿ               | 45000 ਮਿ | ਤੇਜ਼ ਪੜਤਾਲ ਤੋਂ ਬਚੋ ਜੋ ਦਰ ਸੀਮਾਵਾਂ ਨੂੰ ਟਰਿੱਗਰ ਕਰ ਸਕਦੀ ਹੈ        |

### ਪ੍ਰੌਕਸੀ ਸਿਹਤ ਦਾ ਨਿਰੀਖਣ ਕਰਨਾ

```ts
import { getAllProxyHealthStatuses, invalidateProxyHealth } from "omniroute/proxyHealth";

const statuses = getAllProxyHealthStatuses();
for (const s of statuses) {
  console.log(`${s.proxyUrl} → healthy=${s.healthy}, stale=${s.stale}`);
}

// Force re-check a specific proxy
invalidateProxyHealth("http://user:pass@203.0.113.7:8080");
```

`stale` ਫਲੈਗ `true` ਹੁੰਦਾ ਹੈ ਜਦੋਂ ਕੈਸ਼ ਐਂਟਰੀ `HEALTH_CACHE_TTL_MS` ਤੋਂ ਵੱਧ ਜਾਂਦੀ ਹੈ ਅਤੇ ਅਗਲੀ ਬੇਨਤੀ ਇੱਕ ਨਵੀਂ ਜਾਂਚ ਨੂੰ ਚਾਲੂ ਕਰੇਗੀ।

### ਪ੍ਰਤੀ-ਪ੍ਰਾਕਸੀ ਕਿਸਮ ਪੂਰਵ-ਨਿਰਧਾਰਤ

ਸਿਹਤ ਜਾਂਚ URL ਸਕੀਮ ਦੇ ਆਧਾਰ 'ਤੇ ਸਮਝਦਾਰ ਡਿਫਾਲਟਸ ਦੀ ਵਰਤੋਂ ਕਰਦੀ ਹੈ:

| ਸਕੀਮ                       | ਪੂਰਵ-ਨਿਰਧਾਰਤ ਪੋਰਟ |
| -------------------------- | ----------------- |
| `http://`                  | 8080              |
| `https://`                 | 443               |
| `socks5://` / `socks5h://` | 1080              |

URL (`http://host:9999`) ਵਿੱਚ ਕਸਟਮ ਪੋਰਟਾਂ ਨੂੰ ਹਮੇਸ਼ਾਂ ਸਕੀਮ ਡਿਫੌਲਟ ਉੱਤੇ ਤਰਜੀਹ ਦਿੱਤੀ ਜਾਂਦੀ ਹੈ।

## ਪ੍ਰੌਕਸੀ ਵਿਸ਼ਲੇਸ਼ਣ ਅਤੇ ਨਿਰੀਖਣਯੋਗਤਾ

OmniRoute ਰੂਟਿੰਗ ਪੈਟਰਨਾਂ, ਲੇਟੈਂਸੀ ਸਪਾਈਕਸ, ਅਤੇ ਆਵਰਤੀ ਅਸਫਲਤਾਵਾਂ ਦਾ ਨਿਦਾਨ ਕਰਨ ਵਿੱਚ ਓਪਰੇਟਰਾਂ ਦੀ ਮਦਦ ਕਰਨ ਲਈ ਪ੍ਰਤੀ-ਪ੍ਰੌਕਸੀ ਵਰਤੋਂ ਨੂੰ ਟਰੈਕ ਕਰਦਾ ਹੈ।

### ਕੀ ਟਰੈਕ ਕੀਤਾ ਗਿਆ ਹੈ

ਇੱਕ ਕੌਂਫਿਗਰ ਕੀਤੀ ਪ੍ਰੌਕਸੀ ਦੁਆਰਾ ਹਰੇਕ ਬੇਨਤੀ ਲਈ, OmniRoute ਰਿਕਾਰਡ ਕਰਦਾ ਹੈ:

| ਮੈਟ੍ਰਿਕ      | ਵਰਣਨ                                                            |
| ------------ | --------------------------------------------------------------- |
| `proxy_url`  | ਪੂਰਾ ਪ੍ਰੌਕਸੀ URL (ਪ੍ਰਮਾਣਿਕ ਪ੍ਰਮਾਣ ਪੱਤਰਾਂ ਨੂੰ ਨਕਾਬਬੰਦ ਕੀਤਾ ਹੋਇਆ) |
| `provider`   | ਅੱਪਸਟ੍ਰੀਮ ਪ੍ਰਦਾਤਾ ID (ਓਪਨਾਈ, ਮਾਨਵ, ਆਦਿ)                         |
| `latency_ms` | ਪ੍ਰੌਕਸੀ ਹੈਂਡਸ਼ੇਕ ਸਮੇਤ ਕੁੱਲ ਰਾਊਂਡ-ਟਰਿੱਪ ਸਮਾਂ                     |
| `connect_ms` | TCP ਸਿਰਫ ਕੁਨੈਕਟ ਸਮਾਂ                                            |
| `status`     | ਅੱਪਸਟ੍ਰੀਮ ਤੋਂHTTP ਸਥਿਤੀ ਕੋਡ                                     |
| `error`      | ਜੇਕਰ ਬੇਨਤੀ ਅਸਫਲ ਰਹੀ ਤਾਂ ਗਲਤੀ ਸ਼੍ਰੇਣੀ                            |
| `timestamp`  | ISO 8601 UTC                                                    |

### ਡਾਟਾ ਤੱਕ ਪਹੁੰਚ

```bash
# Recent proxy events
curl -H "Authorization: Bearer $OMNIROUTE_KEY" \
  "http://localhost:20128/api/usage/proxy-logs?limit=100"
```

ਅਸਲ ਅੰਤ ਬਿੰਦੂ `/api/usage/proxy-logs` ਹੈ ( `src/app/api/usage/proxy-logs/route.ts` ਵੇਖੋ )। ਇਹ ਅੰਤਮ ਬਿੰਦੂ ਦਾ ਸਮਰਥਨ ਕਰਦਾ ਹੈ:

- `GET /api/usage/proxy-logs` — ਪ੍ਰੌਕਸੀ ਲੌਗ ਪ੍ਰਾਪਤ ਕਰੋ
- `DELETE /api/usage/proxy-logs` — ਸਾਰੇ ਪ੍ਰੌਕਸੀ ਲੌਗਾਂ ਨੂੰ ਸਾਫ਼ ਕਰੋ

ਜੇ ਲੋੜ ਹੋਵੇ ਤਾਂ SQL ਰਾਹੀਂ ਸਿੱਧੇ `proxy_logs` ਟੇਬਲ ਤੋਂ ਸਮੁੱਚੇ ਅੰਕੜਿਆਂ ਦੀ ਪੁੱਛਗਿੱਛ ਕੀਤੀ ਜਾ ਸਕਦੀ ਹੈ। ਡੈਸ਼ਬੋਰਡ UI ਸਮੁੱਚੇ ਦ੍ਰਿਸ਼ ਪੇਸ਼ ਕਰ ਸਕਦਾ ਹੈ।

### ਆਮ ਪੈਟਰਨ

**ਫਲੈਪਿੰਗ ਪ੍ਰੌਕਸੀ ਦਾ ਪਤਾ ਲਗਾਓ** ( success/failure ਵਿਚਕਾਰ ਬਦਲ):

```sql
SELECT proxy_url,
       COUNT(*) AS total,
       SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) AS errors,
       ROUND(100.0 * SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) / COUNT(*), 1) AS error_pct
FROM proxy_logs
WHERE timestamp > datetime('now', '-1 hour')
GROUP BY proxy_url
HAVING error_pct > 5
ORDER BY error_pct DESC;
```

**ਹੌਲੀ ਪ੍ਰੌਕਸੀ ਲੱਭੋ** (p95 ਲੇਟੈਂਸੀ > 2s):

```sql
WITH ranked AS (
  SELECT proxy_url, latency_ms,
         PERCENT_RANK() OVER (PARTITION BY proxy_url ORDER BY latency_ms) AS pct
  FROM proxy_logs
  WHERE timestamp > datetime('now', '-24 hour')
)
SELECT proxy_url, latency_ms
FROM ranked
WHERE pct >= 0.95
ORDER BY latency_ms DESC;
```

## ਰੋਟੇਸ਼ਨ ਰਣਨੀਤੀ ਫੈਸਲੇ ਦਾ ਰੁੱਖ

ਜਦੋਂ ਇੱਕ ਸਕੋਪ ਲਈ ਮਲਟੀਪਲ ਪ੍ਰੌਕਸੀਆਂ ਨਿਰਧਾਰਤ ਕੀਤੀਆਂ ਜਾਂਦੀਆਂ ਹਨ, OmniRoute ਵਰਤਦਾ ਹੈ a** ਰੋਟੇਸ਼ਨ ਰਣਨੀਤੀ** ਇਹ ਚੁਣਨ ਲਈ ਕਿ ਹਰੇਕ ਬੇਨਤੀ ਲਈ ਕਿਹੜਾ ਵਰਤਣਾ ਹੈ। ਰਣਨੀਤੀ ਨੂੰ ਸਕੋਪ ਪੱਧਰ 'ਤੇ ਕੌਂਫਿਗਰ ਕੀਤਾ ਗਿਆ ਹੈ (ਗਲੋਬਲ, ਪ੍ਰਤੀ-ਪ੍ਰਦਾਤਾ, ਪ੍ਰਤੀ-ਖਾਤਾ, ਪ੍ਰਤੀ-ਕੰਬੋ)।

### ਉਪਲਬਧ ਰਣਨੀਤੀਆਂ

| ਰਣਨੀਤੀ          | ਕਦੋਂ ਵਰਤਣਾ ਹੈ                       | ਵਪਾਰ ਬੰਦ                                                                  |
| --------------- | ----------------------------------- | ------------------------------------------------------------------------- |
| `quality` (ਮੂਲ) | ਮਿਸ਼ਰਤ-ਗੁਣਵੱਤਾ ਪ੍ਰੌਕਸੀਜ਼ ਨਾਲ ਉਤਪਾਦਨ | ਉੱਚ ਦਰਜਾ ਪ੍ਰਾਪਤ ਪ੍ਰੌਕਸੀਜ਼ ਦਾ ਪੱਖ ਪੂਰਦਾ ਹੈ; ਘੱਟ ਦਰਜਾ ਵਾਲੇ ਭੁੱਖੇ ਮਰ ਸਕਦੇ ਹਨ |
| `random`        | ਲੋਡ ਵੰਡ, ਗੋਪਨੀਯਤਾ                   | ਵੀ ਵੰਡ; ਗੁਣਵੱਤਾ ਸਿਗਨਲਾਂ ਨੂੰ ਨਜ਼ਰਅੰਦਾਜ਼ ਕਰਦਾ ਹੈ                            |
| `sequential`    | ਡੀਬੱਗਿੰਗ, ਨਿਰਣਾਇਕ ਜਾਂਚ              | ਕ੍ਰਮ ਵਿੱਚ ਪ੍ਰੌਕਸੀ ਦੁਆਰਾ ਚੱਕਰ; ਬਾਰੇ ਤਰਕ ਕਰਨਾ ਆਸਾਨ                          |

### ਫੈਸਲੇ ਦਾ ਰੁੱਖ

## ਤੁਹਾਡੀਆਂ ਖੁਦ ਦੀਆਂ ਪ੍ਰੌਕਸੀਜ਼ ਲਈ ਆਟੋਮੈਟਿਕ ਅਸਫਲਤਾ ਬੇਦਖਲੀ

1ਪ੍ਰੌਕਸੀ ਮਾਰਕਿਟਪਲੇਸ ਪੂਲ ਪਹਿਲਾਂ ਤੋਂ ਹੀ ਅਸਫਲ ਪ੍ਰੌਕਸੀਜ਼ ਨੂੰ ਆਪਣੇ ਆਪ ਡਿਗਰੇਡ ਕਰਦਾ ਹੈ ( [ਪ੍ਰਾਕਸੀ ਕੁਆਲਿਟੀ ਸਕੋਰ](#proxy-quality-scores) ਦੇਖੋ)। ਪ੍ਰੌਕਸੀਜ਼ ਲਈ** ਤੁਸੀਂ** ਰਜਿਸਟਰੀ ਵਿੱਚ ਜੋੜਿਆ ਗਿਆ, ਬੈਕਗ੍ਰਾਉਂਡ ਹੈਲਥ ਸ਼ਡਿਊਲਰ (`src/lib/proxyHealth/scheduler.ts`) ਉਹੀ "ਇੱਕ ਮਰੇ ਹੋਏ ਮੈਂਬਰ ਨੂੰ ਚੇਨ ਵਿੱਚੋਂ ਆਪਣੇ ਆਪ ਬਾਹਰ ਕੱਢੋ" ਵਿਵਹਾਰ ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈ, ਬਿਨਾਂ ਕੁਝ ਮਿਟਾਏ:

```bash
# .env — soft-disable a proxy after 3 consecutive failed probes, re-enable it
# automatically once it starts answering probes again.
PROXY_AUTO_DISABLE=true
PROXY_AUTO_REMOVE_AFTER=3
```

ਇਹ ਇੱਕ ਮਲਟੀ-ਪ੍ਰੌਕਸੀ ਚੇਨ ਵਿੱਚ ਕਿਵੇਂ ਫਿੱਟ ਹੁੰਦਾ ਹੈ:

1. ਸ਼ਡਿਊਲਰ ਹਰ ਰਜਿਸਟਰਡ ਪ੍ਰੌਕਸੀ ਹਰ `PROXY_HEALTH_INTERVAL_MS` (ਡਿਫਾਲਟ 10 ਮਿੰਟ; ਘੱਟੋ-ਘੱਟ 1 ਮਿੰਟ) ਦੀ ਜਾਂਚ ਕਰਦਾ ਹੈ।
2. `PROXY_AUTO_REMOVE_AFTER` ਲਗਾਤਾਰ ਬਾਅਦ** ਨਿਰਣਾਇਕ** ਅਸਫਲਤਾਵਾਂ (ਇੱਕ ਅਸਲੀ ਕੁਨੈਕਸ਼ਨ ਅਸਫਲਤਾ — ਇੱਕ ਸਮਾਂ ਸਮਾਪਤ ਜਾਂ ਪੜਤਾਲ ਦਾ ਆਪਣਾ 5xx ਕਦੇ ਨਹੀਂ ਗਿਣਦਾ ਹੈ, [ਪ੍ਰੌਕਸੀ ਹੈਲਥ ਚੈਕਿੰਗ](#proxy-health-checking-v3816) ਵੇਖੋ), ਪ੍ਰੌਕਸੀ ਦਾ `status` `dead`'ਤੇ ਸੈੱਟ ਹੈ।
3. `dead` ਉਹਨਾਂ ਸਥਿਤੀਆਂ ਵਿੱਚੋਂ ਇੱਕ ਹੈ ਜੋ pool/rotation ਰੈਜ਼ੋਲਿਊਸ਼ਨ ਦੁਆਰਾ ਵਰਤੇ ਗਏ ਲਾਈਵ-ਸਟੇਟਸ ਫਿਲਟਰ ਨੂੰ ਬਾਹਰ ਕੱਢਦੇ ਹਨ, ਇਸਲਈ ਇੱਕ ਸਕੋਪ ਦਾ ਰੋਟੇਸ਼ਨ (ਰਾਊਂਡ-ਰੋਬਿਨ / ਬੇਤਰਤੀਬ / ਸਟਿੱਕੀ / ਲੇਟੈਂਸੀ — [ਰੋਟੇਸ਼ਨ ਰਣਨੀਤੀ ਫੈਸਲਾ ਟ੍ਰੀ](#rotation-strategy-decision-tree) ਵੇਖੋ) ਤੁਰੰਤ ਉਸ ਪ੍ਰੌਕਸੀ ਨੂੰ ਨਵੀਆਂ ਬੇਨਤੀਆਂ ਨੂੰ ਸੌਂਪਣਾ ਬੰਦ ਕਰ ਦਿੰਦਾ ਹੈ। ਪੂਲ ਵਿੱਚ ਕੋਈ ਹੋਰ ਪ੍ਰੌਕਸੀ ਪ੍ਰਭਾਵਿਤ ਨਹੀਂ ਹੁੰਦੀ ਹੈ, ਅਤੇ ਪੂਰਾ ਪੂਲ ਕਦੇ ਵੀ ਚੁੱਪਚਾਪ ਸਿੱਧੇ ਕੁਨੈਕਸ਼ਨ 'ਤੇ ਵਾਪਸ ਨਹੀਂ ਆਉਂਦਾ — [4-ਲੇਵਲ ਪ੍ਰੌਕਸੀ ਸਿਸਟਮ](#4-level-proxy-system) ਫੇਲ-ਬੰਦ ਗਾਰਡ ਦੇਖੋ।
4. ਸ਼ਡਿਊਲਰ ਉਸੇ ਅੰਤਰਾਲ 'ਤੇ `dead` ਪ੍ਰੌਕਸੀਆਂ ਦੀ ਜਾਂਚ ਕਰਦਾ ਰਹਿੰਦਾ ਹੈ। ਅਗਲੀ ਸਫਲ ਪੜਤਾਲ `status` `active` ਤੇ ਵਾਪਸ ਭੇਜਦੀ ਹੈ ਅਤੇ ਇਹ ਰੋਟੇਸ਼ਨ — ਨੂੰ ਮੁੜ-ਪ੍ਰਵੇਸ਼ ਕਰਦੀ ਹੈ, ਕੋਈ ਦਸਤੀ ਰੀ-ਐਡ ਦੀ ਲੋੜ ਨਹੀਂ ਹੈ।

ਇਹ ਜਾਣਬੁੱਝ ਕੇ ਹੈ** ਔਪਟ-ਇਨ ਅਤੇ ਗੈਰ-ਵਿਨਾਸ਼ਕਾਰੀ** : ਡਿਫੌਲਟ ਰੂਪ ਵਿੱਚ ਸ਼ਡਿਊਲਰ ਸਿਰਫ ਅਸਫਲਤਾਵਾਂ ਨੂੰ ਗਿਣਦਾ ਹੈ ਅਤੇ ਲੌਗਸ ਕਰਦਾ ਹੈ (ਵੇਖੋ ਨੀਤੀ C `decision.ts` ਵਿੱਚ), ਅਤੇ `PROXY_AUTO_DISABLE` ਕਦੇ ਵੀ ਇੱਕ ਕਤਾਰ — ਨਹੀਂ ਮਿਟਾਉਂਦਾ ਹੈ ਜਿਸ ਲਈ ਵੱਖਰਾ, ਵਧੇਰੇ ਹਮਲਾਵਰ `PROXY_AUTO_REMOVE` ਫਲੈਗ ਹੈ। ਜੇਕਰ ਦੋਵੇਂ `true`'ਤੇ ਸੈੱਟ ਕੀਤੇ ਗਏ ਹਨ, `PROXY_AUTO_REMOVE` ਜਿੱਤਦਾ ਹੈ (ਮਿਟਾਏ ਜਾਣ ਵਾਲੇ ਪ੍ਰੌਕਸੀ ਦਾ ਵਿਚਕਾਰ ਵਿੱਚ ਸਾਫਟ-ਅਯੋਗ ਕਰਨ ਦਾ ਕੋਈ ਉਪਯੋਗ ਨਹੀਂ ਹੁੰਦਾ)। ਪੂਰੀ ਵੇਰੀਏਬਲ ਸੂਚੀ ਲਈ [ਵਾਤਾਵਰਣ ਸੰਰਚਨਾ](../reference/ENVIRONMENT.md) ਸੰਦਰਭ ਵੇਖੋ।
