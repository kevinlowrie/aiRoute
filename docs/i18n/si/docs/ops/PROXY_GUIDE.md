> **භූගෝලීය අවහිර කිරීම් මඟහරින්න, ඔබේ අනන්‍යතාවය ආරක්ෂා කරන්න, සහ ශුන්‍ය වින්‍යාස සංකීර්ණතාවයකින් ඕනෑම ප්‍රොක්සි — හරහා AI ගමනාගමනය කරන්න.**

OmniRoute සම්පූර්ණ විශේෂාංග සහිත ප්‍රොක්සි කළමනාකරණ පද්ධතියක් ඇතුළත් වන අතර එමඟින් ඔබට HTTP, HTTPS, හෝ SOCKS5 ප්‍රොක්සි හරහා උඩුගං AI සපයන්නන්ගේ ගමනාගමනය මාර්ගගත කිරීමට ඉඩ සලසයි. ඔබ අවහිර කළ කලාපයක සිටියත්, IP භ්‍රමණය අවශ්‍ය වුවත්, හෝ රහසිගත ඇඟිලි සලකුණු — අවශ්‍ය වුවත්, මෙම මාර්ගෝපදේශය සියල්ල ආවරණය කරයි.

## නව ගිණුම් සඳහා පෙරනිමි ප්‍රොක්සි තත්ත්වය

තුළ** සැකසුම් → Proxy → ගෝලීය වින්‍යාසය** , භාවිතා කරන්න** නව සම්බන්ධතා සඳහා පෙරනිමියෙන් ප්‍රොක්සි සබල කරන්න** අලුතින් එකතු කරන ලද සැපයුම්කරුවන්ගේ ගිණුම්වල ආරම්භක ප්‍රොක්සි තත්ත්වය තෝරා ගැනීමට.

නව සැකසුම අලුතින් එකතු කරන ලද සැපයුම්කරුවන්ගේ ගිණුම්වල ආරම්භක ප්‍රොක්සි තත්ත්වය පාලනය කරයි. එය පවතින ගිණුම් වෙනස් නොකරයි හෝ ගෝලීය ප්‍රොක්සි ස්විචය ප්‍රතිස්ථාපනය නොකරයි. එහි ආරම්භක අගය පෙර හැසිරීම ආරක්ෂා කරයි. පෙරනිමියෙන් ප්‍රොක්සි අක්‍රිය කර ඇති අනාගත ගිණුම් සෑදීමට එය එක් වරක් අක්‍රිය කරන්න.

පවතින සිටුවම් API හරහා මනාපය `defaultNewConnectionProxyEnabled` ලෙස ගබඩා කෙරේ. එය කිසිදා සුරැකෙන්නේ නැති විට `true` වෙත පෙරනිමි වේ. `false` සුරැකීම නැවත ආරම්භ කිරීමකින් තොරව පසුකාලීන නව ගිණුම් සඳහා බලාත්මක වේ. `POST /api/providers` විකල්ප දැඩි boolean `proxyEnabled` පිළිගනී; නිර්මාණයේ පෙරනිමියට වඩා පැහැදිලි `true` හෝ `false` ප්‍රමුඛත්වය ගනී. අනුපිටපත් ගිණුමක අතපසු වීම හෝ OAuth නැවත සම්බන්ධ කිරීම එම ගිණුමේ ගබඩා තත්ත්වය ආරක්ෂා කරයි. තනි තනි ගිණුම් තවමත් සක්‍රිය හෝ අක්‍රිය කළ හැක.

තෝරාගත් සැපයුම්කරු මාරු කිරීම් නව ගිණුම් සඳහා ගමනාන්ත ස්ථාපනයේ පෙරනිමිය භාවිතා කරන අතර පවතින ගිණුම් ප්‍රතිස්ථාපනය කිරීමේදී ගමනාන්ත ප්‍රතිපත්තිය ආරක්ෂා කරයි. ප්‍රොක්සි ටොගල් යනු අතේ ගෙන යා හැකි ස්ථාන මාරු ක්ෂේත්‍ර නොවේ. සම්පූර්ණ උපස්ථ ප්‍රතිසාධනය සහ ඓතිහාසික JSON/SQL සංක්‍රමණය සුරකින ලද ගිණුම් අගයන් සහ ලෙගසි ක්‍රම පෙරනිමි ඇතුළුව, ඒවායේ පවතින ප්‍රතිස්ථාපන අර්ථකථන රඳවා තබා ගනී; සම්පූර්ණ සැකසුම් ප්‍රතිසාධනය මඟින් මෙම මනාපය ප්‍රතිසාධනය කළ හැක.

මෙම මනාපය ප්‍රොක්සියක් පවරන්නේ නැත හෝ එකක් සෞඛ්‍ය සම්පන්න හෝ භාවිතයේ පවතින බව තහවුරු නොකරයි. සැබෑ මාර්ගගත කිරීම තවමත් ගෝලීය ප්‍රොක්සි ස්විචය සහ අදාළ ප්‍රොක්සි වින්‍යාසය මත රඳා පවතී. දිගටම පවතින ගිණුමක් නොමැති සින්තටික් සපයන්නන්, ගිණුම් නිර්මාණයට පෙර OAuth ගමනාගමනය, environment/system ප්‍රොක්සි සහ බාහිර පසුබිම් ජාලකරණය එහි විෂය පථයෙන් බැහැර වේ.

## 4-මට්ටමේ ප්‍රොක්සි පද්ධතිය

OmniRoute හි ප්‍රොක්සි වින්‍යාසය සඳහා සහය දක්වයි** ස්වාධීන විෂය පථ හතරක්** , ප්‍රමුඛතා අනුපිළිවෙලින් විසඳා ඇත:

```
Priority Resolution Order (highest → lowest):

  1. 🔵 Account/Connection Proxy  →  per API key / OAuth connection
  2. 🟡 Provider Proxy            →  per provider (e.g., all OpenAI traffic)
  3. 🟠 Combo Proxy               →  per combo/routing configuration
  4. 🟢 Global Proxy              →  all traffic, all providers
```

### විභේදනය ක්‍රියා කරන ආකාරය

OmniRoute ඉහළ ප්‍රවාහ සපයන්නෙකුට ඉල්ලීමක් යවන විට, එය `resolveProxyForConnectionFromRegistry()` අමතයි එය එක් එක් මට්ටම් අනුපිළිවෙලින් පරීක්ෂා කරයි:

1. **ගිණුම් මට්ටම** — මෙම විශේෂිත සම්බන්ධතාවයට ID පවරා ඇති ප්‍රොක්සියක් තිබේද?
2. **සැපයුම්කරු මට්ටම** — මෙම සැපයුම්කරුට (උදා, `openai`) පවරා ඇති ප්‍රොක්සියක් තිබේද?
3. **ගෝලීය මට්ටමේ** — ගෝලීය ප්‍රොක්සියක් වින්‍යාස කර තිබේද?
4. **ප්‍රොක්සි නැත** — සැපයුම්කරු වෙත සෘජු සම්බන්ධතාවය.

පළමු තරගය ජය ගනී. මෙයින් අදහස් කරන්නේ ඔබට ගෝලීය ප්‍රොක්සියක් පසුබැසීමක් ලෙස සැකසිය හැකි නමුත් විශේෂිත සපයන්නන් හෝ සම්බන්ධතා සඳහා එය ප්‍රතික්ෂේප කළ හැකි බවයි.

## ප්‍රොක්සි රෙජිස්ට්‍රිය (CRUD)

ප්‍රොක්සි රෙජිස්ට්‍රිය යනු ඔබගේ සියලුම ප්‍රොක්සි ගබඩා කරන SQLite වගුවකි (`proxy_registry`). සෑම ප්‍රොක්සියක්ම ඇත:

| ක්ෂේත්රය   | ටයිප් කරන්න   | විස්තරය                                         |
| ---------- | ------------- | ----------------------------------------------- |
| `id`       | UUID          | අද්විතීය හඳුනාගැනීමක්                           |
| `name`     | නූල්          | මිනිසුන්ට කියවිය හැකි ලේබලය                     |
| `type`     | නූල්          | ප්රොටෝකෝලය: `http`, `https`, `socks5`           |
| `host`     | නූල්          | ප්‍රොක්සි සත්කාරක නාමය හෝ IP                    |
| `port`     | පූර්ණ සංඛ්යාව | වරාය අංකය                                       |

### Import/Export

ප්‍රොක්සි ඇතුළත් වේ**Backup/Restore** පද්ධතිය. ඔබ ඔබේ OmniRoute වින්‍යාසය අපනයනය කරන විට:

1. වෙත යන්න** උපකරණ පුවරුව → සැකසීම් → උපස්ථය**
2. ක්ලික් කරන්න** අපනයනය කරන්න** — ප්‍රොක්සි රෙජිස්ට්‍රිය සහ පැවරුම් ඇතුළත් වේ
3. ප්‍රතිසාධනය කිරීමට, ක්ලික් කරන්න** ආනයනය කරන්න** සහ උපස්ථ ගොනුව උඩුගත කරන්න

ප්‍රොක්සි රෙජිස්ට්‍රිය ද සහය දක්වයි** සත්කාරක + port මගින් upsert** — ඔබ දැනටමත් පවතින ප්‍රොක්සියක් ආනයනය කරන්නේ නම් (එකම සත්කාරක සහ තොට), එය අනුපිටපතක් සෑදීම වෙනුවට යාවත්කාලීන වේ.

### TLS Fingerprint Spoofing

බ්‍රවුසරයක් වැනි TLS ඇඟිලි සලකුණු ජනනය කිරීමට `wreq-js` භාවිත කරයි, බ්‍රවුසර නොවන TLS හෑන්ඩ්ෂේක් සලකුණු කරන බොට් හඳුනාගැනීමේ පද්ධති මඟ හරියි.

### CLI ඇඟිලි සලකුණු ගැලපීම

ද**CLI ඇඟිලි සලකුණු ටොගල් කරන්න** (`Settings → Security`) ස්වදේශීය CLI ද්විමය (Claude කේතය, Codex, ආදිය) නිශ්චිත අත්සනට ගැළපෙන පරිදි HTTP ශීර්ෂ සහ JSON ශරීර ක්ෂේත්‍ර නැවත ඇණවුම් කරයි. මෙය ක්රියා කරයි** උඩින්** ප්‍රොක්සි:

```
Your IP (blocked) → Proxy IP (US) → Provider API
                    + TLS spoof
                    + CLI fingerprint
```

ඔය දෙකම ලැබෙනවා**IP ආවරණ** සහ** සත්‍යතාව ඉල්ලන්න** එකවරම.

## දෝෂගවේෂණය

### "SOCKS5 proxy අක්‍රිය කර ඇත"

ඔබගේ `.env` ගොනුවේ `ENABLE_SOCKS5_PROXY=true` සකසා නැවත ආරම්භ කරන්න.

### ප්‍රොක්සි හරහා "socket hang up" දෝෂ

අක්‍රිය සම්බන්ධතා අත්හරින ලාභ ප්‍රොක්සි සමඟ මෙය සාමාන්‍ය දෙයකි. OmniRoute දැනටමත් මෙය හසුරුවන්නේ:

- ප්‍රොක්සි සම්බන්ධතා මත තබාගැනීම අක්‍රීය කිරීම (`keepAliveTimeout: 1`)
- නල මාර්ග අබල කිරීම (`pipelining: 0`)
- නැවත නැවතත් අතට අත දීම වැළැක්වීම සඳහා ඩිස්පචර්ස් හැඹිලිගත කිරීම

එය දිගටම පවතින්නේ නම්, වෙනත් ප්‍රොක්සියක් උත්සාහ කරන්න හෝ 1ප්‍රොක්සි භ්‍රමණ විශේෂාංගය භාවිතා කරන්න.

### OAuth අතරතුර "unsupported_country_region_territory"

ප්‍රොක්සි වින්‍යාස කර ඇති බවට වග බලා ගන්න** පෙර** OAuth ප්‍රවාහය ආරම්භ කිරීම. OmniRoute මාර්ග OAuth ටෝකන් හුවමාරුව වින්‍යාසගත ප්‍රොක්සි හරහා. පළමුව ගෝලීය හෝ සපයන්නන්ගේ මට්ටමේ ප්‍රොක්සියක් සකසන්න, පසුව සම්බන්ධ කරන්න.

### ප්‍රොක්සි භාවිතා නොවේ

විභේදන අනුපිළිවෙල පරීක්ෂා කරන්න:

1. `GET /api/settings/proxy?resolve=your-connection-id` සමඟ තහවුරු කරන්න
2. ප්‍රොක්සි `status` `active` ( `inactive` නොවේ) දැයි පරීක්ෂා කරන්න
3. ප්‍රොක්සි පැවරුම් විෂය පථය ඔබේ සම්බන්ධතාවයට ගැළපෙන බව සහතික කර ගන්න

### 1ප්‍රොක්සි සමමුහුර්ත කිරීම අසාර්ථකයි

සමමුහුර්ත තත්ත්වය පරීක්ෂා කරන්න:

```bash
curl "http://localhost:20128/api/settings/oneproxy?action=status"
```

`consecutiveFailures >= 5` නම්, පරිපථ කඩනය අවුල් වී ඇත. නැවත සැකසීමට සේවාදායකය නැවත අරඹන්න, නැතහොත් අතින් යළි පිහිටුවීම සඳහා රැඳී සිටින්න.

## දත්ත සමුදා යෝජනා ක්රමය

### `proxy_registry` වගුව

```sql
CREATE TABLE proxy_registry (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  type TEXT NOT NULL DEFAULT 'http',
  host TEXT NOT NULL,
  port INTEGER NOT NULL,
  username TEXT DEFAULT '',
  password TEXT DEFAULT '',
  region TEXT,
  notes TEXT,
  status TEXT DEFAULT 'active',
  source TEXT NOT NULL DEFAULT 'manual',    -- 'manual' or 'oneproxy'
  quality_score INTEGER,                     -- 0-100 (1proxy only)
  latency_ms INTEGER,                        -- milliseconds (1proxy only)
  anonymity TEXT,                            -- transparent/anonymous/elite
  google_access INTEGER DEFAULT 0,           -- can access Google? (1proxy)
  last_validated TEXT,                       -- ISO timestamp (1proxy)
  country_code TEXT,                         -- ISO 2-letter code (1proxy)
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

### `proxy_assignments` වගුව

```sql
CREATE TABLE proxy_assignments (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  proxy_id TEXT NOT NULL REFERENCES proxy_registry(id),
  scope TEXT NOT NULL,        -- 'global', 'provider', 'account', 'combo'
  scope_id TEXT,              -- provider ID, connection ID, or combo ID
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE(scope, scope_id)
);
```

## ප්‍රොක්සි සෞඛ්‍ය පරීක්ෂාව (v3.8.16 +)

OmniRoute ගේ** proxy fast-fail** යාන්ත්‍රණය (`src/lib/proxyHealth.ts`) ඉක්මන් TCP සම්බන්ධතා පරීක්ෂාවක් හරහා < 2s හි මිය ගිය ප්‍රොක්සි හඳුනා ගනී, පසුව** ප්රතිඵලය හැඹිලි** එක්-ඉල්ලීමකට උඩින් වැලැක්වීමට.

### එය ක්රියා කරන ආකාරය

```
Request ──▶ ProxyHealthCache.get(url)
             │
             ├─ Cache hit + fresh?  ──▶ return cached status
             │
             └─ Cache miss / stale?  ──▶ TCP connect to host:port
                                          (timeout: FAST_FAIL_TIMEOUT_MS)
                                          ──▶ cache for HEALTH_CACHE_TTL_MS
                                          ──▶ return result
```

මෙය නොමැතිව, මිය ගිය ප්‍රොක්සියක් අසාර්ථක වීමට පෙර සම්පූර්ණ `PROXY_TIMEOUT_MS` (පෙරනිමි 30s) සඳහා වන සෑම ඉල්ලීමක්ම අවහිර කරයි.

### සුසර කළ හැකි පරිසර විචල්යයන්

| ---------------------------- | -------- | ------------------------------------------------- |

| `PROXY_HEALTH_CACHE_TTL_MS`  | `30000`  | සෞඛ්‍ය ප්‍රතිඵලයක් කොපමණ කාලයක් හැඹිලිගත කර තිබේද |

### ප්‍රොක්සි සෞඛ්‍යය පරීක්ෂා කිරීම

```ts
invalidateProxyHealth("http://user:pass@203.0.113.7:8080");
```

හැඹිලි ප්‍රවේශය `HEALTH_CACHE_TTL_MS` ඉක්මවූ විට `stale` ධජය `true` වන අතර ඊළඟ ඉල්ලීම මඟින් නැවුම් පරීක්ෂාවක් ඇති කරයි.

### දත්ත වෙත ප්රවේශ වීම

```bash
# Recent proxy events
curl -H "Authorization: Bearer $OMNIROUTE_KEY" \
  "http://localhost:20128/api/usage/proxy-logs?limit=100"
```

සැබෑ අන්ත ලක්ෂ්‍යය `/api/usage/proxy-logs` වේ ( `src/app/api/usage/proxy-logs/route.ts` බලන්න). මෙම අවසාන ලක්ෂ්‍යය සහාය දක්වයි:

- `GET /api/usage/proxy-logs` — ප්‍රොක්සි ලොග් ලබාගන්න
- `DELETE /api/usage/proxy-logs` — සියලුම ප්‍රොක්සි ලොග් ඉවත් කරන්න

අවශ්‍ය නම් සමස්ථ සංඛ්‍යාලේඛන `proxy_logs` වගුවෙන් සෘජුවම SQL හරහා විමසිය හැක. උපකරණ පුවරුව UI සමස්ත දසුන් ලබා දිය හැක.

### පොදු රටා

**Flapping proxy එකක් හඳුනා ගන්න** ( success/failure අතර විකල්ප):

```sql
SELECT proxy_url,
       COUNT(*) AS total,
       SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) AS errors,
       ROUND(100.0 * SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) / COUNT(*), 1) AS error_pct
FROM proxy_logs
WHERE timestamp > datetime('now', '-1 hour')
GROUP BY proxy_url
HAVING error_pct > 5
ORDER BY error_pct DESC;
```

**මන්දගාමී ප්‍රොක්සි සොයන්න** (p95 ප්‍රමාදය > 2s):

```sql
WITH ranked AS (
  SELECT proxy_url, latency_ms,
         PERCENT_RANK() OVER (PARTITION BY proxy_url ORDER BY latency_ms) AS pct
  FROM proxy_logs
  WHERE timestamp > datetime('now', '-24 hour')
)
SELECT proxy_url, latency_ms
FROM ranked
WHERE pct >= 0.95
ORDER BY latency_ms DESC;
```

## ඔබේම ප්‍රොක්සි සඳහා ස්වයංක්‍රීය අසාර්ථකත්වය බැහැර කිරීම

1ප්‍රොක්සි වෙළඳපොළ සංචිතය දැනටමත් අසාර්ථක වූ ප්‍රොක්සි ස්වයංක්‍රීයව පිරිහීමට ලක් කරයි ( [ප්‍රොක්සි තත්ත්ව ලකුණු](#proxy-quality-scores) බලන්න). ප්‍රොක්සි සඳහා** ඔබ** ලේඛනයට එකතු කරන ලද, පසුබිම් සෞඛ්‍ය උපලේඛනය (`src/lib/proxyHealth/scheduler.ts`) කිසිවක් මකා දැමීමකින් තොරව, "මැරුණු සාමාජිකයෙකු ස්වයංක්‍රීයව දාමයෙන් බැහැර කිරීමේ" හැසිරීමම සපයයි:

```bash
# .env — soft-disable a proxy after 3 consecutive failed probes, re-enable it
# automatically once it starts answering probes again.
PROXY_AUTO_DISABLE=true
PROXY_AUTO_REMOVE_AFTER=3
```

එය බහු-ප්‍රොක්සි දාමයකට ගැලපෙන ආකාරය:

1. කාලසටහන්කරු සෑම ලියාපදිංචි ප්‍රොක්සියක්ම සෑම `PROXY_HEALTH_INTERVAL_MS` (පෙරනිමි 10 min; අවම 1 min) පරීක්ෂා කරයි.
2. `PROXY_AUTO_REMOVE_AFTER` පසු අඛණ්ඩව** තීරණාත්මක** අසාර්ථක (සැබෑ සම්බන්ධතා අසාර්ථක — කල් ඉකුත්වීම හෝ විමර්ශන ඉලක්කයේ 5xx කිසිවිටෙක ගණන් නොගනී, [Proxy Health Checking](#proxy-health-checking-v3816) බලන්න), ප්‍රොක්සියේ `status` `dead` ලෙස සකසා ඇත.
3. `dead` යනු pool/rotation විභේදනය විසින් භාවිතා කරන සජීවී තත්ත්‍වයේ පෙරහන බැහැර කරන තත්ත්වයන්ගෙන් එකකි, එබැවින් විෂය පථයේ භ්‍රමණය (වට-රොබින් / සසම්භාවී / ඇලෙන සුළු / ප්‍රමාද — බලන්න [භ්‍රමණ උපාය මාර්ග තීරණ ගස](#rotation-strategy-decision-tree) ) වහාම එම ප්‍රොක්සිය නව ඉල්ලීම් වෙත ලබා දීම නතර කරයි. තටාකයේ ඇති වෙනත් ප්‍රොක්සි වලට බලපෑමක් සිදු නොවන අතර, මුළු තටාකයම කිසි විටෙක නිහඬව සෘජු සම්බන්ධතාවයකට ආපසු නොයනු ඇත — [4-මට්ටමේ ප්‍රොක්සි පද්ධතිය](#4-level-proxy-system) අසාර්ථක-වසා ඇති ආරක්ෂකය බලන්න.
4. උපලේඛකයා එකම කාල පරාසයක `dead` ප්‍රොක්සි විමර්ශනය කරයි. මීළඟ සාර්ථක පරීක්ෂණය `status` ආපසු `active` වෙත පෙරළන අතර එය නැවත භ්‍රමණය — වෙත ඇතුළු වන අතර අතින් නැවත එකතු කිරීම අවශ්‍ය නොවේ.

මෙය හිතාමතාමයි** තෝරා ගැනීම සහ විනාශකාරී නොවන** : පෙරනිමියෙන් කාලසටහන්කරු අසාර්ථක වීම් පමණක් ගණන් කර ලොග් කරයි ( `decision.ts` හි C ප්‍රතිපත්තිය බලන්න), සහ `PROXY_AUTO_DISABLE` කිසිවිටෙකත් — පේළියක් මකන්නේ නැත, එය වෙනම, වඩාත් ආක්‍රමණශීලී `PROXY_AUTO_REMOVE` ධජය සඳහා වේ. දෙකම `true` ලෙස සකසා ඇත්නම්, `PROXY_AUTO_REMOVE` දිනයි (මැකීමට ආසන්න ප්‍රොක්සියක් අතර මෘදු අක්‍රිය වීමක් සඳහා ප්‍රයෝජනයක් නැත). සම්පූර්ණ විචල්‍ය ලැයිස්තුව සඳහා [පරිසර වින්‍යාස](../reference/ENVIRONMENT.md) යොමුව බලන්න.
