OmniRoute HTTP, HTTPS, அல்லது SOCKS5 ப்ராக்ஸிகள் மூலம் அப்ஸ்ட்ரீம் AI வழங்குநர் போக்குவரத்தை வழிநடத்த உங்களை அனுமதிக்கும் முழு அம்சமான ப்ராக்ஸி மேலாண்மை அமைப்பை உள்ளடக்கியது. நீங்கள் தடுக்கப்பட்ட பகுதியில் இருந்தாலும், IP சுழற்சி தேவையா அல்லது திருட்டுத்தனமாக கைரேகை — தேவைப்பட்டாலும் இந்த வழிகாட்டி அனைத்தையும் உள்ளடக்கும்.

## ப்ராக்ஸிகளை ஏன் பயன்படுத்த வேண்டும்?

பல AI வழங்குநர்கள் புவியியல் பகுதியின் அணுகலை கட்டுப்படுத்துகின்றனர். உள்ள டெவலப்பர்கள்** ரஷ்யா, சீனா, ஈரான், கியூபா, துருக்கி** , மற்றும் பிற நாடுகள் இது போன்ற பிழைகளை எதிர்கொள்கின்றன:

```
unsupported_country_region_territory
```

தடுக்கப்பட்ட பகுதிகளுக்கு வெளியே கூட, ப்ராக்ஸிகள் இதற்கு பயனுள்ளதாக இருக்கும்:

| வழக்கைப் பயன்படுத்தவும் | விளக்கம்                                                                    |
| ----------------------- | --------------------------------------------------------------------------- |
| **புவியியல் பைபாஸ்**    | தடுக்கப்பட்ட நாடுகளில் இருந்து OpenAI, Anthropic, Codex, Copilot ஐ அணுகவும் |
| **IP சுழற்சி**          | விகித வரம்பைத் தவிர்க்க பல IPs முழுவதும் கோரிக்கைகளை விநியோகிக்கவும்        |
| **தனியுரிமை**           | அப்ஸ்ட்ரீம் வழங்குநர்களிடமிருந்து உங்கள் உண்மையான IP மறைக்கவும்             |
| **இணக்கம்**             | குறிப்பிட்ட அதிகார வரம்புகள் வழியாக போக்குவரத்து வழி                        |
| **சோதனை**               | வெவ்வேறு பிராந்தியங்களில் இருந்து கோரிக்கைகளை உருவகப்படுத்தவும்             |

## புதிய கணக்குகளுக்கான இயல்புநிலை ப்ராக்ஸி நிலை

இல்** அமைப்புகள் → ப்ராக்ஸி → உலகளாவிய உள்ளமைவு** , பயன்படுத்தவும்** புதிய இணைப்புகளுக்கு இயல்பாக ப்ராக்ஸியை இயக்கவும்** புதிதாக சேர்க்கப்பட்ட வழங்குநர் கணக்குகளின் ஆரம்ப ப்ராக்ஸி நிலையை தேர்வு செய்ய.

புதிய அமைப்பு புதிதாக சேர்க்கப்பட்ட வழங்குநர் கணக்குகளின் ஆரம்ப ப்ராக்ஸி நிலையைக் கட்டுப்படுத்துகிறது. இது ஏற்கனவே உள்ள கணக்குகளை மாற்றாது அல்லது உலகளாவிய ப்ராக்ஸி சுவிட்சை மாற்றாது. அதன் ஆரம்ப மதிப்பு முந்தைய நடத்தையைப் பாதுகாக்கிறது. முன்னிருப்பாக முடக்கப்பட்ட ப்ராக்ஸியுடன் எதிர்கால கணக்குகளை உருவாக்க அதை ஒருமுறை முடக்கவும்.

ஏற்கனவே உள்ள அமைப்புகள் API மூலம் முன்னுரிமை `defaultNewConnectionProxyEnabled` ஆக சேமிக்கப்படுகிறது. சேமிக்கப்படாத போது இது `true` க்கு இயல்புநிலையாக இருக்கும். `false` சேமிப்பது மறுதொடக்கம் இல்லாமல் அடுத்தடுத்த புதிய கணக்குகளுக்குச் செயல்படும். `POST /api/providers` ஒரு விருப்பமான கண்டிப்பான பூலியன் `proxyEnabled` ஏற்றுக்கொள்கிறது; ஒரு வெளிப்படையான `true` அல்லது `false` உருவாக்க இயல்புநிலையை விட முன்னுரிமை பெறுகிறது. நகல் கணக்கு அல்லது OAuth மறுஇணைப்பில் விடுபட்டது அந்தக் கணக்கின் சேமிக்கப்பட்ட நிலையைப் பாதுகாக்கும். தனிப்பட்ட கணக்குகள் பின்னர் இயக்கப்படலாம் அல்லது முடக்கப்படலாம்.

தேர்ந்தெடுக்கப்பட்ட வழங்குநர் இடமாற்றங்கள் புதிய கணக்குகளுக்கு இலக்கு நிறுவலின் இயல்புநிலையைப் பயன்படுத்துகின்றன மற்றும் ஏற்கனவே உள்ள கணக்குகளை மாற்றும்போது இலக்குக் கொள்கையைப் பாதுகாக்கின்றன. ப்ராக்ஸி நிலைமாற்றங்கள் கையடக்க பரிமாற்ற புலங்கள் அல்ல. முழு காப்புப்பிரதி மறுசீரமைப்பு மற்றும் வரலாற்று JSON/SQL இடம்பெயர்வு ஆகியவை அவற்றின் தற்போதைய மீட்டெடுப்பு சொற்பொருளைத் தக்கவைத்துக்கொள்கின்றன, இதில் சேமிக்கப்பட்ட கணக்கு மதிப்புகள் மற்றும் மரபு திட்ட இயல்புநிலைகள் உட்பட; முழு அமைப்புகளை மீட்டமைத்தால் இந்த விருப்பத்தை மீட்டெடுக்க முடியும்.

இந்த விருப்பம் ப்ராக்ஸியை ஒதுக்காது அல்லது ஒன்று ஆரோக்கியமானது அல்லது பயன்பாட்டில் உள்ளது என்பதை நிறுவாது. உண்மையான ரூட்டிங் இன்னும் உலகளாவிய ப்ராக்ஸி சுவிட்ச் மற்றும் பொருந்தக்கூடிய ப்ராக்ஸி உள்ளமைவைப் பொறுத்தது. தொடர்ச்சியான கணக்கு இல்லாத செயற்கை வழங்குநர்கள், கணக்கு உருவாக்கத்திற்கு முன் OAuth டிராஃபிக், environment/system ப்ராக்ஸிகள் மற்றும் வெளிப்புற பின்தளங்களின் நெட்வொர்க்கிங் ஆகியவை அதன் எல்லைக்கு அப்பாற்பட்டவை.

## 4-நிலை ப்ராக்ஸி அமைப்பு

OmniRoute ப்ராக்ஸி உள்ளமைவை ஆதரிக்கிறது** நான்கு சுயாதீன நோக்கங்கள்** , முன்னுரிமை வரிசையில் தீர்க்கப்பட்டது:

```
Priority Resolution Order (highest → lowest):

  1. 🔵 Account/Connection Proxy  →  per API key / OAuth connection
  2. 🟡 Provider Proxy            →  per provider (e.g., all OpenAI traffic)
  3. 🟠 Combo Proxy               →  per combo/routing configuration
  4. 🟢 Global Proxy              →  all traffic, all providers
```

### தீர்மானம் எவ்வாறு செயல்படுகிறது

OmniRoute ஒரு அப்ஸ்ட்ரீம் வழங்குநருக்கு ஒரு கோரிக்கையை அனுப்பும் போது, அது `resolveProxyForConnectionFromRegistry()` அழைக்கிறது, இது ஒவ்வொரு நிலையையும் வரிசையாக சரிபார்க்கிறது:

1. **கணக்கு நிலை** — இந்த குறிப்பிட்ட இணைப்பு ID க்கு ப்ராக்ஸி ஒதுக்கப்பட்டுள்ளதா?
2. **வழங்குநர்-நிலை** — இந்த வழங்குநருக்கு ப்ராக்ஸி ஒதுக்கப்பட்டுள்ளதா (எ.கா., `openai`)?
3. **உலக அளவில்** — உலகளாவிய ப்ராக்ஸி உள்ளமைக்கப்பட்டதா?
4. **ப்ராக்ஸி இல்லை** வழங்குநருடன் — நேரடி இணைப்பு.

முதல் போட்டியில் வெற்றி. இதன் பொருள் நீங்கள் உலகளாவிய ப்ராக்ஸியை ஃபால்பேக்காக அமைக்கலாம் ஆனால் குறிப்பிட்ட வழங்குநர்கள் அல்லது இணைப்புகளுக்கு அதை மேலெழுதலாம்.

## ப்ராக்ஸி ரெஜிஸ்ட்ரி (CRUD)

ப்ராக்ஸி ரெஜிஸ்ட்ரி என்பது SQLite டேபிள் (`proxy_registry`) ஆகும், இது உங்கள் எல்லா ப்ராக்ஸிகளையும் சேமிக்கிறது. ஒவ்வொரு ப்ராக்ஸியும் உள்ளது:

| களம்       | வகை      | விளக்கம்                                                            |
| ---------- | -------- | ------------------------------------------------------------------- |
| `id`       | UUID     | தனித்துவமான அடையாளங்காட்டி                                          |
| `name`     | சரம்     | மனிதர்கள் படிக்கக்கூடிய லேபிள்                                      |
| `type`     | சரம்     | நெறிமுறை: `http`, `https`, `socks5`                                 |
| `host`     | சரம்     | ப்ராக்ஸி ஹோஸ்ட்பெயர் அல்லது IP                                      |
| `port`     | முழு எண் | போர்ட் எண்                                                          |
| `username` | சரம்     | அங்கீகரிப்பு பயனர்பெயர் (ஓய்வு நேரத்தில் குறியாக்கம் செய்யப்பட்டது) |
| `password` | சரம்     | அங்கீகார கடவுச்சொல் (ஓய்வு நேரத்தில் குறியாக்கம் செய்யப்பட்டது)     |
| `region`   | சரம்     | புவியியல் பகுதி லேபிள்                                              |
| `notes`    | சரம்     | இலவச உரை குறிப்புகள்                                                |
| `status`   | சரம்     | `active` அல்லது `inactive`                                          |
| `source`   | சரம்     | `manual` அல்லது `oneproxy`                                          |

### ப்ராக்ஸியை உருவாக்குதல்

**டாஷ்போர்டு வழியாக:**

1. செல்க** அமைப்புகள் → ப்ராக்ஸி**
2. கிளிக் செய்யவும்** ப்ராக்ஸியைச் சேர்க்கவும்**
3. வகை, ஹோஸ்ட், போர்ட் மற்றும் விருப்ப அங்கீகார சான்றுகளை நிரப்பவும்
4. சேமிக்கவும்

**API வழியாக:**

```bash
curl -X POST http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "name": "US Proxy",
    "type": "http",
    "host": "proxy.example.com",
    "port": 8080,
    "username": "user",
    "password": "pass",
    "region": "US"
  }'
```

### ப்ராக்ஸியைப் புதுப்பிக்கிறது

```bash
curl -X PATCH http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "id": "proxy-uuid-here",
    "host": "new-proxy.example.com",
    "port": 9090
  }'
```

> **குறிப்பு:** நீங்கள் வெளிப்படையாக காலியாக இல்லாத மாற்றீடுகளை அனுப்பும் வரை நற்சான்றிதழ்கள் பாதுகாக்கப்படும். `username`/`password` க்கு வெற்று சரங்களை அனுப்புவது சேமிக்கப்பட்ட மதிப்புகளை வைத்திருக்கும்.

### ப்ராக்ஸியை நீக்குகிறது

```bash
# Fails if proxy is assigned to any scope
curl -X DELETE "http://localhost:20128/api/v1/management/proxies?id=proxy-uuid"

# Force delete (removes assignments too)
curl -X DELETE "http://localhost:20128/api/v1/management/proxies?id=proxy-uuid&force=1"
```

### ப்ராக்ஸிகளை பட்டியலிடுதல்

```bash
curl "http://localhost:20128/api/v1/management/proxies?limit=50&offset=0"
```

### ஸ்கோப்களுக்கு ப்ராக்ஸிகளை ஒதுக்குதல்

```bash
# Assign to global scope
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "global", "proxy": {"type":"http","host":"proxy.example.com","port":8080}}'

# Assign to a specific provider
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "provider", "id": "openai", "proxy": {"type":"socks5","host":"socks.example.com","port":1080}}'

# Assign to a specific connection/key
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "key", "id": "connection-uuid", "proxy": {"type":"http","host":"key-proxy.com","port":3128}}'
```

### பயனுள்ள பதிலாள் தீர்வு

கொடுக்கப்பட்ட இணைப்புக்கு எந்த ப்ராக்ஸி பயன்படுத்தப்படும் என்பதைச் சரிபார்க்கவும்:

```bash
curl "http://localhost:20128/api/settings/proxy?resolve=connection-uuid"
```

தீர்க்கப்பட்ட ப்ராக்ஸியை அதன் நிலை (`account`, `provider`, அல்லது `global`) மற்றும் மூலத்துடன் வழங்கும்.

### மொத்த ஒதுக்கீடு

ஒரே நேரத்தில் பல வழங்குநர்கள் அல்லது இணைப்புகளுக்கு ஒரு ப்ராக்ஸியை ஒதுக்கவும்:

```bash
curl -X POST http://localhost:20128/api/v1/management/proxies/bulk-assign \
  -H "Content-Type: application/json" \
  -d '{
    "scope": "provider",
    "scopeIds": ["openai", "anthropic", "codex"],
    "proxyId": "proxy-uuid"
  }'
```

### Import/Export

ப்ராக்ஸிகள் இதில் சேர்க்கப்பட்டுள்ளன**Backup/Restore** அமைப்பு. உங்கள் OmniRoute உள்ளமைவை ஏற்றுமதி செய்யும் போது:

1. செல்க** டாஷ்போர்டு → அமைப்புகள் → காப்புப்பிரதி**
2. கிளிக் செய்யவும்** ஏற்றுமதி** — ப்ராக்ஸி பதிவு மற்றும் பணிகள் சேர்க்கப்பட்டுள்ளன
3. மீட்டமைக்க, கிளிக் செய்யவும்** இறக்குமதி** மற்றும் காப்பு கோப்பை பதிவேற்றவும்

ப்ராக்ஸி ரெஜிஸ்ட்ரியும் ஆதரிக்கிறது** ஹோஸ்ட்+ போர்ட் மூலம் upsert** — ஏற்கனவே இருக்கும் ஒரு ப்ராக்ஸியை நீங்கள் இறக்குமதி செய்தால் (அதே ஹோஸ்ட் மற்றும் போர்ட்), அது ஒரு நகலை உருவாக்குவதற்கு பதிலாக புதுப்பிக்கப்படும்.

### மரபு இடம்பெயர்வு

நீங்கள் ப்ராக்ஸிகளை பழைய பதிப்பில் (முன்பதிவு) உள்ளமைத்திருந்தால், OmniRoute தானாகவே அவற்றை நகர்த்துகிறது:

```
Legacy key_value store → proxy_registry + proxy_assignments
```

மேம்படுத்தப்பட்ட பிறகு முதல் தொடக்கத்தில் இது ஒருமுறை நடக்கும். மீண்டும் இயக்க `migrateLegacyProxyConfigToRegistry({ force: true })` பயன்படுத்தவும்.

## 1ப்ராக்ஸி இலவச ப்ராக்ஸி சந்தை

> 🆕** [@oyi77](https://github.com/oyi77) ஆல் பங்களிக்கப்பட்டது** — PR [#1847](https://github.com/diegosouzapw/OmniRoute/pull/1847) (வெளியீடு [#1788](https://github.com/diegosouzapw/OmniRoute/issues/1788) )

OmniRoute உடன் ஒருங்கிணைக்கிறது** [1ப்ராக்ஸி](https://1proxy-api.aitradepulse.com)** அணுகலை வழங்குவதற்கான சமூக தளம்** நூற்றுக்கணக்கான இலவச, சரிபார்க்கப்பட்ட ப்ராக்ஸிகள்** உலகம் முழுவதும் இருந்து. சொந்த ப்ராக்ஸி உள்கட்டமைப்பு இல்லாத பயனர்களுக்கு இது சரியானது.

### இது எப்படி வேலை செய்கிறது

```
┌─────────────┐     Sync      ┌─────────────────┐    Rotate     ┌──────────┐
│  1proxy API │ ────────────▶ │  proxy_registry  │ ────────────▶ │ Provider │
│  (external) │   up to 500   │  source=oneproxy │  by quality   │   API    │
└─────────────┘    proxies    └─────────────────┘               └──────────┘
```

1. **ஒத்திசை** — OmniRoute 1proxy API இலிருந்து சரிபார்க்கப்பட்ட ப்ராக்ஸிகளைப் பெறுகிறது
2. **ஸ்டோர்** — ப்ராக்ஸிகள் அதே `proxy_registry` அட்டவணையில் `source = 'oneproxy'` உடன் சேமிக்கப்படும்
3. **வடிகட்டி** — நெறிமுறை, நாடு, தர மதிப்பெண் மூலம் வடிகட்டவும்
4. **சுழற்று** — தரம், சீரற்ற அல்லது தொடர் உத்திகளைப் பயன்படுத்தி சிறந்த ப்ராக்ஸியைத் தேர்ந்தெடுக்கவும்
5. **தானாக சீரழிவு** — தோல்வியுற்ற ப்ராக்ஸிகள் அவற்றின் தர மதிப்பெண்ணைக் குறைக்கின்றன; → வாசலுக்குக் கீழே செயலற்றதாகக் குறிக்கப்பட்டது

### ப்ராக்ஸிகளை ஒத்திசைக்கிறது

**டாஷ்போர்டு வழியாக:**

1. செல்க** அமைப்புகள் → 1proxy** தாவல்
2. கிளிக் செய்யவும்** "இப்போது ஒத்திசை"**
3. புள்ளிவிவரங்களைக் காண்க: மொத்த ப்ராக்ஸிகள், செயலில் உள்ள எண்ணிக்கை, சராசரி தரம், நாடுகளுக்கு இடையேயான முறிவு

**API வழியாக:**

```bash
# Trigger sync
curl -X POST http://localhost:20128/api/settings/oneproxy \
  -H "Content-Type: application/json" \
  -d '{}'

# Response:
# { "success": true, "added": 127, "updated": 45, "failed": 2, "total": 172 }
```

### ப்ராக்ஸி தர மதிப்பெண்கள்

ஒவ்வொரு 1ப்ராக்ஸி ப்ராக்ஸியும் மெட்டாடேட்டாவுடன் வருகிறது:

| களம்            | விளக்கம்                                       |
| --------------- | ---------------------------------------------- |
| `qualityScore`  | 1 ப்ராக்ஸி சரிபார்ப்பிலிருந்து 0-100 மதிப்பீடு |
| `latencyMs`     | அளவிடப்பட்ட பிணைய தாமதம்                       |
| `anonymity`     | `transparent`, `anonymous`, அல்லது `elite`     |
| `googleAccess`  | ப்ராக்ஸியால் Google சேவைகளை அணுக முடியுமா      |
| `countryCode`   | இரண்டு எழுத்து ISO நாட்டின் குறியீடு           |
| `lastValidated` | கடைசி சரிபார்ப்பின் நேரமுத்திரை                |

தர மதிப்பெண்கள் மாறும் வகையில் சரிசெய்யப்படுகின்றன:

- **தோல்வியுற்ற கோரிக்கைகள்** மதிப்பெண்ணை 10 புள்ளிகள் குறைக்கவும்
- **ஸ்கோர் ≤ 10க்கு குறைகிறது** → ப்ராக்ஸி `inactive` எனக் குறிக்கப்பட்டுள்ளது
- செயலற்ற ப்ராக்ஸிகள் சுழற்சியில் இருந்து விலக்கப்படுகின்றன


### சர்க்யூட் பிரேக்கர்

1ப்ராக்ஸி ஒத்திசைவில் உள்ளமைக்கப்பட்ட சர்க்யூட் பிரேக்கர் உள்ளது:

- பிறகு** 5 தொடர்ச்சியான ஒத்திசைவு தோல்விகள்** , மேலும் ஒத்திசைவு முயற்சிகள் தடுக்கப்பட்டுள்ளன
- `resetOneproxyCircuitBreaker()` உடன் மீட்டமைக்கவும் அல்லது சேவையகத்தை மறுதொடக்கம் செய்யவும்
- ஒத்திசைவு நிலை `GET /api/settings/oneproxy?action=status` இல் கிடைக்கிறது

### 1ப்ராக்ஸி ப்ராக்ஸிகளை அழிக்கிறது

```bash
# Delete a single 1proxy proxy
curl -X DELETE "http://localhost:20128/api/settings/oneproxy?id=proxy-uuid"

# Clear ALL 1proxy proxies (manual proxies are untouched)
curl -X DELETE "http://localhost:20128/api/settings/oneproxy?clearAll=1"
```

## கண்டறிதல் & திருட்டுத்தனம்

OmniRoute ப்ராக்ஸி — வழியாக போக்குவரத்தை மட்டும் வழிநடத்தாது, இது போக்குவரத்தை சட்டப்பூர்வமாக்குகிறது:

### TLS கைரேகை ஏமாற்றுதல்

உலாவி போன்ற TLS கைரேகைகளை உருவாக்க `wreq-js` பயன்படுத்துகிறது, உலாவி அல்லாத TLS ஹேண்ட்ஷேக்குகளைக் கொடியிடும் போட் கண்டறிதல் அமைப்புகளைத் தவிர்க்கிறது.

### CLI கைரேகை பொருத்தம்

தி**CLI கைரேகை மாற்று** (`Settings → Security`) நேட்டிவ் CLI பைனரிகளின் (Claude குறியீடு, Codex, முதலியன) சரியான கையொப்பத்துடன் பொருந்த HTTP தலைப்புகள் மற்றும் JSON உடல் புலங்களை மறுவரிசைப்படுத்துகிறது. இது வேலை செய்கிறது** மேல்** ப்ராக்ஸி:

```
Your IP (blocked) → Proxy IP (US) → Provider API
                    + TLS spoof
                    + CLI fingerprint
```

உங்களுக்கு இரண்டும் கிடைக்கும்**IP மறைத்தல்** மற்றும்** நம்பகத்தன்மையை கோருங்கள்** ஒரே நேரத்தில்.

### ப்ராக்ஸி IP பாதுகாப்பு

டாஷ்போர்டில் உள்ள வண்ண-குறியிடப்பட்ட பேட்ஜ்கள் எந்த ப்ராக்ஸி நிலை செயலில் உள்ளது என்பதைக் காட்டுகிறது:

| பேட்ஜ் | நிலை       | பொருள்                                                          |
| ------ | ---------- | --------------------------------------------------------------- |
| 🟢     | உலகளாவிய   | அனைத்து போக்குவரத்தும் இந்த ப்ராக்ஸி வழியாக செல்கிறது           |
| 🟡     | வழங்குபவர் | இந்த வழங்குநரின் போக்குவரத்து மட்டுமே ப்ராக்ஸியாக உள்ளது        |
| 🔵     | இணைப்பு    | இந்த குறிப்பிட்ட key/account இந்த ப்ராக்ஸியைப் பயன்படுத்துகிறது |

சரிபார்ப்பிற்கான தீர்க்கப்பட்ட ப்ராக்ஸி IP பேட்ஜ் காட்டுகிறது.

CLIProxyAPI வடிவத்தைப் பயன்படுத்தும் வழங்குநர்களுக்கு, OmniRoute மூன்று அப்ஸ்ட்ரீம் ப்ராக்ஸி முறைகளை ஆதரிக்கிறது:


## சரிசெய்தல்

### "SOCKS5 ப்ராக்ஸி முடக்கப்பட்டுள்ளது"

உங்கள் `.env` கோப்பில் `ENABLE_SOCKS5_PROXY=true` அமைத்து மீண்டும் தொடங்கவும்.

### ப்ராக்ஸி மூலம் "சாக்கெட் ஹேங் அப்" பிழைகள்

செயலற்ற இணைப்புகளை கைவிடும் மலிவான ப்ராக்ஸிகளில் இது இயல்பானது. OmniRoute ஏற்கனவே இதைக் கையாளுகிறது:

- ப்ராக்ஸி இணைப்புகளில் உயிருடன் வைத்திருப்பதை முடக்குகிறது (`keepAliveTimeout: 1`)
- குழாய் இணைப்புகளை முடக்குகிறது (`pipelining: 0`)
- திரும்பத் திரும்ப கைகுலுக்குவதைத் தவிர்க்க, அனுப்பியவர்களை கேச் செய்தல்

இது தொடர்ந்தால், வேறு ப்ராக்ஸியை முயற்சிக்கவும் அல்லது 1ப்ராக்ஸி சுழற்சி அம்சத்தைப் பயன்படுத்தவும்.

### OAuth இன் போது "unsupported_country_region_territory"

ப்ராக்ஸி கட்டமைக்கப்பட்டுள்ளதா என்பதை உறுதிப்படுத்தவும்** முன்** OAuth ஓட்டத்தைத் தொடங்குகிறது. OmniRoute வழிகள் OAuth டோக்கன் பரிமாற்றம் கட்டமைக்கப்பட்ட ப்ராக்ஸி மூலம். முதலில் உலகளாவிய அல்லது வழங்குநர்-நிலை ப்ராக்ஸியை அமைத்து, பின்னர் இணைக்கவும்.

### ப்ராக்ஸி பயன்படுத்தப்படவில்லை

தெளிவுத்திறன் வரிசையைச் சரிபார்க்கவும்:

1. `GET /api/settings/proxy?resolve=your-connection-id` உடன் சரிபார்க்கவும்
2. ப்ராக்ஸி `status` `active` ( `inactive` அல்ல) என்பதைச் சரிபார்க்கவும்
3. ப்ராக்ஸி ஒதுக்கீட்டு நோக்கம் உங்கள் இணைப்போடு பொருந்துகிறதா என்பதை உறுதிப்படுத்தவும்

### 1ப்ராக்ஸி ஒத்திசைவு தோல்வி

ஒத்திசைவு நிலையைச் சரிபார்க்கவும்:

```bash
curl "http://localhost:20128/api/settings/oneproxy?action=status"
```

`consecutiveFailures >= 5` என்றால், சர்க்யூட் பிரேக்கர் தடுமாறியது. மீட்டமைக்க சேவையகத்தை மறுதொடக்கம் செய்யுங்கள் அல்லது கைமுறையாக மீட்டமைக்க காத்திருக்கவும்.

```sql
  host TEXT NOT NULL,

  region TEXT,
  notes TEXT,
  status TEXT DEFAULT 'active',
  source TEXT NOT NULL DEFAULT 'manual',    -- 'manual' or 'oneproxy'
  quality_score INTEGER,                     -- 0-100 (1proxy only)
  latency_ms INTEGER,                        -- milliseconds (1proxy only)
  anonymity TEXT,                            -- transparent/anonymous/elite
  google_access INTEGER DEFAULT 0,           -- can access Google? (1proxy)
```

## ப்ராக்ஸி ஆரோக்கிய சோதனை (v3.8.16 +)

OmniRoute's** ப்ராக்ஸி வேகமாக தோல்வி** மெக்கானிசம் (`src/lib/proxyHealth.ts`) விரைவான TCP இணைப்புச் சரிபார்ப்பு மூலம் < 2s இல் இறந்த ப்ராக்ஸிகளைக் கண்டறிகிறது.** முடிவை தேக்கி வைக்கிறது** ஒரு கோரிக்கை மேல்நிலையைத் தவிர்க்க.

### இது எப்படி வேலை செய்கிறது

```
Request ──▶ ProxyHealthCache.get(url)
             │
             ├─ Cache hit + fresh?  ──▶ return cached status
             │
             └─ Cache miss / stale?  ──▶ TCP connect to host:port
                                          (timeout: FAST_FAIL_TIMEOUT_MS)
                                          ──▶ cache for HEALTH_CACHE_TTL_MS
                                          ──▶ return result
```

இது இல்லாமல், முழு `PROXY_TIMEOUT_MS` (இயல்புநிலை 30 வி)க்கான ஒவ்வொரு கோரிக்கையையும் செயலிழக்கும் முன் ஒரு டெட் ப்ராக்ஸி தடுக்கும்.

### டியூன் செய்யக்கூடிய சுற்றுச்சூழல் மாறிகள்

| மாறி                         | இயல்புநிலை | நோக்கம்                                                        |
| ---------------------------- | ---------- | -------------------------------------------------------------- |
| `PROXY_FAST_FAIL_TIMEOUT_MS` | `2000`     | ஒரு சுகாதார சோதனைக்குTCP இணைப்பு நேரம் முடிந்தது               |
| `PROXY_HEALTH_CACHE_TTL_MS`  | `30000`    | ஒரு சுகாதார முடிவு எவ்வளவு காலம் தற்காலிகமாக சேமிக்கப்படுகிறது |

**பரிந்துரைக்கப்பட்ட மதிப்புகள்:**

| காட்சி                               | விரைவான தோல்வி காலக்கெடு | கேச் TTL | பகுத்தறிவு                                                                                 |
| ------------------------------------ | ------------------------ | -------- | ------------------------------------------------------------------------------------------ |
| உயர்-செயல்திறன் API நுழைவாயில்       | 1500ms                   | 60000ms  | காசோலைகளைக் குறைக்க தீவிரமான தோல்வி-வேகமான, நீண்ட தற்காலிக சேமிப்பு                        |
| புவி-விநியோக முனைகள்                 | 3000ms                   | 15000ms  | மெதுவான நெட்வொர்க்குகளுக்கு அதிக நேரம் தேவை; விரைவான தோல்விக்கான குறுகிய தற்காலிக சேமிப்பு |
| தேவ் / சோதனை                         | 1000ms                   | 10000ms  | உள்ளூர் ப்ராக்ஸிகளில் விரைவான மறு செய்கை                                                   |
| திருட்டுத்தனம் / கண்டறிதல் எதிர்ப்பு | 2500ms                   | 45000ms  | விகித வரம்புகளைத் தூண்டக்கூடிய விரைவான ஆய்வுகளைத் தவிர்க்கவும்                             |

### ப்ராக்ஸி ஆரோக்கியத்தை ஆய்வு செய்தல்

```ts
import { getAllProxyHealthStatuses, invalidateProxyHealth } from "omniroute/proxyHealth";

const statuses = getAllProxyHealthStatuses();
for (const s of statuses) {
  console.log(`${s.proxyUrl} → healthy=${s.healthy}, stale=${s.stale}`);
}

// Force re-check a specific proxy
invalidateProxyHealth("http://user:pass@203.0.113.7:8080");
```

கேச் உள்ளீடு `HEALTH_CACHE_TTL_MS` ஐத் தாண்டினால் `stale` கொடி `true` ஆக இருக்கும், மேலும் அடுத்த கோரிக்கை புதிய சரிபார்ப்பைத் தூண்டும்.

### ஒவ்வொரு ப்ராக்ஸி வகை இயல்புநிலைகள்

சுகாதார சோதனையானது URL திட்டத்தின் அடிப்படையில் விவேகமான இயல்புநிலைகளைப் பயன்படுத்துகிறது:

| திட்டம்                    | இயல்புநிலை போர்ட் |
| -------------------------- | ----------------- |
| `http://`                  | 8080              |
| `https://`                 | 443               |
| `socks5://` / `socks5h://` | 1080              |

URL (`http://host:9999`) இல் உள்ள தனிப்பயன் போர்ட்கள் எப்பொழுதும் திட்டத்தின் இயல்புநிலையை விட முன்னுரிமை பெறும்.

## ப்ராக்ஸி அனலிட்டிக்ஸ் & கவனிப்பு

ரூட்டிங் பேட்டர்ன்கள், லேட்டன்சி ஸ்பைக்குகள் மற்றும் தொடர்ச்சியான தோல்விகளைக் கண்டறிய ஆபரேட்டர்களுக்கு உதவ OmniRoute ஒவ்வொரு ப்ராக்ஸி பயன்பாட்டையும் கண்காணிக்கிறது.

### என்ன கண்காணிக்கப்பட்டது

உள்ளமைக்கப்பட்ட ப்ராக்ஸி மூலம் ஒவ்வொரு கோரிக்கைக்கும், OmniRoute பதிவுகள்:

| மெட்ரிக்     | விளக்கம்                                                  |
| ------------ | --------------------------------------------------------- |
| `proxy_url`  | முழு ப்ராக்ஸி URL (அங்கீகார நற்சான்றிதழ்கள் முகமூடியுடன்) |
| `provider`   | அப்ஸ்ட்ரீம் வழங்குநர் ID (openai, anthropic, முதலியன)     |
| `latency_ms` | ப்ராக்ஸி ஹேண்ட்ஷேக் உட்பட மொத்த சுற்று-பயண நேரம்          |
| `connect_ms` | TCP இணைப்பு நேரம் மட்டும்                                 |
| `status`     | அப்ஸ்ட்ரீமில் இருந்துHTTP நிலைக் குறியீடு                 |
| `error`      | கோரிக்கை தோல்வியுற்றால் வகுப்பு பிழை                      |
| `timestamp`  | ISO 8601 UTC                                              |

### தரவு அணுகல்

```bash
# Recent proxy events
curl -H "Authorization: Bearer $OMNIROUTE_KEY" \
  "http://localhost:20128/api/usage/proxy-logs?limit=100"
```

உண்மையான இறுதிப்புள்ளி `/api/usage/proxy-logs` (பார்க்க `src/app/api/usage/proxy-logs/route.ts`). இந்த இறுதிப்புள்ளி ஆதரிக்கிறது:

- `GET /api/usage/proxy-logs` — ப்ராக்ஸி பதிவுகளை மீட்டெடுக்கிறது
- `DELETE /api/usage/proxy-logs` — அனைத்து ப்ராக்ஸி பதிவுகளையும் அழிக்கவும்

தேவைப்பட்டால் மொத்த புள்ளிவிவரங்களை `proxy_logs` அட்டவணையில் இருந்து SQL வழியாக நேரடியாக வினவலாம். டாஷ்போர்டு UI மொத்த காட்சிகளை வழங்கலாம்.

### பொதுவான வடிவங்கள்

**ஃபிளாப்பிங் ப்ராக்ஸியைக் கண்டறியவும்** ( success/failure க்கு இடையில் மாற்று):

```sql
SELECT proxy_url,
       COUNT(*) AS total,
       SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) AS errors,
       ROUND(100.0 * SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) / COUNT(*), 1) AS error_pct
FROM proxy_logs
WHERE timestamp > datetime('now', '-1 hour')
GROUP BY proxy_url
HAVING error_pct > 5
ORDER BY error_pct DESC;
```

**மெதுவான ப்ராக்ஸிகளைக் கண்டறியவும்** (p95 தாமதம் > 2s):

```sql
WITH ranked AS (
  SELECT proxy_url, latency_ms,
         PERCENT_RANK() OVER (PARTITION BY proxy_url ORDER BY latency_ms) AS pct
  FROM proxy_logs
  WHERE timestamp > datetime('now', '-24 hour')
)
SELECT proxy_url, latency_ms
FROM ranked
WHERE pct >= 0.95
ORDER BY latency_ms DESC;
```

## சுழற்சி உத்தி முடிவு மரம்

ஒரு நோக்கத்திற்கு பல ப்ராக்ஸிகள் ஒதுக்கப்படும் போது, OmniRoute a ஐப் பயன்படுத்துகிறது** சுழற்சி உத்தி** ஒவ்வொரு கோரிக்கைக்கும் எதைப் பயன்படுத்த வேண்டும் என்பதைத் தேர்ந்தெடுக்கவும். மூலோபாயம் ஸ்கோப் மட்டத்தில் கட்டமைக்கப்பட்டுள்ளது (உலகளாவிய, ஒவ்வொரு வழங்குநருக்கும், ஒவ்வொரு கணக்கிற்கும், ஒவ்வொரு சேர்க்கைக்கும்).

### கிடைக்கும் உத்திகள்

| உத்தி                  | எப்போது பயன்படுத்த வேண்டும்       | வர்த்தகம்                                                                                 |
| ---------------------- | --------------------------------- | ----------------------------------------------------------------------------------------- |
| `quality` (இயல்புநிலை) | கலப்பு-தர ப்ராக்ஸிகளுடன் உற்பத்தி | உயர் மதிப்பிடப்பட்ட ப்ராக்ஸிகளை ஆதரிக்கிறது; குறைந்த மதிப்புடையவர்கள் பட்டினியால் வாடலாம் |
| `random`               | சுமை விநியோகம், தனியுரிமை         | சம விநியோகம்; தர சமிக்ஞைகளை புறக்கணிக்கிறது                                               |
| `sequential`           | பிழைத்திருத்தம், உறுதியான சோதனை   | ப்ராக்ஸிகள் மூலம் சுழற்சிகள் வரிசையில்; நியாயப்படுத்துவது எளிது                           |

## உங்கள் சொந்த ப்ராக்ஸிகளுக்கான தானியங்கி தோல்வி விலக்கு

1ப்ராக்ஸி மார்க்கெட்பிளேஸ் பூல் ஏற்கனவே தோல்வியுற்ற ப்ராக்ஸிகளை தானாகவே சிதைக்கிறது ( [ப்ராக்ஸி தர மதிப்பெண்களைப்](#proxy-quality-scores) பார்க்கவும்). ப்ராக்ஸிகளுக்கு** நீ** பதிவேட்டில் சேர்க்கப்பட்டது, பின்னணி சுகாதார திட்டமிடல் (`src/lib/proxyHealth/scheduler.ts`) எதையும் நீக்காமல், அதே "செயினில் இருந்து ஒரு இறந்த உறுப்பினரை தானாக விலக்கு" நடத்தையை வழங்குகிறது:

```bash
# .env — soft-disable a proxy after 3 consecutive failed probes, re-enable it
# automatically once it starts answering probes again.
PROXY_AUTO_DISABLE=true
PROXY_AUTO_REMOVE_AFTER=3
```

மல்டி-ப்ராக்ஸி சங்கிலியில் இது எவ்வாறு பொருந்துகிறது:

1. ஒவ்வொரு `PROXY_HEALTH_INTERVAL_MS` (இயல்புநிலை 10 நிமிடம்; குறைந்தபட்சம் 1 நிமிடம்) பதிவுசெய்யப்பட்ட ஒவ்வொரு ப்ராக்ஸியையும் திட்டமிடுபவர் ஆய்வு செய்கிறார்.
2. தொடர்ந்து `PROXY_AUTO_REMOVE_AFTER` பிறகு** முடிவான** தோல்விகள் (உண்மையான இணைப்பு தோல்வி — ஒரு காலக்கெடு அல்லது ஆய்வு இலக்கின் சொந்த 5xx கணக்கிடப்படாது, [ப்ராக்ஸி ஆரோக்கிய சோதனையைப்](#proxy-health-checking-v3816) பார்க்கவும்), ப்ராக்ஸியின் `status` `dead` க்கு அமைக்கப்பட்டுள்ளது.
3. `dead` என்பது pool/rotation தெளிவுத்திறனால் பயன்படுத்தப்படும் உயிருள்ள-நிலை வடிகட்டியின் நிலைகளில் ஒன்றாகும், எனவே ஒரு ஸ்கோப்பின் சுழற்சி (ரவுண்ட்-ராபின் / ரேண்டம் / ஸ்டிக்கி / லேட்டன்சி — பார்க்க [சுழற்சி உத்தி முடிவு மரம்](#rotation-strategy-decision-tree) ) உடனடியாக அந்த ப்ராக்ஸியை புதிய கோரிக்கைகளுக்கு வழங்குவதை நிறுத்துகிறது. குளத்தில் உள்ள மற்ற ப்ராக்ஸிகள் எதுவும் பாதிக்கப்படவில்லை, மேலும் முழு குளமும் ஒரு நேரடி இணைப்புக்கு மீண்டும் திரும்பாது — [4-நிலை ப்ராக்ஸி சிஸ்டம்](#4-level-proxy-system) தோல்வி-மூடப்பட்ட காவலரைப் பார்க்கவும்.
4. திட்டமிடுபவர் `dead` ப்ராக்ஸிகளை அதே இடைவெளியில் தொடர்ந்து ஆய்வு செய்கிறார். அடுத்த வெற்றிகரமான ஆய்வு `status` மீண்டும் `active` க்கு புரட்டுகிறது மற்றும் அது சுழற்சி — மீண்டும் நுழைகிறது, கைமுறையாக மீண்டும் சேர்க்க தேவையில்லை.

இது வேண்டுமென்றே** தேர்வு மற்றும் அழிவில்லாதது** : முன்னிருப்பாக, திட்டமிடுபவர் தோல்விகளை மட்டுமே கணக்கிட்டு பதிவு செய்கிறார் ( `decision.ts` இல் கொள்கை C ஐப் பார்க்கவும்), மேலும் `PROXY_AUTO_DISABLE` ஒரு வரிசை — நீக்காது, அதுவே தனி, அதிக ஆக்ரோஷமான `PROXY_AUTO_REMOVE` கொடி. இரண்டும் `true` க்கு அமைக்கப்பட்டால், `PROXY_AUTO_REMOVE` வெற்றி பெறும் (நீக்கப்படவிருக்கும் ப்ராக்ஸிக்கு இடையில் சாஃப்ட்-டிசேபிள் செய்வதால் எந்தப் பயனும் இல்லை). முழு மாறி பட்டியலுக்கு [சுற்றுச்சூழல் கட்டமைப்பு](../reference/ENVIRONMENT.md) குறிப்பைப் பார்க்கவும்.
