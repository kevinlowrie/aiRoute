> **ഭൂമിശാസ്ത്രപരമായ ബ്ലോക്കുകൾ മറികടക്കുക, നിങ്ങളുടെ ഐഡൻ്റിറ്റി പരിരക്ഷിക്കുക, സീറോ കോൺഫിഗറേഷൻ സങ്കീർണ്ണതയോടെ ഏത് പ്രോക്സി — ലൂടെയും AI ട്രാഫിക്ക് റൂട്ട് ചെയ്യുക.**

OmniRoute HTTP, HTTPS, അല്ലെങ്കിൽ SOCKS5 പ്രോക്സികൾ വഴി അപ്സ്ട്രീം AI ദാതാവിൻ്റെ ട്രാഫിക്ക് റൂട്ട് ചെയ്യാൻ നിങ്ങളെ അനുവദിക്കുന്ന ഒരു പൂർണ്ണ ഫീച്ചർ ചെയ്ത പ്രോക്സി മാനേജ്മെൻ്റ് സിസ്റ്റം ഉൾപ്പെടുന്നു. നിങ്ങൾ ഒരു ബ്ലോക്ക് ചെയ്ത പ്രദേശത്താണെങ്കിലും, IP റൊട്ടേഷൻ ആവശ്യമാണെങ്കിലും, അല്ലെങ്കിൽ സ്റ്റെൽത്ത് ഫിംഗർപ്രിൻ്റ് — വേണമെങ്കിലും ഈ ഗൈഡ് എല്ലാം ഉൾക്കൊള്ളുന്നു.

## എന്തുകൊണ്ടാണ് പ്രോക്സികൾ ഉപയോഗിക്കുന്നത്?

പല AI ദാതാക്കളും ഭൂമിശാസ്ത്രപരമായ പ്രദേശം വഴിയുള്ള പ്രവേശനം നിയന്ത്രിക്കുന്നു. ഡെവലപ്പർമാർ** റഷ്യ, ചൈന, ഇറാൻ, ക്യൂബ, തുർക്കി** , മറ്റ് രാജ്യങ്ങൾ ഇതുപോലുള്ള പിശകുകൾ നേരിടുന്നു:

```
unsupported_country_region_territory
```

തടഞ്ഞ പ്രദേശങ്ങൾക്ക് പുറത്ത് പോലും, പ്രോക്സികൾ ഇനിപ്പറയുന്നവയ്ക്ക് ഉപയോഗപ്രദമാണ്:

| കേസ് ഉപയോഗിക്കുക            | വിവരണം                                                                                 |
| --------------------------- | -------------------------------------------------------------------------------------- |
| **ഭൂമിശാസ്ത്രപരമായ ബൈപാസ്** | തടഞ്ഞ രാജ്യങ്ങളിൽ നിന്ന് OpenAI, Anthropic, Codex, Copilot ആക്സസ് ചെയ്യുക              |
| **IP ഭ്രമണം**               | നിരക്ക് പരിമിതപ്പെടുത്തുന്നത് ഒഴിവാക്കാൻ ഒന്നിലധികം IPs യിൽ അഭ്യർത്ഥനകൾ വിതരണം ചെയ്യുക |
| **സ്വകാര്യത**               | അപ്സ്ട്രീം ദാതാക്കളിൽ നിന്ന് നിങ്ങളുടെ യഥാർത്ഥ IP മറയ്ക്കുക                            |
| **പാലിക്കൽ**                | നിർദ്ദിഷ്ട അധികാരപരിധികളിലൂടെ ട്രാഫിക്ക് റൂട്ട് ചെയ്യുക                                |
| **ടെസ്റ്റിംഗ്**             | വിവിധ പ്രദേശങ്ങളിൽ നിന്നുള്ള അഭ്യർത്ഥനകൾ അനുകരിക്കുക                                   |

## പുതിയ അക്കൗണ്ടുകൾക്കുള്ള ഡിഫോൾട്ട് പ്രോക്സി നില

ഇൻ** ക്രമീകരണങ്ങൾ → പ്രോക്സി → ഗ്ലോബൽ കോൺഫിഗറേഷൻ** , ഉപയോഗിക്കുക** പുതിയ കണക്ഷനുകൾക്കായി സ്ഥിരസ്ഥിതിയായി പ്രോക്സി പ്രവർത്തനക്ഷമമാക്കുക** പുതുതായി ചേർത്ത ദാതാവിൻ്റെ അക്കൗണ്ടുകളുടെ പ്രാരംഭ പ്രോക്സി നില തിരഞ്ഞെടുക്കാൻ.

പുതിയ ക്രമീകരണം പുതുതായി ചേർത്ത ദാതാവിൻ്റെ അക്കൗണ്ടുകളുടെ പ്രാരംഭ പ്രോക്സി നില നിയന്ത്രിക്കുന്നു. ഇത് നിലവിലുള്ള അക്കൗണ്ടുകൾ മാറ്റുകയോ ആഗോള പ്രോക്സി സ്വിച്ച് മാറ്റിസ്ഥാപിക്കുകയോ ചെയ്യുന്നില്ല. അതിൻ്റെ പ്രാരംഭ മൂല്യം മുമ്പത്തെ സ്വഭാവത്തെ സംരക്ഷിക്കുന്നു. ഡിഫോൾട്ടായി പ്രവർത്തനരഹിതമാക്കിയ പ്രോക്സി ഉപയോഗിച്ച് ഭാവി അക്കൗണ്ടുകൾ സൃഷ്ടിക്കാൻ ഇത് ഒരിക്കൽ ഓഫാക്കുക.

നിലവിലുള്ള ക്രമീകരണങ്ങൾ API വഴി മുൻഗണന `defaultNewConnectionProxyEnabled` ആയി സംഭരിക്കുന്നു. ഒരിക്കലും സംരക്ഷിക്കപ്പെടാത്തപ്പോൾ ഇത് `true` ലേക്ക് ഡിഫോൾട്ടായി മാറുന്നു. `false` സംരക്ഷിക്കുന്നത് പുനരാരംഭിക്കാതെ തന്നെ തുടർന്നുള്ള പുതിയ അക്കൗണ്ടുകൾക്ക് പ്രാബല്യത്തിൽ വരും. `POST /api/providers` ഒരു ഓപ്ഷണൽ കർശനമായ ബൂളിയൻ `proxyEnabled` സ്വീകരിക്കുന്നു; ഒരു വ്യക്തമായ `true` അല്ലെങ്കിൽ `false` സൃഷ്ടിയുടെ സ്ഥിരസ്ഥിതിയെക്കാൾ മുൻഗണന നൽകുന്നു. ഒരു ഡ്യൂപ്ലിക്കേറ്റ് അക്കൗണ്ടിലെ ഒഴിവാക്കൽ അല്ലെങ്കിൽ OAuth വീണ്ടും കണക്റ്റുചെയ്യുന്നത് ആ അക്കൗണ്ടിൻ്റെ സംഭരിച്ച നിലയെ സംരക്ഷിക്കുന്നു. വ്യക്തിഗത അക്കൗണ്ടുകൾ തുടർന്നും പ്രവർത്തനക്ഷമമാക്കാനോ പ്രവർത്തനരഹിതമാക്കാനോ കഴിയും.

സെലക്ടീവ് പ്രൊവൈഡർ ട്രാൻസ്ഫറുകൾ, പുതിയ അക്കൗണ്ടുകൾക്കായി ഡെസ്റ്റിനേഷൻ ഇൻസ്റ്റാളേഷൻ്റെ ഡിഫോൾട്ട് ഉപയോഗിക്കുകയും നിലവിലുള്ള അക്കൗണ്ടുകൾ മാറ്റിസ്ഥാപിക്കുമ്പോൾ ലക്ഷ്യസ്ഥാന നയം സംരക്ഷിക്കുകയും ചെയ്യുന്നു. പ്രോക്സി ടോഗിളുകൾ പോർട്ടബിൾ ട്രാൻസ്ഫർ ഫീൽഡുകളല്ല. സംരക്ഷിച്ച അക്കൗണ്ട് മൂല്യങ്ങളും ലെഗസി സ്കീമ ഡിഫോൾട്ടുകളും ഉൾപ്പെടെ, പൂർണ്ണമായ ബാക്കപ്പ് പുനഃസ്ഥാപനവും ചരിത്രപരമായ JSON/SQL മൈഗ്രേഷനും അവയുടെ നിലവിലുള്ള പുനഃസ്ഥാപിക്കൽ സെമാൻ്റിക്സ് നിലനിർത്തുന്നു; ഒരു പൂർണ്ണ ക്രമീകരണങ്ങൾ പുനഃസ്ഥാപിക്കുന്നതിനും ഈ മുൻഗണന പുനഃസ്ഥാപിക്കാനാകും.

ഈ മുൻഗണന ഒരു പ്രോക്സിയെ അസൈൻ ചെയ്യുകയോ ഒരാൾ ആരോഗ്യകരമോ ഉപയോഗത്തിലാണെന്നോ സ്ഥാപിക്കുകയോ ചെയ്യുന്നില്ല. യഥാർത്ഥ റൂട്ടിംഗ് ഇപ്പോഴും ആഗോള പ്രോക്സി സ്വിച്ചിനെയും ബാധകമായ പ്രോക്സി കോൺഫിഗറേഷനെയും ആശ്രയിച്ചിരിക്കുന്നു. സ്ഥിരമായ അക്കൗണ്ട് ഇല്ലാത്ത സിന്തറ്റിക് ദാതാക്കൾ, അക്കൗണ്ട് സൃഷ്ടിക്കുന്നതിന് മുമ്പുള്ള OAuth ട്രാഫിക്, environment/system പ്രോക്സികൾ, ബാഹ്യ ബാക്കെൻഡുകളുടെ നെറ്റ്വർക്കിംഗ് എന്നിവ അതിൻ്റെ പരിധിക്ക് പുറത്താണ്.

## 4-ലെവൽ പ്രോക്സി സിസ്റ്റം

OmniRoute പ്രോക്സി കോൺഫിഗറേഷനെ പിന്തുണയ്ക്കുന്നു** നാല് സ്വതന്ത്ര സ്കോപ്പുകൾ** , മുൻഗണനാ ക്രമത്തിൽ പരിഹരിച്ചു:

```
Priority Resolution Order (highest → lowest):

  1. 🔵 Account/Connection Proxy  →  per API key / OAuth connection
  2. 🟡 Provider Proxy            →  per provider (e.g., all OpenAI traffic)
  3. 🟠 Combo Proxy               →  per combo/routing configuration
  4. 🟢 Global Proxy              →  all traffic, all providers
```

### റെസല്യൂഷൻ എങ്ങനെ പ്രവർത്തിക്കുന്നു

OmniRoute ഒരു അപ്സ്ട്രീം ദാതാവിന് ഒരു അഭ്യർത്ഥന അയയ്ക്കുമ്പോൾ, അത് `resolveProxyForConnectionFromRegistry()` വിളിക്കുന്നു, അത് ഓരോ ലെവലും ക്രമത്തിൽ പരിശോധിക്കുന്നു:

1. **അക്കൗണ്ട്-ലെവൽ** — ഈ നിർദ്ദിഷ്ട കണക്ഷൻ ID ന് ഒരു പ്രോക്സി നിയോഗിക്കപ്പെട്ടിട്ടുണ്ടോ?
2. **ദാതാവ്-നില** — ഈ ദാതാവിന് (ഉദാ, `openai`) ഒരു പ്രോക്സി അസൈൻ ചെയ്തിട്ടുണ്ടോ?
3. **ആഗോള തലം** — ഒരു ആഗോള പ്രോക്സി കോൺഫിഗർ ചെയ്തിട്ടുണ്ടോ?
4. **പ്രോക്സി ഇല്ല** — ദാതാവിലേക്കുള്ള നേരിട്ടുള്ള കണക്ഷൻ.

ആദ്യ മത്സരം വിജയിക്കും. ഇതിനർത്ഥം നിങ്ങൾക്ക് ഒരു ഗ്ലോബൽ പ്രോക്സി ഒരു ഫാൾബാക്ക് ആയി സജ്ജീകരിക്കാമെന്നും എന്നാൽ നിർദ്ദിഷ്ട ദാതാക്കൾക്കോ കണക്ഷനുകൾക്കോ വേണ്ടി അത് അസാധുവാക്കാനും കഴിയും.

### എന്താണ് പ്രോക്സിഡ് ലഭിക്കുന്നത്

| ട്രാഫിക് തരം             | പ്രോക്സി ചെയ്തോ? | കുറിപ്പുകൾ                                            |

## പ്രോക്സി രജിസ്ട്രി (CRUD)

നിങ്ങളുടെ എല്ലാ പ്രോക്സികളും സംഭരിക്കുന്ന ഒരു SQLite ടേബിൾ (`proxy_registry`) ആണ് പ്രോക്സി രജിസ്ട്രി. ഓരോ പ്രോക്സിക്കും ഉണ്ട്:

| ഫീൽഡ്      | ടൈപ്പ് ചെയ്യുക | വിവരണം                                                              |
| ---------- | -------------- | ------------------------------------------------------------------- |
| `id`       | UUID           | അദ്വിതീയ ഐഡൻ്റിഫയർ                                                  |
| `name`     | സ്ട്രിംഗ്      | മനുഷ്യർക്ക് വായിക്കാവുന്ന ലേബൽ                                      |
| `type`     | സ്ട്രിംഗ്      | പ്രോട്ടോക്കോൾ: `http`, `https`, `socks5`                            |
| `host`     | സ്ട്രിംഗ്      | പ്രോക്സി ഹോസ്റ്റ്നാമം അല്ലെങ്കിൽ IP                                 |
| `port`     | പൂർണ്ണസംഖ്യ    | പോർട്ട് നമ്പർ                                                       |
| `username` | സ്ട്രിംഗ്      | അംഗീകൃത ഉപയോക്തൃനാമം (വിശ്രമ സമയത്ത് എൻക്രിപ്റ്റ് ചെയ്തിരിക്കുന്നു) |
| `password` | സ്ട്രിംഗ്      | ഓത്ത് പാസ്വേഡ് (വിശ്രമ സമയത്ത് എൻക്രിപ്റ്റ് ചെയ്തിരിക്കുന്നു)       |
| `region`   | സ്ട്രിംഗ്      | ഭൂമിശാസ്ത്രപരമായ പ്രദേശ ലേബൽ                                        |
| `notes`    | സ്ട്രിംഗ്      | സ്വതന്ത്ര-വാചക കുറിപ്പുകൾ                                           |
| `status`   | സ്ട്രിംഗ്      | `active` അല്ലെങ്കിൽ `inactive`                                      |
| `source`   | സ്ട്രിംഗ്      | `manual` അല്ലെങ്കിൽ `oneproxy`                                      |

### ഒരു പ്രോക്സി സൃഷ്ടിക്കുന്നു

**ഡാഷ്ബോർഡ് വഴി:**

1. പോകുക** ക്രമീകരണങ്ങൾ → പ്രോക്സി**
2. ക്ലിക്ക് ചെയ്യുക** പ്രോക്സി ചേർക്കുക**
3. തരം, ഹോസ്റ്റ്, പോർട്ട്, ഓപ്ഷണൽ ഓത്ത് ക്രെഡൻഷ്യലുകൾ എന്നിവ പൂരിപ്പിക്കുക
4. സംരക്ഷിക്കുക

**API വഴി:**

```bash
curl -X POST http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "name": "US Proxy",
    "type": "http",
    "host": "proxy.example.com",
    "port": 8080,
    "username": "user",
    "password": "pass",
    "region": "US"
  }'
```

### ഒരു പ്രോക്സി അപ്ഡേറ്റ് ചെയ്യുന്നു

```bash
curl -X PATCH http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "id": "proxy-uuid-here",
    "host": "new-proxy.example.com",
    "port": 9090
  }'
```

> **കുറിപ്പ്:** നിങ്ങൾ ശൂന്യമല്ലാത്ത പകരംവയ്ക്കലുകൾ അയയ്ക്കുന്നില്ലെങ്കിൽ ക്രെഡൻഷ്യലുകൾ സംരക്ഷിക്കപ്പെടും. `username`/`password` എന്നതിനായി ശൂന്യമായ സ്ട്രിംഗുകൾ അയയ്ക്കുന്നത് സംഭരിച്ച മൂല്യങ്ങൾ നിലനിർത്തും.

### ഒരു പ്രോക്സി ഇല്ലാതാക്കുന്നു

```bash
# Fails if proxy is assigned to any scope
curl -X DELETE "http://localhost:20128/api/v1/management/proxies?id=proxy-uuid"

# Force delete (removes assignments too)
curl -X DELETE "http://localhost:20128/api/v1/management/proxies?id=proxy-uuid&force=1"
```

### ലിസ്റ്റിംഗ് പ്രോക്സികൾ

```bash
curl "http://localhost:20128/api/v1/management/proxies?limit=50&offset=0"
```

### സ്കോപ്പുകളിലേക്ക് പ്രോക്സികൾ അസൈൻ ചെയ്യുന്നു

```bash
# Assign to global scope
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "global", "proxy": {"type":"http","host":"proxy.example.com","port":8080}}'

# Assign to a specific provider
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "provider", "id": "openai", "proxy": {"type":"socks5","host":"socks.example.com","port":1080}}'

# Assign to a specific connection/key
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "key", "id": "connection-uuid", "proxy": {"type":"http","host":"key-proxy.com","port":3128}}'
```

### ഫലപ്രദമായ പ്രോക്സി പരിഹരിക്കുന്നു

തന്നിരിക്കുന്ന കണക്ഷനായി ഏത് പ്രോക്സി ഉപയോഗിക്കുമെന്ന് പരിശോധിക്കുക:

```bash
curl "http://localhost:20128/api/settings/proxy?resolve=connection-uuid"
```

പരിഹരിച്ച പ്രോക്സിയെ അതിൻ്റെ ലെവലും (`account`, `provider`, അല്ലെങ്കിൽ `global`) ഉറവിടവും ഉപയോഗിച്ച് നൽകുന്നു.

### ബൾക്ക് അസൈൻമെൻ്റ്

ഒന്നിലധികം ദാതാക്കൾക്കോ കണക്ഷനുകൾക്കോ ഒരേസമയം ഒരു പ്രോക്സി നൽകുക:

```bash
curl -X POST http://localhost:20128/api/v1/management/proxies/bulk-assign \
  -H "Content-Type: application/json" \
  -d '{
    "scope": "provider",
    "scopeIds": ["openai", "anthropic", "codex"],
    "proxyId": "proxy-uuid"
  }'
```

### Import/Export

പ്രോക്സികൾ ഉൾപ്പെടുത്തിയിട്ടുണ്ട്**Backup/Restore** സിസ്റ്റം. നിങ്ങളുടെ OmniRoute കോൺഫിഗറേഷൻ കയറ്റുമതി ചെയ്യുമ്പോൾ:

1. പോകുക** ഡാഷ്ബോർഡ് → ക്രമീകരണങ്ങൾ → ബാക്കപ്പ്**
2. ക്ലിക്ക് ചെയ്യുക** കയറ്റുമതി** — പ്രോക്സി രജിസ്ട്രിയും അസൈൻമെൻ്റുകളും ഉൾപ്പെടുത്തിയിട്ടുണ്ട്
3. പുനഃസ്ഥാപിക്കാൻ, ക്ലിക്ക് ചെയ്യുക** ഇറക്കുമതി ചെയ്യുക** കൂടാതെ ബാക്കപ്പ് ഫയൽ അപ്ലോഡ് ചെയ്യുക

പ്രോക്സി രജിസ്ട്രിയും പിന്തുണയ്ക്കുന്നു** ഹോസ്റ്റ്+ പോർട്ട് വഴി അപ്സേർട്ട് ചെയ്യുക** — നിങ്ങൾ ഇതിനകം നിലവിലുള്ള ഒരു പ്രോക്സി ഇറക്കുമതി ചെയ്യുകയാണെങ്കിൽ (അതേ ഹോസ്റ്റും പോർട്ടും), ഒരു തനിപ്പകർപ്പ് സൃഷ്ടിക്കുന്നതിന് പകരം അത് അപ്ഡേറ്റ് ചെയ്യുന്നു.

### ലെഗസി മൈഗ്രേഷൻ

നിങ്ങൾ ഒരു പഴയ പതിപ്പിൽ (പ്രീ-രജിസ്ട്രി) പ്രോക്സികൾ ക്രമീകരിച്ചിട്ടുണ്ടെങ്കിൽ, OmniRoute അവയെ സ്വയമേവ മൈഗ്രേറ്റ് ചെയ്യുന്നു:

```
Legacy key_value store → proxy_registry + proxy_assignments
```

അപ്ഗ്രേഡുചെയ്തതിനുശേഷം ആദ്യ സ്റ്റാർട്ടപ്പിൽ ഒരിക്കൽ ഇത് സംഭവിക്കുന്നു. വീണ്ടും പ്രവർത്തിപ്പിക്കാൻ `migrateLegacyProxyConfigToRegistry({ force: true })` ഉപയോഗിക്കുക.

## 1പ്രോക്സി ഫ്രീ പ്രോക്സി മാർക്കറ്റ്പ്ലേസ്

> 🆕** [@oyi77](https://github.com/oyi77) സംഭാവന ചെയ്തത്** — PR [#1847](https://github.com/diegosouzapw/OmniRoute/pull/1847) (ഇഷ്യൂ [#1788](https://github.com/diegosouzapw/OmniRoute/issues/1788) )

OmniRoute എന്നതുമായി സംയോജിപ്പിക്കുന്നു** [1പ്രോക്സി](https://1proxy-api.aitradepulse.com)** ആക്സസ് നൽകുന്നതിനുള്ള കമ്മ്യൂണിറ്റി പ്ലാറ്റ്ഫോം** നൂറുകണക്കിന് സൗജന്യ, സാധുതയുള്ള പ്രോക്സികൾ** ലോകമെമ്പാടും നിന്ന്. സ്വന്തമായി പ്രോക്സി ഇൻഫ്രാസ്ട്രക്ചർ ഇല്ലാത്ത ഉപയോക്താക്കൾക്ക് ഇത് അനുയോജ്യമാണ്.

### ഇത് എങ്ങനെ പ്രവർത്തിക്കുന്നു

```
┌─────────────┐     Sync      ┌─────────────────┐    Rotate     ┌──────────┐
│  1proxy API │ ────────────▶ │  proxy_registry  │ ────────────▶ │ Provider │
│  (external) │   up to 500   │  source=oneproxy │  by quality   │   API    │
└─────────────┘    proxies    └─────────────────┘               └──────────┘
```

1. **സമന്വയിപ്പിക്കുക** — OmniRoute, 1proxy API ൽ നിന്ന് സാധുതയുള്ള പ്രോക്സികൾ ലഭ്യമാക്കുന്നു
2. **സ്റ്റോർ** — പ്രോക്സികൾ അതേ `proxy_registry` ടേബിളിൽ `source = 'oneproxy'` ഉപയോഗിച്ച് സേവ് ചെയ്യുന്നു
3. **ഫിൽട്ടർ ചെയ്യുക** പ്രോട്ടോക്കോൾ, രാജ്യം, ഗുണമേന്മയുള്ള സ്കോർ എന്നിവ പ്രകാരം — ഫിൽട്ടർ ചെയ്യുക
4. **തിരിക്കുക** — ഗുണനിലവാരം, ക്രമരഹിതമായ അല്ലെങ്കിൽ തുടർച്ചയായ തന്ത്രങ്ങൾ ഉപയോഗിച്ച് മികച്ച പ്രോക്സി തിരഞ്ഞെടുക്കുക
5. **ഓട്ടോ-ഡീഗ്രേഡ്** — പരാജയപ്പെട്ട പ്രോക്സികളുടെ ഗുണനിലവാരം കുറയുന്നു; ത്രെഷോൾഡിന് താഴെ → നിഷ്ക്രിയമായി അടയാളപ്പെടുത്തി

### പ്രോക്സികൾ സമന്വയിപ്പിക്കുന്നു

**ഡാഷ്ബോർഡ് വഴി:**

1. പോകുക** ക്രമീകരണങ്ങൾ → 1proxy** ടാബ്
2. ക്ലിക്ക് ചെയ്യുക** "ഇപ്പോൾ സമന്വയിപ്പിക്കുക"**
3. സ്ഥിതിവിവരക്കണക്കുകൾ കാണുക: മൊത്തം പ്രോക്സികൾ, സജീവമായ എണ്ണം, ശരാശരി നിലവാരം, ബൈ-കൺട്രി ബ്രേക്ക്ഡൗൺ

**API വഴി:**

```bash

curl -X POST http://localhost:20128/api/settings/oneproxy \
  -H "Content-Type: application/json" \
  -d '{}'

# Response:
# { "success": true, "added": 127, "updated": 45, "failed": 2, "total": 172 }
```

### ഫിൽട്ടറിംഗ് പ്രോക്സികൾ

| ഫീൽഡ്           | വിവരണം                                                 |
| --------------- | ------------------------------------------------------ |
| `qualityScore`  | 1പ്രോക്സി മൂല്യനിർണ്ണയത്തിൽ നിന്ന് 0-100 റേറ്റിംഗ്     |

- **പരാജയപ്പെട്ട അഭ്യർത്ഥനകൾ** സ്കോർ 10 പോയിൻ്റ് കുറയ്ക്കുക
- **സ്കോർ ≤ 10-ലേക്ക് കുറയുന്നു** → പ്രോക്സി `inactive` എന്ന് അടയാളപ്പെടുത്തിയിരിക്കുന്നു
- പ്രവർത്തനരഹിതമായ പ്രോക്സികളെ ഭ്രമണത്തിൽ നിന്ന് ഒഴിവാക്കിയിരിക്കുന്നു

## ആൻ്റി-ഡിറ്റക്ഷൻ & സ്റ്റെൽത്ത്

OmniRoute ഒരു പ്രോക്സി — വഴി ട്രാഫിക്കിനെ നയിക്കുക മാത്രമല്ല, ഇത് ട്രാഫിക്കിനെ നിയമാനുസൃതമാക്കുന്നു:

### TLS ഫിംഗർപ്രിൻ്റ് സ്പൂഫിംഗ്

ബ്രൗസർ പോലെയുള്ള TLS ഫിംഗർപ്രിൻ്റ് സൃഷ്ടിക്കാൻ `wreq-js` ഉപയോഗിക്കുന്നു, നോൺ-ബ്രൗസർ TLS ഹാൻഡ്ഷേക്കുകൾ ഫ്ലാഗ് ചെയ്യുന്ന ബോട്ട് ഡിറ്റക്ഷൻ സിസ്റ്റങ്ങളെ മറികടക്കുന്നു.

### CLI ഫിംഗർപ്രിൻ്റ് പൊരുത്തപ്പെടുത്തൽ

ദി**CLI ഫിംഗർപ്രിൻ്റ് ടോഗിൾ ചെയ്യുക** (`Settings → Security`) നേറ്റീവ് CLI ബൈനറികളുടെ (Claude കോഡ്, Codex, മുതലായവ) കൃത്യമായ ഒപ്പുമായി പൊരുത്തപ്പെടുന്നതിന് HTTP തലക്കെട്ടുകളും JSON ബോഡി ഫീൽഡുകളും പുനഃക്രമീകരിക്കുന്നു. ഇത് പ്രവർത്തിക്കുന്നു** മുകളിൽ** പ്രോക്സി:

```
Your IP (blocked) → Proxy IP (US) → Provider API
                    + TLS spoof
                    + CLI fingerprint
```

രണ്ടും കിട്ടും**IP മാസ്കിംഗ്** ഒപ്പം** ആധികാരികത അഭ്യർത്ഥിക്കുക** ഒരേസമയം.

### പ്രോക്സി IP സംരക്ഷണം

ഡാഷ്ബോർഡിലെ കളർ-കോഡുചെയ്ത ബാഡ്ജുകൾ ഏത് പ്രോക്സി ലെവൽ സജീവമാണെന്ന് കാണിക്കുന്നു:

| ബാഡ്ജ് | ലെവൽ   | അർത്ഥം                                                  |
| ------ | ------ | ------------------------------------------------------- |
| 🟢     | ആഗോള   | എല്ലാ ട്രാഫിക്കും ഈ പ്രോക്സി വഴിയാണ് പോകുന്നത്          |
| 🟡     | ദാതാവ് | ഈ ദാതാവിൻ്റെ ട്രാഫിക്ക് മാത്രമേ പ്രോക്സി ചെയ്തിട്ടുള്ളൂ |
| 🔵     | കണക്ഷൻ | ഈ നിർദ്ദിഷ്ട key/account ഈ പ്രോക്സി ഉപയോഗിക്കുന്നു      |

സ്ഥിരീകരണത്തിനായി പരിഹരിച്ച പ്രോക്സി IP ബാഡ്ജ് കാണിക്കുന്നു.

## അപ്സ്ട്രീം പ്രോക്സി മോഡുകൾ

CLIProxyAPI പാറ്റേൺ ഉപയോഗിക്കുന്ന ദാതാക്കൾക്കായി, OmniRoute മൂന്ന് അപ്സ്ട്രീം പ്രോക്സി മോഡുകളെ പിന്തുണയ്ക്കുന്നു:

| മോഡ്          | വിവരണം                                                                  |
| ------------- | ----------------------------------------------------------------------- |
| `native`      | OmniRoute നേരിട്ട് പ്രോക്സി റൂട്ടിംഗ് കൈകാര്യം ചെയ്യുന്നു (സ്ഥിരസ്ഥിതി) |
| `cliproxyapi` | ഒരു ബാഹ്യ CLIProxyAPI ഉദാഹരണത്തിലേക്ക് പ്രതിനിധികൾ                      |
| `fallback`    | ആദ്യം നേറ്റീവ് പരീക്ഷിക്കുന്നു, വീണ്ടും CLIProxyAPI ലേക്ക് വീഴുന്നു     |

ഓരോ ദാതാവിനും കോൺഫിഗർ ചെയ്യുക:

```bash
curl -X PUT "http://localhost:20128/api/upstream-proxy/openai" \
  -H "Content-Type: application/json" \
  -d '{"mode": "native", "enabled": true}'
```

- **കണക്ഷൻ ടെസ്റ്റ്** ക്രമീകരിച്ച പ്രോക്സി വഴി
- **കളർ കോഡുചെയ്ത ബാഡ്ജുകൾ** സജീവ പ്രോക്സി ലെവൽ കാണിക്കുന്നു

### ക്രമീകരണങ്ങൾ → 1പ്രോക്സി ടാബ്

- **ഇപ്പോൾ സമന്വയിപ്പിക്കുക** സൗജന്യ പ്രോക്സികൾ ലഭ്യമാക്കുന്നതിനുള്ള ബട്ടൺ
- **സ്ഥിതിവിവരക്കണക്കുകൾ കാർഡുകൾ** : ആകെ, സജീവം, ശരാശരി നിലവാരം, അവസാന സമന്വയം
- **ഫിൽട്ടറുകൾ** : പ്രോട്ടോക്കോൾ, രാജ്യ കോഡ്, കുറഞ്ഞ നിലവാരം
- **പ്രോക്സി ടേബിൾ** ഹോസ്റ്റ്, പ്രോട്ടോക്കോൾ, രാജ്യം, ഗുണമേന്മയുള്ള സ്കോർ, ലേറ്റൻസി, അജ്ഞാതത, Google ആക്സസ് എന്നിവയ്ക്കൊപ്പം
- **സമന്വയ നില** success/failure ട്രാക്കിംഗും തുടർച്ചയായ പരാജയങ്ങളുടെ എണ്ണവുമുള്ള പാനൽ
- **എല്ലാം മായ്ക്കുക** എല്ലാ 1പ്രോക്സി എൻട്രികളും നീക്കം ചെയ്യാൻ

## ട്രബിൾഷൂട്ടിംഗ്

### "SOCKS5 പ്രോക്സി പ്രവർത്തനരഹിതമാക്കി"

നിങ്ങളുടെ `.env` ഫയലിൽ `ENABLE_SOCKS5_PROXY=true` സജ്ജമാക്കി പുനരാരംഭിക്കുക.

### പ്രോക്സി വഴി "സോക്കറ്റ് ഹാംഗ് അപ്പ്" പിശകുകൾ

നിഷ്ക്രിയ കണക്ഷനുകൾ ഉപേക്ഷിക്കുന്ന വിലകുറഞ്ഞ പ്രോക്സികളിൽ ഇത് സാധാരണമാണ്. OmniRoute ഇതിനകം ഇത് കൈകാര്യം ചെയ്യുന്നു:

- പ്രോക്സി കണക്ഷനുകളിൽ (`keepAliveTimeout: 1`) Keep-alive പ്രവർത്തനരഹിതമാക്കുന്നു
- പൈപ്പ്ലൈനിംഗ് പ്രവർത്തനരഹിതമാക്കുന്നു (`pipelining: 0`)
- ആവർത്തിച്ചുള്ള ഹാൻഡ്ഷേക്കുകൾ ഒഴിവാക്കാൻ ഡിസ്പാച്ചറുകൾ കാഷെ ചെയ്യുന്നു

ഇത് നിലനിൽക്കുകയാണെങ്കിൽ, മറ്റൊരു പ്രോക്സി പരീക്ഷിക്കുക അല്ലെങ്കിൽ 1പ്രോക്സി റൊട്ടേഷൻ ഫീച്ചർ ഉപയോഗിക്കുക.

### OAuth സമയത്ത് "unsupported_country_region_territory"

പ്രോക്സി കോൺഫിഗർ ചെയ്തിട്ടുണ്ടെന്ന് ഉറപ്പാക്കുക** മുമ്പ്** OAuth ഒഴുക്ക് ആരംഭിക്കുന്നു. ക്രമീകരിച്ച പ്രോക്സി വഴി OmniRoute റൂട്ടുകൾ OAuth ടോക്കൺ എക്സ്ചേഞ്ച്. ആദ്യം ഒരു ഗ്ലോബൽ അല്ലെങ്കിൽ പ്രൊവൈഡർ-ലെവൽ പ്രോക്സി സജ്ജീകരിക്കുക, തുടർന്ന് കണക്റ്റുചെയ്യുക.

### പ്രോക്സി ഉപയോഗിക്കുന്നില്ല

റെസലൂഷൻ ഓർഡർ പരിശോധിക്കുക:

1. `GET /api/settings/proxy?resolve=your-connection-id` ഉപയോഗിച്ച് പരിശോധിക്കുക
2. പ്രോക്സി `status` `active` ആണോ എന്ന് പരിശോധിക്കുക ( `inactive` അല്ല)
3. പ്രോക്സി അസൈൻമെൻ്റ് സ്കോപ്പ് നിങ്ങളുടെ കണക്ഷനുമായി പൊരുത്തപ്പെടുന്നുണ്ടെന്ന് ഉറപ്പാക്കുക

### 1പ്രോക്സി സമന്വയം പരാജയപ്പെടുന്നു

സമന്വയ നില പരിശോധിക്കുക:

```bash
curl "http://localhost:20128/api/settings/oneproxy?action=status"
```

`consecutiveFailures >= 5` ആണെങ്കിൽ, സർക്യൂട്ട് ബ്രേക്കർ ട്രിപ്പ് ചെയ്തു. പുനഃസജ്ജമാക്കാൻ സെർവർ പുനരാരംഭിക്കുക, അല്ലെങ്കിൽ മാനുവൽ റീസെറ്റിനായി കാത്തിരിക്കുക.

## ഡാറ്റാബേസ് സ്കീമ

### `proxy_registry` പട്ടിക

```sql
CREATE TABLE proxy_registry (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  type TEXT NOT NULL DEFAULT 'http',
  host TEXT NOT NULL,
  port INTEGER NOT NULL,
  username TEXT DEFAULT '',
  password TEXT DEFAULT '',
  region TEXT,
  notes TEXT,
  status TEXT DEFAULT 'active',
  source TEXT NOT NULL DEFAULT 'manual',    -- 'manual' or 'oneproxy'
  quality_score INTEGER,                     -- 0-100 (1proxy only)
  latency_ms INTEGER,                        -- milliseconds (1proxy only)
  anonymity TEXT,                            -- transparent/anonymous/elite
  google_access INTEGER DEFAULT 0,           -- can access Google? (1proxy)
  last_validated TEXT,                       -- ISO timestamp (1proxy)
  country_code TEXT,                         -- ISO 2-letter code (1proxy)
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

### `proxy_assignments` പട്ടിക

```sql
CREATE TABLE proxy_assignments (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  proxy_id TEXT NOT NULL REFERENCES proxy_registry(id),
  scope TEXT NOT NULL,        -- 'global', 'provider', 'account', 'combo'
  scope_id TEXT,              -- provider ID, connection ID, or combo ID
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE(scope, scope_id)
);
```

## പ്രോക്സി ആരോഗ്യ പരിശോധന (v3.8.16 +)

OmniRoute ൻ്റെ** പ്രോക്സി ഫാസ്റ്റ് പരാജയം** മെക്കാനിസം (`src/lib/proxyHealth.ts`) ദ്രുത TCP കണക്ഷൻ പരിശോധനയിലൂടെ < 2s-ൽ ഡെഡ് പ്രോക്സികൾ കണ്ടെത്തുന്നു, തുടർന്ന്** ഫലം കാഷ് ചെയ്യുന്നു** ഓരോ അഭ്യർത്ഥനയും ഓവർഹെഡ് ഒഴിവാക്കാൻ.

### ഇത് എങ്ങനെ പ്രവർത്തിക്കുന്നു

```
Request ──▶ ProxyHealthCache.get(url)
             │
             ├─ Cache hit + fresh?  ──▶ return cached status
             │
             └─ Cache miss / stale?  ──▶ TCP connect to host:port
                                          (timeout: FAST_FAIL_TIMEOUT_MS)
                                          ──▶ cache for HEALTH_CACHE_TTL_MS
                                          ──▶ return result
```

ഇത് കൂടാതെ, ഒരു ഡെഡ് പ്രോക്സി പരാജയപ്പെടുന്നതിന് മുമ്പ് പൂർണ്ണ `PROXY_TIMEOUT_MS` (സ്ഥിരസ്ഥിതി 30 സെ) എന്നതിനായുള്ള എല്ലാ അഭ്യർത്ഥനകളും തടയും.

### ട്യൂണബിൾ എൻവയോൺമെൻ്റ് വേരിയബിളുകൾ

| വേരിയബിൾ                     | സ്ഥിരസ്ഥിതി | ഉദ്ദേശ്യം                                    |
| ---------------------------- | ----------- | -------------------------------------------- |
| `PROXY_FAST_FAIL_TIMEOUT_MS` | `2000`      | ഓരോ ആരോഗ്യ പരിശോധനയ്ക്കുംTCP കണക്ഷൻ സമയപരിധി |
| `PROXY_HEALTH_CACHE_TTL_MS`  | `30000`     | ആരോഗ്യ ഫലം എത്രത്തോളം കാഷെ ചെയ്തിരിക്കുന്നു  |

| ജിയോ ഡിസ്ട്രിബ്യൂട്ടഡ് നോഡുകൾ | 3000മി.എസ്              | 15000മി.സെ  | വേഗത കുറഞ്ഞ നെറ്റ്വർക്കുകൾക്ക് കൂടുതൽ സമയം ആവശ്യമാണ്; വേഗത്തിലുള്ള പരാജയത്തിന് ചെറിയ കാഷെ |
| ഡെവലപ്പ് / ടെസ്റ്റിംഗ്        | 1000മി.എസ്              | 10000മി.സെ  | പ്രാദേശിക പ്രോക്സികളിൽ ദ്രുത ആവർത്തനം                                                     |
| സ്റ്റെൽത്ത് / ആൻ്റി ഡിറ്റക്ഷൻ | 2500മി.എസ്              | 45000മിസെ   | നിരക്ക് പരിധികൾ ട്രിഗർ ചെയ്യാൻ കഴിയുന്ന ദ്രുത പരിശോധന ഒഴിവാക്കുക                          |

### പ്രോക്സി ആരോഗ്യം പരിശോധിക്കുന്നു

```ts
import { getAllProxyHealthStatuses, invalidateProxyHealth } from "omniroute/proxyHealth";

const statuses = getAllProxyHealthStatuses();
for (const s of statuses) {
  console.log(`${s.proxyUrl} → healthy=${s.healthy}, stale=${s.stale}`);
}

// Force re-check a specific proxy
invalidateProxyHealth("http://user:pass@203.0.113.7:8080");
```

കാഷെ എൻട്രി `HEALTH_CACHE_TTL_MS` കവിഞ്ഞാൽ `stale` ഫ്ലാഗ് `true` ആണ്, അടുത്ത അഭ്യർത്ഥന ഒരു പുതിയ പരിശോധന ട്രിഗർ ചെയ്യും.

### പെർ-പ്രോക്സി തരം ഡിഫോൾട്ടുകൾ

ആരോഗ്യ പരിശോധന URL സ്കീമിനെ അടിസ്ഥാനമാക്കി സുബോധമുള്ള ഡിഫോൾട്ടുകൾ ഉപയോഗിക്കുന്നു:

| സ്കീം                      | ഡിഫോൾട്ട് പോർട്ട് |
| -------------------------- | ----------------- |
| `http://`                  | 8080              |
| `https://`                 | 443               |
| `socks5://` / `socks5h://` | 1080              |

URL (`http://host:9999`) ലെ ഇഷ്ടാനുസൃത പോർട്ടുകൾ എല്ലായ്പ്പോഴും സ്കീം ഡിഫോൾട്ടിനെക്കാൾ മുൻഗണന നൽകുന്നു.

## പ്രോക്സി അനലിറ്റിക്സും നിരീക്ഷണക്ഷമതയും

റൂട്ടിംഗ് പാറ്റേണുകൾ, ലേറ്റൻസി സ്പൈക്കുകൾ, ആവർത്തിച്ചുള്ള പരാജയങ്ങൾ എന്നിവ നിർണ്ണയിക്കാൻ ഓപ്പറേറ്റർമാരെ സഹായിക്കുന്നതിന്OmniRoute ഓരോ പ്രോക്സി ഉപയോഗം ട്രാക്ക് ചെയ്യുന്നു.

### എന്താണ് ട്രാക്ക് ചെയ്തിരിക്കുന്നത്

ക്രമീകരിച്ച പ്രോക്സി വഴിയുള്ള ഓരോ അഭ്യർത്ഥനയ്ക്കും, OmniRoute രേഖപ്പെടുത്തുന്നു:

| മെട്രിക്     | വിവരണം                                                         |
| ------------ | -------------------------------------------------------------- |
| `proxy_url`  | പൂർണ്ണ പ്രോക്സി URL (ആധികാരിക ക്രെഡൻഷ്യലുകൾ മറച്ചുവെച്ച്)      |
| `provider`   | അപ്സ്ട്രീം പ്രൊവൈഡർ ID (openai, anthropic, മുതലായവ)            |
| `latency_ms` | പ്രോക്സി ഹാൻഡ്ഷേക്ക് ഉൾപ്പെടെയുള്ള മൊത്തം റൗണ്ട്-ട്രിപ്പ് സമയം |
| `connect_ms` | TCP കണക്ട് സമയം മാത്രം                                         |
| `status`     | അപ്സ്ട്രീമിൽ നിന്നുള്ള HTTP സ്റ്റാറ്റസ് കോഡ്                   |
| `error`      | അഭ്യർത്ഥന പരാജയപ്പെട്ടാൽ ക്ലാസ് പിശക്                          |
| `timestamp`  | ISO 8601 UTC                                                   |

### ഡാറ്റ ആക്സസ് ചെയ്യുന്നു

```bash
# Recent proxy events
curl -H "Authorization: Bearer $OMNIROUTE_KEY" \
  "http://localhost:20128/api/usage/proxy-logs?limit=100"
```

യഥാർത്ഥ അവസാന പോയിൻ്റ് `/api/usage/proxy-logs` ആണ് ( `src/app/api/usage/proxy-logs/route.ts` കാണുക). ഈ അവസാന പോയിൻ്റ് പിന്തുണയ്ക്കുന്നു:

- `GET /api/usage/proxy-logs` — പ്രോക്സി ലോഗുകൾ വീണ്ടെടുക്കുക
- `DELETE /api/usage/proxy-logs` — എല്ലാ പ്രോക്സി ലോഗുകളും മായ്ക്കുക

ആവശ്യമെങ്കിൽ മൊത്തം സ്ഥിതിവിവരക്കണക്കുകൾ `proxy_logs` പട്ടികയിൽ നിന്ന് SQL വഴി നേരിട്ട് അന്വേഷിക്കാവുന്നതാണ്. ഡാഷ്ബോർഡ് UI മൊത്തത്തിലുള്ള കാഴ്ചകൾ വാഗ്ദാനം ചെയ്തേക്കാം.

### സാധാരണ പാറ്റേണുകൾ

**ഒരു ഫ്ലാപ്പിംഗ് പ്രോക്സി കണ്ടെത്തുക** ( success/failure യ്ക്കിടയിൽ മാറിമാറി):

```sql
SELECT proxy_url,
       COUNT(*) AS total,
       SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) AS errors,
       ROUND(100.0 * SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) / COUNT(*), 1) AS error_pct
FROM proxy_logs
WHERE timestamp > datetime('now', '-1 hour')
GROUP BY proxy_url
HAVING error_pct > 5
ORDER BY error_pct DESC;
```

**സ്ലോ പ്രോക്സികൾ കണ്ടെത്തുക** (p95 ലേറ്റൻസി > 2s):

```sql
WITH ranked AS (
  SELECT proxy_url, latency_ms,
         PERCENT_RANK() OVER (PARTITION BY proxy_url ORDER BY latency_ms) AS pct
  FROM proxy_logs
  WHERE timestamp > datetime('now', '-24 hour')
)
SELECT proxy_url, latency_ms
FROM ranked
WHERE pct >= 0.95
ORDER BY latency_ms DESC;
```

## റൊട്ടേഷൻ സ്ട്രാറ്റജി ഡിസിഷൻ ട്രീ

ഒരു സ്കോപ്പിലേക്ക് ഒന്നിലധികം പ്രോക്സികൾ നൽകുമ്പോൾ, OmniRoute a ഉപയോഗിക്കുന്നു** ഭ്രമണ തന്ത്രം** ഓരോ അഭ്യർത്ഥനയ്ക്കും ഏതാണ് ഉപയോഗിക്കേണ്ടതെന്ന് തിരഞ്ഞെടുക്കാൻ. സ്കോപ്പ് തലത്തിലാണ് തന്ത്രം ക്രമീകരിച്ചിരിക്കുന്നത് (ആഗോള, ഓരോ ദാതാവിനും, ഓരോ അക്കൗണ്ടിനും, ഓരോ കോംബോ).

### ലഭ്യമായ തന്ത്രങ്ങൾ

| തന്ത്രം                 | എപ്പോൾ ഉപയോഗിക്കണം                                       | തുല്യതയ്ക്കായുള്ള കൈമാറ്റം                                                                    |
| ----------------------- | -------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `quality` (സ്ഥിരസ്ഥിതി) | സമ്മിശ്ര-ഗുണമേന്മയുള്ള പ്രോക്സികൾ ഉപയോഗിച്ചുള്ള ഉത്പാദനം | ഉയർന്ന റേറ്റുചെയ്ത പ്രോക്സികളെ അനുകൂലിക്കുന്നു; താഴ്ന്ന നിലവാരമുള്ളവരെ പട്ടിണിയിലാക്കിയേക്കാം |
| `random`                | ലോഡ് വിതരണം, സ്വകാര്യത                                   | വിതരണം പോലും; ഗുണനിലവാര സിഗ്നലുകൾ അവഗണിക്കുന്നു                                               |
| `sequential`            | ഡീബഗ്ഗിംഗ്, ഡിറ്റർമിനിസ്റ്റിക് ടെസ്റ്റിംഗ്               | ക്രമത്തിൽ പ്രോക്സികൾ വഴി സൈക്കിളുകൾ; ന്യായവാദം ചെയ്യാൻ എളുപ്പമാണ്                             |

## നിങ്ങളുടെ സ്വന്തം പ്രോക്സികൾക്കുള്ള യാന്ത്രിക പരാജയ ഒഴിവാക്കൽ

1പ്രോക്സി മാർക്കറ്റ്പ്ലെയ്സ് പൂൾ ഇതിനകം തന്നെ പരാജയപ്പെട്ട പ്രോക്സികളെ സ്വയമേവ തരംതാഴ്ത്തുന്നു ( [പ്രോക്സി ക്വാളിറ്റി സ്കോറുകൾ](#proxy-quality-scores) കാണുക). പ്രോക്സികൾക്കായി** നിങ്ങൾ** രജിസ്ട്രിയിൽ ചേർത്തു, പശ്ചാത്തല ഹെൽത്ത് ഷെഡ്യൂളർ (`src/lib/proxyHealth/scheduler.ts`) ഒന്നും ഇല്ലാതാക്കാതെ തന്നെ "മരിച്ച അംഗത്തെ ശൃംഖലയിൽ നിന്ന് സ്വയമേവ ഒഴിവാക്കുക" സ്വഭാവം നൽകുന്നു:

```bash
# .env — soft-disable a proxy after 3 consecutive failed probes, re-enable it
# automatically once it starts answering probes again.
PROXY_AUTO_DISABLE=true
PROXY_AUTO_REMOVE_AFTER=3
```

ഒരു മൾട്ടി-പ്രോക്സി ചെയിനിലേക്ക് ഇത് എങ്ങനെ യോജിക്കുന്നു:

1. ഷെഡ്യൂളർ രജിസ്റ്റർ ചെയ്ത എല്ലാ പ്രോക്സികളും ഓരോ `PROXY_HEALTH_INTERVAL_MS` യും പരിശോധിക്കുന്നു (സ്ഥിരസ്ഥിതി 10 മിനിറ്റ്; കുറഞ്ഞത് 1 മിനിറ്റ്).
2. `PROXY_AUTO_REMOVE_AFTER` തുടർച്ചയായി ശേഷം** നിർണായകമായ** പരാജയങ്ങൾ (ഒരു യഥാർത്ഥ കണക്ഷൻ പരാജയം — ഒരു ടൈംഔട്ട് അല്ലെങ്കിൽ പ്രോബ് ടാർഗെറ്റിൻ്റെ സ്വന്തം 5xx ഒരിക്കലും കണക്കാക്കില്ല, [പ്രോക്സി ഹെൽത്ത് ചെക്കിംഗ്](#proxy-health-checking-v3816) കാണുക), പ്രോക്സിയുടെ `status` `dead` ആയി സജ്ജീകരിച്ചിരിക്കുന്നു.
3. pool/rotation റെസല്യൂഷൻ ഉപയോഗിക്കുന്ന ലൈവ്-സ്റ്റാറ്റസ് ഫിൽട്ടർ ഒഴിവാക്കുന്ന സ്റ്റാറ്റസുകളിൽ ഒന്നാണ്`dead`, അതിനാൽ ഒരു സ്കോപ്പിൻ്റെ റൊട്ടേഷൻ (റൗണ്ട്-റോബിൻ / റാൻഡം / സ്റ്റിക്കി / ലേറ്റൻസി — കാണുക [റൊട്ടേഷൻ സ്ട്രാറ്റജി ഡിസിഷൻ ട്രീ](#rotation-strategy-decision-tree) ) ഉടൻ തന്നെ പുതിയ അഭ്യർത്ഥനകൾക്ക് ആ പ്രോക്സി കൈമാറുന്നത് നിർത്തുന്നു. പൂളിലെ മറ്റ് പ്രോക്സികളൊന്നും ബാധിക്കില്ല, കൂടാതെ മുഴുവൻ പൂളും ഒരിക്കലും നിശ്ശബ്ദമായി നേരിട്ടുള്ള കണക്ഷനിലേക്ക് തിരിച്ചുവരില്ല — [4-ലെവൽ പ്രോക്സി സിസ്റ്റം](#4-level-proxy-system) പരാജയം-ക്ലോസ്ഡ് ഗാർഡ് കാണുക.
4. ഷെഡ്യൂളർ ഒരേ ഇടവേളയിൽ `dead` പ്രോക്സികൾ അന്വേഷിക്കുന്നു. അടുത്ത വിജയകരമായ അന്വേഷണം `status` തിരികെ `active` ലേക്ക് ഫ്ലിപ്പുചെയ്യുന്നു, കൂടാതെ ഇത് വീണ്ടും ഭ്രമണം ചെയ്യുന്നു — മാനുവൽ റീ-ആഡ് ആവശ്യമില്ല.

ഇത് ബോധപൂർവമാണ്** ഓപ്റ്റ്-ഇൻ, നോൺ-ഡിസ്ട്രക്റ്റീവ്** : സ്ഥിരസ്ഥിതിയായി ഷെഡ്യൂളർ പരാജയങ്ങൾ മാത്രം കണക്കാക്കുകയും രേഖപ്പെടുത്തുകയും ചെയ്യുന്നു ( `decision.ts` ലെ നയം C കാണുക), കൂടാതെ `PROXY_AUTO_DISABLE` ഒരിക്കലും ഒരു വരി — ഇല്ലാതാക്കില്ല, അതിനാണ് പ്രത്യേകവും കൂടുതൽ ആക്രമണാത്മകവുമായ `PROXY_AUTO_REMOVE` ഫ്ലാഗ്. രണ്ടും `true` ആയി സജ്ജീകരിച്ചാൽ, `PROXY_AUTO_REMOVE` വിജയിക്കും (ഇടയ്ക്കുള്ള സോഫ്റ്റ്-ഡിസേബിൾ കൊണ്ട് ഇല്ലാതാക്കാൻ പോകുന്ന പ്രോക്സിക്ക് പ്രയോജനമില്ല). മുഴുവൻ വേരിയബിൾ ലിസ്റ്റിനായി [എൻവയോൺമെൻ്റ് കോൺഫിഗറേഷൻ](../reference/ENVIRONMENT.md) റഫറൻസ് കാണുക.
