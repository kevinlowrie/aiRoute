> **ಭೌಗೋಳಿಕ ಬ್ಲಾಕ್ಗಳನ್ನು ಬೈಪಾಸ್ ಮಾಡಿ, ನಿಮ್ಮ ಗುರುತನ್ನು ರಕ್ಷಿಸಿ ಮತ್ತು ಶೂನ್ಯ ಕಾನ್ಫಿಗರೇಶನ್ ಸಂಕೀರ್ಣತೆಯೊಂದಿಗೆ ಯಾವುದೇ ಪ್ರಾಕ್ಸಿ — ಮೂಲಕ AI ಟ್ರಾಫಿಕ್ ಅನ್ನು ಮಾರ್ಗ ಮಾಡಿ.**

OmniRoute ಪೂರ್ಣ-ವೈಶಿಷ್ಟ್ಯಗೊಳಿಸಿದ ಪ್ರಾಕ್ಸಿ ನಿರ್ವಹಣಾ ವ್ಯವಸ್ಥೆಯನ್ನು ಒಳಗೊಂಡಿದೆ, ಅದು ನಿಮಗೆ HTTP, HTTPS, ಅಥವಾ SOCKS5 ಪ್ರಾಕ್ಸಿಗಳ ಮೂಲಕ ಅಪ್ಸ್ಟ್ರೀಮ್ AI ಪೂರೈಕೆದಾರರ ದಟ್ಟಣೆಯನ್ನು ಅನುಮತಿಸುತ್ತದೆ. ನೀವು ನಿರ್ಬಂಧಿಸಲಾದ ಪ್ರದೇಶದಲ್ಲಿದ್ದರೆ, IP ತಿರುಗುವಿಕೆಯ ಅಗತ್ಯವಿದೆಯೇ ಅಥವಾ ಸ್ಟೆಲ್ತ್ ಫಿಂಗರ್ಪ್ರಿಂಟಿಂಗ್ — ಬಯಸಿದಲ್ಲಿ ಈ ಮಾರ್ಗದರ್ಶಿ ಎಲ್ಲವನ್ನೂ ಒಳಗೊಂಡಿದೆ.

## ಪ್ರಾಕ್ಸಿಗಳನ್ನು ಏಕೆ ಬಳಸಬೇಕು?

ಅನೇಕ AI ಪೂರೈಕೆದಾರರು ಭೌಗೋಳಿಕ ಪ್ರದೇಶದ ಮೂಲಕ ಪ್ರವೇಶವನ್ನು ನಿರ್ಬಂಧಿಸುತ್ತಾರೆ. ಡೆವಲಪರ್ಗಳು** ರಷ್ಯಾ, ಚೀನಾ, ಇರಾನ್, ಕ್ಯೂಬಾ, ಟರ್ಕಿ** , ಮತ್ತು ಇತರ ದೇಶಗಳು ಈ ರೀತಿಯ ದೋಷಗಳನ್ನು ಎದುರಿಸುತ್ತವೆ:

```
unsupported_country_region_territory
```

ನಿರ್ಬಂಧಿಸಲಾದ ಪ್ರದೇಶಗಳ ಹೊರಗೆ ಸಹ, ಪ್ರಾಕ್ಸಿಗಳು ಇವುಗಳಿಗೆ ಉಪಯುಕ್ತವಾಗಿವೆ:

| ಕೇಸ್ ಬಳಸಿ          | ವಿವರಣೆ                                                                  |
| ------------------ | ----------------------------------------------------------------------- |
| **ಭೌಗೋಳಿಕ ಬೈಪಾಸ್** | ನಿರ್ಬಂಧಿಸಲಾದ ದೇಶಗಳಿಂದ OpenAI, Anthropic, Codex, Copilot ಅನ್ನು ಪ್ರವೇಶಿಸಿ |
| **IP ತಿರುಗುವಿಕೆ**  | ದರ ಮಿತಿಯನ್ನು ತಪ್ಪಿಸಲು ಬಹು IPs ದಾದ್ಯಂತ ವಿನಂತಿಗಳನ್ನು ವಿತರಿಸಿ              |
| **ಗೌಪ್ಯತೆ**        | ಅಪ್ಸ್ಟ್ರೀಮ್ ಪೂರೈಕೆದಾರರಿಂದ ನಿಮ್ಮ ನೈಜ IP ಮರೆಮಾಡಿ                          |
| **ಅನುಸರಣೆ**        | ನಿರ್ದಿಷ್ಟ ನ್ಯಾಯವ್ಯಾಪ್ತಿಗಳ ಮೂಲಕ ಸಂಚಾರ ಮಾರ್ಗ                              |
| **ಪರೀಕ್ಷೆ**        | ವಿವಿಧ ಪ್ರದೇಶಗಳಿಂದ ವಿನಂತಿಗಳನ್ನು ಅನುಕರಿಸಿ                                 |

## ಹೊಸ ಖಾತೆಗಳಿಗಾಗಿ ಡೀಫಾಲ್ಟ್ ಪ್ರಾಕ್ಸಿ ಸ್ಥಿತಿ

ರಲ್ಲಿ** ಸೆಟ್ಟಿಂಗ್ಗಳು → ಪ್ರಾಕ್ಸಿ → ಗ್ಲೋಬಲ್ ಕಾನ್ಫಿಗರೇಶನ್** , ಬಳಸಿ** ಹೊಸ ಸಂಪರ್ಕಗಳಿಗಾಗಿ ಡೀಫಾಲ್ಟ್ ಆಗಿ ಪ್ರಾಕ್ಸಿಯನ್ನು ಸಕ್ರಿಯಗೊಳಿಸಿ** ಹೊಸದಾಗಿ ಸೇರಿಸಲಾದ ಪೂರೈಕೆದಾರರ ಖಾತೆಗಳ ಆರಂಭಿಕ ಪ್ರಾಕ್ಸಿ ಸ್ಥಿತಿಯನ್ನು ಆಯ್ಕೆ ಮಾಡಲು.

ಹೊಸ ಸೆಟ್ಟಿಂಗ್ ಹೊಸದಾಗಿ ಸೇರಿಸಲಾದ ಪೂರೈಕೆದಾರರ ಖಾತೆಗಳ ಆರಂಭಿಕ ಪ್ರಾಕ್ಸಿ ಸ್ಥಿತಿಯನ್ನು ನಿಯಂತ್ರಿಸುತ್ತದೆ. ಇದು ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಖಾತೆಗಳನ್ನು ಬದಲಾಯಿಸುವುದಿಲ್ಲ ಅಥವಾ ಜಾಗತಿಕ ಪ್ರಾಕ್ಸಿ ಸ್ವಿಚ್ ಅನ್ನು ಬದಲಾಯಿಸುವುದಿಲ್ಲ. ಇದರ ಆರಂಭಿಕ ಮೌಲ್ಯವು ಹಿಂದಿನ ನಡವಳಿಕೆಯನ್ನು ಸಂರಕ್ಷಿಸುತ್ತದೆ. ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಿದ ಪ್ರಾಕ್ಸಿಯೊಂದಿಗೆ ಭವಿಷ್ಯದ ಖಾತೆಗಳನ್ನು ರಚಿಸಲು ಅದನ್ನು ಒಮ್ಮೆ ಆಫ್ ಮಾಡಿ.

ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಸೆಟ್ಟಿಂಗ್ಗಳ API ಮೂಲಕ ಆದ್ಯತೆಯನ್ನು `defaultNewConnectionProxyEnabled` ನಂತೆ ಸಂಗ್ರಹಿಸಲಾಗಿದೆ. ಎಂದಿಗೂ ಉಳಿಸದಿದ್ದಾಗ ಇದು `true` ಗೆ ಡೀಫಾಲ್ಟ್ ಆಗುತ್ತದೆ. `false` ಉಳಿಸುವಿಕೆಯು ಮರುಪ್ರಾರಂಭಿಸದೆಯೇ ನಂತರದ ಹೊಸ ಖಾತೆಗಳಿಗೆ ಪರಿಣಾಮ ಬೀರುತ್ತದೆ. `POST /api/providers` ಐಚ್ಛಿಕ ಕಟ್ಟುನಿಟ್ಟಾದ ಬೂಲಿಯನ್ `proxyEnabled` ಅನ್ನು ಸ್ವೀಕರಿಸುತ್ತದೆ; ಒಂದು ಸ್ಪಷ್ಟವಾದ `true` ಅಥವಾ `false` ಸೃಷ್ಟಿ ಡೀಫಾಲ್ಟ್ಗಿಂತ ಆದ್ಯತೆಯನ್ನು ತೆಗೆದುಕೊಳ್ಳುತ್ತದೆ. ನಕಲಿ ಖಾತೆ ಅಥವಾ OAuth ಮರುಸಂಪರ್ಕದಲ್ಲಿನ ಲೋಪವು ಆ ಖಾತೆಯ ಸಂಗ್ರಹವಾಗಿರುವ ಸ್ಥಿತಿಯನ್ನು ಸಂರಕ್ಷಿಸುತ್ತದೆ. ವೈಯಕ್ತಿಕ ಖಾತೆಗಳನ್ನು ನಂತರವೂ ಸಕ್ರಿಯಗೊಳಿಸಬಹುದು ಅಥವಾ ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಬಹುದು.

ಆಯ್ದ ಪೂರೈಕೆದಾರರ ವರ್ಗಾವಣೆಗಳು ಹೊಸ ಖಾತೆಗಳಿಗಾಗಿ ಗಮ್ಯಸ್ಥಾನ ಸ್ಥಾಪನೆಯ ಡೀಫಾಲ್ಟ್ ಅನ್ನು ಬಳಸುತ್ತವೆ ಮತ್ತು ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಖಾತೆಗಳನ್ನು ಬದಲಾಯಿಸುವಾಗ ಗಮ್ಯಸ್ಥಾನ ನೀತಿಯನ್ನು ಸಂರಕ್ಷಿಸುತ್ತದೆ. ಪ್ರಾಕ್ಸಿ ಟಾಗಲ್ಗಳು ಪೋರ್ಟಬಲ್ ವರ್ಗಾವಣೆ ಕ್ಷೇತ್ರಗಳಲ್ಲ. ಸಂಪೂರ್ಣ ಬ್ಯಾಕ್ಅಪ್ ಮರುಸ್ಥಾಪನೆ ಮತ್ತು ಐತಿಹಾಸಿಕ JSON/SQL ವಲಸೆಯು ಉಳಿಸಿದ ಖಾತೆ ಮೌಲ್ಯಗಳು ಮತ್ತು ಲೆಗಸಿ ಸ್ಕೀಮಾ ಡೀಫಾಲ್ಟ್ಗಳನ್ನು ಒಳಗೊಂಡಂತೆ ತಮ್ಮ ಅಸ್ತಿತ್ವದಲ್ಲಿರುವ ಮರುಸ್ಥಾಪನೆ ಶಬ್ದಾರ್ಥವನ್ನು ಉಳಿಸಿಕೊಳ್ಳುತ್ತದೆ; ಪೂರ್ಣ ಸೆಟ್ಟಿಂಗ್ಗಳ ಮರುಸ್ಥಾಪನೆಯು ಈ ಆದ್ಯತೆಯನ್ನು ಸಹ ಮರುಸ್ಥಾಪಿಸಬಹುದು.

ಈ ಆದ್ಯತೆಯು ಪ್ರಾಕ್ಸಿಯನ್ನು ನಿಯೋಜಿಸುವುದಿಲ್ಲ ಅಥವಾ ಅದು ಆರೋಗ್ಯಕರವಾಗಿದೆ ಅಥವಾ ಬಳಕೆಯಲ್ಲಿದೆ ಎಂದು ಸ್ಥಾಪಿಸುವುದಿಲ್ಲ. ನಿಜವಾದ ರೂಟಿಂಗ್ ಇನ್ನೂ ಜಾಗತಿಕ ಪ್ರಾಕ್ಸಿ ಸ್ವಿಚ್ ಮತ್ತು ಅನ್ವಯವಾಗುವ ಪ್ರಾಕ್ಸಿ ಕಾನ್ಫಿಗರೇಶನ್ ಅನ್ನು ಅವಲಂಬಿಸಿರುತ್ತದೆ. ನಿರಂತರ ಖಾತೆಯಿಲ್ಲದ ಸಂಶ್ಲೇಷಿತ ಪೂರೈಕೆದಾರರು, ಖಾತೆ ರಚನೆಯ ಮೊದಲು OAuth ಟ್ರಾಫಿಕ್, environment/system ಪ್ರಾಕ್ಸಿಗಳು ಮತ್ತು ಬಾಹ್ಯ ಬ್ಯಾಕೆಂಡ್ಗಳ ನೆಟ್ವರ್ಕಿಂಗ್ ಅದರ ವ್ಯಾಪ್ತಿಯಿಂದ ಹೊರಗಿದೆ.

## 4-ಹಂತದ ಪ್ರಾಕ್ಸಿ ಸಿಸ್ಟಮ್

OmniRoute ನಲ್ಲಿ ಪ್ರಾಕ್ಸಿ ಕಾನ್ಫಿಗರೇಶನ್ ಅನ್ನು ಬೆಂಬಲಿಸುತ್ತದೆ** ನಾಲ್ಕು ಸ್ವತಂತ್ರ ವ್ಯಾಪ್ತಿಗಳು** , ಆದ್ಯತೆಯ ಕ್ರಮದಲ್ಲಿ ಪರಿಹರಿಸಲಾಗಿದೆ:

```
Priority Resolution Order (highest → lowest):

  1. 🔵 Account/Connection Proxy  →  per API key / OAuth connection
  2. 🟡 Provider Proxy            →  per provider (e.g., all OpenAI traffic)
  3. 🟠 Combo Proxy               →  per combo/routing configuration
  4. 🟢 Global Proxy              →  all traffic, all providers
```

### ರೆಸಲ್ಯೂಶನ್ ಹೇಗೆ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ

OmniRoute ಅಪ್ಸ್ಟ್ರೀಮ್ ಪೂರೈಕೆದಾರರಿಗೆ ವಿನಂತಿಯನ್ನು ಕಳುಹಿಸಿದಾಗ, ಅದು `resolveProxyForConnectionFromRegistry()` ಕರೆಯುತ್ತದೆ ಅದು ಪ್ರತಿ ಹಂತವನ್ನು ಕ್ರಮವಾಗಿ ಪರಿಶೀಲಿಸುತ್ತದೆ:

1. **ಖಾತೆ ಮಟ್ಟ** — ಈ ನಿರ್ದಿಷ್ಟ ಸಂಪರ್ಕ ID ಗೆ ಪ್ರಾಕ್ಸಿ ನಿಯೋಜಿಸಲಾಗಿದೆಯೇ?
2. **ಪೂರೈಕೆದಾರರ ಮಟ್ಟ** — ಈ ಪೂರೈಕೆದಾರರಿಗೆ ಪ್ರಾಕ್ಸಿ ನಿಯೋಜಿಸಲಾಗಿದೆಯೇ (ಉದಾ, `openai`)?
3. **ಜಾಗತಿಕ ಮಟ್ಟದ** — ಜಾಗತಿಕ ಪ್ರಾಕ್ಸಿ ಕಾನ್ಫಿಗರ್ ಮಾಡಲಾಗಿದೆಯೇ?
4. **ಪ್ರಾಕ್ಸಿ ಇಲ್ಲ** ಒದಗಿಸುವವರಿಗೆ — ನೇರ ಸಂಪರ್ಕ.

ಮೊದಲ ಪಂದ್ಯ ಗೆಲ್ಲುತ್ತದೆ. ಇದರರ್ಥ ನೀವು ಜಾಗತಿಕ ಪ್ರಾಕ್ಸಿಯನ್ನು ಫಾಲ್ಬ್ಯಾಕ್ ಆಗಿ ಹೊಂದಿಸಬಹುದು ಆದರೆ ನಿರ್ದಿಷ್ಟ ಪೂರೈಕೆದಾರರು ಅಥವಾ ಸಂಪರ್ಕಗಳಿಗಾಗಿ ಅದನ್ನು ಅತಿಕ್ರಮಿಸಬಹುದು.

### ಏನು ಪ್ರಾಕ್ಸಿಡ್ ಆಗುತ್ತದೆ

| ಟ್ರಾಫಿಕ್ ಪ್ರಕಾರ         | ಪ್ರಾಕ್ಸಿಯೇ? | ಟಿಪ್ಪಣಿಗಳು                                           |
| ----------------------- | ----------- | ---------------------------------------------------- |
| ಚಾಟ್ ಪೂರ್ಣಗೊಳಿಸುವಿಕೆಗಳು | ✅          | ಎಲ್ಲಾ `/v1/chat/completions` ವಿನಂತಿಗಳು               |
| ಎಂಬೆಡಿಂಗ್ಗಳು            | ✅          | `/v1/embeddings`                                     |
| ಚಿತ್ರ ರಚನೆ              | ✅          | `/v1/images/generations`                             |
| ಆಡಿಯೋ (TTS/STT)         | ✅          | `/v1/audio/*`                                        |
| OAuth ಟೋಕನ್ ವಿನಿಮಯ      | ✅          | `unsupported_country_region_territory` ಪರಿಹರಿಸುತ್ತದೆ |
| ಸಂಪರ್ಕ ಪರೀಕ್ಷೆಗಳು       | ✅          | "ಪರೀಕ್ಷಾ ಸಂಪರ್ಕ" ಬಟನ್ ಪ್ರಾಕ್ಸಿಯನ್ನು ಬಳಸುತ್ತದೆ        |
| ಟೋಕನ್ ರಿಫ್ರೆಶ್          | ✅          | ಹಿನ್ನೆಲೆ OAuth ನವೀಕರಣ                                |
| ಮಾದರಿ ಸಿಂಕ್             | ✅          | ಮಾದರಿ ಪಟ್ಟಿ ಮತ್ತು ಅನ್ವೇಷಣೆ                           |

## ಪ್ರಾಕ್ಸಿ ರಿಜಿಸ್ಟ್ರಿ (CRUD)

ಪ್ರಾಕ್ಸಿ ರಿಜಿಸ್ಟ್ರಿಯು ನಿಮ್ಮ ಎಲ್ಲಾ ಪ್ರಾಕ್ಸಿಗಳನ್ನು ಸಂಗ್ರಹಿಸುವ SQLite ಟೇಬಲ್ (`proxy_registry`) ಆಗಿದೆ. ಪ್ರತಿ ಪ್ರಾಕ್ಸಿ ಹೊಂದಿದೆ:

| ಕ್ಷೇತ್ರ    | ಟೈಪ್ ಮಾಡಿ | ವಿವರಣೆ                                                  |
| ---------- | --------- | ------------------------------------------------------- |
| `id`       | UUID      | ವಿಶಿಷ್ಟ ಗುರುತಿಸುವಿಕೆ                                    |
| `name`     | ಸ್ಟ್ರಿಂಗ್ | ಮಾನವ-ಓದಬಲ್ಲ ಲೇಬಲ್                                       |
| `type`     | ಸ್ಟ್ರಿಂಗ್ | ಪ್ರೋಟೋಕಾಲ್: `http`, `https`, `socks5`                   |
| `host`     | ಸ್ಟ್ರಿಂಗ್ | ಪ್ರಾಕ್ಸಿ ಹೋಸ್ಟ್ ಹೆಸರು ಅಥವಾ IP                           |
| `port`     | ಪೂರ್ಣಾಂಕ  | ಪೋರ್ಟ್ ಸಂಖ್ಯೆ                                           |
| `username` | ಸ್ಟ್ರಿಂಗ್ | ದೃಢೀಕರಣ ಬಳಕೆದಾರಹೆಸರು (ಉಳಿದಿರುವಾಗ ಎನ್ಕ್ರಿಪ್ಟ್ ಮಾಡಲಾಗಿದೆ) |
| `password` | ಸ್ಟ್ರಿಂಗ್ | ದೃಢೀಕರಣ ಗುಪ್ತಪದ (ವಿಶ್ರಾಂತಿಯಲ್ಲಿ ಎನ್ಕ್ರಿಪ್ಟ್ ಮಾಡಲಾಗಿದೆ)  |
| `region`   | ಸ್ಟ್ರಿಂಗ್ | ಭೌಗೋಳಿಕ ಪ್ರದೇಶದ ಲೇಬಲ್                                   |
| `notes`    | ಸ್ಟ್ರಿಂಗ್ | ಉಚಿತ ಪಠ್ಯ ಟಿಪ್ಪಣಿಗಳು                                    |
| `status`   | ಸ್ಟ್ರಿಂಗ್ | `active` ಅಥವಾ `inactive`                                |
| `source`   | ಸ್ಟ್ರಿಂಗ್ | `manual` ಅಥವಾ `oneproxy`                                |

### ಪ್ರಾಕ್ಸಿ ರಚಿಸಲಾಗುತ್ತಿದೆ

**ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಮೂಲಕ:**

1. ಗೆ ಹೋಗಿ** ಸೆಟ್ಟಿಂಗ್ಗಳು → ಪ್ರಾಕ್ಸಿ**
2. ಕ್ಲಿಕ್ ಮಾಡಿ** ಪ್ರಾಕ್ಸಿ ಸೇರಿಸಿ**
3. ಪ್ರಕಾರ, ಹೋಸ್ಟ್, ಪೋರ್ಟ್ ಮತ್ತು ಐಚ್ಛಿಕ ದೃಢೀಕರಣ ರುಜುವಾತುಗಳನ್ನು ಭರ್ತಿ ಮಾಡಿ
4. ಉಳಿಸಿ

**API ಮೂಲಕ:**

```bash
curl -X POST http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "name": "US Proxy",
    "type": "http",
    "host": "proxy.example.com",
    "port": 8080,
    "username": "user",
    "password": "pass",
    "region": "US"
  }'
```

### ಪ್ರಾಕ್ಸಿಯನ್ನು ನವೀಕರಿಸಲಾಗುತ್ತಿದೆ

```bash
curl -X PATCH http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "id": "proxy-uuid-here",
    "host": "new-proxy.example.com",
    "port": 9090
  }'
```

> **ಗಮನಿಸಿ:** ನೀವು ಸ್ಪಷ್ಟವಾಗಿ ಖಾಲಿ ಅಲ್ಲದ ಬದಲಿಗಳನ್ನು ಕಳುಹಿಸದ ಹೊರತು ರುಜುವಾತುಗಳನ್ನು ಸಂರಕ್ಷಿಸಲಾಗಿದೆ. `username`/`password` ಗಾಗಿ ಖಾಲಿ ಸ್ಟ್ರಿಂಗ್ಗಳನ್ನು ಕಳುಹಿಸುವುದರಿಂದ ಸಂಗ್ರಹಿಸಿದ ಮೌಲ್ಯಗಳನ್ನು ಇರಿಸುತ್ತದೆ.

### ಪ್ರಾಕ್ಸಿಯನ್ನು ಅಳಿಸಲಾಗುತ್ತಿದೆ

```bash
# Fails if proxy is assigned to any scope
curl -X DELETE "http://localhost:20128/api/v1/management/proxies?id=proxy-uuid"

# Force delete (removes assignments too)
curl -X DELETE "http://localhost:20128/api/v1/management/proxies?id=proxy-uuid&force=1"
```

### ಪ್ರಾಕ್ಸಿಗಳನ್ನು ಪಟ್ಟಿ ಮಾಡುವುದು

```bash
curl "http://localhost:20128/api/v1/management/proxies?limit=50&offset=0"
```

### ವ್ಯಾಪ್ತಿಗಳಿಗೆ ಪ್ರಾಕ್ಸಿಗಳನ್ನು ನಿಯೋಜಿಸುವುದು

```bash
# Assign to global scope
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "global", "proxy": {"type":"http","host":"proxy.example.com","port":8080}}'

# Assign to a specific provider
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "provider", "id": "openai", "proxy": {"type":"socks5","host":"socks.example.com","port":1080}}'

# Assign to a specific connection/key
curl -X PUT http://localhost:20128/api/settings/proxy \
  -H "Content-Type: application/json" \
  -d '{"level": "key", "id": "connection-uuid", "proxy": {"type":"http","host":"key-proxy.com","port":3128}}'
```

### ಪರಿಣಾಮಕಾರಿ ಪ್ರಾಕ್ಸಿಯನ್ನು ಪರಿಹರಿಸಲಾಗುತ್ತಿದೆ

ನೀಡಿರುವ ಸಂಪರ್ಕಕ್ಕಾಗಿ ಯಾವ ಪ್ರಾಕ್ಸಿಯನ್ನು ಬಳಸಲಾಗುವುದು ಎಂಬುದನ್ನು ಪರಿಶೀಲಿಸಿ:

```bash
curl "http://localhost:20128/api/settings/proxy?resolve=connection-uuid"
```

ಪರಿಹರಿಸಲಾದ ಪ್ರಾಕ್ಸಿಯನ್ನು ಅದರ ಮಟ್ಟ (`account`, `provider`, ಅಥವಾ `global`) ಮತ್ತು ಮೂಲದೊಂದಿಗೆ ಹಿಂತಿರುಗಿಸುತ್ತದೆ.

### ಬೃಹತ್ ನಿಯೋಜನೆ

ಏಕಕಾಲದಲ್ಲಿ ಬಹು ಪೂರೈಕೆದಾರರು ಅಥವಾ ಸಂಪರ್ಕಗಳಿಗೆ ಒಂದು ಪ್ರಾಕ್ಸಿಯನ್ನು ನಿಯೋಜಿಸಿ:

```bash
curl -X POST http://localhost:20128/api/v1/management/proxies/bulk-assign \
  -H "Content-Type: application/json" \
  -d '{
    "scope": "provider",
    "scopeIds": ["openai", "anthropic", "codex"],
    "proxyId": "proxy-uuid"
  }'
```

### Import/Export

ಪ್ರಾಕ್ಸಿಗಳನ್ನು ಸೇರಿಸಲಾಗಿದೆ**Backup/Restore** ವ್ಯವಸ್ಥೆ. ನಿಮ್ಮ OmniRoute ಕಾನ್ಫಿಗರೇಶನ್ ಅನ್ನು ನೀವು ರಫ್ತು ಮಾಡಿದಾಗ:

1. ಗೆ ಹೋಗಿ** ಡ್ಯಾಶ್ಬೋರ್ಡ್ → ಸೆಟ್ಟಿಂಗ್ಗಳು → ಬ್ಯಾಕಪ್**
2. ಕ್ಲಿಕ್ ಮಾಡಿ** ರಫ್ತು ಮಾಡಿ** — ಪ್ರಾಕ್ಸಿ ರಿಜಿಸ್ಟ್ರಿ ಮತ್ತು ಕಾರ್ಯಯೋಜನೆಗಳನ್ನು ಸೇರಿಸಲಾಗಿದೆ
3. ಪುನಃಸ್ಥಾಪಿಸಲು, ಕ್ಲಿಕ್ ಮಾಡಿ** ಆಮದು ಮಾಡಿಕೊಳ್ಳಿ** ಮತ್ತು ಬ್ಯಾಕಪ್ ಫೈಲ್ ಅನ್ನು ಅಪ್ಲೋಡ್ ಮಾಡಿ

ಪ್ರಾಕ್ಸಿ ರಿಜಿಸ್ಟ್ರಿ ಸಹ ಬೆಂಬಲಿಸುತ್ತದೆ** ಹೋಸ್ಟ್+ ಪೋರ್ಟ್ ಮೂಲಕ ಅಪ್ಸರ್ಟ್ ಮಾಡಿ** — ಈಗಾಗಲೇ ಇರುವ ಪ್ರಾಕ್ಸಿಯನ್ನು ನೀವು ಆಮದು ಮಾಡಿಕೊಂಡರೆ (ಅದೇ ಹೋಸ್ಟ್ ಮತ್ತು ಪೋರ್ಟ್), ನಕಲು ರಚಿಸುವ ಬದಲು ಅದು ನವೀಕರಿಸುತ್ತದೆ.

### ಲೆಗಸಿ ವಲಸೆ

ನೀವು ಹಳೆಯ ಆವೃತ್ತಿಯಲ್ಲಿ (ಪೂರ್ವ-ನೋಂದಣಿ) ಪ್ರಾಕ್ಸಿಗಳನ್ನು ಕಾನ್ಫಿಗರ್ ಮಾಡಿದ್ದರೆ, OmniRoute ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಅವುಗಳನ್ನು ಸ್ಥಳಾಂತರಿಸುತ್ತದೆ:

```
Legacy key_value store → proxy_registry + proxy_assignments
```

ಅಪ್ಗ್ರೇಡ್ ಮಾಡಿದ ನಂತರ ಮೊದಲ ಪ್ರಾರಂಭದಲ್ಲಿ ಒಮ್ಮೆ ಇದು ಸಂಭವಿಸುತ್ತದೆ. ಮರು ರನ್ ಮಾಡಲು `migrateLegacyProxyConfigToRegistry({ force: true })` ಬಳಸಿ.

## 1ಪ್ರಾಕ್ಸಿ ಉಚಿತ ಪ್ರಾಕ್ಸಿ ಮಾರುಕಟ್ಟೆ

> 🆕** [@oyi77](https://github.com/oyi77) ಅವರಿಂದ ಕೊಡುಗೆ ನೀಡಲಾಗಿದೆ** — PR [#1847](https://github.com/diegosouzapw/OmniRoute/pull/1847) (ಸಂಚಿಕೆ [#1788](https://github.com/diegosouzapw/OmniRoute/issues/1788) )

OmniRoute ಜೊತೆ ಸಂಯೋಜನೆಗೊಳ್ಳುತ್ತದೆ** [1ಪ್ರಾಕ್ಸಿ](https://1proxy-api.aitradepulse.com)** ಪ್ರವೇಶವನ್ನು ಒದಗಿಸಲು ಸಮುದಾಯ ವೇದಿಕೆ** ನೂರಾರು ಉಚಿತ, ಮೌಲ್ಯೀಕರಿಸಿದ ಪ್ರಾಕ್ಸಿಗಳು** ಪ್ರಪಂಚದಾದ್ಯಂತ. ತಮ್ಮದೇ ಆದ ಪ್ರಾಕ್ಸಿ ಮೂಲಸೌಕರ್ಯವನ್ನು ಹೊಂದಿರದ ಬಳಕೆದಾರರಿಗೆ ಇದು ಪರಿಪೂರ್ಣವಾಗಿದೆ.

### ಇದು ಹೇಗೆ ಕೆಲಸ ಮಾಡುತ್ತದೆ

```
┌─────────────┐     Sync      ┌─────────────────┐    Rotate     ┌──────────┐
│  1proxy API │ ────────────▶ │  proxy_registry  │ ────────────▶ │ Provider │
│  (external) │   up to 500   │  source=oneproxy │  by quality   │   API    │
└─────────────┘    proxies    └─────────────────┘               └──────────┘
```

1. **ಸಿಂಕ್ ಮಾಡಿ** — OmniRoute 1proxy API ನಿಂದ ಮೌಲ್ಯೀಕರಿಸಿದ ಪ್ರಾಕ್ಸಿಗಳನ್ನು ಪಡೆಯುತ್ತದೆ
2. **ಅಂಗಡಿ** — ಪ್ರಾಕ್ಸಿಗಳನ್ನು ಅದೇ `proxy_registry` ಕೋಷ್ಟಕದಲ್ಲಿ `source = 'oneproxy'` ನೊಂದಿಗೆ ಉಳಿಸಲಾಗಿದೆ
3. **ಫಿಲ್ಟರ್** ಪ್ರೋಟೋಕಾಲ್, ದೇಶ, ಗುಣಮಟ್ಟದ ಸ್ಕೋರ್ ಮೂಲಕ — ಫಿಲ್ಟರ್ ಮಾಡಿ
4. **ತಿರುಗಿಸಿ** — ಗುಣಮಟ್ಟ, ಯಾದೃಚ್ಛಿಕ ಅಥವಾ ಅನುಕ್ರಮ ತಂತ್ರಗಳನ್ನು ಬಳಸಿಕೊಂಡು ಉತ್ತಮ ಪ್ರಾಕ್ಸಿಯನ್ನು ಆರಿಸಿ
5. **ಸ್ವಯಂ-ಡಿಗ್ರೇಡ್** — ವಿಫಲವಾದ ಪ್ರಾಕ್ಸಿಗಳು ತಮ್ಮ ಗುಣಮಟ್ಟದ ಸ್ಕೋರ್ ಅನ್ನು ಕಡಿಮೆಗೊಳಿಸುತ್ತಾರೆ; ಕೆಳಗಿನ ಮಿತಿ → ನಿಷ್ಕ್ರಿಯ ಎಂದು ಗುರುತಿಸಲಾಗಿದೆ

### ಪ್ರಾಕ್ಸಿಗಳನ್ನು ಸಿಂಕ್ ಮಾಡಲಾಗುತ್ತಿದೆ

**ಡ್ಯಾಶ್ಬೋರ್ಡ್ ಮೂಲಕ:**

1. ಗೆ ಹೋಗಿ** → 1ಪ್ರಾಕ್ಸಿ ಸೆಟ್ಟಿಂಗ್ಗಳು** ಟ್ಯಾಬ್
2. ಕ್ಲಿಕ್ ಮಾಡಿ** "ಈಗ ಸಿಂಕ್ ಮಾಡಿ"**
3. ಅಂಕಿಅಂಶಗಳನ್ನು ವೀಕ್ಷಿಸಿ: ಒಟ್ಟು ಪ್ರಾಕ್ಸಿಗಳು, ಸಕ್ರಿಯ ಎಣಿಕೆ, ಸರಾಸರಿ ಗುಣಮಟ್ಟ, ದೇಶ-ದೇಶದ ಸ್ಥಗಿತ

**API ಮೂಲಕ:**

```bash
# Trigger sync
curl -X POST http://localhost:20128/api/settings/oneproxy \
  -H "Content-Type: application/json" \
  -d '{}'

# Response:
# { "success": true, "added": 127, "updated": 45, "failed": 2, "total": 172 }
```

### ಫಿಲ್ಟರಿಂಗ್ ಪ್ರಾಕ್ಸಿಗಳು

```bash
# Filter by protocol
curl "http://localhost:20128/api/settings/oneproxy?protocol=socks5"

# Filter by country
curl "http://localhost:20128/api/settings/oneproxy?countryCode=US"

# Filter by minimum quality score
curl "http://localhost:20128/api/settings/oneproxy?minQuality=80"

# Combine filters
curl "http://localhost:20128/api/settings/oneproxy?protocol=http&countryCode=DE&minQuality=70"
```

### ಪ್ರಾಕ್ಸಿ ಗುಣಮಟ್ಟದ ಅಂಕಗಳು

ಪ್ರತಿ 1ಪ್ರಾಕ್ಸಿ ಪ್ರಾಕ್ಸಿ ಮೆಟಾಡೇಟಾದೊಂದಿಗೆ ಬರುತ್ತದೆ:

| ಕ್ಷೇತ್ರ         | ವಿವರಣೆ                                     |
| --------------- | ------------------------------------------ |
| `qualityScore`  | 1ಪ್ರಾಕ್ಸಿ ಮೌಲ್ಯೀಕರಣದಿಂದ 0-100 ರೇಟಿಂಗ್      |
| `latencyMs`     | ನೆಟ್ವರ್ಕ್ ಲೇಟೆನ್ಸಿಯನ್ನು ಅಳೆಯಲಾಗುತ್ತದೆ      |
| `anonymity`     | `transparent`, `anonymous`, ಅಥವಾ `elite`   |
| `googleAccess`  | ಪ್ರಾಕ್ಸಿಯು Google ಸೇವೆಗಳನ್ನು ಪ್ರವೇಶಿಸಬಹುದೇ |
| `countryCode`   | ಎರಡು ಅಕ್ಷರಗಳ ISO ದೇಶದ ಕೋಡ್                 |
| `lastValidated` | ಕೊನೆಯ ದೃಢೀಕರಣದ ಟೈಮ್ಸ್ಟ್ಯಾಂಪ್               |

ಗುಣಮಟ್ಟದ ಸ್ಕೋರ್ಗಳನ್ನು ಕ್ರಿಯಾತ್ಮಕವಾಗಿ ಹೊಂದಿಸಲಾಗಿದೆ:

- **ವಿಫಲವಾದ ವಿನಂತಿಗಳು** ಸ್ಕೋರ್ ಅನ್ನು 10 ಅಂಕಗಳಿಂದ ಕಡಿಮೆ ಮಾಡಿ
- **ಸ್ಕೋರ್ ≤ 10 ಗೆ ಇಳಿಯುತ್ತದೆ** → ಪ್ರಾಕ್ಸಿಯನ್ನು `inactive` ಎಂದು ಗುರುತಿಸಲಾಗಿದೆ
- ನಿಷ್ಕ್ರಿಯ ಪ್ರಾಕ್ಸಿಗಳನ್ನು ತಿರುಗುವಿಕೆಯಿಂದ ಹೊರಗಿಡಲಾಗಿದೆ

### ತಿರುಗುವಿಕೆಯ ತಂತ್ರಗಳು

```bash
# Rotate by quality (best proxy first) — default
curl -X POST http://localhost:20128/api/settings/oneproxy/rotate \
  -H "Content-Type: application/json" \
  -d '{"strategy": "quality"}'

# Random rotation
curl -X POST http://localhost:20128/api/settings/oneproxy/rotate \
  -d '{"strategy": "random"}'

# Sequential (least recently validated first)
curl -X POST http://localhost:20128/api/settings/oneproxy/rotate \
  -d '{"strategy": "sequential"}'
```

### ಸರ್ಕ್ಯೂಟ್ ಬ್ರೇಕರ್

1ಪ್ರಾಕ್ಸಿ ಸಿಂಕ್ ಅಂತರ್ನಿರ್ಮಿತ ಸರ್ಕ್ಯೂಟ್ ಬ್ರೇಕರ್ ಅನ್ನು ಹೊಂದಿದೆ:

- ನಂತರ** 5 ಸತತ ಸಿಂಕ್ ವಿಫಲತೆಗಳು** , ಮತ್ತಷ್ಟು ಸಿಂಕ್ ಪ್ರಯತ್ನಗಳನ್ನು ನಿರ್ಬಂಧಿಸಲಾಗಿದೆ
- ಇದರೊಂದಿಗೆ ಮರುಹೊಂದಿಸಿ: `resetOneproxyCircuitBreaker()` ಅಥವಾ ಸರ್ವರ್ ಅನ್ನು ಮರುಪ್ರಾರಂಭಿಸಿ
- ಸಿಂಕ್ ಸ್ಥಿತಿ `GET /api/settings/oneproxy?action=status` ನಲ್ಲಿ ಲಭ್ಯವಿದೆ

### 1ಪ್ರಾಕ್ಸಿ ಪ್ರಾಕ್ಸಿಗಳನ್ನು ತೆರವುಗೊಳಿಸಲಾಗುತ್ತಿದೆ

## ಆಂಟಿ-ಡಿಟೆಕ್ಷನ್ ಮತ್ತು ಸ್ಟೆಲ್ತ್

OmniRoute ಕೇವಲ ಪ್ರಾಕ್ಸಿ — ಮೂಲಕ ಸಂಚಾರ ಮಾರ್ಗವನ್ನು ಮಾಡುವುದಿಲ್ಲ ಇದು ಸಂಚಾರವನ್ನು ನ್ಯಾಯಸಮ್ಮತವಾಗಿ ಕಾಣುವಂತೆ ಮಾಡುತ್ತದೆ:

### TLS ಫಿಂಗರ್ಪ್ರಿಂಟ್ ವಂಚನೆ

ಬ್ರೌಸರ್-ತರಹದ TLS ಫಿಂಗರ್ಪ್ರಿಂಟ್ಗಳನ್ನು ರಚಿಸಲು `wreq-js` ಬಳಸುತ್ತದೆ, ಬ್ರೌಸರ್ ಅಲ್ಲದ TLS ಹ್ಯಾಂಡ್ಶೇಕ್ಗಳನ್ನು ಫ್ಲ್ಯಾಗ್ ಮಾಡುವ ಬೋಟ್ ಪತ್ತೆ ವ್ಯವಸ್ಥೆಗಳನ್ನು ಬೈಪಾಸ್ ಮಾಡುತ್ತದೆ.

### CLI ಫಿಂಗರ್ಪ್ರಿಂಟ್ ಹೊಂದಾಣಿಕೆ

ದಿ**CLI ಫಿಂಗರ್ಪ್ರಿಂಟ್ ಟಾಗಲ್** (`Settings → Security`) ಸ್ಥಳೀಯ CLI ಬೈನರಿಗಳ (Claude ಕೋಡ್, Codex, ಇತ್ಯಾದಿ) ನಿಖರವಾದ ಸಹಿಯನ್ನು ಹೊಂದಿಸಲು HTTP ಹೆಡರ್ಗಳು ಮತ್ತು JSON ಬಾಡಿ ಫೀಲ್ಡ್ಗಳನ್ನು ಮರುಕ್ರಮಗೊಳಿಸುತ್ತದೆ. ಇದು ಕೆಲಸ ಮಾಡುತ್ತದೆ** ಮೇಲೆ** ಪ್ರಾಕ್ಸಿ:

```
Your IP (blocked) → Proxy IP (US) → Provider API
                    + TLS spoof
                    + CLI fingerprint
```

ನೀವು ಎರಡನ್ನೂ ಪಡೆಯುತ್ತೀರಿ**IP ಮರೆಮಾಚುವಿಕೆ** ಮತ್ತು** ದೃಢೀಕರಣವನ್ನು ವಿನಂತಿಸಿ** ಏಕಕಾಲದಲ್ಲಿ.

### ಪ್ರಾಕ್ಸಿ IP ಸಂರಕ್ಷಣೆ

ಡ್ಯಾಶ್ಬೋರ್ಡ್ನಲ್ಲಿ ಬಣ್ಣ-ಕೋಡೆಡ್ ಬ್ಯಾಡ್ಜ್ಗಳು ಯಾವ ಪ್ರಾಕ್ಸಿ ಹಂತವು ಸಕ್ರಿಯವಾಗಿದೆ ಎಂಬುದನ್ನು ತೋರಿಸುತ್ತದೆ:

| ಬ್ಯಾಡ್ಜ್ | ಮಟ್ಟ       | ಅರ್ಥ                                              |
| -------- | ---------- | ------------------------------------------------- |
| 🟢       | ಜಾಗತಿಕ     | ಎಲ್ಲಾ ಸಂಚಾರವು ಈ ಪ್ರಾಕ್ಸಿ ಮೂಲಕ ಹೋಗುತ್ತದೆ           |
| 🟡       | ಒದಗಿಸುವವರು | ಈ ಪೂರೈಕೆದಾರರ ದಟ್ಟಣೆಯನ್ನು ಮಾತ್ರ ಪ್ರಾಕ್ಸಿ ಮಾಡಲಾಗಿದೆ |
| 🔵       | ಸಂಪರ್ಕ     | ಈ ನಿರ್ದಿಷ್ಟ key/account ಈ ಪ್ರಾಕ್ಸಿಯನ್ನು ಬಳಸುತ್ತದೆ |

ಬ್ಯಾಡ್ಜ್ ಪರಿಶೀಲನೆಗಾಗಿ ಪರಿಹರಿಸಲಾದ ಪ್ರಾಕ್ಸಿ IP ಅನ್ನು ಸಹ ತೋರಿಸುತ್ತದೆ.

## ಅಪ್ಸ್ಟ್ರೀಮ್ ಪ್ರಾಕ್ಸಿ ಮೋಡ್ಗಳು

CLIProxyAPI ಮಾದರಿಯನ್ನು ಬಳಸುವ ಪೂರೈಕೆದಾರರಿಗೆ, OmniRoute ಮೂರು ಅಪ್ಸ್ಟ್ರೀಮ್ ಪ್ರಾಕ್ಸಿ ಮೋಡ್ಗಳನ್ನು ಬೆಂಬಲಿಸುತ್ತದೆ:

| ಮೋಡ್          | ವಿವರಣೆ                                                             |
| ------------- | ------------------------------------------------------------------ |
| `native`      | OmniRoute ನೇರವಾಗಿ ಪ್ರಾಕ್ಸಿ ರೂಟಿಂಗ್ ಅನ್ನು ನಿರ್ವಹಿಸುತ್ತದೆ (ಡೀಫಾಲ್ಟ್) |
| `cliproxyapi` | ಬಾಹ್ಯ CLIProxyAPI ನಿದರ್ಶನಕ್ಕೆ ಪ್ರತಿನಿಧಿಗಳು                         |
| `fallback`    | ಮೊದಲು ಸ್ಥಳೀಯವಾಗಿ ಪ್ರಯತ್ನಿಸುತ್ತದೆ, CLIProxyAPI ಗೆ ಹಿಂತಿರುಗುತ್ತದೆ    |

ಪ್ರತಿ ಪೂರೈಕೆದಾರರನ್ನು ಕಾನ್ಫಿಗರ್ ಮಾಡಿ:

```bash
curl -X PUT "http://localhost:20128/api/upstream-proxy/openai" \
  -H "Content-Type: application/json" \
  -d '{"mode": "native", "enabled": true}'
```

- **ಸಂಪರ್ಕ ಪರೀಕ್ಷೆ** ಕಾನ್ಫಿಗರ್ ಮಾಡಿದ ಪ್ರಾಕ್ಸಿ ಮೂಲಕ
- **ಬಣ್ಣ-ಕೋಡೆಡ್ ಬ್ಯಾಡ್ಜ್ಗಳು** ಸಕ್ರಿಯ ಪ್ರಾಕ್ಸಿ ಮಟ್ಟವನ್ನು ತೋರಿಸುತ್ತಿದೆ

### ಸೆಟ್ಟಿಂಗ್ಗಳು → 1ಪ್ರಾಕ್ಸಿ ಟ್ಯಾಬ್

- **ಈಗ ಸಿಂಕ್ ಮಾಡಿ** ಉಚಿತ ಪ್ರಾಕ್ಸಿಗಳನ್ನು ಪಡೆಯಲು ಬಟನ್
- **ಅಂಕಿಅಂಶ ಕಾರ್ಡ್ಗಳು** : ಒಟ್ಟು, ಸಕ್ರಿಯ, ಸರಾಸರಿ ಗುಣಮಟ್ಟ, ಕೊನೆಯ ಸಿಂಕ್
- **ಶೋಧಕಗಳು** : ಪ್ರೋಟೋಕಾಲ್, ದೇಶದ ಕೋಡ್, ಕನಿಷ್ಠ ಗುಣಮಟ್ಟ
- **ಪ್ರಾಕ್ಸಿ ಟೇಬಲ್** ಹೋಸ್ಟ್, ಪ್ರೋಟೋಕಾಲ್, ದೇಶ, ಗುಣಮಟ್ಟದ ಸ್ಕೋರ್, ಲೇಟೆನ್ಸಿ, ಅನಾಮಧೇಯತೆ, Google ಪ್ರವೇಶದೊಂದಿಗೆ
- **ಸಿಂಕ್ ಸ್ಥಿತಿ** success/failure ಟ್ರ್ಯಾಕಿಂಗ್ ಮತ್ತು ಸತತ ವೈಫಲ್ಯದ ಎಣಿಕೆಯೊಂದಿಗೆ ಫಲಕ
- **ಎಲ್ಲವನ್ನೂ ತೆರವುಗೊಳಿಸಿ** ಎಲ್ಲಾ 1ಪ್ರಾಕ್ಸಿ ನಮೂದುಗಳನ್ನು ತೆಗೆದುಹಾಕಲು

## ದೋಷನಿವಾರಣೆ

### "SOCKS5 ಪ್ರಾಕ್ಸಿ ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಲಾಗಿದೆ"

ನಿಮ್ಮ `.env` ಫೈಲ್ನಲ್ಲಿ `ENABLE_SOCKS5_PROXY=true` ಹೊಂದಿಸಿ ಮತ್ತು ಮರುಪ್ರಾರಂಭಿಸಿ.

### ಪ್ರಾಕ್ಸಿ ಮೂಲಕ "ಸಾಕೆಟ್ ಹ್ಯಾಂಗ್ ಅಪ್" ದೋಷಗಳು

ನಿಷ್ಕ್ರಿಯ ಸಂಪರ್ಕಗಳನ್ನು ಬಿಡುವ ಅಗ್ಗದ ಪ್ರಾಕ್ಸಿಗಳೊಂದಿಗೆ ಇದು ಸಾಮಾನ್ಯವಾಗಿದೆ. OmniRoute ಈಗಾಗಲೇ ಇದನ್ನು ನಿರ್ವಹಿಸುತ್ತದೆ:

- ಪ್ರಾಕ್ಸಿ ಸಂಪರ್ಕಗಳಲ್ಲಿ ಕೀಪ್-ಲೈವ್ ಅನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಲಾಗುತ್ತಿದೆ (`keepAliveTimeout: 1`)
- ಪೈಪ್ಲೈನ್ ಅನ್ನು ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಲಾಗುತ್ತಿದೆ (`pipelining: 0`)
- ಪುನರಾವರ್ತಿತ ಹ್ಯಾಂಡ್ಶೇಕ್ಗಳನ್ನು ತಪ್ಪಿಸಲು ರವಾನೆದಾರರನ್ನು ಹಿಡಿದಿಟ್ಟುಕೊಳ್ಳುವುದು

ಇದು ಮುಂದುವರಿದರೆ, ಬೇರೆ ಪ್ರಾಕ್ಸಿಯನ್ನು ಪ್ರಯತ್ನಿಸಿ ಅಥವಾ 1ಪ್ರಾಕ್ಸಿ ತಿರುಗುವಿಕೆ ವೈಶಿಷ್ಟ್ಯವನ್ನು ಬಳಸಿ.

### OAuth ಸಮಯದಲ್ಲಿ "unsupported_country_region_territory"

ಪ್ರಾಕ್ಸಿಯನ್ನು ಕಾನ್ಫಿಗರ್ ಮಾಡಲಾಗಿದೆ ಎಂದು ಖಚಿತಪಡಿಸಿಕೊಳ್ಳಿ** ಮೊದಲು** OAuth ಹರಿವನ್ನು ಪ್ರಾರಂಭಿಸುವುದು. ಕಾನ್ಫಿಗರ್ ಮಾಡಿದ ಪ್ರಾಕ್ಸಿ ಮೂಲಕ OmniRoute ಮಾರ್ಗಗಳು OAuth ಟೋಕನ್ ವಿನಿಮಯ. ಮೊದಲು ಜಾಗತಿಕ ಅಥವಾ ಪೂರೈಕೆದಾರರ ಮಟ್ಟದ ಪ್ರಾಕ್ಸಿಯನ್ನು ಹೊಂದಿಸಿ, ನಂತರ ಸಂಪರ್ಕಿಸಿ.

### ಪ್ರಾಕ್ಸಿ ಬಳಸಲಾಗುತ್ತಿಲ್ಲ

ರೆಸಲ್ಯೂಶನ್ ಕ್ರಮವನ್ನು ಪರಿಶೀಲಿಸಿ:

1. `GET /api/settings/proxy?resolve=your-connection-id` ನೊಂದಿಗೆ ಪರಿಶೀಲಿಸಿ
2. ಪ್ರಾಕ್ಸಿ `status` `active` ಆಗಿದೆಯೇ ಎಂದು ಪರಿಶೀಲಿಸಿ ( `inactive` ಅಲ್ಲ)
3. ಪ್ರಾಕ್ಸಿ ಅಸೈನ್ಮೆಂಟ್ ಸ್ಕೋಪ್ ನಿಮ್ಮ ಸಂಪರ್ಕಕ್ಕೆ ಹೊಂದಿಕೆಯಾಗುತ್ತದೆ ಎಂದು ಖಚಿತಪಡಿಸಿಕೊಳ್ಳಿ

### 1ಪ್ರಾಕ್ಸಿ ಸಿಂಕ್ ವಿಫಲವಾಗಿದೆ

ಸಿಂಕ್ ಸ್ಥಿತಿಯನ್ನು ಪರಿಶೀಲಿಸಿ:

```bash
curl "http://localhost:20128/api/settings/oneproxy?action=status"
```

`consecutiveFailures >= 5` ಆಗಿದ್ದರೆ, ಸರ್ಕ್ಯೂಟ್ ಬ್ರೇಕರ್ ಟ್ರಿಪ್ ಆಗಿದೆ. ಮರುಹೊಂದಿಸಲು ಸರ್ವರ್ ಅನ್ನು ಮರುಪ್ರಾರಂಭಿಸಿ ಅಥವಾ ಹಸ್ತಚಾಲಿತ ಮರುಹೊಂದಿಸಲು ನಿರೀಕ್ಷಿಸಿ.

### `proxy_registry` ಟೇಬಲ್

```sql
CREATE TABLE proxy_registry (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  type TEXT NOT NULL DEFAULT 'http',
  host TEXT NOT NULL,
  port INTEGER NOT NULL,
  username TEXT DEFAULT '',
  password TEXT DEFAULT '',
  region TEXT,
  notes TEXT,
  status TEXT DEFAULT 'active',
  source TEXT NOT NULL DEFAULT 'manual',    -- 'manual' or 'oneproxy'
  quality_score INTEGER,                     -- 0-100 (1proxy only)
  latency_ms INTEGER,                        -- milliseconds (1proxy only)
  anonymity TEXT,                            -- transparent/anonymous/elite
  google_access INTEGER DEFAULT 0,           -- can access Google? (1proxy)
  last_validated TEXT,                       -- ISO timestamp (1proxy)
  country_code TEXT,                         -- ISO 2-letter code (1proxy)
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

### `proxy_assignments` ಟೇಬಲ್

```sql
CREATE TABLE proxy_assignments (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  proxy_id TEXT NOT NULL REFERENCES proxy_registry(id),
  scope TEXT NOT NULL,        -- 'global', 'provider', 'account', 'combo'
  scope_id TEXT,              -- provider ID, connection ID, or combo ID
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE(scope, scope_id)
);
```

## ಪ್ರಾಕ್ಸಿ ಆರೋಗ್ಯ ತಪಾಸಣೆ (v3.8.16 +)

OmniRoute ನ** ಪ್ರಾಕ್ಸಿ ಫಾಸ್ಟ್-ಫೇಲ್** ಯಾಂತ್ರಿಕತೆ (`src/lib/proxyHealth.ts`) ತ್ವರಿತ TCP ಸಂಪರ್ಕ ಪರಿಶೀಲನೆಯ ಮೂಲಕ < 2s ನಲ್ಲಿ ಸತ್ತ ಪ್ರಾಕ್ಸಿಗಳನ್ನು ಪತ್ತೆ ಮಾಡುತ್ತದೆ, ನಂತರ** ಫಲಿತಾಂಶವನ್ನು ಸಂಗ್ರಹಿಸುತ್ತದೆ** ಪ್ರತಿ ವಿನಂತಿಯ ಓವರ್ಹೆಡ್ ಅನ್ನು ತಪ್ಪಿಸಲು.

### ಇದು ಹೇಗೆ ಕೆಲಸ ಮಾಡುತ್ತದೆ

```
Request ──▶ ProxyHealthCache.get(url)
             │
             ├─ Cache hit + fresh?  ──▶ return cached status
             │
             └─ Cache miss / stale?  ──▶ TCP connect to host:port
                                          (timeout: FAST_FAIL_TIMEOUT_MS)
                                          ──▶ cache for HEALTH_CACHE_TTL_MS
                                          ──▶ return result
```

ಇದು ಇಲ್ಲದೆ, ವಿಫಲಗೊಳ್ಳುವ ಮೊದಲು ಡೆಡ್ ಪ್ರಾಕ್ಸಿಯು ಪೂರ್ಣ `PROXY_TIMEOUT_MS` (ಡೀಫಾಲ್ಟ್ 30 ಸೆ) ಗಾಗಿ ಪ್ರತಿ ವಿನಂತಿಯನ್ನು ನಿರ್ಬಂಧಿಸುತ್ತದೆ.

### ಟ್ಯೂನಬಲ್ ಎನ್ವಿರಾನ್ಮೆಂಟ್ ವೇರಿಯಬಲ್ಸ್

| ವೇರಿಯಬಲ್                     | ಡೀಫಾಲ್ಟ್ | ಉದ್ದೇಶ                                                |
| ---------------------------- | -------- | ----------------------------------------------------- |
| `PROXY_FAST_FAIL_TIMEOUT_MS` | `2000`   | ಪ್ರತಿ ಆರೋಗ್ಯ ತಪಾಸಣೆಗೆTCP ಸಂಪರ್ಕದ ಅವಧಿ ಮೀರಿದೆ          |
| `PROXY_HEALTH_CACHE_TTL_MS`  | `30000`  | ಆರೋಗ್ಯ ಫಲಿತಾಂಶವನ್ನು ಎಷ್ಟು ಸಮಯದವರೆಗೆ ಸಂಗ್ರಹಿಸಲಾಗುತ್ತದೆ |

| ಜಿಯೋ ಡಿಸ್ಟ್ರಿಬ್ಯೂಟೆಡ್ ನೋಡ್ಗಳು | 3000ms              | 15000ms    | ನಿಧಾನಗತಿಯ ನೆಟ್ವರ್ಕ್ಗಳಿಗೆ ಹೆಚ್ಚಿನ ಸಮಯ ಬೇಕಾಗುತ್ತದೆ; ವೇಗದ ವೈಫಲ್ಯಕ್ಕಾಗಿ ಕಡಿಮೆ ಸಂಗ್ರಹ |
| ದೇವ್ / ಪರೀಕ್ಷೆ                | 1000ms              | 10000ms    | ಸ್ಥಳೀಯ ಪ್ರಾಕ್ಸಿಗಳಲ್ಲಿ ತ್ವರಿತ ಪುನರಾವರ್ತನೆ                                         |
| ಸ್ಟೆಲ್ತ್ / ವಿರೋಧಿ ಪತ್ತೆ       | 2500ms              | 45000ms    | ದರ ಮಿತಿಗಳನ್ನು ಪ್ರಚೋದಿಸುವ ಕ್ಷಿಪ್ರ ತನಿಖೆಯನ್ನು ತಪ್ಪಿಸಿ                              |

### ಪ್ರಾಕ್ಸಿ ಆರೋಗ್ಯವನ್ನು ಪರಿಶೀಲಿಸಲಾಗುತ್ತಿದೆ

```ts
import { getAllProxyHealthStatuses, invalidateProxyHealth } from "omniroute/proxyHealth";

const statuses = getAllProxyHealthStatuses();
for (const s of statuses) {
  console.log(`${s.proxyUrl} → healthy=${s.healthy}, stale=${s.stale}`);
}

// Force re-check a specific proxy
invalidateProxyHealth("http://user:pass@203.0.113.7:8080");
```

ಸಂಗ್ರಹ ಪ್ರವೇಶವು `HEALTH_CACHE_TTL_MS` ಮೀರಿದಾಗ `stale` ಫ್ಲ್ಯಾಗ್ `true` ಆಗಿರುತ್ತದೆ ಮತ್ತು ಮುಂದಿನ ವಿನಂತಿಯು ಹೊಸ ಪರಿಶೀಲನೆಯನ್ನು ಪ್ರಚೋದಿಸುತ್ತದೆ.

### ಪ್ರತಿ-ಪ್ರಾಕ್ಸಿ ಪ್ರಕಾರ ಡೀಫಾಲ್ಟ್ಗಳು

ಆರೋಗ್ಯ ತಪಾಸಣೆಯು URL ಯೋಜನೆಯ ಆಧಾರದ ಮೇಲೆ ಸಂವೇದನಾಶೀಲ ಡೀಫಾಲ್ಟ್ಗಳನ್ನು ಬಳಸುತ್ತದೆ:

| ಯೋಜನೆ                      | ಡೀಫಾಲ್ಟ್ ಪೋರ್ಟ್ |
| -------------------------- | --------------- |
| `http://`                  | 8080            |
| `https://`                 | 443             |
| `socks5://` / `socks5h://` | 1080            |

URL (`http://host:9999`) ನಲ್ಲಿನ ಕಸ್ಟಮ್ ಪೋರ್ಟ್ಗಳು ಯಾವಾಗಲೂ ಸ್ಕೀಮ್ ಡೀಫಾಲ್ಟ್ಗಿಂತ ಆದ್ಯತೆಯನ್ನು ತೆಗೆದುಕೊಳ್ಳುತ್ತವೆ.

## ಪ್ರಾಕ್ಸಿ ಅನಾಲಿಟಿಕ್ಸ್ ಮತ್ತು ವೀಕ್ಷಣೆ

ರೂಟಿಂಗ್ ಮಾದರಿಗಳು, ಲೇಟೆನ್ಸಿ ಸ್ಪೈಕ್ಗಳು ಮತ್ತು ಮರುಕಳಿಸುವ ವೈಫಲ್ಯಗಳನ್ನು ಪತ್ತೆಹಚ್ಚಲು ನಿರ್ವಾಹಕರಿಗೆ ಸಹಾಯ ಮಾಡಲುOmniRoute ಪ್ರತಿ-ಪ್ರಾಕ್ಸಿ ಬಳಕೆಯನ್ನು ಟ್ರ್ಯಾಕ್ ಮಾಡುತ್ತದೆ.

### ಏನು ಟ್ರ್ಯಾಕ್ ಮಾಡಲಾಗಿದೆ

ಕಾನ್ಫಿಗರ್ ಮಾಡಿದ ಪ್ರಾಕ್ಸಿ ಮೂಲಕ ಪ್ರತಿ ವಿನಂತಿಗಾಗಿ, OmniRoute ದಾಖಲೆಗಳು:

| ಮೆಟ್ರಿಕ್     | ವಿವರಣೆ                                                      |
| ------------ | ----------------------------------------------------------- |
| `proxy_url`  | ಪೂರ್ಣ ಪ್ರಾಕ್ಸಿ URL (ಮಾಸ್ಕ್ ಮಾಡಲಾದ ದೃಢೀಕರಣ ರುಜುವಾತುಗಳೊಂದಿಗೆ) |
| `provider`   | ಅಪ್ಸ್ಟ್ರೀಮ್ ಪೂರೈಕೆದಾರ ID (openai, anthropic, ಇತ್ಯಾದಿ)       |
| `latency_ms` | ಪ್ರಾಕ್ಸಿ ಹ್ಯಾಂಡ್ಶೇಕ್ ಸೇರಿದಂತೆ ಒಟ್ಟು ರೌಂಡ್-ಟ್ರಿಪ್ ಸಮಯ        |
| `connect_ms` | TCP ಸಂಪರ್ಕ ಸಮಯ ಮಾತ್ರ                                        |
| `status`     | ಅಪ್ಸ್ಟ್ರೀಮ್ನಿಂದ HTTP ಸ್ಥಿತಿ ಕೋಡ್                            |
| `error`      | ವಿನಂತಿಯು ವಿಫಲವಾದರೆ ದೋಷ ವರ್ಗ                                 |
| `timestamp`  | ISO 8601 UTC                                                |

### ಡೇಟಾವನ್ನು ಪ್ರವೇಶಿಸಲಾಗುತ್ತಿದೆ

```bash
# Recent proxy events
curl -H "Authorization: Bearer $OMNIROUTE_KEY" \
  "http://localhost:20128/api/usage/proxy-logs?limit=100"
```

ನಿಜವಾದ ಅಂತಿಮ ಬಿಂದು `/api/usage/proxy-logs` ಆಗಿದೆ ( `src/app/api/usage/proxy-logs/route.ts` ನೋಡಿ). ಈ ಅಂತಿಮ ಬಿಂದುವು ಬೆಂಬಲಿಸುತ್ತದೆ:

- `GET /api/usage/proxy-logs` — ಪ್ರಾಕ್ಸಿ ಲಾಗ್ಗಳನ್ನು ಹಿಂಪಡೆಯಿರಿ
- `DELETE /api/usage/proxy-logs` — ಎಲ್ಲಾ ಪ್ರಾಕ್ಸಿ ಲಾಗ್ಗಳನ್ನು ತೆರವುಗೊಳಿಸಿ

ಅಗತ್ಯವಿದ್ದರೆ ಒಟ್ಟು ಅಂಕಿಅಂಶಗಳನ್ನು `proxy_logs` ಟೇಬಲ್ನಿಂದ ನೇರವಾಗಿ SQL ಮೂಲಕ ಪ್ರಶ್ನಿಸಬಹುದು. ಡ್ಯಾಶ್ಬೋರ್ಡ್ UI ಒಟ್ಟು ವೀಕ್ಷಣೆಗಳನ್ನು ನೀಡಬಹುದು.

### ಸಾಮಾನ್ಯ ಮಾದರಿಗಳು

**ಫ್ಲಾಪಿಂಗ್ ಪ್ರಾಕ್ಸಿಯನ್ನು ಪತ್ತೆ ಮಾಡಿ** ( success/failure ನಡುವೆ ಪರ್ಯಾಯ):

```sql
SELECT proxy_url,
       COUNT(*) AS total,
       SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) AS errors,
       ROUND(100.0 * SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) / COUNT(*), 1) AS error_pct
FROM proxy_logs
WHERE timestamp > datetime('now', '-1 hour')
GROUP BY proxy_url
HAVING error_pct > 5
ORDER BY error_pct DESC;
```

**ನಿಧಾನ ಪ್ರಾಕ್ಸಿಗಳನ್ನು ಹುಡುಕಿ** (p95 ಲೇಟೆನ್ಸಿ > 2s):

```sql
WITH ranked AS (
  SELECT proxy_url, latency_ms,
         PERCENT_RANK() OVER (PARTITION BY proxy_url ORDER BY latency_ms) AS pct
  FROM proxy_logs
  WHERE timestamp > datetime('now', '-24 hour')
)
SELECT proxy_url, latency_ms
FROM ranked
WHERE pct >= 0.95
ORDER BY latency_ms DESC;
```

## ತಿರುಗುವಿಕೆಯ ತಂತ್ರ ನಿರ್ಧಾರ ಮರ

ಸ್ಕೋಪ್ಗೆ ಬಹು ಪ್ರಾಕ್ಸಿಗಳನ್ನು ನಿಯೋಜಿಸಿದಾಗ, OmniRoute a ಅನ್ನು ಬಳಸುತ್ತದೆ** ತಿರುಗುವಿಕೆಯ ತಂತ್ರ** ಪ್ರತಿ ವಿನಂತಿಗೆ ಯಾವುದನ್ನು ಬಳಸಬೇಕೆಂದು ಆಯ್ಕೆ ಮಾಡಲು. ಕಾರ್ಯತಂತ್ರವನ್ನು ಸ್ಕೋಪ್ ಮಟ್ಟದಲ್ಲಿ ಕಾನ್ಫಿಗರ್ ಮಾಡಲಾಗಿದೆ (ಜಾಗತಿಕ, ಪ್ರತಿ ಪೂರೈಕೆದಾರ, ಪ್ರತಿ ಖಾತೆ, ಪ್ರತಿ ಕಾಂಬೊ).

### ಲಭ್ಯವಿರುವ ತಂತ್ರಗಳು

| ತಂತ್ರ                | ಯಾವಾಗ ಬಳಸಬೇಕು                            | ವ್ಯಾಪಾರ-ವಹಿವಾಟು                                                                 |
| -------------------- | ---------------------------------------- | ------------------------------------------------------------------------------- |
| `quality` (ಡೀಫಾಲ್ಟ್) | ಮಿಶ್ರ ಗುಣಮಟ್ಟದ ಪ್ರಾಕ್ಸಿಗಳೊಂದಿಗೆ ಉತ್ಪಾದನೆ | ಉನ್ನತ ದರ್ಜೆಯ ಪ್ರಾಕ್ಸಿಗಳನ್ನು ಬೆಂಬಲಿಸುತ್ತದೆ; ಕಡಿಮೆ ದರದವರನ್ನು ಹಸಿವಿನಿಂದ ಸಾಯಿಸಬಹುದು |
| `random`             | ಲೋಡ್ ವಿತರಣೆ, ಗೌಪ್ಯತೆ                     | ಸಮ ವಿತರಣೆ; ಗುಣಮಟ್ಟದ ಸಂಕೇತಗಳನ್ನು ನಿರ್ಲಕ್ಷಿಸುತ್ತದೆ                                |
| `sequential`         | ಡೀಬಗ್ ಮಾಡುವಿಕೆ, ನಿರ್ಣಾಯಕ ಪರೀಕ್ಷೆ         | ಕ್ರಮದಲ್ಲಿ ಪ್ರಾಕ್ಸಿಗಳ ಮೂಲಕ ಸೈಕಲ್ಗಳು; ತರ್ಕಿಸಲು ಸುಲಭ                               |

## ನಿಮ್ಮ ಸ್ವಂತ ಪ್ರಾಕ್ಸಿಗಳಿಗಾಗಿ ಸ್ವಯಂಚಾಲಿತ ವೈಫಲ್ಯ ಹೊರಗಿಡುವಿಕೆ

1ಪ್ರಾಕ್ಸಿ ಮಾರ್ಕೆಟ್ಪ್ಲೇಸ್ ಪೂಲ್ ಈಗಾಗಲೇ ವಿಫಲವಾದ ಪ್ರಾಕ್ಸಿಗಳನ್ನು ತನ್ನದೇ ಆದ ಮೇಲೆ ಸ್ವಯಂ-ಡಿಗ್ರೇಡ್ ಮಾಡುತ್ತದೆ ( [ಪ್ರಾಕ್ಸಿ ಗುಣಮಟ್ಟದ ಸ್ಕೋರ್ಗಳನ್ನು](#proxy-quality-scores) ನೋಡಿ). ಪ್ರಾಕ್ಸಿಗಳಿಗಾಗಿ** ನೀವು** ನೋಂದಾವಣೆಗೆ ಸೇರಿಸಲಾಗಿದೆ, ಹಿನ್ನೆಲೆ ಆರೋಗ್ಯ ಶೆಡ್ಯೂಲರ್ (`src/lib/proxyHealth/scheduler.ts`) ಏನನ್ನೂ ಅಳಿಸದೆ ಅದೇ "ಸತ್ತ ಸದಸ್ಯರನ್ನು ಸರಪಳಿಯಿಂದ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಹೊರಗಿಡಿ" ನಡವಳಿಕೆಯನ್ನು ಒದಗಿಸುತ್ತದೆ:

```bash
# .env — soft-disable a proxy after 3 consecutive failed probes, re-enable it
# automatically once it starts answering probes again.
PROXY_AUTO_DISABLE=true
PROXY_AUTO_REMOVE_AFTER=3
```

ಇದು ಬಹು-ಪ್ರಾಕ್ಸಿ ಸರಪಳಿಗೆ ಹೇಗೆ ಹೊಂದಿಕೊಳ್ಳುತ್ತದೆ:

1. ಶೆಡ್ಯೂಲರ್ ಪ್ರತಿ ನೋಂದಾಯಿತ ಪ್ರಾಕ್ಸಿಯನ್ನು ಪ್ರತಿ `PROXY_HEALTH_INTERVAL_MS` (ಡೀಫಾಲ್ಟ್ 10 ನಿಮಿಷ; ಕನಿಷ್ಠ 1 ನಿಮಿಷ) ತನಿಖೆ ಮಾಡುತ್ತದೆ.
2. `PROXY_AUTO_REMOVE_AFTER` ಸತತ ನಂತರ** ನಿರ್ಣಾಯಕ** ವೈಫಲ್ಯಗಳು (ನಿಜವಾದ ಸಂಪರ್ಕ ವೈಫಲ್ಯ — ಸಮಯ ಮೀರಿದೆ ಅಥವಾ ತನಿಖೆಯ ಗುರಿಯ ಸ್ವಂತ 5xx ಎಂದಿಗೂ ಎಣಿಕೆಯಾಗುವುದಿಲ್ಲ, [ಪ್ರಾಕ್ಸಿ ಆರೋಗ್ಯ ತಪಾಸಣೆ](#proxy-health-checking-v3816) ನೋಡಿ), ಪ್ರಾಕ್ಸಿಯ `status` ಅನ್ನು `dead` ಗೆ ಹೊಂದಿಸಲಾಗಿದೆ.
3. `dead` ಎಂಬುದು pool/rotation ರೆಸಲ್ಯೂಶನ್ ಹೊರತುಪಡಿಸಿದ ಜೀವಂತ-ಸ್ಥಿತಿಯ ಫಿಲ್ಟರ್ ಸ್ಥಿತಿಗಳಲ್ಲಿ ಒಂದಾಗಿದೆ, ಆದ್ದರಿಂದ ಸ್ಕೋಪ್ನ ತಿರುಗುವಿಕೆಯು (ರೌಂಡ್-ರಾಬಿನ್ / ಯಾದೃಚ್ಛಿಕ / ಜಿಗುಟಾದ / ಲೇಟೆನ್ಸಿ — ನೋಡಿ [ರೊಟೇಶನ್ ಸ್ಟ್ರಾಟಜಿ ಡಿಸಿಷನ್ ಟ್ರೀ](#rotation-strategy-decision-tree) ) ಆ ಪ್ರಾಕ್ಸಿಯನ್ನು ಹೊಸ ವಿನಂತಿಗಳಿಗೆ ಹಸ್ತಾಂತರಿಸುವುದನ್ನು ತಕ್ಷಣವೇ ನಿಲ್ಲಿಸುತ್ತದೆ. ಪೂಲ್ನಲ್ಲಿ ಯಾವುದೇ ಇತರ ಪ್ರಾಕ್ಸಿಗಳು ಪರಿಣಾಮ ಬೀರುವುದಿಲ್ಲ, ಮತ್ತು ಸಂಪೂರ್ಣ ಪೂಲ್ ಎಂದಿಗೂ ಮೌನವಾಗಿ ನೇರ ಸಂಪರ್ಕಕ್ಕೆ ಹಿಂತಿರುಗುವುದಿಲ್ಲ — [4-ಹಂತದ ಪ್ರಾಕ್ಸಿ ಸಿಸ್ಟಮ್](#4-level-proxy-system) ವಿಫಲ-ಮುಚ್ಚಿದ ಗಾರ್ಡ್ ಅನ್ನು ನೋಡಿ.
4. ಶೆಡ್ಯೂಲರ್ ಅದೇ ಮಧ್ಯಂತರದಲ್ಲಿ `dead` ಪ್ರಾಕ್ಸಿಗಳನ್ನು ತನಿಖೆ ಮಾಡುತ್ತಿರುತ್ತದೆ. ಮುಂದಿನ ಯಶಸ್ವಿ ತನಿಖೆಯು `status` ಮತ್ತೆ `active` ಗೆ ತಿರುಗಿಸುತ್ತದೆ ಮತ್ತು ಇದು ರೊಟೇಶನ್ — ಅನ್ನು ಮರು-ಪ್ರವೇಶಿಸುತ್ತದೆ ಯಾವುದೇ ಹಸ್ತಚಾಲಿತ ಮರು-ಸೇರಿಸುವ ಅಗತ್ಯವಿಲ್ಲ.

ಇದು ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿದೆ** ಆಯ್ಕೆ ಮತ್ತು ವಿನಾಶಕಾರಿಯಲ್ಲ** : ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ ಶೆಡ್ಯೂಲರ್ ವೈಫಲ್ಯಗಳನ್ನು ಮಾತ್ರ ಎಣಿಕೆ ಮಾಡುತ್ತದೆ ಮತ್ತು ಲಾಗ್ ಮಾಡುತ್ತದೆ ( `decision.ts` ನಲ್ಲಿ C ನೀತಿಯನ್ನು ನೋಡಿ), ಮತ್ತು `PROXY_AUTO_DISABLE` ಎಂದಿಗೂ — ಸಾಲನ್ನು ಅಳಿಸುವುದಿಲ್ಲ, ಅದು ಪ್ರತ್ಯೇಕವಾದ, ಹೆಚ್ಚು ಆಕ್ರಮಣಕಾರಿ `PROXY_AUTO_REMOVE` ಧ್ವಜಕ್ಕಾಗಿ. ಎರಡನ್ನೂ `true` ಗೆ ಹೊಂದಿಸಿದರೆ, `PROXY_AUTO_REMOVE` ಗೆಲ್ಲುತ್ತದೆ (ಅಳಿಸಲಿರುವ ಪ್ರಾಕ್ಸಿಯು ನಡುವೆ ಮೃದು-ನಿಷ್ಕ್ರಿಯಗೊಳಿಸಲು ಯಾವುದೇ ಪ್ರಯೋಜನವಿಲ್ಲ). ಸಂಪೂರ್ಣ ವೇರಿಯಬಲ್ ಪಟ್ಟಿಗಾಗಿ [ಪರಿಸರ ಸಂರಚನೆಯ](../reference/ENVIRONMENT.md) ಉಲ್ಲೇಖವನ್ನು ನೋಡಿ.
